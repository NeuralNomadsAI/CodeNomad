# Custom keyboard shortcuts

## Agent conventions

- Settings → Keyboard shortcuts (`components/settings/hotkeys-settings-section.tsx`, square token-based styles in `styles/components/hotkeys-settings.css`) manages the static renderer-only catalog in `lib/hotkey-definitions.ts` in both app and native Preferences renderers, without mounting the app. Keep the `hotkeys` section allowlist identical in renderer, Electron and Tauri. Initially unbound palette commands appear with “No shortcut” under their existing translated names; aliases (`new-session` → `session-new`) keep one row. Native workspace actions are configurable but register for execution only in local desktop windows.
- Bindings live in the UI owner's `settings.hotkeyOverrides`: a missing ID uses its default, `[]` disables it, merge-patch `null` resets one ID or the map. The saved `promptSubmitOnEnter` supplies Enter defaults until an explicit composer override replaces them.
- Recording is renderer-only and target-scoped: it suppresses app shortcuts (not native accelerators), ignores IME composition and bare modifiers, lets unmodified Tab leave normally, and ends on blur, cancellation, inactive settings or disposal. Conflicts warn on every affected row and never silently disable a binding.
- Digit-row and bracket keys share one physical identity for recording, dispatch and conflicts (`Digit1` → `1`, `BracketLeft` → `[`, including AZERTY and QWERTZ); other keys stay logical. Saved layout-symbol overrides (`&`, `ü`, `!`) must be re-recorded to bind physical slots; never guess or silently migrate them.
- Initially unbound commands dispatch the palette's real action through `use-app-lifecycle.ts` and the existing keyboard registry, respecting its disabled state, active project/session and modal/selector guards, without key repeat; global commands also work on the home view.
- Shortcut hints live only in tooltips and the manager, never status strips or help footers: a bound control sets `title={withHotkey(label, id)}` (`lib/hotkeys.ts`) and menu items set `description: hotkeyLabel(id) || undefined`, leaving the accessible name unchanged, only where the shortcut performs that action in the control's current context (Ctrl+W only on the active tab).
- Composer shortcuts (Clear, agent/model/thinking selectors) reach the shown composer, including the no-session draft, through the instance's `session-sidebar-events` request; Clear dispatches `PROMPT_CLEAR_EVENT` so the composer runs its own Clear action, never a bare textarea write.
- Jump to previous/next user message (`user-message-prev`/`-next`, `components/user-message-navigation.ts`) defaults to Alt+↑/↓, and to Cmd+Option+↑/↓ on macOS, where Option+↑/↓ moves within a text field's paragraphs: neither default edits text, so the jump also works from the composer and other text fields. It runs in the active `MessageSection`'s capture-phase handler, before the transcript reads arrows as scrolling; palette commands reach it through `JUMP_USER_MESSAGE_EVENT`. Code editors and terminals (which bind modified arrows), arrow-key widgets, selects and popup triggers (Alt+↓ opens them), fields that move a list's active option (`aria-activedescendant`, `input[aria-controls]`, such as the mission picker search), non-text inputs, IME composition, modal dialogs and an open composer picker (`[data-prompt-picker]`, which moves its selection with every arrow) keep the keystroke; key repeat does not repeat the jump. Targets are the timeline's markers, including indexed history beyond the resident window (requested even while the timeline is hidden; a jump that finds nothing resident runs once it arrives). The last target stays the reference while loading or shown, until a scroll gesture or other navigation. Covered by `tests/browser/history-navigation.test.ts`.
- Native hotkeys keep their platform defaults outside the manager; native menu keys and OS-reserved combinations may intercept assignments before the renderer.
