## One ownership split

OpenCode owns child birth, actual ancestry, delegation, permissions, execution,
results, background jobs and exact-child continuation. Missions owns objectives,
declared task contracts, dependencies, evidence, reporting and human intervention.

The shared `MissionJournal` and reducer are the only business truth. Experimental
`plan/owner/current/report/history` stores are acceptance references, not a second
production engine. Authority reservation metadata is not a business plan.

Keep task generation, journal/document revision, grant epoch, signer generation,
writer incarnation and current invocation identity distinct. An unrelated edit
must not revoke unaffected work. Retirement preserves historical evidence, not
new execution authority.

## Mandatory negative and race controls

- Foreign sibling/ancestor refs, progress, report and continuation IDs refuse.
- Correct textual path/project with wrong workspace, checkout, parent, native
  process or writer incarnation refuses.
- Revocation/disposal/profile replacement during catalog, idle, ENV or progress
  awaits never admits a subsequent effect.
- Task/child overlap refuses immediately rather than waiting to become runnable.
- Parallel final-capacity births cannot create an excess child or ghost actor.
- Ambiguous admission/binding/ENV settlement remains denied, without replay,
  receipt repair or quota release inferred from absence of progress.
- Raw descendants obey family ENV/lifecycle policy without business reporting or
  topology authority; they do not become declared parents merely by ancestry.
- Report-before-return and return-without-report remain independent facts.
- A successful old report cannot settle a later current invocation.
- Background launch-return is not child terminal execution. Restart observation
  never becomes automatic Mission assignment replay.
- Native-return reports do not manufacture coordinator notification admission.
- Forks never inherit a business binding or derived authority implicitly.
- Hidden display demand stays cache-first and fenced; no progress polling.
- Unknown/native-unqualified host proof fails closed, with no permissive flag,
  caller-shaped attestation or process-proof substitution.

### Runtime prerequisites, not a guessed version floor

Current-version inspection used the installed 2.0.22 plugin declarations and
`C:/Users/Admin/AppData/Local/Temp/opencode/plugin-cancellation-audit-20261003/published-core-2.0.22/`.
The unrelated `D:/opencode` 2.0.15 checkout supplied source-path navigation only;
it is not evidence for the active ABI. Required runtime-owned capabilities are:

1. An opaque activation/writer identity plus complete bounded writer inventory
   across loaded Locations, including conservative treatment of unknown writers.
2. Targeted revocation/quiescence receipts covering already captured tool, hook,
   RPC and storage callbacks. Registry disposal and scope cleanup alone do not
   prove all old privileged writes have settled.
3. A namespace-restricted synchronous publication boundary binding current native
   writer/generation checks to the actual SQLite commit. Async plugin
   `storage.get/set/remove/scan`, JS locks and an immediate caller check do not
   provide a transaction/CAS or indivisible native guard.
4. Final Shell admission after mutable hooks, permission preparation and cwd/env
   changes, carrying authoritative session/operation/tool identity. The current
   `shell.create.before` draft has no such identity and is not the final boundary.
5. Final managed effect enforcement where later mutable model/tool/HTTP/WS hooks
   or revocation could otherwise supersede cooperative preparation.

Cooperative per-request preparation can use current session context, compaction,
generate, title, model/HTTP/WS/retry and tool hooks. It does not implement the
missing producer above. OpenCode's public plugin Session domain lacks environment
replacement; the authenticated backend prepares it. A later hook cannot update
environment bytes already assembled for the current Shell invocation.

A narrow owned SQLite producer could be separately designed, with a fresh actual
daemon-storage challenge and synchronous guarded commit. The pruning exception
is not a generic authority API and its session execution claim cannot establish
writer inventory or human/root ownership. No such shortcut, upstream/vendor fork,
shared-daemon change or new public runtime minimum is authorized or implemented
by these receipts. The whole-product gate remains blocked, rather than reporting
zero findings by excluding these prerequisites.

Captured component replay is not live authenticated native-to-backend HTTP/SSE
qualification. Process-local exclusion is not crash-atomic or cross-process
authority. Provider request inclusion is not model understanding. Interrupt or
Shell-removal acknowledgement is not universal OS-descendant suspension; measured
post-cancel effects exist for matched roots too.

Deterministic mutation fixtures use only isolated owned runtimes, profiles,
