# Projects and tabs

Closing project tabs, temporary workspaces, the new-instance launcher and the Git-unavailable degraded mode.

## Agent conventions

- Empty tabs (`kind: "blank"`, `stores/app-tabs.ts`) have window-local IDs and are filtered before session capture. A successful local/remote project or SideCar choice replaces its originating blank slot; keep that ID across asynchronous folder/clone selection, remote browsing, workspace creation and SideCar opens. Adding a server saves its profile and preserves empty tabs; selecting its Browse row shows its recent projects and folders in place until a folder is chosen. Other empty tabs retain their positions. Closing an empty tab makes no backend call. `FolderSelectionView` owns the Home and blank layouts, with shared `BrowseMenu`, `NewTabActions`, recent rows and browse/clone dialogs; the compact launcher uses `RecentTabsMenu`. Recent and Browse counts include their available entries; Browse counts the computer, saved servers visible to this host and configured SideCars, with the add-server field treated as an action.

- Closing a project tab detaches it immediately and requests deletion of that occurrence's logical backend workspace record; failures notify and never retry automatically. Separate occurrences of the same folder are independent. A `workspace.stopped` deletion closes the same record in other windows and notifies only windows displaying it that did not initiate the close. CodeNomad never evicts native Locations; OpenCode sessions keep running and reopening finds them. Whole-window close, app quit, renderer reload and backend shutdown keep existing restoration behavior. Temporary discard and server stop events use local-only tab detachment, not another DELETE; Keep closes the retained project normally.
- Git is a full-functionality prerequisite, with directory-only degraded conversations when the backend cannot find Git. Only the explicitly opened physical folder is session authority in that mode; never infer sibling worktrees from native project IDs. Keep ancestor/descendant mutation identities covered by the deletion fence across Git availability changes. Inform agents through the owned native `codenomad.git-availability` instruction before prompts/custom commands, remove stale context after recovery, and keep this advisory separate from fail-closed environment synchronization. Do not add a blocking Git setup UI. Validate with `scripts/test-git-degraded-native.mjs` using an isolated CLI/database and provider.
- Temporary instances (`workspaces/temporary-workspaces.ts`, UI `stores/temporary-instances.ts`) are ordinary non-Git workspaces on CodeNomad-created direct children of `<config>/temporary-workspaces`. Registry membership (`temporary-workspaces.json`), not location, makes a folder temporary; keeping only unregisters it and adds a named recent project. Discard deletes only registered children of that root, refuses running conversations and other open tabs of the folder, removes conversations deepest-first, closes the workspace before deleting the folder and keeps failed removals registered; such a folder is reachable only by browsing to it. Closing a temporary tab from the UI asks Keep/Discard/Cancel, except that an untouched one (no conversation, file or unsent draft) closes and is discarded silently (`onlyIfEmpty`: the server refuses with `temporary_has_conversations`/`temporary_not_empty`, and any failure of that quiet discard returns the choice without an error). Before the server stops it, a visible temporary tab yields to its neighbour (or closes if alone) and a refusal restores it in place; `workspace.stopped` likewise closes the tab first and clears the instance in a microtask, because clearing a visible shell's state in the same update as its tab freezes the window. Same-minute names get a `(n)` suffix. Registry changes broadcast `workspace.temporaryChanged`, which clears kept marks in every window. Open temporary tabs are saved and restored with the app state like any project tab (still marked temporary). Only the choice dialog overrides initial focus (to its last, non-destructive choice); confirms keep focus on Cancel. Refusals use stable `temporary_*` codes localized by the client. Validate with `scripts/test-temporary-workspaces-native.mjs` against an isolated CLI.
- The tab-bar new-instance button follows the last tab: the instance `TabScroll` frame spans its tabs and the button sits after it, outside the scroller, reaching the strip's end on overflow. Dragged tabs stay within the list (`KeepDraggedTabInStrip`), while the drop slot follows the unbounded pointer (`closestUnboundedCenter`). Clicking `+` or Cmd/Ctrl+N opens an empty tab. A long press, right-click, Alt+Down, Shift+F10 or Menu opens `NewInstanceLauncher` (`lib/long-press.ts`), titled Recent tabs, containing search and recents with their separate Open action. Its title-bar hourglass uses `window-icon-button` and the existing New temporary tab label and action. Keep browsing, authentication and server addition in the canonical selector. Escape dismisses the launcher and returns focus to `+`, without stealing focus from another surface or Home.
- Home uses two columns when space allows: full-width Clone Git Repo, New temporary tab and New SideCar actions followed by the OpenCode line on the left, and the Recent tabs | Browse selector with search on the right. The right panel stretches to the bottom of the left column, with its list scrolling inside. It preserves the centered CodeNomad logo/name, language, settings, Sponsor, GitHub stars and Discord links. Tab counts use `EntryCount` below their names; selected header tabs use `--surface-control`, with `--surface-hover-overlay` on hover. Recent rows retain inline rename/remove controls. Home, blank-tab and launcher recents share the uppercase `folder-home-open-instance-button` badge and its existing hover/focus treatment and switch tooltip. Blank tabs center the same logo/name block above two equal-width panels: Recent tabs and search on the left, Browse on the right, stacking at the narrow-layout breakpoint. Their background uses the active blank-tab chip's `--surface-shade-light`. Browse includes This computer, saved servers, SideCars and in-place server navigation; in blank tabs its shared server-add field sits above Clone Git Repo / New temporary tab at the bottom of Browse. New SideCar on Home opens `openSettingsRow("sidecars", "sidecar-add")`. `FolderSelectionView` shares recent data and Browse behavior between the layouts. Row selection persists only for keyboard navigation; pointer hover clears on leaving the row. Clone and temporary folders target the local backend explicitly, independently of the server being browsed. Blank-tab rename/remove actions use the recent-row menu. Servers are managed in Settings → Servers, SideCars in Settings → SideCars. Browse/clone dialogs live in `components/new-instance-dialogs.tsx`; display helpers in `lib/recent-folder-display.ts`.
- Recents share `launchableRecents`, `filterRecents` and `components/recent-tab-icon.tsx`: local projects, remote projects and configured SideCars. SideCars enter `ui.sidecarRecents` when opened (`stores/sidecar-open.ts`), storing only id and time. Across Home, blank tabs, quick launcher and Browse, selecting an entry creates a new occurrence for local projects, remote projects and SideCars even if already open. The separate Open action joins an existing occurrence; keep its click and keyboard activation distinct from the row's open-new action. Resolve remote identity by profile/server and folder, SideCars by configured id, and local projects by folder.
- Browse (`components/browse-menu.tsx`) lists This computer, host-visible saved servers, configured SideCars and the inline server-add field. `components/server-add-field.tsx` saves a profile; pasting adds immediately and Enter or + submits typed text. An existing address reuses its profile. Credentials in an address are rejected. A `tls_error` offers Skip TLS verification with explicit confirmation and a window-only profile. A Remote Control pairing link also asks the local backend to redeem its one-use code over the dedicated HTTPS tunnel protocol and persist a private device credential for browsing ([REMOTE_CONTROL.md](REMOTE_CONTROL.md#backend-to-backend-pairing)). The UI receives success only and scrubs the field after the attempt. Never persist a pairing code or retain it for native opening. Expired/replayed codes and rate limits have localized errors; unsupported remote pairing offers inline password recovery, which requires a direct-listener URL or a remote update for tunnel pairing.
- Choosing a saved Browse row shows that server's name through authentication and navigation. Visible username/password labels identify the inline direct-access form. Recent and Folders sections distinguish immediate project opening from folder traversal; Open this folder opens the current folder, replacing the originating blank slot. Back to Browse returns to the server list. Keep this flow shared by Home and blank tabs. Backend pairing survives launches; repair tunnel browsing with a fresh pairing link after revocation. Pairing errors name the affected server. TLS and unreachable-server failures use short localized messages with technical diagnostics available on demand. The edit dialog's URL/TLS help uses keyboard-accessible information controls.
- Known authentication limitation: backend browsing and native embedded views own independent authentication. Backend credentials persist privately; native views keep their own cookies and can require another sign-in or pairing. Unifying those authorities requires a separate backend/native authentication change; preserve the single-use pairing-code boundary.
- Separate-window fallback is explicit at project selection: opening actions identify the separate window for profiles skipping TLS verification and platforms without embedded-view support. Preserve that disclosure across canonical selectors and recent-entry opening paths.
- Settings → Servers (`settings/servers-settings-section.tsx`, host windows only) manages profiles through the same add field, the edit-only `RemoteServerDialog` (address, name, certificate check) and confirmed removal. Removal must call the backend forget endpoint before removing the profile, then clear its recents and close its tabs. Saving keeps the profile id; a rename with unchanged URL/TLS skips the probe (`saveProfile`). Opening from the tabless native Preferences window opens the server's window. `serverDisplayName` (`lib/codenomad-link.ts`) uses the saved name or hostname, showing a port when another saved server shares that hostname.
- A selected remote folder opens a `remote-project` app tab (`stores/remote-project-tabs.ts`, `stores/remote-project-open.ts`). `RemoteProjectView` places a native view over its content area: Electron `WebContentsView` (`electron/main/remote-view.ts`) or a Windows Tauri child webview (`src-tauri/src/remote_view.rs`). Other platforms and profiles that skip TLS verification open a separate remote window. Embedded views share the server's remote-window storage (Electron partition or Tauri data directory) and keep their own sign-in/device cookie; backend browsing uses its private credential store. Native access permits notifications only. Views stay on the server origin, open public help externally and return bare-root navigation after authentication to their tab entry. Tauri's `external-link-guard` checks registered `remote-view-*` labels through `RemoteViews::navigation_allowed` before window-origin rules. Views open lazily, track placeholder bounds, hide for inactive tabs and local overlays (`localOverlayOpen()`), and close with their owning page.
- Embedded single-project mode (`lib/embed-mode.ts`, `/?codenomadEmbed=project[&folder=…]`) shows one project without the title/tab bars, Home or native badge; its folder picker handles entries without a folder. It records the folder in the URL and project name in `document.title`, and restores the active session per folder (`rememberEmbeddedSession`, `stores/embedded-project-session.ts`). The host accepts title updates only from the server origin with a folder in the address. Servers without this mode show their full interface and retain the server title. Password sessions last seven days (`PASSWORD_SESSION_TTL_MS`) with matching cookie `Max-Age`; logout revokes them and bootstrap sessions use browser-session cookies. Tabs restore as `{kind: "remote-project", profileId, folder?}`; missing/window-only profiles drop their tabs. Remote recents (`ui.remoteProjectRecents`) contain server, folder and name only. Covered by `tests/browser/remote-project-tabs.test.ts`, `electron/main/remote-view.test.ts` and `remote_view.rs` tests.
- The clone dialog (`components/new-instance-dialogs.tsx`) suggests the repository's `git clone` folder name (`lib/clone-destination.ts`) inside a parent: the folder chosen with Browse, else the server-scoped `ui` state `lastCloneParent` (the folder above the last successful clone), else the folder above the most recent project. A destination the user types is kept as entered and sent unchanged; the server creates it.
