# Projects and tabs

## Agent conventions

### Remote opening ownership

- Browse keys its selected server by validated profile policy. Settings → Servers opens a new empty tab with that server selected. Origin, TLS and SSH changes dispose the browser and its work. Remote admission requires the enabled host preference (`multiBackend`, on by default), compatible metadata, the registered client, its live attachment and its bound relay proof.
- Web and desktop remote restoration check the saved server installation, then match the saved record before its folder occurrence. A missing or different saved installation identity keeps the tab and drafts unavailable. Reload and Retry bind existing records; explicit Open can create a missing record through the same inventory, commit, draft and uncertain-creation fences. Native local restoration keeps its own creation policy.
- The remote stream's first inventory refresh follows admission. A stream-triggered refresh captures the opening's connection generation before waiting for admission and checks it before requesting or publishing inventory. If a subsequent inventory omits a remote record during startup hydration, its placeholder takes the existing tab's position and selection. Retry uses the retained snapshot, which combines live state with saved state still awaiting hydration.
- `openRemoteProject` captures `WorkspaceCreationOwnership` from `createInstance.onCreation` before dispatch. Each untransferred exit joins one bounded discard flight against its exact backend/client/attachment/request. The commit gate fences obsolete receipts; later explicit opening preserves replacement occurrences. After guarded selection transfers ownership to the tab, the release ACK keeps the original API and request identity. Native selection ACKs match their exact opener and request.
- A suspended occurrence retains its ordered, selectable placeholder and complete snapshot. Retry shares the backend inventory flight and revalidates metadata and attachment; Connect admits credentials or a fresh pairing link. Failed, skipped or superseded reads leave the previous snapshot. Uncertain creations stay parked for original-request reconciliation; closure revokes pending creation and hands saved drafts to the occurrence-scoped vault. Temporary-folder discard authority follows the current backend event attachment.
- Profile removal confirms once, forgets its saved connection and hides its recents. Open tabs retain their positions and drafts, and projects and conversations stay on the owning backend. Retargeting checks authoritative inventory and tabs/drafts, including other-window drafts. Names may change in place.

### Browse and recent tabs

- Home presents Recent tabs and Browse as tabs; each empty tab presents both panels below its logo, Temporary and Clone. Browse counts places: this computer, saved servers and SideCars. The add field appears last, fixed at the bottom in empty tabs. Choosing a server opens its address field, folder list and connection controls in place; folder rows descend, Parent goes up, and Enter or the path arrow opens the folder. Recent tabs shows that server's shortcuts until Back restores the mixed list, with the count hidden while the server is unavailable. Browsing starts at the last known project path; a rejected directory offers Server root. Settings → Servers owns profile edits/removal and SSH.
- `recent-projects.ts` merges local recents with metadata from successful explicit remote opens. Host `state.ui.remoteProjectHistory` uses exact saved profile policy (ID, address, TLS verification and SSH target) plus the normalized workspace folder. The host folds list-shaped history at load and compacts after writes, retaining the newest 20 across profiles plus the latest for each active saved profile outside those 20. A successful open records the canonical folder and removes the requested alias; a retained row keeps its greatest access timestamp regardless of write order. Open and rename patch individual fields with owner Merge Patch. Remove deletes the keyed entry; stale name-only edits cannot recreate it, and reopening records it again. Retired targets disappear; offline targets retain their metadata. The mixed list also includes recently opened running SideCars. Choosing a row creates an occurrence. The separate Open action selects a matching tab, including a restore placeholder, and consumes the originating empty tab. In-flight Browse and recent operations are cancelled when their surface closes or their profile policy is retired.

### Project occurrences

- Host Git probes report `git_required` only for an absent executable (`ENOENT`). Timeouts, killed processes, unsuccessful exits and invalid version output yield `git_probe_unavailable` (503, retryable); the availability advisory propagates uncertainty to its best-effort caller rather than publishing installation guidance. The probe retains its five-second deadline and rechecks on demand.

- Browser history, URL and viewport sharing across duplicate tabs applies to local previews. Remote preview resources and saved data remain occurrence-scoped; never import remote URLs into the local session browser cache.

- Closing a project tab detaches it immediately and requests deletion of that occurrence's logical backend workspace record; failures notify and never retry automatically. Separate occurrences of the same folder are independent. A `workspace.stopped` deletion closes the same record in other windows and notifies only windows displaying it that did not initiate the close. CodeNomad never evicts native Locations; OpenCode sessions keep running and reopening finds them. Whole-window close, app quit, renderer reload and backend shutdown keep existing restoration behavior. Temporary discard and server stop events use local-only tab detachment, not another DELETE; Keep closes the retained project normally.
- Restorable workspace descriptors carry an optional versioned `viewState` envelope. `stores/tab-view-state.ts` owns its runtime copy by instance UUID; capture writes each occurrence's envelope alongside its own descriptor, and hydration seeds it onto the restored UUID before selecting a conversation. Repeated hydration preserves local gestures. Runtime tab bindings keep views attached through reorder and partial restore; explicit removal clears only that occurrence, while backend unavailability preserves recovery state. The envelope carries per-session chat/preview modes, Mission reader/selection/expanded rows/disclosures, right-panel selection and Files mode. Session-owned browser URLs/history/viewport persist in `opencode-session-browser-state-v1`. Consumers read `getTabViewState`, replace individual fields with `updateTabViewState` and reserve `seedTabViewState` for restoration; capture's optional accessor preserves unhydrated fallback state. Seeded Mission reader targets bind their instance references to the restored UUID. See [the restore payload](architecture.md#native-profiles-windows-and-client-state) for its storage contract.
- Client-state initialization adopts bounded folder/session preview entries into matching saved descriptors. A project-wide URL belongs to the first matching descriptor with a saved conversation, in descriptor order. Imported occurrence browser entries merge by session, preferring the active descriptor; local-storage entries prefer their most recently written occurrence. Each tab keeps its foreground mode. Resource URLs publish before imported envelopes reduce to modes; unmatched folders remain eligible for migration and consumed entries retire after accepted publication. Restoration seeds data only; a preview consumer must explicitly open its saved URL. Session browser persistence shares a 4,000-character window budget, with 32 sessions and 32 credential-free HTTP(S) history entries per session; history trims before preview eviction.
- Unsent drafts and attachments outlive their project tab in the window's memory (`stores/closed-workspace-drafts.ts`). `removeInstance` hands them over just before clearing them, keyed by project identity (`closedWorkspaceDraftKey`: backend profile, server installation for remote projects, and the `normalizeWorkspacePath` folder), for every removal: user close, a close from another window, a backend stop or restart reconciliation. Temporary discards (`drafts: "discard"`) keep nothing and purge the project's whole entry, drafts and attachments, because the folder is deleted. Every window recognizes them: the server deletes a discarded record (`workspace.stopped` with reason `deleted`) before unregistering its folder, whereas Keep unregisters first, so a deleted record whose folder the latest `workspace.temporaryChanged` still lists was discarded. That registry state is the only authority: the instance's `temporary` mark can be stale (a workspace-list response requested before Keep, a Keep missed while disconnected). Without a broadcast on the current event connection (none yet, or reset on reconnect) no removal is a discard and the drafts are kept, since an entry for a deleted folder is harmless and bounded while dropping a kept project's drafts loses work. Restoration-owned instances discarded by `removeRestoreCreatedInstanceFromUi` keep nothing either (`drafts: "skip"`; restoration still holds what it seeded). Closing several occurrences of a folder merges them, the later close replacing a session's text and attachments together, including a session it emptied by typing, clearing or sending (draft/attachment authority with no content), which removes the older value. Folder fallback supersedes older shared bundles, parked or pending. An exact occurrence updates or clears only its own bundles, even when its latest copy is in the shared entry. Saved snapshots remain scoped to their own occurrence. A restoration claims clear marks only for its exact saved workspace ID and folder. The opening claims vault bundles after its own saved prompts are known. Text, files and clear marks take precedence only for the exact saved workspace ID in the same folder. A successful delivery transfers the bundle to the receiving occurrence; undelivered bundles remain with their original owner. A plain folder opening fills an empty, untouched bundle from shared content or an unambiguous delivered successor. The new-conversation draft applies immediately and session drafts wait for initial hydration and owned native reads. A confirmed deletion transfers the text and attachments through the startup recovery rule; an unresolved draft stays in the vault. Filling empty sessions can copy one occurrence's draft into an empty, untouched session of another occurrence of the folder; nothing is overwritten. A restore that fails, or whose tab closes before it finishes, puts back underneath only the sessions it could not apply and the user did not touch there. The vault keeps up to 16 projects and up to 16 returned exact occurrences per project, evicting the oldest entry first. Desktop and web restoration persist open tabs across reloads.
- Git is a full-functionality prerequisite, with directory-only degraded conversations when the backend cannot find Git. Only the explicitly opened physical folder is session authority in that mode; never infer sibling worktrees from native project IDs. Keep ancestor/descendant mutation identities covered by the deletion fence across Git availability changes. Inform agents through the owned native `codenomad.git-availability` instruction before prompts/custom commands, remove stale context after recovery, and keep this advisory separate from fail-closed environment synchronization. Do not add a blocking Git setup UI. Validate with `scripts/test-git-degraded-native.mjs` using an isolated CLI/database and provider.
- Temporary instances (`workspaces/temporary-workspaces.ts`, UI `stores/temporary-instances.ts`) are ordinary non-Git workspaces on CodeNomad-created direct children of `<config>/temporary-workspaces`. Registry membership (`temporary-workspaces.json`), not location, makes a folder temporary; Keep and Discard use the owning backend; Keep unregisters the folder and adds a named recent project. Discard deletes only registered children of that root, refuses running conversations and other open tabs of the folder, removes conversations deepest-first, closes the workspace before deleting the folder and keeps failed removals registered; such a folder is reachable only by browsing to it. Closing a temporary tab from the UI asks Keep/Discard/Cancel, except that an untouched one (no conversation, file or unsent draft) closes and is discarded silently (`onlyIfEmpty`: the server refuses with `temporary_has_conversations`/`temporary_not_empty`, and any failure of that quiet discard returns the choice without an error). Before the server stops it, a visible temporary tab yields to its neighbour (or closes if alone) and a refusal restores it in place; `workspace.stopped` likewise closes the tab first and clears the instance in a microtask, because clearing a visible shell's state in the same update as its tab freezes the window. Same-minute names get a `(n)` suffix. Registry changes broadcast `workspace.temporaryChanged`, which clears kept marks in every window. Open temporary tabs are saved and restored with the app state like any project tab (still marked temporary). Only the choice dialog overrides initial focus (to its last, non-destructive choice); confirms keep focus on Cancel. Refusals use stable `temporary_*` codes localized by the client. Validate with `scripts/test-temporary-workspaces-native.mjs` against an isolated CLI.
- The tab-bar new-instance button follows the last tab outside `TabScroll`. Dragged tabs stay visually within the strip (`KeepDraggedTabInStrip`); the drop slot uses the pointer's unbounded position (`closestUnboundedCenter`). Click or Cmd/Ctrl+N opens an empty tab. A long press, right-click, Alt+Down, Shift+F10 or Menu opens the anchored `NewInstanceLauncher`: recent tabs with search and the Temporary action. Escape dismisses the launcher and returns focus to `+` when it still owns focus. Empty tabs are renderer-only and excluded from startup capture. Opening a folder or SideCar fills the originating slot; the Open action joins a tab in its current slot. Temporary and Clone target this computer. Home and empty tabs share `FolderSelectionView` and the local browse/clone dialogs.
- The clone dialog (`components/new-instance-dialogs.tsx`) suggests the repository's `git clone` folder name (`lib/clone-destination.ts`) inside a parent: the folder chosen with Browse, else the server-scoped `ui` state `lastCloneParent` (the folder above the last successful clone), else the folder above the most recent project. A destination the user types is kept as entered and sent unchanged; the server creates it.
