# Projects and tabs

Closing project tabs, temporary workspaces, the new-instance launcher and the Git-unavailable degraded mode.

## Agent conventions

- Closing a project tab detaches it immediately and requests deletion of that occurrence's logical backend workspace record; failures notify and never retry automatically. Separate occurrences of the same folder are independent. A `workspace.stopped` deletion closes the same record in other windows and notifies only windows displaying it that did not initiate the close. CodeNomad never evicts native Locations; OpenCode sessions keep running and reopening finds them. Whole-window close, app quit, renderer reload and backend shutdown keep existing restoration behavior. Temporary discard and server stop events use local-only tab detachment, not another DELETE; Keep closes the retained project normally.
- Git is a full-functionality prerequisite, with directory-only degraded conversations when the backend cannot find Git. Only the explicitly opened physical folder is session authority in that mode; never infer sibling worktrees from native project IDs. Keep ancestor/descendant mutation identities covered by the deletion fence across Git availability changes. Inform agents through the owned native `codenomad.git-availability` instruction before prompts/custom commands, remove stale context after recovery, and keep this advisory separate from fail-closed environment synchronization. Do not add a blocking Git setup UI. Validate with `scripts/test-git-degraded-native.mjs` using an isolated CLI/database and provider.
- Temporary instances (`workspaces/temporary-workspaces.ts`, UI `stores/temporary-instances.ts`) are ordinary non-Git workspaces on CodeNomad-created direct children of `<config>/temporary-workspaces`. Registry membership (`temporary-workspaces.json`), not location, makes a folder temporary; keeping only unregisters it and adds a named recent project. Discard deletes only registered children of that root, refuses running conversations and other open tabs of the folder, removes conversations deepest-first, closes the workspace before deleting the folder and keeps failed removals registered; such a folder is reachable only by browsing to it. Closing a temporary tab from the UI asks Keep/Discard/Cancel, except that an untouched one (no conversation, file or unsent draft) closes and is discarded silently (`onlyIfEmpty`: the server refuses with `temporary_has_conversations`/`temporary_not_empty`, and any failure of that quiet discard returns the choice without an error). Before the server stops it, a visible temporary tab yields to its neighbour (or closes if alone) and a refusal restores it in place; `workspace.stopped` likewise closes the tab first and clears the instance in a microtask, because clearing a visible shell's state in the same update as its tab freezes the window. Same-minute names get a `(n)` suffix. Registry changes broadcast `workspace.temporaryChanged`, which clears kept marks in every window. Open temporary tabs are saved and restored with the app state like any project tab (still marked temporary). Only the choice dialog overrides initial focus (to its last, non-destructive choice); confirms keep focus on Cancel. Refusals use stable `temporary_*` codes localized by the client. Validate with `scripts/test-temporary-workspaces-native.mjs` against an isolated CLI.
- The tab-bar new-instance button follows the last tab like a browser: the instance `TabScroll` frame only spans its tabs and the button sits after it, outside the scroller (so focusing it never scrolls the strip), ending up at the strip's end once tabs overflow. Dragged tabs stay visually within the tab list like a browser's (`KeepDraggedTabInStrip`), while the drop slot follows the pointer's unbounded position (`closestUnboundedCenter`). The button keeps its click (full home page, Cmd/Ctrl+N) while a long press, right-click, Alt+Down, Shift+F10 or Menu opens the anchored `NewInstanceLauncher` (`lib/long-press.ts`; only Escape returns focus to the button, never over another surface or the home page): search-first recent projects (an open project switches to its tab), Temporary/Clone, then the folded Browse section. SideCar and the management of recents stay on the home page; servers are managed in Settings → Servers. Browse/clone flows live once in `components/new-instance-dialogs.tsx` and recent-folder display helpers in `lib/recent-folder-display.ts`, shared with `FolderSelectionView`; styles in `styles/components/new-instance-launcher.css`.
- Remote project tabs show one project of a saved remote CodeNomad server inside a local window. Browse (`components/browse-menu.tsx`, one component below the home page's and the launcher's actions, its disclosure state shared per window) lists This computer (the native dialog or folder browser), then, in host windows only (`canOpenRemoteWindows()`), each saved server profile and Add server…; it offers no server management (no context menu). Add server… opens `RemoteServerDialog` through `components/remote-server-editor.tsx` (state `stores/remote-server-editor.ts`), mounted once in `App` because the launcher unmounts Browse as it closes. The dialog takes an address or a pairing link (`lib/remote-pairing-link.ts`); the name is optional (`codeNomadLinkName`), an address carrying credentials is refused, an address already saved reuses its profile, and a probe failing with `tls_error` shows its error so the user can skip TLS verification, which saves a window-only profile. Settings → Servers (`settings/servers-settings-section.tsx`, host windows only) is the one management surface: open, edit and remove (confirmed) each server, and add one, through the same dialog with `submitServer` (`lib/hooks/use-remote-server-profiles.ts`). Saving keeps the profile id, so its storage and sign-in stay, and a rename with the same URL and TLS setting skips the probe (`saveProfile`). Opening from the native Preferences window, which has no tabs, opens the server's window. Sign-in happens on the server's own page; the view's storage keeps it across launches. Servers read as `serverDisplayName` (`lib/codenomad-link.ts`): the saved name, or the host name when that name is a raw address (pasted servers are saved under `url.host`), with the port only when another saved server shares the host name; Browse, recents, Settings → Servers and a tab whose project is not chosen yet use it. Choosing a server opens a `remote-project` app tab (`stores/remote-project-tabs.ts`, actions in `stores/remote-project-open.ts`) whose `RemoteProjectView` places a native view (Electron `WebContentsView`, `electron/main/remote-view.ts`; Tauri child webview on Windows, `src-tauri/src/remote_view.rs`) over its content area; elsewhere, and for profiles that skip TLS verification, the server keeps its separate remote window. The view uses that server's remote-window storage (Electron partition, Tauri data directory), so its session or paired device cookie is reused without signing in again, and the remote preload/capability: of native access only notifications reach the host (badges and every local command are refused). It stays on the server's origin, the public help site opening in the system browser; a navigation to the bare root (end of login or pairing) returns to the tab's entry. Under Tauri every navigation also passes the app-wide `external-link-guard` plugin after the view's own handler: `intercept_navigation` asks `RemoteViews::navigation_allowed` first for registered `remote-view-*` labels, since the window-origin rules would cancel the view's first load. The view opens the first time its tab shows, follows the placeholder's bounds and hides while its tab is hidden or a local dialog, menu or list is open (`localOverlayOpen()`, shared with browser previews); a reload or close of the owning page closes its views. The remote page runs in embedded single-project mode (`lib/embed-mode.ts`, `/?codenomadEmbed=project[&folder=…]`): no title bar, tab bar or home page, a folder picker (`components/embedded-project-picker.tsx`) until a project opens, no native badge; it records the folder in its address and the project name in `document.title`, and keeps its active session per folder in its own persistent storage (`rememberEmbeddedSession`), reselected on reopening through the restored-tab hydration (`stores/embedded-project-session.ts`). A direct-access password sign-in lasts `PASSWORD_SESSION_TTL_MS` (seven days) with a matching cookie `Max-Age`, so the view stays signed in across host restarts while the server runs; logout revokes it server-side; bootstrap-token sessions keep browser-session cookies. The host accepts a title change only from the server's origin with a folder in the address, so a server without this mode shows its full interface and the tab keeps the server's name. Tabs restore as `{kind: "remote-project", profileId, folder?}` (a removed or window-only server drops its tab); projects opened in tabs join this host's recents beside local folders (`ui` state `remoteProjectRecents`, server, folder and name only; removing a server forgets them and closes its tabs). Covered by `tests/browser/remote-project-tabs.test.ts`, `electron/main/remote-view.test.ts` and `remote_view.rs` tests (navigation, ownership, ACL of the child label).
- The clone dialog (`components/new-instance-dialogs.tsx`) suggests the repository's `git clone` folder name (`lib/clone-destination.ts`) inside a parent: the folder chosen with Browse, else the server-scoped `ui` state `lastCloneParent` (the folder above the last successful clone), else the folder above the most recent project. A destination the user types is kept as entered and sent unchanged; the server creates it.
