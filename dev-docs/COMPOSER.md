# Composer

The prompt composer: context selectors, height, focus after send, alternate delivery, attachments, `@` mentions, overlays and `/btw`.

## Agent conventions

- The worktree selector admits its owning project before constructing its inventory, dialogs or handlers. Native chat shell commands and server-provided agents retain their separate chat authority.

- The composer shows no upload destination text. Device bytes travel with the message to the source composer's execution server; selection only reads them on the device. The existing device-read epoch includes server/directory binding and source disappearance, fencing pending pickers/reads on same-directory retargets while retaining settled drafts and attachments.

- Explicit-server chat uses the captured target's native agent/model/command/skill catalogues. Catalogue continuations and dependent built-in reads retain instance/binding/native/connection authority; a stale admission never acquires a replacement target. The mention menu explains unavailable project file references and guards discovery, synthetic roots, selection handlers and prompt admission independently. Device byte uploads retain their separate attachment path. Queued edits and failed sends preserve draft protections and never replay a mutation automatically.

- A send's failure restores its initiating draft only while its source occurrence and durable binding remain held and its draft has not changed. `usePromptState` advances the local text revision synchronously, including edit/clear cycles and hydration; attachment state has its own captured owner. Changing the displayed target preserves that target's newer typing; recovery writes the original source's draft/attachments without moving focus. Source lifecycle retirement fences recovery into a reused occurrence. Same-target catalogue read demand can recapture after a first native connection invalidates its initial read; queued mutations retain their first capture.

- Queue editing captures the real composer draft, attachment owner and known native payload before cancellation. Acknowledged cancellation restores the known payload only into that unchanged active draft, preserving intervening user focus. A changed draft, displayed target or failed acknowledgement keeps the known payload in the open source view through `usePromptRecovery`; the person checks the queue, clears the current draft/attachments and explicitly restores it for editing. Recovery copy keeps cancellation outcome conditional. Restoration uses the ordinary draft/attachment stores and never sends. These source-local recovery entries retire with the view or occurrence. Undo prefill follows the same draft/focus checks. A first-prompt creation captures its draft before awaiting and activates the created conversation only while that draft remains unchanged; registration captures its new composer's draft before a pending first-send failure can restore it.

- Retired actions and uncertain HTTP outcomes use one deduplicated, polite, non-modal source-conversation notice in `PromptRecoveryNotice`; known ordinary action errors retain their existing error dialog. Late callbacks preserve user focus. The notice distinguishes refused remaining steps from an earlier request that may already have been accepted, with an explicit conversation check before retry. Native multi-request actions keep their per-request fences.

- The CodeNomad explicit workspace proxy reports its uncertain 502 outcome with `explicit_request_uncertain`. The SDK adapter recognizes that structured envelope only on workspace-native proxy URLs and retains its code through the client's cause chain. Known environment/account admission failures retain their ordinary error identity through that same chain; transport wrapping keeps their dialog treatment.

- The composer reserves `/btw` for native `session.generate`, outside ordinary prompt/command submission. Its ephemeral question/answer window uses `DismissibleWindow` and `styles/components/session-aside.css`; cancellation and inactive/session transitions fence late results without interrupting the main session. Response publication requires captured instance authority; settling `pending` requires ownership of that question's controller. A retired connection's settled owner becomes explicitly retryable with contextual feedback, while a cancelled/closed owner leaves a newer question untouched.
- The aside's Markdown receives its instance owner. Explicit or unowned aside content accepts validated, bounded embedded images only: its ephemeral answer holds no qualified native-message reference. Explicit attachment display/download uses the transcript media policy; device selection budgets and sending bytes retain their existing independent controls.
- Keep agent, model and thinking controls in the composer footer via `PromptContextControls`, on one row with the actions on desktop and touch (truncate selector labels, never wrap the footer); adapt it with the named `prompt-composer` container rather than viewport-only breakpoints. Dense conversation toolbar/footer controls and the session list header actions use `--touch-target-size-compact` (the latter must fit five actions plus the panel-toggle reserve in the 220 px minimum sidebar); timeline markers use the compact control height rather than the global touch target. Toolbar touch spacing lives in `styles/panels/session-toolbar-touch.css`.
- Composer height limits depend only on the visible conversation height: minimum 8% (44 px floor), maximum 60% (never below that minimum). `prompt-input/usePromptViewport.ts` observes the conversation and its intersection with `visualViewport`, including keyboard resize/pan. Store manually chosen heights as proportions so the field itself follows viewport changes; saved pixel heights convert to a proportion on the first valid measurement. Viewport-driven changes never overwrite the saved proportion; pointer and keyboard resize controls share the same limits and long drafts remain scrollable.
- On desktop a send moves focus to the conversation stream for keyboard reading (arrows, paging, Space); a printable character typed there resumes the composer with that character (`prompt-input/type-to-focus.ts`), while fields, controls, IME composition and plain-key shortcuts keep their keys. Touch-only devices keep the keyboard closed. Do not add delayed refocus timers or a preference for this.
- The composer's More actions menu offers the other follow-up delivery than Enter (Queue message when Enter steers, Steer now when Enter queues), enabled only in normal mode while the session runs and a draft can be sent; it reuses the shortcut's delivery resolution and its tooltip shows the `prompt-alternate-send` shortcuts: Alt+Enter plus Mod+Shift+Enter by default, except on macOS where Option+Return is the native line break and only Cmd+Shift+Return sends. Pickers ignore any modified Enter. Covered by `tests/browser/composer-alternate-send.test.ts` and `composer-picker-enter.test.ts`.
- Composer overlays show attachment counts, shell-mode state and transient stop confirmation only; keep the textarea's semantic description and transient status announcement. Do not add a keyboard-shortcut strip or help footer. Keep overlay styling in `styles/components/prompt-help.css`, without changing field height limits or adding a footer row.
- Composer attachments use one native-device action and project-scoped `@` references. Picker/drop/clipboard bytes share `prompt-input/useDeviceAttachments.ts` for serialized budgets and epoch-based draft/focus fencing; keep lifecycle and read logic out of `prompt-input.tsx`. File listing/search validate the session directory through existing workspace ownership before reading a worktree or translated WSL root.
- An Images conversation (root session marked `codenomad.companion: images`) whose selected agent is `design` while its own Location's loaded agent catalog lacks it (a list read for another Location counts as not loaded, `agentCatalogLocations`) shows `DesignAgentNotice` above the composer, with "Use the default agent" (the catalog's first selectable primary agent, through the session's agent change), and `PromptInput`'s `sendBlocked` refuses every send (prompt, command, shell, `/btw`) while typing stays available. Another selected agent, an unmarked conversation and an unloaded catalog never block. Covered by `tests/browser/images-conversation.test.ts`.
- Panel extensions add text to the displayed conversation's draft only through API 4 `composer.prefill` (`components/panel-extensions/composer-prefill.ts`, [rules](PANEL_EXTENSIONS.md#api-4)): `PromptInputApi.setPromptText` with the draft composed from `getPromptText()`, refused in shell mode (`getMode()`), when the result starts with `/` or when `findMentionStart` (exported from `prompt-input/usePromptPicker.ts`, the picker's own rule) finds an open mention at its end. Never send, attach or resolve mentions from it; Ctrl+Z in the composer leaves the added text in place. Covered by `tests/browser/panel-extension-api4.test.ts`.
- Host actions that show a conversation and hand it the keyboard call `requestComposerFocus` (`stores/composer-focus.ts`); the active `SessionView` consumes the request and focuses its composer two frames later, on every layout. Do not focus composers from stores through DOM queries.
- The `@` mention menu lists Location skills with search, names and descriptions; selecting one attaches a removable skill and drops the `@query` token. Skills use the existing `PromptAttachmentsBar` alongside files and agents, never a separate composer row. The default prompt placeholder lists skills alongside files and agents in every locale. Keep the composer free of a permanent Skills button or `/skills` shortcut. Explicit attachments use native `skill.list` for the session Location and send IDs through `prompt.skills`; selection lives in `prompt-input/usePromptPicker.ts`. Sending clears only the composer selection; OpenCode keeps the instructions stored with the message. `MessageBlock` retains skill labels in sent and historical messages without exposing instruction bodies or inventing tool calls; test through the full transcript, not an isolated badge. Queued edits restore removable attachments, never reinsert removed skills from the original payload.
- A long paste becomes a `pasted #N` text attachment and a `[pasted #N]` placeholder in the draft. Sending resolves each placeholder in place (`lib/prompt-display-metadata.ts`), so the model receives the pasted text exactly once, wherever the placeholder stood (inside code fences too), and never as a separate part. The local display metadata records only inline/pasted segment lengths; `splitPromptDisplaySections` renders each pasted segment as a folded "Pasted text" section (line count, copy), and a fenced code block (```` ``` ````/`~~~`, any info string, closed or running to the end) containing pasted text renders as one such section holding the block's code, counting and copying the code between its fences (without the line break before the closer, LF or CRLF). Lines touching pasted text are never fence lines (a paste ending in a line break ends its line), closers take only spaces or tabs after the fence. The section holds only the code and its opening fence (`codeFence`): Markdown bounds the code itself and `formatFencedCode` (its `formatText`) fences each displayed window with a fence longer than any run of its marker in that window, so fences inside a paste stay literal code and the display bound never cuts a generated fence. Never rewrite the sent text to change its display. Covered by `lib/prompt-display-metadata.test.ts` and `tests/browser/pasted-code-fence.test.ts`.
