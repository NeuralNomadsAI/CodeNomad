# ブラウザープレビューと SideCar

## セッションのブラウザーを開く {#session-browser}

1. 会話のツールバーで **Web プレビューを開く** を選びます。
2. 認証情報を含まない `http://` または `https://` の **プレビュー URL** を入力し、**プレビューを開く** を選びます。ツールバーで移動、更新、戻る／進むを行います。
3. プレビューの閉じるボタンでチャットに戻ります。その会話で開き直すと続行できます。

会話内の `localhost` または `127.0.0.1` リンクをクリックすると、どのクライアントでもそのセッションのプレビューで自動的に開きます。サーバーがループバックのプレビューをプロキシするため、別のマシンの通常のブラウザーからでも機能します。プロキシされたループバックプレビューは **設定 → プレビュー** に従い、既定の不透明モードでは CodeNomad から分離されます。外部リンクは引き続き新しいブラウザータブで開きます。

各プレビューは、プロジェクトフォルダーとセッションに属します。会話、プロジェクト、情報、チャットの切り替えでは、明示的に開いたネイティブゲストを非表示にしますが、現在の文書／履歴を破棄しません。非表示のゲストは自動操作の対象ではありません。プロジェクト／ウィンドウを閉じるか、レンダラーを再起動すると、現在の文書は終了します。

保存済み履歴は、そのセッションのブラウザーを明示的に開き直したときにだけ復元し、起動時やセッション選択時には復元しません。保存するのは URL とカーソルであり、未送信フォーム、DOM、POST 本文、JavaScript のメモリではありません。履歴はセッションごとに 32 URL と共有レイアウト容量の上限があり、古い項目は削られる場合があります。URL の復元は新しいページ読み込みを行う場合があり、トランザクションの再実行ではありません。

## プレビューのオリジンと権限 {#preview-origins}

プレビューは会話内に留まり、CodeNomad が別のプレビューウィンドウを開くことはありません。**設定 → プレビュー** は CodeNomad サーバー全体に 1 つのポリシーを設定します。これはブラウザー表示とリモート表示のプレビューに適用されます。macOS と Linux の Tauri は iframe を使用します。ローカルウィンドウが loopback で配信される場合はトークンごとの分離されたオリジンを維持し、それ以外は選択したパスオリジンを使用して、これらの切り替えに従います。Electron と Windows Tauri のネイティブ WebView は独自の権限、ダウンロード、ポップアップの動作を維持します。

| オリジンモード | 動作 |
| --- | --- |
| 不透明（推奨） | どのプレビューも CodeNomad や他のプレビューとオリジンを共有しません。ストレージ、Cookie、Service Worker、オリジンに依存するブラウザー API が利用できないため、一部の Web アプリは動作しない場合があります。 |
| CodeNomad と同じオリジン | ループバックプレビューは CodeNomad のオリジンで実行され、外部プレビューは不透明のままです。 |
| 専用プレビューオリジン | ループバックプレビューは設定したオリジンで実行され、外部プレビューは不透明のままです。 |

**CodeNomad と同じオリジンは完全な信頼を意味します。** プレビューのコードは CodeNomad のストレージ、トランスクリプト、DOM を読み取り・変更し、セッションでアプリの API を呼び出し、プレビューを閉じた後も残る Service Worker を登録できます。管理下にあり信頼できるサーバーでのみ使用し、共有サーバーやリモートサーバーでは決して使用しないでください。CodeNomad は有効化の前に確認を求めます。

**専用プレビューオリジン** では、CodeNomad が配信されるすべてのオリジンと異なるホスト名を使用し、`/previews/*` とその WebSocket アップグレードを同じサーバーへルーティングしてください。`Host` ヘッダー、レスポンスヘッダー、注入されたコンテンツセキュリティポリシーを維持し、安全なコンテキスト API のためにオリジンを TLS で配信します。CodeNomad はオリジンに到達できるか確認できません。ルートが壊れているとプレビューは失敗します。書き換えられた `/previews/<token>/...` 名前空間を迂回するルート相対の Worker と Service Worker は、専用オリジンではサポートされません。Cookie を分けるのは別のポートではなく別のホスト名です。

CodeNomad は専用プレビューオリジン自身の Cookie を CodeNomad オリジンから分離します。プレビューオリジンが兄弟サブドメインの場合も同一サイトのままなので、ブラウザーは CodeNomad へのリクエストに `SameSite=Lax` の CodeNomad セッション Cookie を送ります。CodeNomad は、そのオリジンを `Origin` または `Referer` に含むアプリ API リクエスト（`/api/`、`/workspaces/`、`/sidecars/`）を拒否します。厳密な Cookie 分離が必要な場合は別のサイトを使用してください。

**サンドボックス**の切り替えは、iframe プレビューでフォーム、モーダルダイアログ、ポップアップ、ダウンロードを許可します。スクリプトは常に必要です。**ブラウザー機能**の切り替えは、プレビューがカメラ、マイク、クリップボードの読み取り/書き込み、位置情報、全画面表示を要求できるようにするだけです。ブラウザーは引き続き許可を求め、ブラウザーのサイト設定が最終的な判断となります。CodeNomad の切り替えでブラウザーのブロックを解除することはできず、ブラウザーで許可しても無効な機能は復元されません。Electron と Windows Tauri のネイティブ WebView はこれらの iframe 切り替えに従いません。

オリジンモード、専用オリジン、サンドボックス、機能ポリシーを変更すると、開いているプレビューが再読み込みされ、信頼レベルを下げた後に以前の信頼された文書が残り続けることはありません。

## 共有ログインと自動操作の境界 {#signins-automation}

ネイティブプレビューは、同じデスクトップエンジンとプロファイル／設定範囲のプロジェクト／セッション間で、Cookie、ログイン、サイトストレージを共有します。信頼された CodeNomad レンダラーとは分離されています。1 つのプレビューでサイトからログアウトすると、同じストアを使う他のプレビューにも影響します。文書、フォーム、セッションストレージ、移動履歴、自動操作の接続はセッションに属したままです。iframe プレビューは、完全な共有ネイティブブラウザープロファイルではありません。

| クライアント | プレビューの実装 | エージェントのブラウザー自動操作 | モバイルテンプレート |
| --- | --- | --- | --- |
| 対応デスクトップ環境の Electron | ネイティブ Chromium ゲスト | 所有する表示中のセッションプレビューで対応 | Android/Chromium の識別、タッチ、密度のエミュレーション |
| Windows Tauri | ネイティブ WebView2 子 | 所有する表示中のセッションプレビューで対応 | Android/Chromium の識別、タッチ、密度のエミュレーション |
| macOS/Linux Tauri | サンドボックス化 iframe | ネイティブブラウザー自動操作なし | 寸法のみ |
| 通常のブラウザー／リモート表示 | 代替 iframe | ローカルのネイティブプレビュー対象なし | 寸法のみ |

ネイティブ自動操作はデスクトップ起動時に準備され、セッションに紐づく `codenomad.browser` ツールで open、navigate、snapshot、screenshot と、ページ操作（クリック、入力、選択、ホバー、ドラッグ、スクロール、キー入力、テキストの出現待ち）を行います。ツールが使えることは、全ウィンドウの操作許可ではありません。実行時に、所有するバックエンド、ネイティブ機能、セッション、表示中の対象を確認します。その間にページが非表示、置き換え、移動された操作は、別のページへ送られずに拒否され、操作が自動的に繰り返されることもありません。ページ内容は引き続き信頼できない情報です。埋め込みを対象が禁止して iframe が失敗する場合は、保護を弱めず外部ブラウザーを使ってください。

## 6 種類のビューポートテンプレートから選ぶ {#templates}

1. プレビューのビューポートメニューを開きます。
2. 下表から選びます。縦／横の項目を直接使い、独立した回転コントロールはありません。
3. モバイルエミュレーションの開始／変更や、寸法のみのテンプレートへ戻る際は、ネイティブの再読み込みが行われます。

| テンプレート | CSS ビューポート |
| --- | --- |
| レスポンシブビューポート | 利用可能なプレビュー領域 |
| デスクトップビューポート | 1440 × 900 |
| タブレットビューポート | 768 × 1024 |
| タブレット横向き | 1024 × 768 |
| モバイルビューポート | 390 × 844 |
| モバイル横向き | 844 × 390 |

ネイティブのモバイルテンプレートは、所有するゲストにだけ Android/Chromium の識別、向き、タッチ、DPR 2.75 を設定します。レスポンシブ／デスクトップ／タブレットへ戻ると上書きを解除し再読み込みします。代替 iframe はサイズを変えるだけです。再現可能なレイアウトの基準であり、Safari/Firefox のエミュレーションや、携帯のキーボード、ブラウザー／システムバー、モバイル OS の文字設定のシミュレーションではありません。再読み込みで未送信のページ状態を失う場合があるため、テンプレート変更前にページ上の作業を保存してください。

## SideCar を登録する {#register-sidecar}

1. CodeNomad バックエンドホストで、ウェブツールを別途起動し、`127.0.0.1:<port>` で待ち受けます。
2. **設定 → SideCar** を開き、**名前** と **ポート** を入力し、算出された **ベースパス**（`/sidecars/<id>`）を確認します。
3. 上流サービスに合わせて **プロトコル** を設定し、**プレフィックスモード** を選びます。
4. **SideCar を追加** を選び、ホームページの **SideCar を開く** でタブを開きます。

| 選択 | 正確な効果 |
| --- | --- |
| HTTPS（フォームの既定） | CodeNomad は `https://127.0.0.1:<port>` として上流に接続します。 |
| HTTP | CodeNomad は `http://127.0.0.1:<port>` として上流に接続します。公開側の CodeNomad 接続の TLS 設定は変えません。 |
| プレフィックスを削除（既定） | `/sidecars/<id>/path` を `/path` として上流に転送します。 |
| プレフィックスを保持 | `/sidecars/<id>/path` を変更せずに上流へ転送します。サービス自体のベースパスを一致させてください。 |

登録はクライアント間で共有されるサーバー設定であり、サービスのインストールや起動はしません。ポートはバックエンドホスト上にあり、閲覧中のノートパソコンやスマートフォン上ではありません。**実行中** は到達可能性を示し、ツールのアプリ／認証が正常だとは限りません。登録を削除しても、別に起動したプロセスは停止しません。タブを閉じても停止しません。

到達できない場合はバックエンドのプロセスとポートを確認します。HTML は読めても資産／WebSocket が失敗する場合は、ツールのベースパスとプレフィックスモードを確認します。誤った登録は目的の設定で作り直してください。プロキシエラーの回避だけのために上流を公開しないでください。SideCar アプリは、サーバーアカウントの権限でターミナルやファイルを公開できるため、利用者と設定を信頼する必要があります。

SideCar はサンドボックス化されたプレビューではなく、CodeNomad の信頼された拡張です。そのページは CodeNomad 自身のオリジンで動作するため、スクリプトはサインイン済みのアクセス権で CodeNomad を利用できます。コードを信頼できるサービスだけを登録してください。CodeNomad は自身のサインイン Cookie をサービスへ転送しませんが、サービス自身の Cookie は保持されます。リモートコントロールは SideCar アプリのプロキシ通信を公開しません。[リモートアクセス](remote-access.md)と[リモートコントロール](remote-control.md)に記載の適切な直接接続経路を使用します。

## OpenVSCode Server の例 {#openvscode}

1. バックエンドホストで、サービスをループバックにバインドして Docker を実行します。

```sh
docker run -it --init -p 127.0.0.1:8000:3000 -v "${HOME}:${HOME}:cached" -e HOME=${HOME} gitpod/openvscode-server --server-base-path /sidecars/vscode
```

2. **名前** `VSCode`、**ポート** `8000`、**プロトコル** `HTTP`、**プレフィックスモード** **プレフィックスを保持** で登録します。
3. 表示されたベースパスが `/sidecars/vscode` であることを確認し、SideCar を開きます。

このシェルの例は、ホームディレクトリをコンテナーにマウントします。エディターのアクセス範囲を絞るなら、より狭いマウントを使用してください。サービスの `--server-base-path` は、登録と正確に一致する必要があります。終わったらコンテナーを別途停止してください。SideCar の削除ではコンテナーやそのファイルは削除されません。

## ttyd ターミナルの例 {#ttyd}

1. バックエンドホストで、書き込み可能なシェルターミナルをループバックにバインドして起動します。

```sh
ttyd --interface 127.0.0.1 --writable zsh
```

2. **名前** `Terminal`、**ポート** `7681`、**プロトコル** `HTTP`、**プレフィックスモード** **プレフィックスを削除** で登録します。
3. 表示された `/sidecars/terminal` ベースパスで SideCar を開きます。

ターミナルは ttyd を起動したアカウントの権限で実行します。`zsh` がなければ別のシェルを選びます。ttyd の既定ポートを変えた場合は実際のポートを使い、終了時は ttyd を別途停止してください。CodeNomad へのアクセスを認証・保護してください。書き込み可能なターミナルはサンドボックスではありません。
