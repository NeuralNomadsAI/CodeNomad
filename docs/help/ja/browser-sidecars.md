# ブラウザープレビューと SideCar

## セッションのブラウザーを開く {#session-browser}

1. 会話のツールバーで **Web プレビューを開く** を選びます。
2. 認証情報を含まない `http://` または `https://` の **プレビュー URL** を入力し、**プレビューを開く** を選びます。ツールバーで移動、更新、戻る／進むを行います。
3. プレビューの閉じるボタンでチャットに戻ります。その会話で開き直すと続行できます。

会話内の `localhost` または `127.0.0.1` リンクをクリックすると、プレビューが利用できるクライアントではそのセッションの Web プレビューで開きます。Remote Control でホストが Web プレビューをオフにしている場合や、プレビューがそれ以外の理由で利用できないクライアントでは、こうしたリンクは通常のブラウザー動作のままです。Ctrl+クリック（macOS では ⌘+クリック）または中クリックで、代わりにブラウザーで開きます。実際のストレージを利用できないサンドボックス化されたプレビューフレーム内では、ページは現在のページ読み込み用のメモリ上の `localStorage`・`sessionStorage`・`document.cookie` を受け取ります。単独で開いたトークンごとのプレビューホストは実際のストレージを保持します。

各プレビューは、プロジェクトフォルダーとセッションに属します。会話、プロジェクト、情報、チャットの切り替えでは、明示的に開いたネイティブゲストを非表示にしますが、現在の文書／履歴を破棄しません。非表示のゲストは自動操作の対象ではありません。プロジェクト／ウィンドウを閉じるか、レンダラーを再起動すると、現在の文書は終了します。

保存済み履歴は、そのセッションのブラウザーを明示的に開き直したときにだけ復元し、起動時やセッション選択時には復元しません。保存するのは URL とカーソルであり、未送信フォーム、DOM、POST 本文、JavaScript のメモリではありません。履歴はセッションごとに 32 URL と共有レイアウト容量の上限があり、古い項目は削られる場合があります。URL の復元は新しいページ読み込みを行う場合があり、トランザクションの再実行ではありません。

## 共有ログインと自動操作の境界 {#signins-automation}

ネイティブプレビューは、同じデスクトップエンジンとプロファイル／設定範囲のプロジェクト／セッション間で、Cookie、ログイン、サイトストレージを共有します。信頼された CodeNomad レンダラーとは分離されています。1 つのプレビューでサイトからログアウトすると、同じストアを使う他のプレビューにも影響します。文書、フォーム、セッションストレージ、移動履歴、自動操作の接続はセッションに属したままです。iframe プレビューは、完全な共有ネイティブブラウザープロファイルではありません。

| クライアント | プレビューの実装 | エージェントのブラウザー自動操作 | モバイルテンプレート |
| --- | --- | --- | --- |
| 対応デスクトップ環境の Electron | ネイティブ Chromium ゲスト。OAuth ポップアップ、ダウンロード、ダイアログに対応 | 所有する表示中のセッションプレビューで対応 | Android/Chromium の識別、タッチ、密度のエミュレーション |
| Windows Tauri | ネイティブ WebView2 子。OAuth ポップアップ、ダウンロード、ダイアログに対応 | 所有する表示中のセッションプレビューで対応 | Android/Chromium の識別、タッチ、密度のエミュレーション |
| macOS Tauri (14+) | ネイティブ WKWebView 子。OAuth ポップアップ、ダウンロード、ダイアログに対応 | 所有する表示中のセッションプレビューで対応 | WebKit モバイル識別と CSS ビューポート。入力はネイティブ環境の制約あり |
| Linux Tauri | ネイティブ WebKitGTK 子。OAuth ポップアップ、ダウンロード、ダイアログに対応 | 所有する表示中のセッションプレビューで対応 | WebKit モバイル識別と CSS ビューポート。密度と入力はネイティブ環境の制約あり |
| 通常のブラウザー／リモート表示 | 代替 iframe | ローカルのネイティブプレビュー対象なし | 寸法のみ |

すべてのネイティブデスクトップホストで、セッションに紐づく `codenomad.browser` がプレビューを開き、移動、スナップショット、スクリーンショット、クリック、入力、選択、ホバー、ドラッグ、スクロール、キー入力、テキスト待機を実行します。所有するバックエンド、ネイティブ機能、セッション、表示中の対象を確認します。非表示、置き換え、移動済みの対象は拒否し、操作を自動で繰り返しません。ページ内容は信頼できない情報です。iframe を禁止するサイトは外部ブラウザーで開いてください。

ネイティブプレビューは手動またはエージェントで開き、再起動後もログインを保持し、戻る／進む履歴を使用します。ローカルメニューやダイアログはプレビューを隠します。ネイティブモードでは要素コメントは利用できません。WebKit はスクリプトで作成した閉じた shadow root を取得し、宣言的な閉じた root は不透明なままです。macOS の最初のホバーは pointerenter を省く場合があり、⌘A は A keydown なしでネイティブ選択します。GTK のクリップボード読取は明示的な Ctrl+V で行い、書込とネイティブのコピー／貼付は動作します。

ネイティブポップアップはプレビューのログイン状態を共有し、`opener`/`postMessage` を保持し、元のページとともに閉じます。入力・復元するアドレスは認証情報のない HTTP(S) のみで、サイトは空白文書や同一オリジンの blob 文書も開けます。ファイル・アプリのスキームは拒否されます。ダウンロードは安全な一意の名前でダウンロードフォルダーに保存され、上書き・自動実行しません。カメラ、マイク、位置情報、通知は拒否され、分類済み権限には同意が必要です。不明な要求はエラーを表示します。Tauri と Electron は `alert`/`confirm`/`prompt` に対応し、Electron の prompt ダイアログはプレビューのトップレベルページ、ポップアップ、サブフレームで利用できます。デバイスと画面の選択リストはスクロールできます。その他の API はエンジンとハードウェアに依存します。

サイトはネイティブポップアップを閉じる際に確認を求めることがあります。Linux のポインターロック同意は、そのウィンドウの上部に表示されます。2.52.6 など [WebKit 323277](https://bugs.webkit.org/show_bug.cgi?id=323277) の影響を受ける WebKitGTK では、セキュリティ上ドロップされたファイルへのアクセスがブロックされるため、アップロードにはページのファイル選択を使ってください。ページを含む CodeNomad ウィンドウを閉じる、または再読み込みする前に、ページの作業を保存してください。

Tauri macOS/Linux では、プレビューにフォーカスして ⌘/Ctrl と +、−、0、またはアプリのズームメニューでプレビューを拡大・縮小できます。ほかの場所にフォーカスがある場合、これらのメニュー操作はアプリのズームを変更します。

## 6 種類のビューポートテンプレートから選ぶ {#templates}

1. プレビューのビューポートメニューを開きます。
2. 下表から選びます。縦／横の項目を直接使い、独立した回転コントロールはありません。
3. Electron と Windows Tauri では、モバイルエミュレーションの開始／変更や、寸法のみのテンプレートへ戻る際は、ネイティブの再読み込みが行われます。

| テンプレート | CSS ビューポート |
| --- | --- |
| レスポンシブビューポート | 利用可能なプレビュー領域 |
| デスクトップビューポート | 1440 × 900 |
| タブレットビューポート | 768 × 1024 |
| タブレット横向き | 1024 × 768 |
| モバイルビューポート | 390 × 844 |
| モバイル横向き | 844 × 390 |

Electron と Windows Tauri では、モバイルテンプレートは、所有するゲストにだけ Android/Chromium の識別、向き、タッチ、DPR 2.75 を設定します。レスポンシブ／デスクトップ／タブレットへ戻ると上書きを解除し再読み込みします。macOS/Linux Tauri は HTTP と JavaScript に汎用 WebKit モバイル識別を適用し、アプリのズームや DPI に依存せず CSS ビューポートを合わせ、テンプレートの変更やリセットで再読み込みします。macOS は利用可能ならネイティブ DPR 2.75 を使用し、GTK の密度は表示倍率とモニターに従います。画面、プラットフォーム、ポインター／ホバーのメディア、最大タッチ数はネイティブのデスクトップ値を保持します。GTK のモバイルクリックはネイティブのタッチと互換マウスイベントを生成し、macOS はマウス入力を保持します。代替 iframe はサイズのみ変更します。これらはレイアウトの基準で、携帯のキーボード、システムバー、モバイルの文字設定は対象外です。再読み込みで未送信のページ状態を失う場合があるため、テンプレート変更前にページ上の作業を保存してください。

## SideCar を登録する {#register-sidecar}

1. CodeNomad バックエンドホストで、ウェブツールを別途起動し、`127.0.0.1:<port>` で待ち受けます。
2. **設定 → SideCar** を開き、**名前** と **ポート** を入力し、算出された **ベースパス**（`/sidecars/<id>`）を確認します。
3. 上流サービスに合わせて **プロトコル** を設定し、**プレフィックスモード** を選びます。
4. **SideCar を追加** を選び、ホームページの **SideCar を開く** でタブを開きます。

| 選択 | 正確な効果 |
| --- | --- |
| HTTPS（フォームの既定） | CodeNomad は `https://127.0.0.1:<port>` として上流に接続します。 |
| HTTP | CodeNomad は `http://127.0.0.1:<port>` として上流に接続します。公開側の CodeNomad 接続の TLS 設定は変えません。 |
| プレフィックスを削除（既定） | `/sidecars/<id>/path` を `/path` として上流に転送します。 |
| プレフィックスを保持 | `/sidecars/<id>/path` を変更せずに上流へ転送します。サービス自体のベースパスを一致させてください。 |

登録はクライアント間で共有されるサーバー設定であり、サービスのインストールや起動はしません。ポートはバックエンドホスト上にあり、閲覧中のノートパソコンやスマートフォン上ではありません。**実行中** は到達可能性を示し、ツールのアプリ／認証が正常だとは限りません。登録を削除しても、別に起動したプロセスは停止しません。タブを閉じても停止しません。

到達できない場合はバックエンドのプロセスとポートを確認します。HTML は読めても資産／WebSocket が失敗する場合は、ツールのベースパスとプレフィックスモードを確認します。誤った登録は目的の設定で作り直してください。プロキシエラーの回避だけのために上流を公開しないでください。SideCar アプリは、サーバーアカウントの権限でターミナルやファイルを公開できるため、利用者と設定を信頼する必要があります。

SideCar はサンドボックス化されたプレビューではなく、CodeNomad の信頼された拡張です。そのページは CodeNomad 自身のオリジンで動作するため、スクリプトはサインイン済みのアクセス権で CodeNomad を利用できます。コードを信頼できるサービスだけを登録してください。CodeNomad は自身のサインイン Cookie をサービスへ転送しませんが、サービス自身の Cookie は保持されます。

SideCar のコンテンツ（`/sidecars/`）と WebSocket には、ホスト上のループバック接続が必要です。`/api/sidecars` による登録は、ペアリング済み端末と認証済みの LAN 直接接続クライアントで利用できます。有効なケイパビリティトークンがあれば、アクティブなプレビューのコンテンツ（`/previews/`）は LAN からの直接アクセスで利用できます。[リモートコントロール](remote-control.md#remote-surface)の Web プレビューは、有効な間、ケイパビリティトークンで利用できます。直接アクセスの要件は[アップグレード](remote-access.md#upgrading)を参照してください。

## OpenVSCode Server の例 {#openvscode}

1. バックエンドホストで、サービスをループバックにバインドして Docker を実行します。

```sh
docker run -it --init -p 127.0.0.1:8000:3000 -v "${HOME}:${HOME}:cached" -e HOME=${HOME} gitpod/openvscode-server --server-base-path /sidecars/vscode
```

2. **名前** `VSCode`、**ポート** `8000`、**プロトコル** `HTTP`、**プレフィックスモード** **プレフィックスを保持** で登録します。
3. 表示されたベースパスが `/sidecars/vscode` であることを確認し、SideCar を開きます。

このシェルの例は、ホームディレクトリをコンテナーにマウントします。エディターのアクセス範囲を絞るなら、より狭いマウントを使用してください。サービスの `--server-base-path` は、登録と正確に一致する必要があります。終わったらコンテナーを別途停止してください。SideCar の削除ではコンテナーやそのファイルは削除されません。

## ttyd ターミナルの例 {#ttyd}

1. バックエンドホストで、書き込み可能なシェルターミナルをループバックにバインドして起動します。

```sh
ttyd --interface 127.0.0.1 --writable zsh
```

2. **名前** `Terminal`、**ポート** `7681`、**プロトコル** `HTTP`、**プレフィックスモード** **プレフィックスを削除** で登録します。
3. 表示された `/sidecars/terminal` ベースパスで SideCar を開きます。

ターミナルは ttyd を起動したアカウントの権限で実行します。`zsh` がなければ別のシェルを選びます。ttyd の既定ポートを変えた場合は実際のポートを使い、終了時は ttyd を別途停止してください。CodeNomad へのアクセスを認証・保護してください。書き込み可能なターミナルはサンドボックスではありません。
