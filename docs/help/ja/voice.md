# 音声入力と再生

## 音声 API を設定する {#configure}

1. **設定 → 音声** を開きます。**音声** カードは、会話のモデルプロバイダーとは独立した OpenAI 互換のサーバー側アダプターを使います。
2. **API キー**、任意で **ベース URL**、**文字起こしモデル**、**音声モデル**、**既定の音声** を入力します。
3. 入出力で異なるサービスが必要なら、**入力と出力で異なるプロバイダーを使用** を有効にし、入力／出力のキー、ベース URL、モデル欄を入力します。
4. **再生モード** と **出力形式** を選び、**保存** します（未保存の変更がある間に使用できます）。テスト前に、テストボタンの横の状態（**設定済み**、**一部設定済み**、**APIキーがありません**）を確認します。保存に失敗すると **保存に失敗しました** と表示されます。

音声設定とキーは、選択中のプロジェクトや OpenCode プロバイダー接続ではなく、接続先の CodeNomad サーバー設定に属します。共有する他のクライアントもその設定を使います。保存済みキーは非表示で、空欄なら保存値を保持し、**保存済みキーを削除** は次回保存時の削除を指定します。独自のエンドポイントもキーもない方向では共通設定を使えます。別のエンドポイントには独自キーが、別のキーにはそのエンドポイントが必要です。エンドポイントを変えるときは、意図するキーを明示的に指定し、保存済み設定を確認してください。別ホストに送らないよう、エンドポイント変更ではその枠の保存済みキーを消去します。

バックエンドは、共通の既定値に `OPENAI_API_KEY` と `OPENAI_BASE_URL` も使えます。保存済みキーを消しても、環境由来の認証情報は消えません。代替値を除去したい場合は、バックエンドの環境を変えて再起動します。

| 設定 | 意味／既定値 |
| --- | --- |
| ベース URL | OpenAI 互換 API のルート。既定は `https://api.openai.com/v1`。入力は `audio/transcriptions`、出力は `audio/speech` を使用。 |
| 文字起こしモデル／入力モデル | STT エンドポイントが受け付けるモデル。既定は `gpt-4o-mini-transcribe`。 |
| 音声モデル／出力モデル | TTS エンドポイントが受け付けるモデル。既定は `gpt-4o-mini-tts`。 |
| 既定の音声 | プロバイダーの音声識別子。既定は `alloy`。OS の音声ピッカーではありません。 |
| ストリーミング | 既定値。選択形式にプロバイダーとブラウザーが対応する場合、音声の到着とともに再生を開始。 |
| バッファ再生 | 音声応答全体を待ってから再生。 |
| 出力形式 | `mp3`、`wav`、`opus`、`aac`。既定は `mp3`。互換性はブラウザー／プロバイダーで異なります。 |

これらは設定したサービスへの要求であり、互換エンドポイントすべてが全モデル、音声、形式に対応する保証ではありません。

## 入力と出力をテストする {#test}

1. 先にエンドポイント、キー、モデル、音声の変更を保存します。
2. **入力をテスト** を選び、マイクを許可して話し、**録音を停止** します。返された文字起こしを確認します。
3. **再生をテスト** でサンプルを聞き、**サンプルを停止** で終了します。

再生テストは、選んだ再生モード／形式を直ちに使いますが、エンドポイント、キー、モデル、音声は保存済み設定を使います。入力テストは会話のプロンプトを送りません。ただしテストでも、設定した音声プロバイダーに音声／テキストを送り、その料金が発生する場合があります。

## プロンプトを音声で入力する {#dictate}

1. **音声** で **プロンプト音声入力** を有効のままにします（既定でオンです）。
2. 入力欄で **その他の操作 → 音声入力** を選び、マイクを許可します。**音声入力：音声設定を開く** が表示された場合は、そこでエンジンを選ぶか設定してから下書きに戻ります。
3. テキストにするには **録音を停止して文字起こし**、録音を破棄するには **音声入力をキャンセル** を選びます。会話の切り替えや入力欄を閉じる操作でもキャンセルされます。
4. テキストを確認します。下書きと選択範囲が変わっていない場合にのみ、元の選択範囲が置き換わります。変わっていた場合は **文字起こしを挿入** または **文字起こしを破棄** を選びます。音声入力でプロンプトが送信されることはありません。

Linux の Tauri で API が代替の WAV 録音を使う場合、音声入力と入力テストの録音は 24 秒で停止します。録音は、**文字起こし**で音声サービスのプロバイダーに送るか、**キャンセル**で破棄するまで、このデバイスにとどまります。

### デスクトップの音声入力エンジンを選ぶ {#desktop-dictation}

ローカルのデスクトップアプリで **環境設定 → 音声** を開き、**このデバイスの音声入力エンジン** を選びます。この選択は同じデバイスの全プロジェクトに適用されます。接続先サーバーの API は引き続き **音声** カードで設定します。ブラウザーとモバイルでは設定済みの API プロバイダーを使い、マイクの利用には安全なコンテキストが必要です。

- **システムのローカル音声認識** は OS の音声入力パネルを開かずに CodeNomad 内で動作します。Windows または macOS に、アプリの言語に対応するローカルエンジンがインストールされている必要があります。Linux の場合やエンジンまたは言語がない場合は、表示されていれば Hex を試してください。
- 音声設定には Hex に不足しているコンポーネントと、個別および合計のダウンロード容量が表示されます。**Hex を有効化** を一度押すと、互換ファイルを検証して再利用し、不足分を取得し、準備ができた Hex を選択します。ここで進捗を確認でき、**Hex の有効化をキャンセル** や、表示された場合は **Hex の有効化を再開** を使えます。失敗またはキャンセル時は元のエンジンが選択されたままです。設定を開き直す、準備済みの **Hex（ローカル）** を選ぶ、音声入力する、いずれの場合も再ダウンロードは始まりません。
- Hex が候補になるのは Windows x64/arm64、macOS 15 以降の Apple Silicon、および glibc 2.36 以降と必要なライブラリを備えた Linux x64/arm64 です。Intel Mac や古い glibc または musl を使う Linux には対応しません。エンジンとモデルは CodeNomad のインストーラーに含まれず、ターミナルや API キーは不要です。

Ubuntu 24.04 は glibc の要件を満たしますが、Ubuntu 22.04 は満たしません。Hex は英語やフランス語など、[Parakeet が対応する言語](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)から発話言語を自動で判定します。この一覧はアプリの表示言語とは別です。

ローカル認識はこのデバイスのマイクを使い、ローカルアプリで開いた WSL プロジェクトでもオフラインで動作します。対応するリモートウィンドウで **音声入力** を選ぶと、別のローカルウィンドウ **このデバイスで音声入力** が開きます。表示された宛先を確認し、**音声入力を開始**、**録音を停止して文字起こし**、**文字起こしを挿入** を選ぶと、テキストだけが下書きに戻ります。リモートプロジェクト自体にはサーバーへの接続が必要です。

Linux のリモート Tauri ウィンドウでは、**入力をテスト**で音声入力エンジンを変更せずにサーバーの音声 API を確認できます。API 向けの録音を許可するたびに、マイクのネイティブダイアログに表示されるサーバーのアドレスを確認してください。録音には PulseAudio または PipeWire の PulseAudio サービスを使い、上記の WAV の 24 秒制限が常に適用されます。

## メッセージを読み上げる {#playback}

1. TTS が利用できる場合、メッセージの **メッセージを読み上げ**、またはツール呼び出しの同じ操作を使用します。
2. 終了するには、同じコントロールで **再生を停止** を使用します。別の読み上げを始めると、現在の読み上げは停止します。
3. 次のリクエスト用に、**音声** で保存済みの声、モデル、モード、形式を変更します。

再生は画面の実況ではなく、CodeNomad のテキスト表現を使います。バイナリ／画像のバイト列と権限の記録は音声内容ではありません。プロンプトの実行や、選択中の OpenCode モデルの変更はしません。

会話の自動読み上げには、入力欄の **その他の操作** メニューから **会話モードを有効化** を使います。そのプロジェクトタブに適用され、再読み込み後は保持されません。有効な間、CodeNomad は送信する各プロンプトとともに、短いフェンス付き `spoken` の要約から返信を始めるようエージェントに求めます。アクティブなメインセッションで、その完了したブロックだけを読み上げます。すべての返信やサブエージェントの自動読み上げではありません。**会話モードを無効化** はキューを停止し、要約の要求もやめます。マイク入力の開始も、現在の会話読み上げを停止します。会話モードには、対応する形式での再生設定が必要です。

## データの流れとプライバシー {#privacy}

ローカル音声入力では音声は端末に残り、API に切り替わることはありません。**API プロバイダー** を選ぶと、マイク音声は CodeNomad サーバーを経由して設定した文字起こし先へ送られます。読み上げ用テキストはサーバー経由で TTS の送信先へ渡り、返った音声はクライアントで再生されます。API キーはサーバー側に残ります。

入力・読み上げる内容を預けられる、信頼するエンドポイントを使ってください。OpenCode の認証情報は音声機能を自動的に許可しません。キーやエンドポイントの変更は今後のリクエストに適用されます。サーバー公開の前に、[セキュリティ](security.md)を確認してください。
