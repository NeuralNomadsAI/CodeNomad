# 音声入力・再生・音声会話

## 音声を設定する {#configure}

**環境設定 → 音声** を開きます（ブラウザーやリモートウィンドウでは **設定 → 音声**）。**音声入力**、**再生**、**会話** の各カードに状態が表示されます。

1. ローカルのデスクトップアプリでは、**音声入力** で[デバイスのエンジン](#desktop-dictation)を選びます。ブラウザーとモバイルは API のみを使います。
2. API で音声入力や再生を行うには、どちらかのカードから **API認証情報** を開きます。**API キー** と、必要に応じて **ベース URL**、**文字起こしモデル**、**音声モデル** を入力します。別々のサービスを使う場合は **入力と出力で異なるプロバイダーを使用** を有効にし、各欄を入力して **保存** します。
3. **再生** には **プロバイダー** が表示されます。**既定の音声**、**再生モード**、**出力形式** を指定して **保存** します。

音声設定とキーは、選択中のプロジェクトや OpenCode プロバイダー接続ではなく、接続先の CodeNomad サーバー設定に属します。共有する他のクライアントもその設定を使います。保存済みキーは非表示で、空欄なら保存値を保持し、**保存済みキーを削除** は次回保存時の削除を指定します。独自のエンドポイントもキーもない方向では共通設定を使えます。別のエンドポイントには独自キーが、別のキーにはそのエンドポイントが必要です。エンドポイントを変えるときは、意図するキーを明示的に指定し、保存済み設定を確認してください。別ホストに送らないよう、エンドポイント変更ではその枠の保存済みキーを消去します。

バックエンドは、共通の既定値に `OPENAI_API_KEY` と `OPENAI_BASE_URL` も使えます。保存済みキーを消しても、環境由来の認証情報は消えません。代替値を除去したい場合は、バックエンドの環境を変えて再起動します。

| 設定 | 意味／既定値 |
| --- | --- |
| ベース URL | OpenAI 互換 API のルート。既定は `https://api.openai.com/v1`。入力は `audio/transcriptions`、出力は `audio/speech` を使用。 |
| 文字起こしモデル／入力モデル | STT エンドポイントが受け付けるモデル。既定は `gpt-4o-mini-transcribe`。 |
| 音声モデル／出力モデル | TTS エンドポイントが受け付けるモデル。既定は `gpt-4o-mini-tts`。 |
| 既定の音声 | プロバイダーの音声識別子。既定は `alloy`。OS の音声ピッカーではありません。 |
| ストリーミング | 既定値。選択形式にプロバイダーとブラウザーが対応する場合、音声の到着とともに再生を開始。 |
| バッファ再生 | 音声応答全体を待ってから再生。 |
| 出力形式 | `mp3`、`wav`、`opus`、`aac`。既定は `mp3`。互換性はブラウザー／プロバイダーで異なります。 |

これらは設定したサービスへの要求であり、互換エンドポイントすべてが全モデル、音声、形式に対応する保証ではありません。

## 入力と出力をテストする {#test}

1. 先にエンドポイント、キー、モデル、音声の変更を保存します。
2. **API 入力をテスト** を選び、マイクを許可して話し、**録音を停止** します。返された文字起こしを確認します。
3. **再生をテスト** でサンプルを聞き、**サンプルを停止** で終了します。

再生テストは、選んだ再生モードと形式を直ちに使いますが、エンドポイント、キー、モデル、音声は保存済み設定を使います。**API 入力をテスト**は、音声入力エンジンにかかわらず、設定した API プロバイダーに音声を送ります。会話のプロンプトは送信しません。テストには料金がかかる場合があります。

## プロンプトを音声で入力する {#dictate}

1. **音声** で **プロンプト音声入力** を有効のままにします（既定でオンです）。
2. **その他の操作** で **音声入力モード** にチェックを入れます。別のモードを選ぶ前に、現在のモードのチェックを外します。
3. **その他の操作** の隣のマイクを押しながら話し、離すと文字起こしされます。必要に応じてマイクを許可します。対応するリモートウィンドウでは、マイクをクリックするとローカルの録音操作が開きます。
4. テキストを確認します。下書きと選択範囲が変わっていない場合にのみ、元の選択範囲が置き換わります。変わっていた場合は、次の音声入力の前に通常モードで **文字起こしを挿入** するか、**文字起こしを破棄** します。音声入力でプロンプトが送信されることはありません。

Linux の Tauri で API が代替の WAV 録音を使う場合、音声入力と入力テストの録音は 24 秒で停止します。録音は、**文字起こし**で音声サービスのプロバイダーに送るか、**キャンセル**で破棄するまで、このデバイスにとどまります。

API 用の圧縮録音もサイズの上限で止まり、**文字起こし** または **キャンセル** を選べます。

### デスクトップの音声入力エンジンを選ぶ {#desktop-dictation}

ローカルのデスクトップアプリで **環境設定 → 音声 → 音声入力** を開き、**このデバイスの音声入力エンジン** を選びます。この選択は同じデバイスの全プロジェクトに適用されます。**API プロバイダー** は接続先サーバーの設定を使い、マイクには安全なコンテキストが必要です。

- 保存したエンジンが利用できない場合は、音声入力の前にここで **Hex（ローカル）**（利用できる場合）または **API プロバイダー** を選びます。Intel Mac や macOS 15 未満の Mac では **API プロバイダー** を使います。
- 音声設定には Hex に不足しているコンポーネントと、個別および合計のダウンロード容量が表示されます。**Hex を有効化** を一度押すと、互換ファイルを検証して再利用し、不足分を取得し、準備ができた Hex を選択します。ここで進捗を確認でき、**Hex の有効化をキャンセル** や、表示された場合は **Hex の有効化を再開** を使えます。失敗またはキャンセル時は元のエンジンが選択されたままです。設定を開き直す、準備済みの **Hex（ローカル）** を選ぶ、音声入力する、いずれの場合も再ダウンロードは始まりません。
- Hex が候補になるのは Windows x64/arm64、macOS 15 以降の Apple Silicon、および glibc 2.36 以降と必要なライブラリを備えた Linux x64/arm64 です。Intel Mac や古い glibc または musl を使う Linux には対応しません。エンジンとモデルは CodeNomad のインストーラーに含まれず、ターミナルや API キーは不要です。

Ubuntu 24.04 は glibc の要件を満たしますが、Ubuntu 22.04 は満たしません。Hex は英語やフランス語など、[Parakeet が対応する言語](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)から発話言語を自動で判定します。この一覧はアプリの表示言語とは別です。

Hex は録音の開始時にバックグラウンドでモデルを読み込み、最後の音声入力から 3 分間、使える状態に保ちます。

ローカル認識は、ローカルアプリで開いた WSL プロジェクトでもオフラインで動作します。対応するリモートウィンドウでマイクをクリックすると **このデバイスで音声入力** が開きます。宛先を確認し、そのウィンドウで録音して文字起こしを挿入します。下書きに戻るのはテキストだけです。リモートプロジェクトにはサーバーへの接続が必要です。

Linux のリモート Tauri ウィンドウでは、**API 入力をテスト** で音声入力エンジンを変更せずにサーバーの音声 API を確認できます。API 向けの録音を許可するたびに、マイクのネイティブダイアログに表示されるサーバーのアドレスを確認してください。録音には PulseAudio または PipeWire の PulseAudio サービスを使い、上記の WAV の 24 秒制限が常に適用されます。

Linux のリモート Tauri ウィンドウでは、Gemini Live と OpenAI Realtime は利用できません。このウィンドウは音声入力と入力テストにネイティブの録音機能を使い、WebKit がマイクへの直接アクセスを遮断します。

## メッセージを読み上げる {#playback}

1. TTS が利用できる場合、メッセージの **メッセージを読み上げ**、またはツール呼び出しの同じ操作を使用します。
2. 終了するには、同じコントロールで **再生を停止** を使用します。別の読み上げを始めると、現在の読み上げは停止します。
3. 音声、モード、形式は **再生** で、モデルは **API認証情報** で変更して保存します。

再生は画面の実況ではなく、CodeNomad のテキスト表現を使います。バイナリ／画像のバイト列と権限の記録は音声内容ではありません。プロンプトの実行や、選択中の OpenCode モデルの変更はしません。

## 音声会話 {#conversation}

Gemini Live と OpenAI Realtime は、このウィンドウを開いたサーバー上のセッションでのみ利用できます。

**会話** で **会話エンジン** を選びます。

- **クラシック** には、対応する形式での再生設定だけが必要です。**その他の操作** で **会話モード** にチェックを入れます。CodeNomad はアクティブなメインセッションで返信の `spoken` 要約を読み上げます。チェックを外すか再読み込みするまでプロジェクトタブに適用されます。
- **Gemini Live** と **OpenAI Realtime** には、それぞれの **API キー**、**モデル**、任意の **音声** を設定できます。選んだプロバイダーの設定を保存します。対象セッションを開き、**その他の操作** で **会話モード** を選び、同意ダイアログが表示されたら **同意して開始** を押します。マイクへのアクセスを許可します。

同意ダイアログを開いている間にプロバイダーが利用できなくなった場合は、**音声設定** から会話のカードを開きます。

音声モデルは開始時に固定されたセッションの状態、最後に表示された返信、最近のエラーを読み取れます。ファイルにはアクセスできません。エージェントに依頼を送るよう指示すると、画面で確認することなく、あなたのメッセージとして直接送信します。[会話の権限モード](permissions.md#conversation-mode)とエージェントからの質問は通常どおり適用されます。

サーバーで同時に行えるライブ会話は、ログインユーザーごとに 1 件です。リモートコントロールではペアリング済みデバイスごとに 1 件です。**停止** で音声を終了し、文字起こしを表示したままにできます。ウィンドウを閉じるまで文字起こしはメモリーに保持され、送信済みの依頼はセッション内のメッセージとして残ります。発話が 2 分間ない場合、開始から 8 分が経過した場合、対象の変更、ウィンドウの終了、接続切断でも会話は終了します。自動再接続やプロバイダーの切り替えは行いません。

OpenAI Realtime の **応答を中断** は再生を停止し、現在の応答のキャンセルを要求します。Gemini Live の **再生を停止** はこのデバイスの音を止めるだけです。Gemini は応答の生成を続けたり、エージェントに依頼を送ったりできます。

## データの流れとプライバシー {#privacy}

ローカル音声入力では音声は端末に残り、API に切り替わることはありません。**API プロバイダー** を選ぶと、マイク音声は CodeNomad サーバーを経由して設定した文字起こし先へ送られます。読み上げ用テキストはサーバー経由で TTS の送信先へ渡り、返った音声はクライアントで再生されます。API キーはサーバー側に残ります。

**Gemini Live** または **OpenAI Realtime** では、Google または OpenAI にマイク音声、プロジェクト名、ブランチ、ワークツリー、セッションのタイトルと状態が送られます。最後に表示されたエージェントの返信テキストや最近のエラーも送られることがあります。使用量に応じて、選んだプロバイダーのアカウントに請求される場合があります。

音声入力、読み上げ、共有の内容は、信頼できるプロバイダーにだけ送ってください。OpenCode の認証情報は音声サービスを自動で許可しません。サーバーを公開する前に[セキュリティ](security.md)を確認してください。
