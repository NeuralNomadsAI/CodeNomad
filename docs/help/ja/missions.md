# ミッション

保存済みフィールドが大きすぎる場合は、**生のJSONをページ単位で読む**を選びます。**前のページ**と**次のページ**で正確な範囲を読みます。コレクションが変わった場合は、再試行して最初のページから読み直します。

ピッカーは一度に50件の概要を読み込み、**さらに読み込む**で続行します。検索は読み込み済みのミッションのみが対象です。選択中またはリーダーで指定したミッションだけが詳細を読み込みます。クリーンアップ、活動、リクエストには個別の件数と読み込み操作があります。別々のウィンドウを観測しても未読のアクターやリクエストは不明のままです。**保存されたフィールドを読む**でアクター、報告、履歴、受領記録、メタデータを正確なページで確認できます。失敗時は最後の表示を保持し、再試行でそのウィンドウを読み直します。変更された集合は最初から読み直します。読み取りは作業を開始しません。過去の完了は永続カウンターで一度だけ既読にし、新しい完了は表示されるまで未読です。

ミッションは、永続的なプロジェクト計画と OpenCode ネイティブの会話を組み合わせます。コーディネーターが計画と委任を行い、タスクツリーが依存関係と結果を記録します。保存済みの計画、受け付けられた入力、観測された実行は、それぞれ別の事実です。

## 作成してから明示的に開始する {#create}

1. 右パネルの **ミッション** を開き、**ミッションを作成** を選びます。作成またはキャンセルするまで、フォームがミッション一覧と選択中のミッションのタスクに代わって表示されます。
2. **ミッションで何をしますか？** を入力し、最初の文から事前入力される **タイトル**（最大 60 文字）を確認します。
3. **1回、今すぐ**、**条件なし** の場合は **スケジュール** を折りたたんだままにします。頻度、条件、任意の上限を選ぶには展開します。作業を予約する前に、**保存するタイムゾーン（IANA）** とプレビューを確認してください。
4. **オプション** を展開すると、**プレイブック**、**メモ**、**エージェントとモデル**、**タスクセッション**、プロジェクトの **サブセッションの入れ子の深さ**、保存済みの概要、任意の参照する会話を設定できます。**2つのモデルを比較** では、**モデルA** と **モデルB** のセレクターがメインフォームに表示されます。
5. **作成** を選びます。一時停止中の項目を選んで確認し、準備ができたら ▶ **開始** を使用します。条件なしの即時実行は 1 つのミッションを開始し、遅延、繰り返し、条件付きの方針はネイティブスケジュールを有効にします。

**作成すると一時停止中のミッションが保存されます。** 作業とネイティブカレンダーを有効にするのは再生操作だけです。作成や概要の保存では、共有サービスの監視設定を保持します。作成は選択したプロジェクト／Location に属し、要求されたプロファイルとタスクセッションの方針を記録します。検証結果は該当項目の横に表示され、何も送信されなかったとする拒否では修正用の下書きが残ります。単発のコーディネーターが別のフォローアップを準備することもできます。**準備済み** と表示され、その項目自身の ▶ 操作で開始します。

保存済みの単発ミッションでは、実行操作、タスクツリー、会話、最終レポートが保持されます。既存の日次スケジュールは、日次の操作と [日次の時刻規則](#existing-daily-schedules) とともに一覧に残ります。項目を選び、その対象で利用できる操作を使用してください。

### プレイブック {#playbooks}

**プレイブック** セレクターのすぐ下に、選択したプレイブックの 1 文の説明が表示されます。**詳細を表示** を選ぶと、選択したプレイブックが中央のリーダーに開き、手順、役割、そして末尾に折りたたまれた、エージェントが受け取る正確な英語の指示が表示されます。[プレイブック](playbooks.md) では、各プレイブックの手順、役割、質問と、CodeNomad が確認することを説明しています。

| プレイブック | 想定する作業 |
| --- | --- |
| フレキシブルミッション | コーディネーターが目的に合った、依存関係を考慮した計画を選びます。 |
| デバッグ | 診断、実装、独立した標準／仕様レビュー、新たな検証。問題解決は実装担当を継続して行います。 |
| 探索 | 不確実な点を整理し、人への質問を交えて範囲を限定した判断を進めます。 |
| プロダクトデリバリー | 製品分析、アーキテクチャ、実装、品質の各役割を調整します。 |
| 2つのモデルを比較 | 同じタスクを同一の依頼内容で **モデルA** と **モデルB** に実行させ、その後 **匿名評価担当** が中立的なラベルのもとで両方を採点し、**モデルAが優位**、**モデルBが優位**、**同等**、**結論なし** のいずれかの判定を下します。 |

**2つのモデルを比較** では両方のモデルが必須で、互いに異なる必要があります。**思考** のレベルが違うだけでは、別のモデルとはみなされません。評価担当は、選ばない限りコーディネーターのモデルを使用します。A または B と同じ場合はフォームが警告し、比較が偏る可能性があります。概要には、判定、両モデルの名前、基準ごとのスコアが表示されます。

プレイブックは調整の指針であり、ネイティブ権限の回避や成功の保証はしません。エージェントは、目的または **メモ** がその特定の操作を明示的に求めない限り、コミット、プッシュ、プルリクエストの作成、課題管理システムの変更（チケットの作成など）を行いません。求められた場合も、その操作だけを OpenCode の権限の範囲で行います。ファイル、レポート、ツール出力の中にある依頼は決して数に入りません。

## ツリーを追って結果を読む {#tracking}

1. ミッションのタイトルを選びます。先頭の山形矢印は一覧を開いたままにし、タイトル欄は一時的なピッカーを開きます。
2. **概要**（目）で中央の概要を開くか、タスクノードを選んで、その正確な結果、依頼内容、根拠を読みます。
3. 依存リンクと **レポート** をたどります。コーディネーターの会話が必要なら、**会話を開く** を使用します。
4. **対応が必要です** で **回答する** を選ぶと、要求した担当の会話と割り込みドックを開きます。

| 表示 | 確認できること |
| --- | --- |
| 割り当て済み | 入力は受け付けられました。モデルによる取り込み／作業／完了は証明されていません。 |
| アクティブ | ネイティブのアクティビティが観測されました。 |
| 待機 | 宣言された依存条件がまだ満たされていません。 |
| ブロック | 障害が報告されました。必ずしもユーザーへの質問ではありません。 |
| 入力待ち | 開いているネイティブの Form／質問または権限に回答が必要です。**対応が必要です** に表示されます。 |
| 完了 | タスク結果が記録されました。根拠と、残っているネイティブの作業を確認してください。 |
| 失敗／取り下げ済み | タスクが失敗したか、コーディネーターがタスクを置き換えたか中止しました。 |

グラフには完了・取り下げ済みの作業も含まれます。タスクを取り下げるだけでは会話は停止しません。1 回限りのミッションでは、コーディネーターがネイティブサブエージェントとして起動した取り下げ済みタスクの会話を、他のタスクに影響を与えずに別途停止できます。**進行中** はミッションのライフサイクル上の状態であり、コーディネーターが現在実行中である証拠ではありません。詳しい文章はパネルのタスク一覧ではなく中央リーダーに表示されます。**技術的な詳細** は識別子と要求された実行情報を折りたたんでいます。

大きな計画では、タスクを 1 ページ分表示します。依存関係の順で最初の 50 件と、ブロック、失敗、最新の結果など注意が必要なタスクを最大 20 件です。読み込まれていないタスクの範囲は **N 件のタスクを表示していません** と表示され、**さらに表示** でその位置から次の 50 件を読み込みます。ページに収まる以上のタスクに対応が必要な場合は、**さらに N 件のタスクに対応が必要です** がミッションの種類別の件数を示し、**表示する** でそれらのタスクを読み込みます。点線の短い線は表示されていない依存先や後続タスクを示し、タスクのリーダーの依存関係リンクはまずそのタスクを読み込みます。タスクのリーダーは最新の結果を表示します。**以前の結果 N 件を表示していません** には **すべて表示** があり、履歴全体を読み込みます。タスクやレポートを読み込めない場合はリーダーにそう表示され、**再試行** で再度読み込みます。

タスクページは全体の受信が完了してから表示されます。読み込みの失敗や変更があっても、直前のタスク表示は保持されます。読み込み中に一覧が変わった場合は、**更新**してから**再試行**してください。ページは先頭から読み直されます。一部が未取得でも、タスクやリクエストが存在しないことを意味しません。読み込みの再試行で作業が開始されることはありません。Missions プラグインがページを返せない場合は、再接続またはプラグインの再読み込み後に再試行してください。

### 色と中断したミッション {#status-colours}

ミッションのマーク、タスクのアイコン、一覧の山形矢印はセッション一覧と同じ色を使います。色が示すのは、いまあなたの対応が必要なことだけです。

| 色 | 意味 |
| --- | --- |
| 赤 | あなたの回答が待たれています。**対応が必要です** に表示されます。 |
| 黄色（点滅） | 作業が進行中です。 |
| オレンジ | ミッションが一時停止中または中断中で、続行するための操作があります。 |
| 緑 | このウィンドウでまだ開いていない完了したミッションです。選択すると通常の表示に戻ります。 |
| 青 | 準備済みのミッションです。作成済みのプロンプトと同じく、開始を待っています。 |

それ以外はすべて通常の表示で、完了・失敗したタスクも同様です。結果は状態テキストとアイコンで示されます。一覧を折りたたんでいる間、山形矢印はほかのミッションの赤、黄色、緑のうち最も緊急な色になります。折りたたんだセッションと同じく、オレンジと青はそれぞれの行にのみ表示されます。

ほかに何も実行されていないのにコーディネーターが結論を出さずに止まった場合、ミッションは **中断** になります。**失敗** と表示されたミッションも再開できます。どちらの場合も、ツールバーの最初のボタンが **中断したミッションを復旧** に変わります。保存された計画と結果からコーディネーターに状況を見直させ、失敗したミッションは先に再び開きます。コーディネーターは単発のミッションを失敗として終了しません。あなたなしでは何も進められないときは、**対応が必要です** であなたに質問します。ミッションを停止できるのはあなただけです。

### 質問と判断 {#questions}

あなたに質問するのはコーディネーターだけです。タスクとそれが起動するサブエージェントは、未解決の質問を選択肢、根拠、推奨案とともにコーディネーターへ返します。質問する前に、コーディネーターはまず自分で解決を試みます。プロジェクトを読み、調査し、タスクに調べさせ、または元に戻しやすい既定値を採用して前提として記録します。質問するのは、自分では決められないことだけです。つまり、あなたの同意、認証情報、元に戻すのが難しい選択、目的が決めていないプロダクト上の判断です。保留中の質問は **対応が必要です** の 1 つのフォームにまとめ、関係のない作業を先に開始します。

**探索** では、判断タスクが要約を用意し、コーディネーターが各判断を決めます。根拠が十分で元に戻しやすい選択なら自分で決め、後で扱う質問は **メモ** に残し、それ以外はあなたに質問します。**ネイティブのサブエージェント** では、判断タスクの結果に誰が決めたかが表示されます。

| ラベル | 意味 |
| --- | --- |
| **コーディネーターの判断** | コーディネーターがあなたに確認せずに決めました。結果に理由と、コーディネーターが示した場合は元に戻す方法が表示されます。変更するには、**会話を開く** からコーディネーターに書き込んでください。 |
| **あなたの回答** | あなたが CodeNomad の割り込みドックでこの質問に回答しました。 |

**あなたの回答** と見なされるのは、割り込みドックであなたが入力した回答だけです。エージェントがあなたの代わりに回答することはできません。**ネイティブのサブエージェント** では、判断の質問は、それが決める 1 つの判断のタグ（例: `[decision choose-seam 3fa9c21b]`）で終わります。複数の判断をまとめて質問する場合は、判断ごとに独自のタグを付けた別々の質問になります。2 つの判断を示す質問はどちらも決めません。**独立したセッション** では、代わりにコーディネーターが各結果を、自分とあなたのどちらが決めたかとともに **メモ** に記録します。**プロダクトデリバリー** では、動作の変更をすでに正確に記述した目的は承認済みの仕様と見なされます。そうでない場合、コーディネーターは保留中の承認をまとめて、あなたに承認を求めます。

### 状況報告と更新の依頼 {#briefings}

コーディネーターは、初期計画の後、タスクの確定後、人の対応を待つとき、最終レポートの前に、プロジェクトの状況報告を公開するよう指示されます。これは作成された評価であり、ライブのアクティビティカウンターや、定期的な生存通知の保証ではありません。報告後にマップが変わった場合は、通知で示します。

ツールバーの下の **最新状況を依頼** でコーディネーターに新たな評価を求め、**概要** を読みます。**最新状況を依頼済み…** は依頼が保留中であり、回答済みではないことを意味します。**送信未確認** は自動再送を許可しません。別の新しい依頼を行う前に、コーディネーターの会話を開いてください。これは通常のネイティブ入力であって読み取り専用サンドボックスではなく、コーディネーターは通常の権限を保持します。

## ミッション内でのコンテキストの流れ {#context-flow}

ミッションマップは、ミッションで共有される永続的な記憶です。目的と **メモ**、各タスクの **タスク概要**、依存関係（**… に依存**）と状態、完了した作業について記録された **レポート**（要約、**根拠**、**推奨される次の手順**、あれば **構造化レポート**）、コーディネーターの状況報告、**計画の変更** を保持します。OpenCode がプロジェクトとともに保存するため、会話や再起動の後も残ります。ミッションコントロールはこのマップを表示し、復旧もここから再開します。各参加者は、その決まった一部を受け取ります。

| 参加者 | 受け取るもの |
| --- | --- |
| コーディネーター | 毎ターン、目的、メモ、プレイブックの指示を受け取ります。必要なときはいつでもマップ全体を読みます。保存済みの会話には読んだ結果がすべて残りますが、モデルのコンテキストは OpenCode によって [コンパクト化](history.md#compact-session) される場合があります。 |
| タスク（**ネイティブのサブエージェント**） | コーディネーターが通常の OpenCode サブエージェント呼び出しで渡す割り当てです。目的、タスクのタイトルと依頼内容、役割の指示、依存するタスクを含みます。コーディネーターは、それまでの結果などのコンテキストを添えることができます。 |
| タスク（**独立したセッション**） | 同じ割り当てを、自身の会話へのメッセージとして受け取ります。毎ターン、目的、メモ、未完了の割り当ても受け取り、マップ全体を読めます。 |
| タスクが起動したヘルパー | 親が呼び出しに書いた内容です。プレイブックは各親に、ヘルパーに必要な範囲、制約、安全ルールを渡すよう指示しています。 |

結果も同じ経路で戻ります。ネイティブサブエージェントは、起動元の会話（通常はコーディネーター）に結果を返し、コーディネーターがそれをタスクのレポートとして記録します。独立したセッションは自らレポートを記録し、CodeNomad がその要約をメッセージとしてコーディネーターに届けます。

後のタスクは、2 つの方法で以前の作業を活用します。依存関係は作業の順序を決めます。コーディネーターは依存先のタスクが完了してからタスクを開始し、関係する結果を依頼内容に入れるか割り当てに添えます。独立したセッションは、それらのレポートをマップで読むこともできます。完了したタスクの会話そのものを続けるには、コーディネーターがその会話を再利用するフォローアップタスクを宣言します。フォローアップはその会話の現在のコンテキストで続行します。このコンテキストは OpenCode によって [コンパクト化](history.md#compact-session) されている場合があり、以前の詳細は保存済みの履歴に残って検索で見つけられます。デバッグのプレイブックは、この方法で両方のレビューを実装担当に戻します。**独立したセッション** では、コーディネーターが既存のメインの会話にタスクを割り当てることもできます。その会話は、無関係な以前の作業を含め、自身のコンテキストを保ちます。それ以外の場合、タスクは割り当てをもとに新しい会話で始まり、別のタスクの会話記録はコーディネーター経由か検索で届きます。**2つのモデルを比較** では、評価担当の割り当てとコンテキストから目的とメモが除かれ、依頼内容に匿名化された出力が入ります。

スケジュールされた各実行は、保存済みの指示と固定された入力を使い、専用のコーディネーターとミッションマップで始まります。参照する会話からは、範囲を限定した新しいユーザーとアシスタントのテキストが加わり、実行の成功後に消費済みカーソルが進みます。過去の実行はスケジュール履歴に残ります。実行内で起動した会話はそのマップを読めます。新しい単発ミッションは別のマップを持ちます。引き継ぐ結果は目的や **メモ** に書くか、そのコンテキストを含むフォローアップをコーディネーターに準備させてください。

### 以前の会話を検索する {#context-search}

CodeNomad の実行中は、ミッションのコーディネーターやタスクを含め、プロジェクト内のすべてのエージェントの会話で CodeNomad のセッション検索ツール（`codenomad.session_search`、OpenCode の Code Mode から使用）を利用できます。会話のプロジェクトフォルダーに保存された会話を、**ワークスペース全体** の [検索](history.md#full-history-search) と同じ順位付けで検索し、各会話のタイトルと識別子付きの短い抜粋と、会話全体を読む方法を返します。ネイティブのツール権限が適用されます。エージェントは、自ら判断したとき、または目的、メモ、あなたのメッセージで求められたときに検索します。たとえば、以前のミッションやタスクの結論を探すときです。CodeNomad を閉じている間に動くスケジュール実行は、このツールなしで作業します。

## プロファイル、委任、深さ {#profiles}

深さを保存すると、プロジェクト設定で有効なネイティブスケジュールが保持されます。プロジェクトで明示した `schedules:false` は無効のままです。深さを削除してもスケジュール設定は保持されます。ネイティブ設定を保存する前に、JSON と JSONC ファイルの競合を解消してください。

1. ミッションの歯車、または **設定 → ミッション** から **新規ミッションの既定値** を編集します。
2. **適用先** で **すべてのミッション** または 1 つのプレイブックを選び、**タスクセッション** と、**エージェントとモデル** の下で役割ごとに 1 行（コーディネーター、続いてプレイブックの各役割）を設定します。各選択はすぐに保存され、保存ボタンはありません。
3. プレイブックの範囲では、各行に **グローバル** の印付きでグローバルの値が表示されます。項目を変更すると、その値をもとにその役割をカスタマイズします。元に戻すアイコンで、再びグローバルの値を使用します。**リセット**（確認後）は、表示中の範囲のエージェントとモデルだけを消去します。
4. 作成時に特定のプロファイルを要求するには、**オプション → エージェントとモデル** を使用します。**保存済みの既定値を使用** で保存済みの値に戻せます。
5. ネイティブの再帰制限には、**サブセッションの入れ子の深さ → プロジェクトで指定する深さ** を、ここまたは作成時の **オプション** で編集します。Enter を押すかフィールドを離れると、変更された有効な値が保存されます。**継承** はすぐに保存され、Escape で未保存の値を破棄します。

| 設定 | 範囲と効果 |
| --- | --- |
| 新規ミッションの既定値 | **新しい** ミッションのみに適用する、設定全体の既定値。プレイブックの例外は一般の既定値を上書きします。 |
| エージェント／モデル／思考 | 作成時に記録する、要求されたコーディネーター／役割の選択。後の作業に合わせて処理中の担当を無断で切り替えません。スケジュール実行は、保存済みの要求プロファイルを使用します。編集は今後の実行に適用されます。 |
| ネイティブサブエージェント | タスクセッションはコーディネーター配下で、ネイティブの subagent/all エージェントを使用します。 |
| 独立したセッション | 宣言したタスクセッションは primary/all エージェントと独立した会話を使用します。内部のネイティブヘルパーは無効にしません。 |
| サブセッションの入れ子の深さ | ミッションだけでなく、そこにある **すべての** OpenCode 会話に適用するプロジェクト設定。空欄は継承です。**継承** はプロジェクトの上書きと、それによって空になるか、グローバルの **画像を一度だけ保存** の値だけが残る `experimental` ブロックを削除します。OpenCode はプロジェクトの `experimental` ブロックを全体として読み込むため、そこに他の実験的設定が残っていると、グローバルの深さは引き続き隠されます。OpenCode に組み込まれた **General** サブエージェントは既定ではサブエージェントを起動できないため、その会話は入れ子になりません。プロジェクトの深さを保存すると、値に関係なく、サブエージェントがその深さまで独自のサブエージェントを起動できるルールも同じファイルに追加されます。このルールは他の設定ファイルにある General の制限より優先されます（深さ 1 では、OpenCode の深さの上限により引き続き入れ子になりません）。**継承** でこのルールは削除されます。**OpenCode の有効な深さ** の下に、General サブエージェントが入れ子にできるかどうかが表示されます。プロジェクトが旧形式で General を単一の `permission` 値、またはすでに `task` と `subagent` の両方を設定して定義している場合は、深さだけが保存され、エディターがその旨を表示します。そのファイルで General のサブエージェントをご自身で許可してください。保存しても OpenCode の再読み込みや実行中の会話の変更は行いません。 |

**ネイティブの既定値** と **グローバル** は異なります。前者は OpenCode 自身の既定値を要求し、後者はグローバルの選択を継承します。プレイブックの範囲でネイティブの既定値を選ぶことは、引き続き明示的な例外になります。カタログ上の利用可否を確認しますが、要求したプロファイルは、会話が現在使用するプロファイルの証拠ではありません。どちらのタスクモードでも、内部ヘルパーの呼び出しにはネイティブ権限と設定済みの深さが適用されます。

各 **モデル** リストには、会話の **モデル** セレクターと同じモデルが同じ名前でプロバイダーごとに表示されます。非表示のモデルは含まれず、お気に入りのみの絞り込みが有効な間はお気に入り以外のモデルも含まれません（[モデルの表示、お気に入り、思考](providers.md#models) を参照）。ツールに対応していないモデルも含まれません。リストにない保存済みのモデルは選択されたまま残ります。**利用不可** は、プロジェクトの現在のカタログにない、非推奨である、またはツールに対応していないため、セレクターが現在提供できない保存済みのモデルに付きます。

拒否された選択や未確認の選択が再送されることはありません。保存済みの値が再び表示され、**再読み込み** はそれらを読み取れない場合にだけ表示されます。深さの変更が未確認の場合は入力した値が保持されるので、次の変更の前に **プロジェクトの深さを更新** を使用します。**OpenCode の有効な深さは不明** をゼロや無効と解釈しないでください。

## 保存済みの概要を再利用する {#saved-briefs}

1. 作成画面で **オプション → 保存済みの概要から始める** を展開し、保存済みの概要を選びます。
2. コピーされた目的、メモ、プレイブック、プロファイル、委任を確認してから **作成** します。
3. **概要として保存** で再利用可能な下書きに名前を付けます。完了済みを含む選択中の 1 回限りのミッションにも **概要として保存** があります。

概要が保存するのは指示と要求した選択であり、タスク計画、結果、会話、スケジュール時刻、実行権限ではありません。読み込むと通常の作成下書きを埋めますが、開始やスケジュールはしません。概要を削除しても既存のミッション／会話は残ります。**設定 → ミッション → 保存済みの概要** でライブラリを管理します。ライブラリを読み取れなくなった場合、**保存済みライブラリをリセット**（確認後）は、実行ではなく保存済みの概要を削除します。スケジュール自体に概要として保存する操作はありません。

## スケジュール、遅延実行、参照する会話 {#daily-schedules}

### ネイティブスケジュール {#native-scheduling}

ラベル横の **i** で選択肢の説明を確認できます。マウスを重ねる、キーボードでフォーカスする、またはタップしてください。

作成または編集で **スケジュール** を展開します。**頻度** には次の選択肢があります。

| 選択肢 | タイミング |
| --- | --- |
| 1回、今すぐ | 再生時に 1 回起動します。任意の条件は後述の方法で確認します。 |
| 1回、日時を指定 | IANA ゾーンで保存した 1 つの日時です。再生時に過去になっている日時は拒否されます。 |
| 1回、一定時間後 | 分または時間の正の整数で指定した期間です。再生時に始まります。 |
| 一定間隔 | 最短 15 分です。最初の起動通知は再生から 1 間隔後です。 |
| 毎日 | 保存したゾーンの現地時刻を 1 つ指定します。 |
| 指定した曜日 | チェックした曜日に 1 つの時刻で実行します。 |
| 1日に複数回 | 09:15 と 17:45 など、最大 8 つの独立した時刻です。同じ時刻は 1 回の実行にまとめられます。 |
| 毎月の指定日 | 1〜31 日の選んだ時刻です。その日がない月はスキップします。 |
| 詳細（cron） | ネイティブの cron 式で、最多で 1 分に 1 回です。 |

**次の予定（最大5件）** は、保存したゾーンと仮定した再生時刻でプレビューします。条件がある場合、**次の確認（最大5件）** は確認の予定を示し、実行には検証済みの変更が必要です。変更していない保存済み間隔はネイティブの位相を保持します。一時停止中または不明の位相は、ネイティブ状態を読めるまで利用不可と表示されます。遅延と間隔は経過時間を使い、現地暦によるカレンダーは保存したゾーンと OpenCode の夏時間規則に従います。表示する日時は、サービスとホストの稼働状況に左右される予測です。

障害後、ネイティブスケジュールは最大 1 回の遅延実行を行ってから将来の予定に戻ります。記録されたネイティブの予定枠を使うため、後から逃した枠より前の枠になる場合があります。1 日の複数の時刻は、この遅延実行と同じ重複防止を共有します。未解決の実行は、元の会話とメッセージの識別情報で照合されてから次の実行を開始できます。明示的に一時停止した繰り返しを再開すると、次の将来の予定を使います。一時停止した単発の予定は、遅れて 1 回届く場合があります。

### 条件とソース {#scheduling-conditions}

任意の **条件** を 1 つと、その **このプロジェクトの対象** を選びます。**別のスケジュールの成功**、**ローカルブランチの新しいコミット**、**単発ミッションの正常完了**、**フォロー中の会話の新しいメッセージ**、**明示したファイルの変更** から選べます。条件だけの場合は **1回、今すぐ** のままにします。1 回の実行が始まるまで、ネイティブの確認を 15 分ごとに行います。カレンダーがある場合は、その予定時刻に条件を確認します。繰り返す条件は、新たに条件を満たす変更があると再び起動できます。

最初の再生で開始基準を設定します。再開は、一時停止後に観測した変更も含めてその基準を保持します。成功を条件にするソースには、検証済みの成功結果と確定済みのネイティブファミリーが必要です。ブランチの確認は、取得操作をせずにローカルのコミットと祖先関係を使います。会話の確認は、完全で安定した新しいメッセージを待ち、技術用の起動通知と実行自身の会話を除外します。ファイルはプロジェクト相対の明示的なパスを最大 128 件、1 行に 1 件指定します。再帰パターンとリンクされたパスは拒否します。ソースが欠落、移動、曖昧、または容量超過の場合、説明とともに実行受付をブロックします。確認の間に起きた変更を検出するには、ソースに永続的な痕跡が必要です。

同時に観測した変更はまとめられます。実行は観測したソースの根拠を固定し、成功として確定するとそのスナップショットを消費して、以後の変更を将来の確認に残します。失敗した実行はソースのチェックポイントを保持し、介入が必要になります。**オプション** の **参照する会話（任意）** は、会話メッセージの条件の選択とは別にコンテキストを提供します。

### 終了と回数 {#scheduling-limits}

繰り返しを継続するには上限を空欄にします。**最後に許可する予定日時** と **初回再生から最後の予定までの時間数（任意）** は対象となる予定を制限し、早い方の上限が適用されます。期間は最初の再生で始まり、一時停止中も進みます。終了前に記録された予定は、長い障害の後に遅れて届く場合があります。受け付け済みの実行は、結果が出るまで観測できます。

**開始する実行の最大数** は、すべての時刻と **今すぐ実行** で共有する総数です。コーディネーターの最初の入力を受け付けた時点で 1 回と数え、後に失敗する実行も含みます。確認、変化のない条件、拒否された起動通知は回数を消費しません。受付が不確かな場合は照合まで 1 回分を確保します。単発の方針は最大 1 回の実行を許可します。消費済み回数は編集や再起動後も残ります。変更していない終了上限は、最初の再生を起点とした基準と絶対的な終了予定を保持します。最大数を変更すると累積回数の上限が変わり、消費済み回数以下にするとスケジュールが終了します。頻度を変えると、エディターの説明どおり、保存時に新しい間隔の位相が始まる場合があります。

選択中のネイティブスケジュールには、**希望状態**、**ネイティブカレンダー**、**次の起動通知** または **次の確認**、**確認回数** と記録の開始日時、**開始した実行**、**成功した実行**、終了条件、**過去の実行** が表示されます。以前の実行は **会話を開く** から読みます。**スケジュール終了** はスケジュールの終了を表します。各実行の結果は別に確認してください。結果は最新 30 件を保持し、累積回数はその範囲を越えて残ります。**Missionをさらに読み込む** は、保存済み対象の次のページを読み込みます。

一覧では設定済みの条件と終了条件だけを表示し、**確認回数** は条件がある場合だけ表示します。

### 既存の日次スケジュール {#existing-daily-schedules}

既存の日次スケジュールは、保存した IANA ゾーンと現地時刻を使います。実行ごとに専用のコーディネーターとミッションマップを持ちます。現在のタスクツリーや過去の日付／結果を選ぶと、中央で結果を読めます。保存する履歴は 30 件です。次の日次規則がこれらの項目に適用されます。

| 状況 | スケジュールの動作 |
| --- | --- |
| 複数の予定日を逃した | 確定済みの日次マーカーより新しい、最新の予定日だけを実行します。逃した日すべてを順に実行しません。 |
| 夏時間開始による時刻の欠落 | その後の最初の有効な分に進みます。日の終わりの欠落では日付境界を越えます。 |
| 時計の同じ時間の繰り返し | 最初の出現を使用し、2 回目の日次実行は作りません。 |
| 現地暦日が丸ごとスキップされた | その日の実行はありません。 |
| 時計が後退した | 処理済みの日を再び実行対象にしません。 |
| 既存の実行がまだ保留中 | 新しい日次実行を重複させません。 |

作成時刻も対象となる日次作業を制限します。既存の日次項目で **今すぐ実行** が利用できる場合、保留中の実行を防護する仕組みのもとで別の手動実行を開始し、日次の時計を保持します。表示される次回時刻は、サービスとホストの稼働状況に左右される予測です。

**参照する会話（任意）** は、選んだ会話から範囲を限定したコンテキストを追加します。処理済みメッセージのカーソルを進めるのは完了した実行だけであり、失敗／中断した実行が無断でコンテキストを消費することはありません。指示とコンテキストが容量を超える場合は、履歴を無制限に読むと思い込まず、指示を短くするか参照する会話を削除します。

## 寿命とサービスの再起動 {#lifetime}

**技術詳細** 横の **i** で技術的な活動と費用の説明を確認できます。**設定 → OpenCode** の監視では状態とエラーを表示し、一般的な説明は **i** にまとめています。

ネイティブスケジュールでは、**技術詳細**を展開すると、**主キャリア**と**整合用キャリア**、それぞれのネイティブカレンダー、および**クリーンアップは整合処理待ち**の状態を確認できます。これらの技術用会話にはメッセージ入力の操作がなく、通常の会話やソースの選択候補にも表示されません。技術用の起動通知、タイトル、コンパクションにはローカルモデルを使用し、プロバイダーへのHTTPリクエストは行いません。ネイティブのイベントや統計にはこれらが含まれる場合がありますが、実際の実行には通常のモデル費用がかかります。コンパクションは、会話とカレンダーの識別情報を維持しながら処理対象のコンテキストを制限します。保存されたネイティブのメッセージとイベントは、終了したスケジュールを明示的にクリーンアップするまで増える場合があります。保持される30件のMission結果とは別です。深さの設定と**スケジュール**には、パスが取得できる場合に**OpenCode 設定ファイル：**として表示され、深さの設定では**プロジェクトの書き込み先**を別に示します。

| 要素 | 閉じた場合の意味 |
| --- | --- |
| CodeNomad のプロジェクトタブ | CodeNomad 内でそのプロジェクトを閉じます。ネイティブのセッションは OpenCode で続き、プロジェクトを開き直すと再び確認できます。 |
| ウィンドウ全体、アプリの終了、レンダラーの再読み込み | 復元のためにプロジェクト接続を保持します。ネイティブの作業や OpenCode サービスは停止しません。 |
| CodeNomad バックエンド | OpenCode は停止しません。実行中の 1 回限りのミッションは続行します。コーディネーター、ネイティブサブエージェントのタスク、ミッションツールは OpenCode 内で動作します。独立したセッションへのタスクの割り当てとそのレポートのコーディネーターへの配信、コーディネーターが準備するミッション、取り下げ済みタスクの会話の停止、復旧、ミッションコントロールはバックエンドを待ちます。OpenCode サービスの再起動後に 1 回限りのミッションを続行する場合も同様です。 |
| 有効化したネイティブスケジュール | 永続化された OpenCode カレンダーがプロジェクトを起動し、実行ホストとサービスが利用できる間は CodeNomad UI とバックエンドを閉じても実行します。 |
| OpenCode サービスの再起動 — 正常なネイティブスケジュール | 希望状態が稼働中の正常なスケジュールは、カレンダーを自動で再開します。保留中の作業は新たな受付の前に元の識別情報で照合されます。 |
| 既存の日次スケジュール | サービスが動作する間、CodeNomad を閉じてもプラグインの時計は動きます。サービスの再起動で **中断** となり、明示的な **再開** で保留中の実行を照合して日次の時計を再び有効にします。 |

ネイティブスケジュールでは、明示的な一時停止、停止、失敗した作業、不確かな結果による受付の障壁は再起動後も保持されます。保持された実行と元のリクエストを確認し、利用できる **実行を確認** または **保存済みリクエストを更新** を使用してから、状態が許す場合にだけ **再開** してください。ネイティブの続行は既存の識別情報で観測します。確認された失敗やレポートなしの終了には人による復旧が必要で、根拠が不十分なら実行は不確かなままです。開始済みのツールの影響を再試行するために、再起動を使わないでください。

[OpenCode の起動を維持](opencode.md#service-supervision) は、実行ホストの共有サービスを別途監視します。明示的な無効化を保存していなければ、ミッションの最初の再生で有効になります。一時停止中のミッションを作成しても、その選択を保持します。無効にすると OpenCode は動作を続けますが、自動再起動は行いません。Windows、macOS、WSL はログインの境界を使い、ネイティブ Linux は権限に応じてユーザーサービスの常駐を使います。スリープ、休止、WSL のアイドル時の寿命、外部ホストの制御により稼働状況は制限されます。監視状態はスケジュールと別に確認してください。

ミッションは、デスクトップアプリでも、スタンドアロンの CodeNomad [サーバー](server.md)でも動作します。パネルに **ミッションコントロールを利用できません** と表示された場合、そのメッセージに原因が示されます。

| 原因 | 対処 |
| --- | --- |
| OpenCode ワークスペースの準備ができていない | プロジェクトに再接続してから更新します。 |
| OpenCode がミッションプラグインを読み込んでいない | しばらくしてから更新します。解決しない場合は、**設定 → OpenCode** の **OpenCode の設定を再読み込み** を使用します。 |
| OpenCode がミッションプラグインを読み込めなかった | プラグイン一覧でエラーを確認し、修正後に更新します。 |
| CodeNomad サーバーがミッション用のローカル接続（127.0.0.1）を開けなかった | サーバーログを確認します。OpenCode を再読み込みしても解決しません。 |

## 一時停止、停止、不確かな結果 {#controls-recovery}

1. 項目を選び、操作前に現在の状態と会話を確認します。
2. 再開可能な保留には一時停止アイコン、終端の停止には停止アイコンと確認を使用します。1 回限りのツールチップは **ミッションを一時停止** と **ミッションを完全に停止** です。スケジュールのツールチップはスケジュールを明記します。
3. 結果が未確認なら、**状態を確認**／**制御状況を確認** で既存の結果を読みます。不確実性を回避するための代替操作は送らないでください。
4. 1 回限りの操作では、ヘッダーの **更新して未確認の操作を再送信** がまず状態を確認し、明示的なクリックから、その同一の操作がまだ未確認の場合に限り再送します。

1 回限りの一時停止では、進行中の作業を終えてから止まります。コーディネーターとサブエージェントは現在のステップを完了し、新しい作業を始めずに停止します。その間、パネルには **一時停止中: 実行中のステップを完了しています。** と表示されます。**今すぐ中断** を使うと代わりにすぐ止まり、ミッションのネイティブファミリーを中断して調整を保留します。停止も中断を行い、キューにあるファミリーの入力／配信をキャンセルし、終端状態になります。中断には上限があり、**一部のサブエージェントがまだ実行中の可能性があります。** はいずれかが不完全であることを意味します。すべてのシェル／ツールの影響がキャンセルされたと想定せず、保持された結果を確認し、明示的な再試行を使用してください。再開時には一時停止または中断された内容がコーディネーターに通知され、作業の続け方はコーディネーターが判断します。

ネイティブスケジュールの **一時停止** は今後の受付を閉じ、受け付け済み実行の中断を要求します。**再開** は既存の作業を照合してから再び有効にします。**停止…** は終端です。**今すぐ実行** はカレンダーを維持しながら、同じ保留防護と開始回数の上限を使います。**実行を確認** は元の実行を照合します。未確認の操作を保持し、**保存済みリクエストを更新** を使用してください。受動的な更新や再接続でもそのリクエストを保持します。開始済みのツールの影響は中断後も続く場合があります。

既存の日次項目は、日次の一時停止、停止、再開、今すぐ実行、実行を確認の操作を保持します。一時停止／停止は時計を解除し、独立した専門担当を含む登録済みルートの中断を要求します。ネイティブファミリーと中断の部分的な結果を確認してください。一時的な日次確認の失敗は、警告を表示して再試行します。ユーザー操作の応答が失われても元のリクエストに関連付けたままです。停止済みの項目は終端のままです。

レポートなしで待機している 1 回限りのコーディネーターは、主操作の ▶ で確認・復旧できる場合があります。タスクにも、対象条件を満たせば個別の不足レポート復旧があります。復旧は先にネイティブのアクティビティ、子孫、待機を確認し、アクティビティが不明なら受け付けを拒否します。割り当ての再実行や計画の置き換えはしません。会話を開いて、未解決の質問、権限、シェル、バックグラウンド作業を解消してください。

**作成** が未確認の場合、ウィンドウは送信したリクエストを保持し、そのプロジェクトの追加作成を無効にします。ワークツリー削除も保留されたままになる場合があります。更新は状態を読むだけです。エディターの開閉では修復しません。ウィンドウの再読み込み前にミッション一覧を確認してください。再読み込みはローカルのロックを消しますが、**作成に失敗した証拠ではありません**。再読み込みや再起動の後に、無条件で重複作成しないでください。

## 編集、削除、会話のクリーンアップ {#cleanup}

フォームの読み込み中に目的やメモが変わった場合は、入力せずに開いた後にミッションが変更されたことを表示します。現在の版を編集するには **開き直す** を選択します。

実行の合間には、一時停止中または稼働中のネイティブスケジュールで、実行や未解決の操作が対象を保持していなければ、タイトル、指示、メモ、要求プロファイル、タスクセッションのモード、ソース、カレンダー、上限を編集できます。一時停止中のスケジュールはそのまま、有効なスケジュールはカレンダーを照合してから続行します。保存時には過去の結果、消費済みソース、開始回数、最初の再生を起点とする基準を保持します。変更していない終了上限は絶対的な終了予定を保持します。

受け付け済みの実行中は、指示とメモだけが実行中のテキスト編集の契約に従います。変更は履歴と今後の実行用設定に保存されます。既存のタスク、依頼内容、プロファイル、実行の識別情報は受付時の値を保持します。構造に関わる項目は、一時停止後も含め、実行が確定するまでロックされます。プレイブックは完了・取り下げ済みを含むタスクが 1 件でも作成されるとロックされたままです。受付／操作が不確か、または整合性の根拠が不十分な場合、構造編集は読み取り専用です。作成と編集はカレンダーの検証を共有し、プレビューは編集した最後の許可予定を保存済みの次回起動に適用します。遅れた起動も対象です。

ローカルブランチの選択にはworktreeを持たないブランチも含まれ、ローカル参照だけを読み取ります。最大200ブランチに対応し、それを超える場合はソースが利用不可と表示されます。**開始**と**再開**は有効化が可能な場合に正確な設定パスを示して同意を求めます。ネイティブスケジュールが無効な間、**今すぐ実行**は理由を表示して無効になります。OpenCodeの設定で `experimental.schedules` を有効にしてから更新してください。有効化の応答が失われた場合、元のリクエストを保持して結果を照合します。

最初の Play 前なら、**オプション**の追跡中の会話を保持したまま、条件なしの即時起動に戻せます。Play は完全で安定したメッセージの連続部分を読み取り固定します（ソースごとに最大32件、起動入力全体で16,384文字以内）。ソースの欠落、移動、容量超過は説明とともに起動をブロックします。再試行でも固定されたコンテキストと元の起動 ID を維持します。

受領記録の読み取りで準備が部分的に完了していると確認されると、**再試行**が表示されます。クリックすると同じ記録を再確認し、ミッションを一時停止したまま元の保存済み変更だけを再開します。

新しく準備したミッションの初回起動前には、タイトル、指示、メモ、プレイブック、要求するエージェント・モデル・思考設定、タスクセッションのモード、**スケジュール**を編集できます。同じミッションを保ったまま、即時・遅延・繰り返し・条件付きの起動を切り替えられます。保存すると一時停止を維持したまま、新しい空のコーディネーターを準備し、元の会話を保持します。作業の開始やスケジュールの有効化は Play で行います。起動後の指示とメモは、実行中ミッションの編集規則に従います。保存が未確認の場合、**保存済みリクエストを更新**で元の結果を読み取ります。準備の一部が未完了で起動・テキスト編集・削除がブロックされている間は、同じリクエストを保持してください。

編集可能な単発ミッションまたはネイティブスケジュールで **選択したミッションを編集** を使用します。ロックされた項目の横の説明を読んでください。リビジョンが競合した場合は **現在の設定を再読み込み** を選び、**比較用の以前の下書き** を開いて保持された下書きを確認してから再度保存します。既存の日次スケジュールは専用ツールバーの操作を保持します。

ネイティブスケジュールの **選択したミッションを削除…** は、今後の実行を無効にしてから項目を削除します。会話と結果は保持され、照合待ちのクリーンアップは **技術詳細** に表示され続けます。未確認の削除を保持し、元のリクエストを更新してください。

1. 不要になった 1 回限りのミッションで、**選択したミッションを削除…** を選び、確認内容を読みます。
2. 必要に応じて、確認前に **このミッション用に作成された専門担当の会話も削除する** を選びます。
3. **会話のクリーンアップ** で削除／保持／保留の件数を確認します。再試行が提示される場合は、記録された残りのクリーンアップだけを再試行します。

ミッションの削除と停止は同じではありません。先に停止を使用して残った作業を確認してください。コーディネーターと再利用された会話は保持されます。共有、移動済み、子を持つ、所有関係を確認できない専門担当も保持される場合があります。部分的なクリーンアップは巻き戻されず、バックグラウンドで無断で完了されることもありません。会話のクリーンアップが保留 0 件でも、削除の確認が保留中のままミッションカードが消える場合があります。削除が確認されるまで、元の **再試行** 操作を使ってください。同じ削除要求とオプションが保持されます。概要リーダーには、完了したクリーンアップのうち最新の 20 件が残ります。ミッションを削除すると、プロジェクト内のその保存領域が解放されます。古い削除済みミッションは自動的に消去されます。

ネイティブの作業とサービス制御については、[権限](permissions.md)、[会話](conversations.md)、[OpenCode のセットアップ](opencode.md)を参照してください。
