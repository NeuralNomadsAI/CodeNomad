# 更新

## リリースフィードを選ぶ {#feed}

1. **設定 → 情報 → 更新** を開きます。
2. **アップデートチャネル** を **安定版リリース** または **プレビュー版と安定版リリース** に設定します。
3. 更新の確認／再取得を行い、インストールを受け入れる前に、提示されたリリースを確認します。

フィードは CodeNomad サーバー設定に保存され、提示されるリリースだけを変えます。デスクトップデータプロファイル、下書き、ウィンドウ、OpenCode セッション、サービス設定は変えません。明示的に選んでいない場合、プレビューと表示されたビルドはプレビュー、他は安定版が既定です。

安定版は最新の正式リリースを選びます。開発ビルドが同じ基底バージョン番号を共有できるため、プレビューは公開順に従います。数字のバージョンだけで比較しないでください。プレビューパッケージは、リリース前の動作を試す意思のあるユーザー向けです。再起動前にリリースノートを確認し、重要な下書きを保護してください。

## デスクトップのインストールを更新する {#desktop-update}

1. **Help → Get Updates...**、更新通知、または **設定 → 情報 → 更新** のボタンを使用します。
2. Electron ではリリースページに進み、使用するホスト／プラットフォーム用のアーカイブ／パッケージを取得します。
3. 対象となるローカル Tauri 環境では、ネイティブの提示内容を確認し、明示的に **インストールして再起動** を選びます。
4. インストール／再起動の前に全ウィンドウの重要な作業を保存し、再起動後に **情報** を確認します。

| Tauri のインストール形態 | アプリ内インストールの可否 |
| --- | --- |
| Windows x64 NSIS インストール | 埋め込みの更新キーと署名済みリリースペイロードがあれば対応。 |
| macOS x64 / arm64 アプリ | 埋め込みの更新キーと署名済み `.app.tar.gz` ペイロードがあれば対応。 |
| Linux x64 AppImage | AppImage バンドルマーカー、空でない `APPIMAGE` パス、署名付き更新への対応が必要。`APPRUN` だけでは不十分。 |
| Debian/RPM、単体 Windows 実行ファイル、未署名／キーなしビルド | アプリ内インストールの代わりにリリースページを開く。 |

Tauri のアプリウィンドウとネイティブの **環境設定** ウィンドウでは、リリースが提示されると、更新カードに **アップデートをインストール** が表示されます。選択したフィードを確認し、アプリ内更新が利用できる場合は **インストールして再起動** を提示します。それ以外の場合は、カードに表示されたリリースページを開きます。Electron、Web、リモートウィンドウでは、代わりに **更新をダウンロード** リンクが表示され、ネイティブ更新機能による確認は行いません。

Tauri の **Help → Get Updates...** メニューは、フォーカスされているアプリウィンドウで更新処理を実行します。環境設定またはリモートウィンドウから使用すると、最後に使用したアプリウィンドウを前面に出して確認を実行します。リモートウィンドウを通じてインストールすることはありません。対象が読み込み中、ログイン、ペアリング画面である場合など、操作を受け取れるアプリウィンドウがない場合は、代わりにリリースページを開きます。

Tauri は、選んだフィード／対象向けに更新マニフェストが公開されたリリースだけを提示します。発表直後のリリースは、まだインストールできない場合があります。その際、通知はリリースページを開くことがあります。インストール前にネイティブの署名検証が必要です。更新用署名は、OS の公証／コード署名による保証とは別です。

インストールは、全アプリウィンドウの状態を書き出し、所有する CodeNomad バックエンドを停止してから、アプリを置き換え／再起動します。独立して管理される OpenCode デーモンは、この終了処理の対象外です。CodeNomad を閉じると、戻るまでバックエンド依存機能は利用できません。OpenCode セッションの継続から、UI サービスも無中断だと推測しないでください。

確認が使用中なら、別ウィンドウの処理を待ちます。ダウンロード、検証、終了処理の失敗では、エラーを読んで新しく確認してください。古い通知は古いバイト列を再インストールする許可ではありません。インストール失敗時にはバックエンドとウィンドウを復旧する場合がありますが、インストールを自動再実行しません。ネイティブインストールが利用できなければ、リリースページから適切なパッケージを使ってください。[インストール](install.md)を参照してください。

## スタンドアロンサーバーを更新する {#standalone-update}

1. CodeNomad の起動方法を確認し、そのバックエンドに依存する作業を保存します。
2. 通常のプロセス／サービス制御で、その CodeNomad サーバープロセスを停止します。
3. 同じパッケージのインストールを更新し、意図した設定とフラグで再起動します。

| 起動／インストール方法 | 更新コマンド |
| --- | --- |
| 安定版 npm の単発起動 | 通常のフラグを付けた `npx @neuralnomads/codenomad@latest` |
| 安定版のグローバルインストール | `npm install -g @neuralnomads/codenomad@latest` |
| 安定版のローカルインストール | そのパッケージディレクトリで `npm install @neuralnomads/codenomad@latest` |
| プレビューの単発起動 | 通常のフラグを付けた `npx @neuralnomads/codenomad-dev@latest` |
| プレビューのグローバル／ローカルインストール | 同じグローバル／ローカルの npm 形式で `@neuralnomads/codenomad-dev@latest` をインストール |

npm がインストールしただけで、実行中のプロセスに新しいコードは入りません。同じ設定パスを意図的に維持してください。設定画面のフィード選択は、npm パッケージの置き換えや、安定版／プレビューのパッケージ名の自動切り替えをしません。再起動時も認証／TLS フラグを維持します。[サーバー](server.md)を参照してください。

## OpenCode の保守は分けて扱う {#opencode-separate}

CodeNomad の更新と、選択した OpenCode CLI の更新は別です。CLI の更新と、稼働中の共有デーモンの再起動も別です。ネイティブ設定の再読み込みは、読み込み済み Location とリクエストに固有の影響を持つ、さらに別の明示的操作です。

デスクトップの Node/npm リソースはアプリに同梱され、アプリリリースで更新されます。システムの Node/npm、Electron 内部ランタイム、プラットフォームの webview、独立管理の OpenCode サービスを置き換えるものではありません。

ランタイムの選択、インストール／更新、明示的なサービス制御には **設定 → OpenCode** を使います。特に他ウィンドウ／ユーザーやミッションがデーモンを共有している場合、再起動／再読み込み前に [OpenCode のセットアップ](opencode.md)を確認してください。更新／再接続が終わったという理由だけで、不確かなプロンプトや変更操作を繰り返さないでください。
