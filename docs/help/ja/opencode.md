# OpenCode のセットアップ

CodeNomad は、実行ホストの共有 OpenCode サービスに接続します。CLI の選択、そのファイルの更新、サービスの再起動、設定の再読み込みは別の操作であり、互いの代わりにはなりません。

## CLI の選択・インストール {#select-cli}

1. **設定 → OpenCode** を開き、**OpenCode バージョン** の下にある **OpenCode バイナリ** カードで実行ファイルを選びます。
2. 自動の項目を選択したままにすると、サーバーの PATH（古い OpenCode がある場合を除く）、次にユーザーの npm の OpenCode 2 インストールを優先します。または、**バイナリを参照…** を使うか、パスを入力して **追加** を選びます。
3. **状態と更新を確認** を使用します。OpenCode がなければ **OpenCode をインストールして起動** を選びます。先にホストとインストール範囲を確認してください。
4. セットアップに **接続して続行** が表示される場合は、報告された問題を解決してから使用します。

インストールでは同梱の Node/npm を使用し、他のクライアントと共有する標準のユーザーインストールを行います。**ユーザー用にインストールして PATH を設定** は、そのユーザーのターミナル設定を変更します。後で新しいターミナルを開いてください。ブラウザーは CodeNomad サーバーに接続するため、ファイルピッカーと実行ファイル選択の対象は、閲覧端末ではなくそのサーバーです。

PATH の先頭に古い OpenCode がある場合、提示される操作はそのインストール方法によって異なります。npm でインストールした OpenCode 1.x では、**OpenCode {version} を OpenCode 2 に置き換える** が確認を求めたうえで、その npm パッケージを削除し、同じ npm フォルダーに OpenCode 2 をインストールします。OpenCode のデータフォルダーは保持され、OpenCode 2 が 1.x の会話を自動で取り込みます。別の方法（winget、Homebrew、手動）でインストールされた古いまたは使用できない OpenCode は変更されません。**CodeNomad 用に OpenCode 2 をインストール** がその横のユーザー npm フォルダーに OpenCode 2 をインストールし、以後 CodeNomad はそのコピーを使用します。その古いコマンド自体がユーザー npm フォルダーにある場合（たとえば `~/.local/bin` 内のリンク）や、そのフォルダーに書き込めない場合は、この操作の代わりに理由が表示されます。コマンドを移動するか名前を変更する、またはフォルダーの権限を修正してから、**状態と更新を確認** を選択してください。ターミナルの `opencode` コマンドは、引き続き古いバージョンを起動する場合があります。明示的に選択したカスタム実行ファイルが置き換えられることはありません。

インストール済み実行ファイルと、実行中のサービスは、バージョンが異なる場合があります。別の実行ファイルを選ぶと稼働中のデーモンも置き換わったと思わず、**OpenCode バージョン** カードの **インストール済みバージョン** と **実行中のサービス** を比較してください。**バージョンの詳細** には最低バージョンと推奨バージョンが記載されています。インストール中や実行ファイルのロック中は、インストーラーやプロセスが解放するまで待ち、状態を確認してから再試行します。競合するインストーラーを実行しないでください。

## 必須、推奨、未検証のバージョン {#versions}

| 分類 | 現在の要件 | 意味 |
| --- | --- | --- |
| 最低 | OpenCode **2.2.3** | **画像** の設定と Design 拡張機能が使う画像生成ツール、Code Mode の JavaScript ジョブの正しい実行順序、ネイティブ再生・圧縮形式。以前のバージョンで保存した会話は、更新後も読み込めます。 |
| 推奨 | OpenCode **2.2.5** | 検証済みの対象。技術的な最低要件とは別です。 |
| 未検証 | 完全には検証していない、新しいまたはカスタムのバージョン | 未テストという理由だけで拒否せず、接続先サービスの実際の API 契約を確認します。 |

接続先サービスは、必要なセッション、権限、フォーム、受信箱、セッション環境の契約を提供する必要があります。ネイティブのミッションスケジュールは、スケジュール API、プラグイン／プロバイダーのバンドル、有効な `experimental.schedules` 設定も確認します。利用可否はこれらの使用する機能で決まり、互換性のある将来のバージョンにも適用されます。セットアップが実行中のサービスを未対応と報告した場合は、対応する CLI を選択／インストールし、準備ができたら明示的に共有サービスを再起動します。

## ホスト、WSL、共有サービスの範囲 {#execution-host}

Windows で WSL の実行ファイルを選ぶと、選択したディストリビューション内で実行します。そこでインストール／更新し、そのディストリビューション内で意味のあるパスを使用してください。WSL の接続は Windows の localhost 転送に依存します。Windows CLI と WSL CLI は、交換可能な実行環境ではありません。

グローバルなサービス登録、セッション、メッセージ、データベースは OpenCode が管理します。CodeNomad は、ウィンドウやプロジェクトごとに専用の OpenCode データベースを作りません。プロジェクトタブを閉じると CodeNomad 内でそのプロジェクトが閉じられますが、セッションは OpenCode で続き、プロジェクトを開き直すと再び表示されます。CodeNomad がネイティブの Location を解放することはありません。ウィンドウ全体を閉じる、終了する、再読み込みする場合は、復元のためにプロジェクト接続が保持されます。これらの操作も、バックエンドの終了も、共有デーモンを停止しません。[プロジェクト](projects.md)を参照してください。

## OpenCode の起動を維持 {#service-supervision}

最初の Mission の再生前に、**最初の Mission 再生時もオフを維持** で、監視を先にインストールせずに明示的なオフを保存できます。

**設定 → OpenCode** の **OpenCode の起動を維持** は、実行ホストに OS の監視をインストールし、そのサービスを使うすべての CodeNomad プロファイルで共有します。Missions とは独立して動作し、CodeNomad を閉じても有効です。事前に明示的に無効にしなければ、最初の Mission の再生で有効になります。一時停止状態の Mission の作成は選択を維持します。Mission の一時停止、停止、削除でもこの設定は維持されます。

無効にすると監視を削除し、OpenCode は動作を続けますが再起動されなくなります。継続的に停止するには、先に無効にしてから OpenCode を明示的に停止してください。監視が有効な場合、`opencode service stop` の後に再起動されます。

**稼働中 · 監視有効** には、OS 監視プロセスの稼働と OpenCode サービスの正常性が必要です。**インストール済み · サービス起動中**、**監視をインストールまたは削除中…**、**監視に失敗** は異なる状態です。サービスの応答だけでは監視は未確認のままです。詳細には、分かっている場合に原因、最終試行、監視プロセスの再試行、OS 復旧の安全確認が表示されます。**監視状態を確認** は読み取りのみ、**監視を再試行** は要求した設定の明示的な修復です。未確認の操作は元の要求を保持し、**元の操作を再試行** は同じ操作だけを再送します。設定リビジョンが変更された場合は上書きせず、確認のため更新します。

Windows、macOS、WSL はログイン後に起動します。WSL は選択したディストリビューションの localhost 転送が必要です。ネイティブ Linux の linger は、**有効なすべてのユーザーサービス** をログイン前に起動し、ログアウト後も動作させます。無効化時は CodeNomad が有効化し、他の監視が必要としない場合のみ linger を復元し、個人設定は維持します。ユーザーセッションが開かれていない状態で linger を復元すると監視から解放された OpenCode プロセスが停止するおそれがある場合、復元は保留され、**監視を再試行** とともに表示されます。ユーザーセッションが開かれるか、監視から解放された OpenCode プロセスが終了し、安全に復元できる状態になってから再試行してください。Linux が権限を求める場合は実行ホストで許可し、再試行してください。要求した設定は保存されたままです。スリープと休止状態は OS が制御します。利用できない、または未対応のホストでは、説明付きで操作を無効にします。

## 更新、再起動、再読み込み {#maintenance}

1. **設定 → OpenCode** で、**状態と更新を確認** を選びます。
2. インストール済み CLI のファイルを置き換えるには、提示された **OpenCode {version} に更新** を選び、完了を待ちます。
3. 実行中サービスの状態を確認します。接続中の全クライアントで選択したインストールを有効にしたい場合にのみ、**共有サービスを再起動** を使用します。
4. 何もインストールせずにプロセスを再起動するには、**トラブルシューティング** を展開し、**OpenCode サービスを再起動** を選んで確認します。

| 操作 | 範囲と効果 | 安全な復旧 |
| --- | --- | --- |
| CLI の更新 | 対応するインストール済み実行ファイルを変更します。実行中のデーモンは暗黙に再起動しません。 | 失敗後はインストール済みと稼働中の両バージョンを確認し、エラー解決後にのみ明示的に再試行します。 |
| サービスの再起動 | 共有プロセスを置き換え、接続中の全 OpenCode クライアントの作業を中断します。セッション履歴は残ります。 | 正常に稼働中のネイティブミッションスケジュールは自動復旧します。保留中の実行と、一時停止／エラー／不確かな状態を確認してください。既存の日次項目には再開が必要です。単発の会話と復旧操作は別に確認してください。[ミッション](missions.md#lifetime)を参照してください。 |
| OpenCode の設定を再読み込み | プロセスは維持しますが、全クライアントの **読み込み済みのすべての Location** を再構築します。保留中の権限／Form をキャンセルし、ターミナル／バックグラウンドコマンドを閉じます。進行中の作業が中断される場合があります。 | 再読み込み後にリソースと保留中の作業を再確認します。応答が失われたという理由だけで、プロンプトや変更操作を繰り返さないでください。 |

保存した設定やインストール済みプラグインがまだ利用できず、中断を許容できる場合に、明示的に **OpenCode の設定を再読み込み**（実行中のサービスが対応していれば **トラブルシューティング** の下にあります）を使用します。無害な表示更新ではありません。CodeNomad は、古い選択済み CLI を使って、新しい実行中デーモンをダウングレードしません。

## セッション環境 {#session-environment}

1. **設定 → 詳細設定** を開き、**環境変数** を展開します。
2. プロファイルの上書き値を追加、変更、削除します。各変更はすぐに保存されます。
3. CodeNomad から次のプロンプト、カスタムコマンド、セッションシェルリクエストを送信すると、その会話に現在の環境が適用されます。

これは設定プロファイルの設定であり、毎回の送信前にサーバー側で適用します。会話を開く／読むだけ、または設定の保存だけではネイティブセッションは変わりません。上書きを削除すると、実行ホストから継承する値に戻り、そこにない場合は削除します。環境を適用できない場合は、古い値を使わず送信をブロックします。

環境は、そのネイティブセッションで今後起動するローカルシェルを制御します。実行済みのプロセスは自分の環境を保持します。プロバイダー、MCP/LSP サーバー、独立したターミナル、Location のみのバックグラウンドシェルは再設定 **しません**。キューの各プロンプトが独自の環境を記録するわけではなく、別の OpenCode クライアントが同じセッション環境を置き換える場合もあります。OpenCode 内だけで作られた子セッションが CodeNomad の送信時更新を受けるとは想定しないでください。

許可された変数は、停止中のサービスを起動するときにも渡されます。既存デーモンへの接続では、そのプロセス環境は変更しません。WSL では、Windows の PATH/HOME ではなく、Linux の実行環境と値を組み合わせます。これらの上書きを変えても、OpenCode のデータベースやサービス登録の場所は移動しません。

## ネイティブ設定ファイルを編集する {#configuration-files}

1. **設定 → 設定ファイル** を開き、**ファイル** を選びます。
2. 表示されたパスを確認して編集し、**保存** を選びます。
3. **再読み込み** はファイルを読み直します。**OpenCode の設定を再読み込み** とは異なります。

このエディターが公開するのは、**CodeNomad サーバーユーザーの** `.config/opencode` ディレクトリにある、一覧に記載されたグローバルな `opencode.json` と `opencode.jsonc` のみです。任意のファイルのエディターやプロジェクト設定セレクターではなく、WSL／独自検出ルートのデーモンがそのファイルを読む保証もありません。表示パスで対象を確認し、ほかのルートにはデーモン自身のツールを使ってください。

保存はファイルをテキストとして書き込みます。ネイティブ設定全体の検証や OpenCode の再起動／再読み込みはしません。この画面には外部変更のマージ機能がないため、他クライアントと編集を調整してください。大幅な置き換えの前にコピーを保持します。ファイル切り替えや未保存下書きの再読み込み時には、破棄するか確認します。

設定固有の手順は、[連携](integrations.md)、[プロバイダー](providers.md)、[ミッション](missions.md)、[OpenCode ドキュメント](https://opencode.ai/v2/docs/)を参照してください。
