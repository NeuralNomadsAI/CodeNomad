# リモートコントロール

リモートコントロールを使うと、受信ネットワークポートを開かずに、ペアリングしたブラウザーやデスクトップクライアントから、稼働中の CodeNomad バックエンドを利用できます。サーバーパスワード、ループバック以外の `--host`、VPN は不要です。[直接接続](remote-access.md)とは別のアクセス経路です。

## 開始してペアリングする {#start-and-pair}

1. ホストで **設定 → リモートアクセス** を開きます。
2. **リモートコントロールを開始** を選び、**リモート接続の準備ができました** を待ちます。初回はトンネルの識別情報と証明書の準備に時間がかかる場合があります。
3. **別の端末を接続** で QR コードを読み取るか **リンクをコピー** し、その使い捨てリンクを目的の端末で開きます。
4. ペアリングしたブラウザーのサイトデータを保持します。バックエンドの稼働中はトンネルアドレスを開き直すと再接続できます。

リンクの有効期間は **5 分**、成功するのは **1 回** です。利用した人はペアリング済み端末になれるため、認証情報として扱ってください。コードはクエリ文字列ではなく URL フラグメントに入ります。**新しいペアリングリンクを作成** は、直前の未使用リンクを即座に無効化します。バックエンドの終了は未使用のペアリングリンクをキャンセルし、停止とトンネル障害はトンネルのリンクをキャンセルします。

別のデスクトップの CodeNomad で、ペアリングリンクを次の欄に貼り付けます：**設定 → サーバー → サーバーのアドレスまたはリンク**。

ペアリングし直すには、サーバーまたはプロジェクトの接続フォームに新しいリンクを貼り付けます。

## 直接 HTTPS でペアリングする {#direct-https}

トンネルがブロックされていても、実証明書を使うリバースプロキシなど、信頼できる HTTPS でバックエンドに到達できる場合は、そのアドレスで端末をペアリングできます。対象は、このバックエンド自身の HTTPS アドレスと `CODENOMAD_ALLOWED_ORIGINS` の HTTPS オリジンです（[許可するオリジン](remote-access.md#upgrading)を参照）。ループバック名と平文 HTTP ではペアリングできません。リモートコントロールを開始する必要はありません。

1. ホストで **設定 → リモートアクセス → リモートコントロール** を開きます。
2. **HTTPS 直接ペアリング** で、複数ある場合は **HTTPS アドレス** を選び、**HTTPS ペアリングリンクを作成** を選択します。
3. トンネルのリンクと同様に、端末でリンクを開きます。別のページからリンクをクリックして開くこともできます。

リンクには同じ 5 分・1 回限りのルールが適用され、未使用のリンクを置き換えます。誤ったコードの繰り返しは制限されます。リバースプロキシは信頼できる TLS を終端し、元の `Host` と `Origin` ヘッダーを渡し、ループバックまたは保護されたネットワーク経由でバックエンドに接続する必要があります。

この端末は HTTPS アドレス経由でのみ接続し、トンネル経由では接続しません。**ペアリング済み端末** には名前の下にそのアドレスが表示されます。リモートコントロールを停止しても、リンクは取り消されず、これらの端末も切断されません。**取り消す**、30 日間の未使用、32 台の上限、または設定からのアドレス削除でアクセスが終わります。そのアドレスで失効または期限切れの端末認証情報を送るブラウザーは、サーバーパスワードに切り替えられません。再度ペアリングするか、サイトデータを消去してパスワードでログインしてください。

[利用できる機能](#remote-surface)には、SideCar コンテンツの直接 HTTPS 接続に関する例外があります。ホスト上のプロキシを経由しても、ペアリングでループバック権限は得られません。

## ペアリング済み端末を管理する {#paired-devices}

1. ホストで **設定 → リモートアクセス → リモートコントロール** に戻ります。
2. **ペアリング済み端末** と **最終アクセス** の時刻を確認します。各端末には、`iPhone · Safari` のように、ペアリングしたプラットフォームとブラウザーにちなんだ名前が付きます。
3. 接続を許可しなくなった端末には **取り消す** を選びます。**アクセス取り消し保留中** と表示されたら、ホストを再起動する前にもう一度 **取り消す** を選びます。

取り消しは、その端末の現在の HTTP/SSE 接続と将来のアクセスを終了します。復旧するには新しいリンクで再ペアリングします。端末は **30 日間未使用** で期限切れになります。**上限の 32 台** に達すると、新しいペアリングは最も長く見られていない端末を置き換え、その接続を閉じます。

サイトデータの消去、ブラウザープロファイルの切り替え、プライベートブラウジングでは、再ペアリングが必要になる場合があります。

直接アクセスのパスワードを変えても、端末は失効 **しません**。**リモートコントロールを停止** はトンネルを切断しますが、ペアリング済み端末一覧は保持します。許可を取り除く場合は **取り消す** を使ってください。

### 現在の表示を失わず再ペアリングする {#re-pair}

1. クライアントに **このデバイスを再ペアリング** が表示されたら、そのページを開いたままにします。
2. ホストで元の接続用のリンクを作成します。トンネルでは **新しいペアリングリンクを作成**、直接 HTTPS では **HTTPS 直接ペアリング** で元の **HTTPS アドレス** を選んで **HTTPS ペアリングリンクを作成** を選びます。同じクライアントのブラウザー／プロファイルで開いてください。別のリモートウィンドウでは既存の保存領域を再利用します。
3. 待機しているページに戻り、**接続を確認** を選びます。ページにフォーカスが戻ったときにも再確認されます。

復旧は開いているページと下書きを保持しますが、失敗した操作は再実行しません。再試行の前に、送信、回答、削除が実際に反映されたか確認してください。直接アクセスのパスワードでは、リモートコントロールのペアリングを復旧できません。

## 利用可能性と寿命 {#lifetime}

| 操作／状態 | 効果 |
| --- | --- |
| リモートコントロールを開始 | このバックエンドを接続し、今後の起動用に選択を記憶します。 |
| リモートブラウザーを閉じる | ホストのバックエンド停止や端末の失効は行いません。 |
| リモートコントロールを停止 | トンネル経由のアクセスを切断し、起動時の自動再開を解除します。端末記録は保持します。 |
| バックエンドの終了／最後のデスクトップウィンドウを閉じてアプリを終了 | リモートコントロールはオフラインになります。OpenCode の共有サービスが稼働し続けても、停止したバックエンドを通してこの UI は提供できません。 |
| リモートコントロールを開始したままにした後の起動 | 新しいペアリングリンクを発行せず、バックグラウンドで再接続します。一度も開始していない環境で自動有効化することはありません。 |

起動時の自動再開は、設定ディレクトリごとに 1 つのバックエンドに限られます。トンネル容量を増やすために、同じ設定で競合するホストを起動しないでください。デスクトップ終了後も到達可能にするには、別途管理する[スタンドアロンサーバー](server.md)を配備します。リモートコントロール自体は独立したデーモンではありません。

## 利用できる画面と利用できない画面 {#remote-surface}

ペアリング済み端末は、同じ所有関係チェックの下で、通常のプロジェクト／会話 API、プロンプト送信、ファイル確認、権限／Form への回答を利用できます。ペアリングは強力なアクセスであり、読み取り専用の共有リンクではありません。トンネルがホスト内部で通信を転送しても、ループバック権限を与えることはありません。

| 対象 | リモートコントロール経由 |
| --- | --- |
| 通常の認証済み UI、ワークスペース、会話、SSE | ペアリング済み端末で利用可能。 |
| パスワードログイン／ログアウト、パスワード変更、ローカルトークン初期設定 | 利用不可。直接接続の認証が無効でも、端末認証情報が必要です。 |
| リモートコントロールの状態 | ペアリング済み端末で読み取り可能ですが管理は不可。開始／停止、ペアリング作成、端末一覧、取り消しはホストのアクセス経路に限ります。 |
| 保存済みサーバーとバックエンド中継 | 機能とホストの能力設定で許可されている場合、認証済みのリモートクライアントはホストに保存されたすべてのサーバーを利用・管理できます。新しいサーバーパスワードやペアリングリンクにはリモートコントロールまたは HTTPS が必要で、暗号化されていない LAN HTTP は使えません。[保存済みサーバー](remote-access.md#saved-servers)を参照してください。 |
| デスクトップのリモートウィンドウとウィンドウプロキシ | ホスト専用（`/api/remote-proxy/`）。 |
| SideCar コンテンツと WebSocket（`/sidecars/`） | トンネル経由では利用できません。ループバックを使うか、ホストで [SideCar への HTTPS 直接アクセス](browser-sidecars.md#register-sidecar)を有効にします。 |
| SideCar 登録（`/api/sidecars`） | ペアリング済み端末と認証済みの直接接続クライアントで利用できます。 |
| Web プレビューの内容 | [セッションのブラウザーを開く](browser-sidecars.md#session-browser) |
| 自動操作ブリッジ | 利用不可（`/api/opencode-plugin/`）。ネイティブデスクトップの能力がブラウザーの能力になるわけではありません。 |
| WebSocket アップグレード | Web プレビューで利用可能。ペアリング済み端末では[リアルタイム音声会話](voice.md#conversation)にも利用可能。 |

ホスト専用のプロキシ／WebSocket とリモートコントロールの管理（`/api/remote-control/`）には、ホスト上のループバック接続を使います。LAN からの直接アクセスでも、これらの操作にはループバックが必要です。[許可するオリジン](remote-access.md#upgrading)。

## リレーとプライバシー {#relay-privacy}

CodeNomad は [OpenTunnel](https://github.com/anomalyco/opentunnel) を使用し、マシンの共有既定トンネル識別情報上のランダムな 1 ルートを取得します。

TLS は CodeNomad バックエンドで終端します。リレーは暗号文を転送するためアプリ内容を読めませんが、ホスト名、接続の時刻、通信量を観測できます。トンネルの証明書／秘密鍵はホストに残ります。ホストのトンネルストレージと CodeNomad 設定を認証情報として保護してください。推測困難なアドレスは認可ではありません。

`CODENOMAD_REMOTE_CONTROL_API` はセルフホストの OpenTunnel API を選び、未設定ならホスト型サービスを使用します。変わるのはトンネルの配置であり、ペアリング要件やブロック対象ではありません。認証情報と診断の扱いは、[セキュリティ](security.md)を参照してください。

## 管理者ポリシー {#administrator-policy}

管理者は、コンピューター上のすべてのユーザーに対してリモートコントロールを無効にできます。環境変数 `CODENOMAD_REMOTE_CONTROL=disabled` をシステム全体に設定し、CodeNomad を再起動します。バックエンドはトンネルを接続せず、**リモートコントロールを開始** とペアリングリンクを拒否し、起動時に再接続しません。設定には **管理者により無効化** と表示されます。以前にペアリングしたデバイスは接続できず、取り消せるよう一覧に残ります。未設定または空の場合はポリシーなしです。それ以外の値 (空白のみも含む) ではバックエンドは起動しません。
