# パネル拡張機能

## インストール済み・オンラインの拡張機能を探す {#browse}

1. 右パネルのタブバーで **右パネルをカスタマイズ** を開きます。
2. 区切り線の下の **拡張機能** を展開します。
3. **拡張機能を検索** で、インストール済みアドオンと公式オンラインカタログをまとめた単一の一覧を検索します。項目にカーソルを合わせるかフォーカスするとメタデータを確認できます。

開閉セクションは、カスタマイズのポップアップを開くたびに折りたたまれています。インストール済みとオンラインの項目は拡張機能 ID でまとめられ、別の管理ウィンドウやインストール済み／オンラインのモードはありません。カタログのメタデータを閲覧しても、作者のパネルコードのダウンロードや実行はしません。カタログは [CodeNomad Extensions](https://github.com/NeuralNomadsAI/CodeNomad-Extensions) で管理されています。掲載や申告された作者名は、署名や信頼の証明ではありません。

カタログが利用できなくても、インストール済み拡張機能と **ZIP からインストール…** は利用できます。更新して検出を再試行してください。ポップアップを折りたたむ／閉じると、保留中の確認 UI は破棄されます。無断でインストールすることはありません。

## 確認して無効のままインストールする {#install}

1. カタログ項目の **インストール…**、または別途入手したパッケージの **ZIP からインストール…** を選びます。
2. パッケージ ID、作者、リポジトリ、バージョン、API／権限、SHA-256 ダイジェストを確認します。必要なら技術詳細を展開します。
3. 発行者を確認し、可能なら信頼できる経路でダイジェストを比較します。
4. コードを信頼する場合にのみ、**このパッケージと作者を信頼します** を選び、**無効のままインストール** を選びます。

検査では、選択したパッケージをダウンロード／再検証しますが、作者のコードは実行しません。ダイジェストは正確なバイト列を識別するもので、作者の身元を示すものではありません。カタログパッケージは、任意の URL ではなく、正確に宣言された GitHub リリース資産から取得します。手動パッケージは `manifest.json` と自己完結型の `panel.html` だけを含む ZIP です。不正／未対応のパッケージは拒否されます。

インストールに OpenCode の再起動は不要で、自動的に有効化を許可することもありません。検証失敗、競合、ストレージ操作の失敗は、異なるバイト列での再試行を許可しません。新たにインストールを試みる前に、パッケージを再検査してください。

## 有効化と適用範囲を理解する {#activate-scope}

1. **右パネルをカスタマイズ** の **拡張機能** セクションより上にあるアドオン行に戻ります。インストール済みで無効のアドオンも、この一覧に残ります。
2. チェックボックスを選んで有効化します。同じチェックボックスを外すと無効になります。

そのチェックボックスが唯一の有効化コントロールです。追加の管理スイッチや、ウィンドウごとの表示ゲートはありません。有効化はフォルダー単位ではなく、設定を使う全プロジェクトに適用されます。リモート接続では、閲覧端末だけでなくサーバーのインストール済み拡張機能ストアに影響します。

拡張機能ストアは、選択した CodeNomad 設定の隣の `panel-extensions/` です。別のデスクトップデータプロファイルでも、同じ設定ディレクトリを使う場合、拡張機能は分離 **されません**。逆に、別の設定を開くことは、他所にインストールしたアドオンの実行許可ではありません。違いは[デスクトップのウィンドウとデータ](desktop.md)を参照してください。

有効なパネルは選択時にマウントされ、非表示で一時的な UI 状態を破棄する場合があります。無効化は実行許可を取り消します。カスタマイズの **リセット** は組み込みレイアウトだけを復元し、拡張機能の有効化、無効化、アンインストールはしません。

## 置き換え・削除する {#replace-remove}

1. **バージョンを変更…**、または同じ ID の別 ZIP の検査で、インストール済みパッケージを置き換えます。
2. 新しいダイジェストと権限を確認し、信頼を認めてから、無効のままインストールします。
3. 置き換え版を信頼すると判断してから、通常のチェックボックスで再有効化します。
4. アンインストールには、対象を確認して **削除…** と **削除を確認** を使用します。

置き換えは毎回、権限一覧が同じでも、全プロジェクトの有効化を取り消し、パネル独自の保存済み設定を消去します。検証／競合／ストレージの失敗では、インストール済みパッケージを保持します。無断の拡張機能更新はありません。削除はパッケージ、有効化設定、保存済みのパネル設定を消しますが、OpenCode セッションやプロジェクトファイルは消しません。望ましくないコードから復旧するには、先に無効化し、確認済みの信頼できるパッケージだけを再インストールしてください。

## コンテキスト、資産への同意、サンドボックスの制限 {#permissions-sandbox}

| 契約 | 有効化で許可するもの |
| --- | --- |
| API 1 / `session.context` | 現在のセッション識別子（またはなし）、UI 言語、外観。会話テキストやファイルシステムアクセスはありません。 |
| API 2 / `session.assets.read` とコンテキスト | 明示的に確認した許可により、現在のセッションのツール結果画像／添付のメタデータを範囲を限定して一覧し、対応する埋め込みバイト列を読み取れます。一般的な会話、ファイル、URL へのアクセスではありません。 |
| API 3 / `repository.workItems.read` とコンテキスト | GitHub、GitLab、Gitea/Forgejo 上のプロジェクトリポジトリの issue と pull request を上限付きのページで一覧表示し、そのひとつをブラウザーで開くための、明示的に確認された権限です。ファイル、認証情報、一般的なネットワークへのアクセスではありません。 |
| API 4 / コンテキストと以下の権限の 1 つ以上 | 確認画面には宣言された権限ごとに 1 文が表示されます。有効化ではそれらすべてをまとめて許可し、置き換えではすべてを取り消します。 |
| `session.images.read` | 表示中の会話で read ツールが返した画像を、検証できる場合は生成状態と系譜とともに読み取ります。 |
| `session.images.prompts`（`session.images.read` が必要） | プロジェクトの「画像」会話で生成された各画像のプロンプトとモデルを読み取ります。 |
| `composer.prefill` | 表示中の会話の入力欄にテキストを追加します。メッセージを送信することはありません。 |
| `images.conversation` | このプロジェクトの「画像」会話を開くか開始します。 |
| `opencode.designAgent` | この拡張機能が有効な間、CodeNomad の Design エージェントとその画像スキルを OpenCode に追加します。 |
| `panel.preferences` | このパネル独自の設定を記憶します。 |

資産へのアクセスは、作者が選んだセッションではなく、現在マウントされたホスト／セッションに従います。ローカル／リモート参照は利用不可として一覧される場合があり、資産 API は任意のリモート URL を取得したりローカルファイルを開いたりしません。セッション切り替え、切断、同意の取り消しで古いアクセスは無効になります。

API 4 では、画像の読み取りも同様に表示中の会話に従い、エージェントが会話に読み戻した画像だけを表示します。`session.images.prompts` を持つ拡張機能は、「画像」会話であなたやエージェントが画像のために書いたプロンプトを読み取れ、サンドボックスがあっても他へ渡す可能性があるため、それらを任せられる作者にだけ許可してください。`composer.prefill` で追加されたテキストは、編集するか **メッセージを送信** を選ぶまで入力欄に残ります。コマンドで始まることも、閉じていない `@` メンションで終わることもなく、画像パスはプレーンテキストとして記載されます。入力欄で Ctrl+Z（macOS では Cmd+Z）で元に戻しても削除されません。保存済みのパネル設定はこの CodeNomad プロファイルに属し、拡張機能ごとに最大 4 KiB です。拡張機能を無効にしても保持されます。

項目はプロジェクトフォルダーのリモート `upstream`（なければ `origin`）から取得します。CodeNomad はサインイン済みの GitHub、GitLab、Gitea の CLI（`gh`、`glab`、`tea`）で、または公開リポジトリでは匿名で読み取り、トークンは保存しません。拡張機能に見えるのはリポジトリ名と項目だけです。匿名で読み取れるのは github.com、gitlab.com、codeberg.org、gitea.com です。セルフホストのフォージは、そこにサインインした CLI 経由でのみ読み取ります。項目を開くと、CodeNomad が同じフォージ上のその項目のページをブラウザーで開きます（最大で 1 秒に 1 回）。拡張機能が他のアドレスを開くことはできません。

作者のコードは、信頼されたアプリケーションレンダラーではなく、制限された iframe 内で実行します。ネイティブ／OpenCode ブリッジ、認証情報アクセス、汎用 RPC、フォーム、ポップアップ、ダウンロードは与えられず、ネットワーク API と外部リソースも制限されます。拡張機能は UI のアドオンであり、[OpenCode プラグイン](integrations.md)ではありません。

サンドボックスはプロセス／CPU の隔離ではなく、承認したコードが無害だという保証でもありません。悪意のある拡張機能はレンダラーを妨害できます。信頼する作者だけをインストールし、秘密情報を渡さず、予期しない動作をしたら無効化／削除してください。

## Design 拡張機能で画像を作成する {#design}

**Design** 拡張機能は、プロジェクトの **画像の会話** で CodeNomad の Design エージェントと作成する画像のためのライトテーブルです。画像を表示し、メッセージ欄に依頼を用意しますが、生成はすべてあなたが送信するメッセージに任せます。

1. 画像モデルを提供するプロバイダーを接続します。画像生成は、**設定 → プロバイダー → 画像** でオフにしていない限りオンです（[画像の生成と保存](providers.md#images)）。
2. **右パネルをカスタマイズ → 拡張機能** で、権限を確認したうえで（[コンテキスト、資産への同意、サンドボックスの制限](#permissions-sandbox)）カタログから **Design** をインストールし（[確認して無効のままインストールする](#install)）、そのチェックボックスを選びます（[有効化と適用範囲を理解する](#activate-scope)）。
3. **Design** パネルを開き、**画像の会話を開く** を選びます。

拡張機能が有効な間、CodeNomad は Design エージェントと画像スキルを OpenCode に追加します。独自の `design` エージェントや独自の `design-*` スキルが常に優先されます。独自の `design` エージェントを用意した場合、パネルには **独自のDesignエージェントを使用しています。** と表示されます。画像生成、画像モデル、Design エージェントのいずれかが欠けているときも、パネルがそれを示します。

### 画像の会話 {#design-conversation}

プロジェクトフォルダーや worktree ごとに、**画像** というタイトルの画像の会話が 1 つあります。**画像の会話を開く** はそれを見つけるか、Design エージェントと、そのエージェントの新しい会話に CodeNomad が選ぶモデルで作成し、メッセージ欄にフォーカスを置いて表示します。開くだけでは何も送信されません。既存の画像の会話は自分のモデルを保ちます。**新しい画像の会話** は空のライトテーブルで別の会話を始めます。会話の画像が多くなるとパネルがこれを勧め、以後 **開く** は最も新しい会話を表示します。アーカイブまたは削除された画像の会話は対象外です。

必要なものを書いて送信すると、エージェントはいくつか質問して方向性を確かめ、生成する画像の枚数を伝えてから生成し、各画像を読み込み直して評価します。画像はプロジェクトフォルダーの `.codenomad/design/` に保存されます。CodeNomad はこのフォルダーをリポジトリのローカルな Git 除外設定（`.git/info/exclude`）に追加し、`.gitignore` には触れません。追加できない場合、パネルには **この場所の画像がGitに表示される可能性があります。** と表示されます。ターンを元に戻すと、その画像はライトテーブルから消えますがファイルは残り、エージェントが上書きした画像は復元できません。エージェントは約 1K ピクセルの画像を依頼しますが、プロバイダーがより大きな画像を返すこともあり、大きな画像を同時に何枚も生成すると共有 OpenCode サービスのメモリを大量に使うことがあります。

Design エージェントを使う画像の会話でそのエージェントが見つからない場合、メッセージ欄に **Design エージェントは利用できません** と表示され、送信がブロックされます。**既定のエージェントを使用** を選ぶか、Design 拡張機能を再び有効にしてください。会話のチャットモデルが画像を受け取れない場合、エージェントが画像を視覚的に評価できないことをパネルが警告しますが、読み込み直された画像はライトテーブルに表示され続けます。

### ライトテーブル {#design-light-table}

**ライトテーブル** には、表示中の会話でエージェントが読み込み直した画像が、新しい順に、返信ごとにまとめて表示されます。画像を選ぶと大きく表示され、**小さいサイズ** で 16、32、64 px のプレビューも確認できます。**比較** は 2 枚の画像を並べ、**フルサイズで表示** はビューアーを開きます。パネルが狭いときは、広げてから比較してください。系譜（**元の画像**、**派生先**）と、画像の会話ではプロンプトとモデルは、どの生成がその画像を作ったかを CodeNomad が確認できる場合にだけ表示されます。確認できない画像もピクセルは表示され、**出所を確認できません** と示されます。**生成** は各画像生成とその状態を一覧にします。進行状況は会話で確認してください。別の会話では、パネルはその会話で読み込み直された画像をプロンプトや依頼なしで表示し、画像の会話を開くよう提案します。

画像の会話では、**テンプレートから開始**（アプリアイコンやロゴなどのレシピ）、**改良**、**バリエーション**、**方向性を適用**、**プロジェクトに保存…**、**エージェントに表示を依頼**、**再試行** は、編集できるテキストをメッセージ欄に追加するだけです。パネルがメッセージを送信したり画像を生成したりすることはありません。選んだ画像についての操作は、その画像をプロジェクトからの相対パスで引用します。引用できるのは、出所を確認できるプロジェクト内の画像だけです。依頼を編集してから、自分で送信してください。**プロジェクトに保存…** は、依頼の後に入力したコピー先へ画像をコピーするようエージェントに頼みます。**1回あたりの画像数**（1〜4、既定は 3）は新しい画像を生成する依頼に含まれ、パネルの保存済み設定に保持されます。スマートフォンではパネルはフローティング表示になり、依頼を追加すると閉じます。

### CodeNomad なしで Design エージェントを使う {#design-without-codenomad}

Design エージェントとスキルは通常の OpenCode ファイルです。CodeNomad なしで OpenCode の TUI や他のクライアントから使うには、[Design コンテンツフォルダー](../../../packages/server/src/opencode/design/opencode/) の中身を、プロジェクトの `.opencode/` フォルダーかグローバルな OpenCode 設定フォルダー（`~/.config/opencode/`）にコピーし、`NOTICE.md` とライセンスも一緒に置いてください。その後 **design** エージェントを選びます。このエージェントはスキルを名前で読み込み、他のエージェントは名前を指定したときだけそれらのスキルを使います。

Design エージェントとスキルは [Open Design](https://github.com/nexu-io/open-design)（Apache-2.0）と [taste-skill](https://github.com/Leonxlnx/taste-skill)（MIT）の素材を翻案しています。翻案した各ファイルは `NOTICE.md` に記載されています。Design 拡張機能は MCP Assets 拡張機能のコード（MIT）を再利用しています。
