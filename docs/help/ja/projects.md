# プロジェクトとワークツリー

プロジェクトタブは、CodeNomad をバックエンドコンピューター上のフォルダーに接続します。タブを開くこと、チェックアウトを閲覧すること、会話ファミリーを移動することは、それぞれ異なる操作です。

## プロジェクトを開く {#open-project}

1. **新しいインスタンス**（`+`）または `Ctrl/Cmd+N` で空のタブを開きます。中央のロゴと CodeNomad 名の下に **一時**、**クローン** の順でボタンが並び、その下の 2 列に左は **最近のタブ**、右は **参照** を表示します。参照の下部には **サーバーのアドレスまたはリンク** があります。背景は選択中のタブと同じです。狭い画面では縦に並びます。ロゴで開くホームでは、左に **Git リポジトリをクローン**、**新しい一時タブ**、**新しい SideCar** と OpenCode の行、右に **最近のタブ | 参照** を表示し、件数は見出しの下に並びます。右パネルの下端は左列と揃い、一覧は内部でスクロールします。ホームには言語、設定、**スポンサー**（[CodeNomad を支援](sponsor.md)）、GitHub、スター、Discord があります。クローンと一時フォルダーはローカルバックエンドを対象とします。プロジェクトや SideCar を選ぶと空のタブがその位置で切り替わります。空のタブは再読み込みまで有効です。
2. **最近のタブ** でプロジェクトを選ぶか、**参照** を開いて **このコンピューター** を選び、バックエンドのフォルダーを選択して開きます。**参照** には保存した CodeNomad サーバー（[リモートプロジェクトのタブ](remote-access.md#remote-project-tabs)）と SideCar（[SideCar](browser-sidecars.md#register-sidecar)）も表示されます。
3. リポジトリをコピーするには、**Git リポジトリをクローン** を選び、**リポジトリ URL** と **保存先フォルダ** を入力して **クローン** を選びます。**保存先フォルダ** には、前回のクローンがあるフォルダー(なければ最近のプロジェクトと同じ場所)にリポジトリ名のフォルダーが入力されます。**参照** ではクローンを置くフォルダーを選びます。クローンのフォルダー名を含め、パスは直接編集することもできます。

リモートサーバーの参照とは、そのサーバーのファイルシステムの参照であり、スマートフォンやノートパソコンの参照ではありません。プロジェクトを開いても、タブごとに別の OpenCode デーモンは作成されません。会話は OpenCode ネイティブのセッションであり、その寿命はタブの寿命と同じではありません。

**参照** でサーバーを選ぶと、そのフォルダーを表示し、サインイン中も移動中もサーバー名を表示します。サーバーの最近のプロジェクトは **最近のタブ** のみに表示され、空タブでは左側に配置されます。別の **開いています** 操作で既存のタブに切り替えられます。ホームで **最近のタブ** と **参照** を切り替えても、サーバーとフォルダーは保持されます。サーバー選択中はそのサーバーの履歴と開く操作だけを表示し、参照に戻ると通常の混合履歴に戻ります。入力欄にはラベルがあります。フォルダー行は移動専用です。パス欄に表示されたフォルダーを開くには、Enter キーまたはパス欄の末尾の矢印を押します。プロジェクトを選ぶと空タブが切り替わります。

最近のリモートプロジェクトに認証情報が必要な場合、ホーム、新しいタブ左側の **最近のタブ**、`+` メニューでは、プロジェクトタブを開く前にその場でログインフォームを表示します。復元されたリモートタブではタブ内に表示します。ユーザー名は常に `codenomad` で、パスワード欄にフォーカスします。エラーはフォームのそばに表示され、再試行できます。取り消されたリモートコントロール端末には[ペアリングの修復](remote-access.md#saved-servers)を使います。バックエンドが埋め込みビューのセッションを自動準備し、パスワード接続には専用セッションを使い、ペアリング接続は端末の有効期間と取り消しを共有します。

クローンは保存先にリポジトリを書き込みます。**保存先フォルダが既に存在する場合は先に削除します。** は破壊的な操作です。そこに既にあるすべての内容を削除してよい場合にのみ有効にしてください。不確かな場合は、新しい保存先を使用します。クローンの失敗を理由に既存のプロジェクトを削除しないでください。再試行する前に、表示された保存先とエラーを確認します。

最近の項目はショートカットです。ホームの行内ボタンと空タブの操作メニューでは、項目に応じて **ワークスペース名を変更** と **履歴から削除** を使えます。ファイルと会話は保持されます。ホーム、空タブ、クイックランチャーのどこでも、ローカル・リモートプロジェクトや SideCar の行を選ぶと、既に開いていても新しいインスタンスを作ります。独立した **開いています** 操作（**開いているプロジェクトに切り替え**）は既存のものを選びます。

## 新しいインスタンスのランチャーを使う {#new-instance-launcher}

開くとメニューにフォーカスします。Tab またはクリックで検索欄を選べます。矢印キーで履歴を移動し、Escape で閉じます。

1. `+` を長押しまたは右クリックします。キーボードフォーカスがある場合は、**Alt+Down**、**Shift+F10**、または Menu キーを使用します。
2. **最近のタブ** には検索と最近のローカル・リモートプロジェクト、SideCar、および独立した **開いています** 操作があります。行を選ぶと新しいインスタンスを作り、**開いています** を選ぶと既存のものに移ります。タイトルバーの砂時計ボタン **新しい一時タブ** で一時タブを作成できます。

通常のクリックでは空タブが開きます。最近の項目はホームか空タブ、サーバーは **設定 → サーバー**、SideCar は **設定 → SideCar** で管理します。ホーム、空タブ、クイックランチャーでは、行の選択状態はキーボード操作中だけ保持されます。ホバーの強調表示はポインターが行を離れると消えます。Escape で閉じ、フォーカスが `+` に戻ります。

## タブを閉じてプロジェクトを閉じる {#close-stop}

1. タブの閉じるボタン、またはコマンドパレットの **タブを閉じる**（レンダラーでは `Ctrl/Cmd+W`）を使用します。
2. タブを閉じると、CodeNomad 内でそのプロジェクトが閉じられ、そのイベントとリクエストの追跡をやめます。セッションは OpenCode で実行を続けます。
3. フォルダーの参照、または最近使った項目からフォルダーを開き直すと、それらの会話を再び確認できます。

| 操作 | 範囲と効果 | 行わないこと |
| --- | --- | --- |
| タブを閉じる | そのタブの CodeNomad プロジェクト接続を削除します。同じフォルダーを別に開いたタブには影響しません | プロジェクトファイルやネイティブ履歴の削除、セッションの停止、OpenCode の Location の解放はしません |
| セッションを停止 | 選択した会話の実行 | プロジェクトを閉じたり、その履歴を削除したりしません |

同じプロジェクト接続を別のウィンドウでも表示している場合は、そちらのタブも閉じ、そのウィンドウに通知が表示されます。操作したウィンドウには表示されません。閉じる操作は直ちに行われます。バックエンドがプロジェクトを閉じられない場合はエラーが表示され、ホームページの **開いているプロジェクトに切り替え** から引き続きアクセスできます。自動的な再試行はありません。閉じたタブの未送信の下書きは、起動時の復元で保持されません。

ウィンドウ全体を閉じる、終了する、再読み込みする操作では、プロジェクト接続は閉じられず、通常の起動時復元が適用されます。実行の終了を確認する必要がある場合は、該当する実行を明示的に停止してください。CodeNomad がネイティブの Location を解放することはありません。共有サービスの保守は、[OpenCode のセットアップ](opencode.md)で説明しています。

## 一時ワークスペース {#temporary-workspaces}

1. ホームの **新しい一時タブ**、または空タブの列の上にある **一時** を選びます。
2. CodeNomad が管理する空のフォルダーで作業します。Git は自動初期化されません。
3. タブを閉じるときに、**保持**、**破棄**、**キャンセル** を選びます。タブメニューには **プロジェクトとして保持** もあります。

| 選択 | 効果 | 復旧 |
| --- | --- | --- |
| 保持 | CodeNomad 内でプロジェクトを閉じ、フォルダーと会話を保持し、一時状態を解除して最近のプロジェクトに追加 | 最近使った項目から再度開きます。フォルダーは移動しません |
| 破棄 | 一時ワークスペースの会話とファイルを削除 | 元に戻せません。必要なものは先に別の場所へ保存してください |
| キャンセル | 一時ワークスペースを開いたままにする | 作業を続けるか、後で決めます |

会話、ファイル、未送信の下書きがなく、手を加えていない一時タブは、閉じるときに確認なしで破棄されます。開いている一時タブは通常の起動時復元の対象ですが、ホームページには閉じた一時フォルダーを再開する専用リストはありません。

会話が実行中、または別のタブ／ウィンドウでフォルダーが開いている場合、破棄は拒否されます。先に実行を停止し、ほかの表示を閉じてください。破棄に失敗しても一時状態は保持されます。親ディレクトリを手動で削除するのではなく、表示された問題を解決して再試行してください。

## ワークツリーを選択・作成する {#select-create-worktree}

1. 親会話を開き、入力欄のワークツリーセレクターを使用します。狭いレイアウトでは矢印だけのコントロールです。
2. 検出された既存のワークツリーを選ぶか、**+ worktree を作成** を選びます。
3. 作成する場合は、**名前** を入力して **worktree を作成して使用** を選びます。

CodeNomad は OpenCode を通じてワークツリーを検出し、開いているリポジトリに属することを確認します。新しいブランチ名は選択したチェックアウトの HEAD から始まります。既存のブランチ名は、そのブランチの現在のリビジョンを使用します。別の場所で既にチェックアウトされているブランチは Git に拒否されることがあります。ワークツリーは、既定の `.codenomad/worktrees` を使用します。未コミットの変更は元のチェックアウトに残り、新しいワークツリーにはコピーされません。

入力欄のセレクターは、親会話とその配下の再帰的な子孫を、確認済みのファミリーとして移動します。サブセッションが独立してこのセレクターを変更することはできません。アクティブなセッションがあると操作はブロックされます。ファミリーの完了を待つか、先に実行を停止してください。移動が確定するまで次の移動を要求しないでください。エラー時は、更新された会話／ワークツリーの状態を確認してから再試行します。

一方、[ファイル](files.md)の **参照するワークツリー** は、パネルが読み取るチェックアウトだけを変更します。会話の移動、ブランチの切り替え、次のシェルコマンドの実行場所の変更は行いません。

## ワークツリーを削除する {#remove-worktree}

1. 入力欄のワークツリー一覧で、削除可能なブランチワークツリーの **worktree を削除** を使用します。
2. 対象フォルダーを確認します。ローカルの変更を失ってよい場合を除き、**強制削除（ローカルの変更を破棄）** はオフのままにしてください。
3. 削除を確認し、処理後の一覧を確認します。

削除すると、ワークツリーのローカルフォルダーがなくなります。Git のメインチェックアウトは削除対象にできません。CodeNomad は、影響する会話ファミリーをルートのチェックアウトに戻し、配置を確認してからワークツリーを削除します。アクティブなセッションがあると削除がブロックされる場合があります。削除は未コミットファイルのアーカイブやバックアップではありません。

変更済み／未追跡ファイルのため Git が拒否する場合は、それらを保存または整理してから再試行します。強制削除は、明示的にそれらを破棄します。ディレクトリがロックされている場合は、それを使用中のターミナル、エディター、監視ツール、バックグラウンドプロセスを閉じます。記録が見つからない場合は、ワークツリーを更新し、パスを確認してから再試行してください。診断の共有用に、エラーダイアログには **サニタイズ済みをコピー** があります。サニタイズ済みのテキストも、先に内容を確認してください。

## Git を初期化する／Git なしで作業する {#initialize-git}

1. Git が利用できる通常のフォルダーで、**ファイル → 変更** または **コミット** を開きます。
2. **Git を初期化** を選びます。追加確認なしで直ちに実行されます。
3. プロジェクトのメタデータと会話が更新されるまで待ちます。CodeNomad の外で Git を初期化した場合は、**更新** を使用します。

初期化では、親ではなく、明示的に開いたフォルダーにリポジトリを作成します。コミットは行いません。失敗した場合は、メッセージを確認し、更新してから再試行してください。応答が不確かな操作は自動的に再実行されません。

バックエンドが Git を実行できなくても、明示的に開いたフォルダーでは、ディレクトリ専用モードで会話と範囲を限定したファイル閲覧を利用できます。ワークツリー操作と Git 初期化には、そのバックエンド上の Git が必要です。[インストール](install.md)と[ファイル](files.md)を参照してください。
