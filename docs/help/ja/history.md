# 履歴、検索、クリーンアップ

保存された履歴、会話欄に現在表示されている内容、モデルのコンパクト化されたコンテキストは別物です。何かを削除する前に、移動やフィルターを選んでください。

## 全履歴を検索する {#full-history-search}

1. 会話ヘッダーの **チャット履歴を検索** を開くか、設定したショートカット（既定は **Ctrl/Cmd+F**）を使用します。
2. **セッション全体** または **ワークスペース全体** を選び、検索語を入力します。
3. 読みやすいテキストだけでなく技術的な内容も必要な場合は、**ツールと思考を含める** を有効にします。
4. 抜粋を選ぶか、**次の結果** で現在のページ以降を表示します。

検索は大文字と小文字を区別しないリテラル検索で、マウント中の会話行だけでなく、保存された履歴を対象とします。ワークスペースの範囲は、開いたプロジェクトの許可されたディレクトリツリーとワークツリーであり、OpenCode サービス上の全プロジェクトではありません。ファイル／画像添付のバイト列や、不透明なプロバイダー状態は、検索可能なテキストではありません。

進捗行 **このページ：検索結果 … 件 · メッセージ … 件を検索済み** は、この結果ページを示し、ワークスペース全体の合計ではありません。結果はバッチ単位で届きます。サイズ超過や未対応でスキップしたメッセージは報告されます。ヒットがないことは、それらのメッセージに一致がない証拠ではありません。スキャン中に届いた新しいメッセージを一貫して含めるには、新しく検索する必要があります。

空の検索を開くだけでは履歴をスキャンしません。検索語／範囲の変更、ウィンドウを閉じる操作、セッションからの移動は、不要になった検索処理をキャンセルします。読み取りに失敗した場合は、**再試行** を使用します。プロンプトの送信や履歴の変更は行いません。

## 結果を開き、タイムラインを使う {#timeline-navigation}

1. 現在のセッションの検索結果を選ぶと、その周辺の箇所へ移動します。
2. 別セッションの結果を選ぶと、そのメッセージの個別のプレビューを開きます。
3. **メッセージタイムライン** で、マーカーにカーソルを合わせるかフォーカスして抜粋を確認し、選択して移動します。最初／最新のメッセージのコントロールで、保存された履歴の両端に戻れます。

会話欄が範囲を限定した一部分だけを保持していても、タイムラインはセッション全体の構造を表します。移動では、間の全メッセージを取得せず、移動先を読み込みます。別セッションの検索プレビューは、そのセッションの会話全体を読み込んだり、無断でそのセッションを選んだりしません。

移動先の読み込み中は、元の箇所を表示し続けます。新しい移動や会話欄への手動操作は、古くなった移動を置き換えます。移動に失敗しても表示中の箇所は残ります。プロジェクト全体を何度も再読み込みせず、移動先を再試行してください。過去の内容を読んでも、入力欄のエージェント／モデル選択は変わりません。

会話の幅が狭すぎる場合（420 CSS ピクセル未満）、タイムラインは非表示になります。その場合は検索や会話欄のコントロールを使用してください。このレスポンシブな変化によって、保存済みの表示設定は消えません。

## 適切な履歴操作を選ぶ {#operation-reference}

| 操作 | 場所 | 範囲と結果 |
| --- | --- | --- |
| 表示フィルター | **メッセージの内容**、または **設定 → チャット** | 共有の会話表示設定。内容を削除せずに非表示／折りたたみにします |
| コンパクト化 | パレットの **セッションをコンパクト化** | 選択したセッションのネイティブな要約／コンテキスト圧縮。技術的な出力の削除ではありません |
| 1 回の応答のクリーンアップ | メッセージの **その他の操作 → この回答からツールと推論を削除** | 対象となる完了済みの技術パーツを完全に削除し、最終テキストは保持します |
| セッションの技術クリーンアップ | パレットの **セッションのツールと推論を削除** | コンパクト化前を含む保存済みセッション履歴全体を対象に計画します。最終テキストとメッセージ／セッションのメタデータは保持します |
| セッション削除 | セッション行の **セッションを削除**、または選択セッションの削除 | 確認後、ネイティブ会話と子孫のサブセッション／履歴を再帰的に削除します。元に戻せません |
| セッションを整理 | コマンドパレット | より広範なセッション削除。表示やコンテキストサイズの設定ではありません |

**メッセージの内容** は会話間で共通です。ツールを非表示にしても、ツールの無効化、権限の変更、保存済み出力の削除は行いません。極端に大きい個別メッセージには、描画の応答性を保つため、省略箇所に **さらに … 件を表示** が表示されることもあります。その箇所を展開しても、削除済み内容は復旧しません。

## セッションをコンパクト化する {#compact-session}

1. 対象の会話を選びます。
2. コマンドパレットから **セッションをコンパクト化** を実行します。
3. ネイティブのコンパクト化結果を待つか、**コンパクト化に失敗** を確認してから、再試行するか判断します。

コンパクト化は、OpenCode がセッションの続行に使うコンテキストを変更します。以前の保存済みメッセージの消去を保証するものではなく、全履歴検索や技術クリーンアップはコンパクト化前の内容にも到達できます。機密の保存済み履歴の削除の代わりに、コンパクト化を使用しないでください。

## ツールと推論を削除する {#technical-cleanup}

1. 1 回の応答の操作を選ぶか、選択中のセッションで **セッションのツールと推論を削除** を実行します。
2. 計画されたツール／推論の件数と、スキップされる内容の警告を確認します。
3. **削除** を確認します。セッション全体の場合は、会話欄の上に表示される進捗を確認し、必要に応じてキャンセル操作を使用します。

対象となる完了済みのツールと推論だけが削除されます。アクティブ／未完了の内容は削除されません。内容が変わった場合は、確認した範囲を無断で広げずに拒否します。最終テキストとメッセージ／セッションのメタデータは残りますが、削除した技術的出力は元に戻せません。確認前に必要な内容を保存してください。

セッションのクリーンアップは、セッション全体でアトミックではありません。後のメッセージで競合や失敗が起きても、それ以前に成功した削除は残ります。**キャンセルは今後のバッチを停止しますが、既に送出したバッチを巻き戻しません**。そのバッチはまだ確定する場合があります。

ストレージ使用中のエラーでは、現在の実行／ストレージ処理の完了を待ちます。メッセージ変更のエラーでは、再読み込みして再選択します。プラグインが利用できない場合は、CodeNomad に再接続／再度開き、エラーを確認してから再試行します。応答が不確かな場合は更新して残りの内容を調べてください。何も起きなかったとも、セッション全体が整理されたとも決めつけないでください。

## セッションの削除と整理 {#delete-scrub}

親セッションを削除すると、子孫のサブセッションとその履歴も削除されます。確認前に会話ファミリーを確認してください。ミッションの専門担当クリーンアップは別で、子を持つセッションを保持します。

1. 削除すべき会話が明確なら、特定の行の **セッションを削除** を優先します。
2. より広範な保守には、**セッションを整理** を実行し、**セッションを徹底クリーン** の確認を読みます。
3. 空のセッション、完了したサブエージェントセッション、未使用のフォークを削除してよい場合にのみ確認します。

整理は、現在のプロジェクトの既知のセッション候補を対象とし、空のメインセッション以外も削除する場合があります。アーカイブ操作ではなく、元に戻せません。混み合ったサイドバーを隠すだけの目的では使わないでください。独立した **空のセッションを自動クリーンアップ** 設定は、より限定的です。未読み込みの会話欄を空とみなさず、本当に空かを確認します。

削除は会話を取り除きますが、Git コミットを削除したり、ファイルシステム／外部への影響を巻き戻したりはしません。クリーンアップが一部しか成功しなかった場合も、削除済みのセッションは削除されたままです。再試行前に残りの一覧とエラーを確認してください。フォーク／取り消しは[会話](conversations.md)、一時フォルダーやワークツリーの削除は[プロジェクト](projects.md)を参照してください。
