# ネイティブ連携

CodeNomad は、OpenCode ネイティブの MCP 接続、プラグイン有効化、スキル、カスタムコマンドを提供します。これらは実行ホスト上で動きます。サンドボックス化された[パネル拡張機能](extensions.md)や [SideCar](browser-sidecars.md)とは別です。

## 適切なコントロールを選ぶ {#integration-scopes}

| 連携 | 操作する場所 | 変更するもの |
| --- | --- | --- |
| MCP サーバー | **ステータス → MCP サーバー** | 表示された Location のネイティブ接続。サーバーはインストールしません。 |
| ネイティブプラグイン | **ステータス → プラグイン** | パッケージの宣言を追加・削除し、永続的な **グローバル** または **プロジェクト** の有効化ルールを設定します。パッケージプラグインでは、そのパッケージの明示的な更新確認または更新。 |
| スキル | 入力欄の `@` メニュー | 会話の Location で、次のプロンプトへの明示的な添付。 |
| カスタムコマンド | 入力欄の `/` メニュー | その Location に対して OpenCode が公開するコマンドを実行。 |

ネイティブ連携は、OpenCode の権限に従ってホストプロセスの権限を持ち、サンドボックス化された HTML パネルではありません。

## MCP を接続・切断する {#mcp}

1. [OpenCode MCP ドキュメント](https://opencode.ai/v2/docs/mcp-servers/)に従い、OpenCode 実行ホストで MCP サーバーを設定します。
2. プロジェクトの **ステータス → MCP サーバー** を開きます。
3. サーバー横のスイッチで接続／切断し、接続表示が確定するまで待ちます。

その Location を使う他のクライアントにも接続変更が見える場合があります。 切断してもサーバー宣言や実行ファイルは削除されません。

接続に失敗したら、サーバー設定、必要な環境、認証を確認してください。スイッチでは OAuth は完了しません。

## グローバル／プロジェクト範囲でプラグインを有効にする {#plugins}

CodeNomad が管理するプラグインは、通常のプラグイン一覧やその有効化・更新・削除操作の対象外です。

**CodeNomad プラグインの確認が必要です** では **i** で詳細を確認します。無効なプラグインには **再度有効化** が表示されます。実行前に表示された設定範囲を確認してください。

1. [プラグインを追加](#plugin-sources)するか OpenCode の設定で宣言し、**ステータス → プラグイン** を開きます。
2. 名前にカーソルを合わせるかフォーカスし、ソース、ランタイムの失敗、設定対象の詳細を確認します。
3. **グローバル** または **プロジェクト** を意図的に切り替えます。書き込みを待ち、状態が不明なら **プラグインコントロールを更新** を使用します。
4. パッケージからインストールしたプラグインでは、名前の横のアイコンを使用します。そのメニューには正確な操作が表示されます。パッケージの **… の更新を確認**、または新しいバージョンが見つかった後の **… を更新** です。

グローバルは、接続先デーモンが検出したグローバル設定を対象とします。プロジェクトは、継承した上位ファイルではなく、アクティブな Location 内の設定を対象とします。後のプロジェクトルールはグローバルを上書きできますが、グローバルのスイッチは、最終的なプロジェクト状態を装わず、グローバルのルールを表示します。プロジェクトルールがなければ、解決済みのグローバル状態を継承します。

OpenCode 組み込みプラグインには、ユーザー用の有効化スイッチを提供しません。 対象をグローバルから安全に分離できない、またはアクティブな Location の外に出る場合、プロジェクトは無効になります。

パッケージの更新は、ツールチップに記載のとおり、OpenCode の共有キャッシュ内のそのパッケージを、それを使う全 Location について変更します。 有効化ルールの変更、OpenCode の再起動、設定の再読み込みは行いません。 ローカル、組み込み、SDK 提供のプラグインにはパッケージ操作がありません。

## プラグインを追加・削除する {#plugin-sources}

1. **ステータス → プラグイン** で **+** を開き、**プラグインを追加…** を選びます。
2. npm レジストリのパッケージ（`name`、`name@1.2.3`、`@scope/name@^1`）または Git リポジトリ（`github:owner/repo`、`git+https://…`）を入力します。
3. プラグインをこのプロジェクトだけで実行する場合を除き **グローバル** のままにして、**追加** を選びます。
4. 新しい行は OpenCode が報告するまで **インストール中** と表示されます。

プラグインを削除するには、名前の横のメニューを開いて **グローバル から削除** または **プロジェクト から削除** を選びます。そのスコープの設定ファイルにある宣言と有効化ルールが削除されます。ただし、プラグインの別の宣言が残っている間の無効化ルールと、先行する宣言がまだ定義している有効化ルールは残ります。定義を失う有効化ルールはこのプロジェクトの設定からも削除されます。残すと OpenCode が同名のレジストリパッケージをダウンロードするためです。CodeNomad が編集しないファイルにある場合、削除は拒否されます。OpenCode のパッケージキャッシュはそのまま残ります。OpenCode が識別できなかったプラグイン（無効化中、または読み込み前に失敗）のルールは専用の行に残り、そのメニューから同じ削除ができます。

プラグインのコードは OpenCode 内であなたの権限で実行されます。**プロジェクト** のエントリはそのフォルダーを OpenCode で開くたびに実行され、OpenCode デスクトップアプリ向けの部分を持つパッケージはそれを **グローバル** からのみ読み込みます。そのようなパッケージが別の場所で宣言されている場合はツールチップに表示されます。ローカルパス、設定変数、プラグイン ID はここでは受け付けません。ローカルプラグインは設定ファイルで宣言してください。この Location に適用される設定ですでに宣言されたパッケージは、バージョン、範囲、形式にかかわらず拒否されます。

インストール済みパッケージのバージョンはプラグイン名の横に表示されます。Git プラグインの詳細にはコミットが含まれ、バージョンが取得できない場合は名前の横に7文字のコミットが表示されます。名前にポインターを置くかフォーカスすると、詳細、**更新があります**、インストールに失敗した場合は OpenCode のログにある参照付きのエラーが表示されます。

## スキルを添付する {#skills}

1. 入力欄に `@` を入力し、Location の利用可能なスキルを検索して選びます。
2. ファイル／エージェントと並ぶ削除可能な添付を確認し、意図しない場合は送信前に削除します。
3. プロンプトを送信します。スキルのラベルは送信済みメッセージに残ります。

添付の削除で以前の送信を取り消すことはできません。

スキルの利用可否は、CodeNomad 全体のスキルカタログではなく、会話の Location から取得します。 [OpenCode スキルドキュメント](https://opencode.ai/v2/docs/skills/)と[会話](conversations.md)を参照してください。

## カスタムコマンドを実行する {#commands}

1. 入力欄に `/` を入力し、利用可能なネイティブコマンドを選びます。
2. 引数を指定し、そのコマンドに応じて送信前に **エージェント**、**モデル**、**思考** を確認します。
3. 受け付けが不明な場合は、何度も送信せず、結果の会話を確認します。

コマンドはアクティブな Location の OpenCode から検出します。 `/btw` は CodeNomad 独自の一時的な質問フローであり、通常のカスタムコマンドではありません。

コマンド定義とネイティブ設定の継承は、[OpenCode コマンドドキュメント](https://opencode.ai/v2/docs/commands/)を参照してください。設定変更後は、まず関連画面を更新／開き直します。ランタイムがまだ必要とする場合にのみ、明示的な設定再読み込みを使用してください。表示更新のためだけに、受け付け済みかもしれないコマンドを再実行しないでください。
## プラグイン内の連携 {#integration-rows}

**ステータス → プラグイン** の **+** から **連携を追加…** または **プラグインを追加…** を選びます。連携の選択画面にはレビュー済みカタログの未インストール項目が表示されます。スコープと **インストール** を選ぶと、CodeNomad が選択したカタログ ID をインストールします。ネイティブ連携は **グローバルのみ** です。**カタログを利用できません** では **更新** を選べます。**{date} のカタログ** は、最後の有効なカタログが古い状態であることを示します。

アクセントカラーの状態行から **Blender にインストール**、**Blender を更新**、または表示中の会話を開いた文書に **接続** できます（複数から選ぶ場合は **接続…**）。チェーンのアイコンと文書は接続済みを示し、選ぶと解除します。会話は、そのエージェントが初めて連携を使うときにも自動で接続されます。

行の **…** メニューは接続状態（例: **Blender: 開いている文書 1 件**、**Blender は閉じています**）から始まります。続いて **ドキュメント**、**アプリにインストール…**、**アプリを更新…** または **アプリに再インストール…**（[下記参照](#application-installation)）、パッケージの更新確認、**グローバル から削除** または **プロジェクト から削除**、**プラグインコントロールを更新** が並びます。接続の解除は確認なしの 1 クリックで、この会話だけに適用されます。アプリは開いたまま、パーツはインストールされたままで、他の会話の接続も保たれます。

カタログからのインストール、アプリ側パーツのインストール/更新、削除には確認が必要です。最初に **キャンセル** にフォーカスがあり、確認操作は 600 ms 後に有効になります。有効化、プラグインの更新、接続と接続の解除はすぐに実行されます。

削除時はプラグイン名と正確な範囲を示す警告が開きます。 初期フォーカスは **キャンセル** です。 **グローバル/プロジェクトから削除** は 600 ミリ秒後に有効となり、明示的な操作が必要です。 使用中の会話で利用や接続が中断される場合があり、グローバルでは他のプロジェクトにも影響します。 削除するのは確認した宣言と上記の有効化ルールのみで、キャッシュ、アプリのファイル、保存済みの接続ヒントは保持します。 設定が変わった場合は再選択と確認が必要です。

## アプリ連携をインストールまたは更新 {#application-installation}

**ステータス → プラグイン** で、最新の状態が操作を提示しているときは連携の状態行の **Blender にインストール** または **Blender を更新** を選ぶか、その **…** メニューで **アプリにインストール…**、**アプリを更新…** または **アプリに再インストール…** を選びます。再インストールは、アプリが開いていても閉じていてもアプリ側のパーツを書き直します。会話や開いた文書がなくても使えます。

確認画面には、アプリとインストーラーを提供する **連携パッケージのバージョン** が表示されます。 両方とマシンの警告を確認してください。 インストール先は OpenCode が動作するマシンで、リモートの場合もあります。 初期フォーカスは **キャンセル** です。 続行するには明示的に確認します。

WSL では、開いているアプリに互換性があるように見えても、アプリへのインストールは常に拒否されます。対応マシンでアプリを開いてください。

インストールまたは更新の後、アプリを開いて連携を確認してください。

エラーで結果が不明な場合、その要求を繰り返さないでください。 まずアプリを調べ、必要に応じて新しい操作を開始し、改めて確認してください。
