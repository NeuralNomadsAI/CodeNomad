# CodeNomad ヘルプ

このガイドでは、OpenCode サービスに接続した現在の CodeNomad デスクトップ版またはブラウザー版ワークスペースの操作方法を説明します。OpenCode の設定チュートリアルや過去のバージョンの記録ではなく、CodeNomad の操作、実行範囲、復旧に焦点を当てています。

## 最初にお読みください {#read-this-first}

CodeNomad は、ワークスペースを 1 つの共有 OpenCode バックグラウンドサービスに接続します。セッションとメッセージは OpenCode が、タブ、入力欄の下書き、レイアウトは CodeNomad クライアントが管理します。タブを閉じてもワークスペースは停止せず、CodeNomad を閉じても OpenCode は停止しません。

1. [ホストの要件](install.md#requirements)と [OpenCode のセットアップ](opencode.md)を確認します。
2. [プロジェクトを開き](projects.md)、会話のエージェント、モデル、思考の設定を選びます。
3. 認証情報の変更、サービスの再起動、履歴の削除を行う前に、影響する範囲を確認します。他のクライアントも同じネイティブサービスを使用している場合があります。

公開ヘルプサイトは、CodeNomad、そのバックエンド、ログインがなくても利用できます。デスクトップの **Help → CodeNomad Help** とコマンドパレットの **ヘルプを開く** は、現在の UI 言語でヘルプを別に開きます。言語を変更しても、保存済みの会話は翻訳されません。

ローカルデスクトップクライアントの **設定** は、ネイティブの **設定** ウィンドウを開きます。ブラウザーおよびリモートクライアントでは、埋め込みの設定画面を使用します。**設定 → プロバイダー** のような経路は、どちらでも同じ設定セクションを指します。

準備済みのホストでスタンドアロンのブラウザーワークスペースを使用する場合は、[サーバーガイド](server.md)で、次の起動方法と認証・TLS の要件を説明しています。

```sh
npx @neuralnomads/codenomad --generate-token --launch
```

## クライアントを選ぶ {#choose-your-client}

| 機能 | ローカルデスクトップ | 直接接続のブラウザーまたはリモートサーバーウィンドウ | リモートコントロールでペアリングした端末 |
| --- | --- | --- | --- |
| プロジェクト、会話、ファイル、履歴 | バックエンドのフォルダーとネイティブセッション | 接続先サーバーのフォルダーとセッション | ホストの許可されたワークスペース画面 |
| ネイティブの設定とデスクトップウィンドウ | 利用可能 | ブラウザー／リモート設定はクライアント内で表示 | ホスト専用のデスクトップ操作は利用不可 |
| セッションのブラウザープレビュー | Electron と Windows Tauri ではネイティブ、その他の Tauri 環境では iframe | 利用可能な環境で iframe | ホスト専用のプレビューエンドポイントは利用不可 |
| ネイティブのデスクトップ／ブラウザー自動操作 | 所有するローカルウィンドウ／プレビュー | ネイティブのデスクトップ自動操作の代替にはならない | ホスト専用の自動操作エンドポイントは利用不可 |
| 認証 | ローカル初期設定またはパスワードセッション | サーバーパスワードセッション | ペアリング済み端末の認証情報 |
| PWA のインストール | ネイティブアプリまたはブラウザーを使用 | ブラウザー依存。安全なコンテキストが必要 | ブラウザー依存。ペアリングも必要 |

詳細な制限は、[ブラウザープレビューと SideCar](browser-sidecars.md)、[リモートコントロール](remote-control.md)、[モバイル／PWA](mobile.md)を参照してください。リモートウィンドウを開いても、端末のファイルシステムがサーバーのワークスペースになるわけではありません。

## 状態の管理元を理解する {#state-and-scope}

| 用語 | CodeNomad での意味 |
| --- | --- |
| プロジェクトタブ／ワークスペース／インスタンス | 明示的に開いたフォルダーへの CodeNomad の接続。複数のタブが共有サービスを使用できます。 |
| 会話／セッション | ディレクトリに関連付けられた、OpenCode ネイティブの履歴と実行。 |
| ファミリー | 会話と、その配下の再帰的なサブセッション。移動、アクティビティ、Yolo、ミッション操作に関係します。 |
| ワークツリー | 閲覧またはセッション配置用に選んだ、所有関係が確認されたリポジトリのチェックアウト。閲覧しても会話は移動しません。 |
| Location | ディレクトリ単位の OpenCode ネイティブ実行コンテキスト。明示的な **ワークスペースを停止** は、そのリソースを解放しますが、共有デーモンは停止しません。 |
| CodeNomad バックエンド | ワークスペース、Git、認証、クライアント接続を提供するサーバー。そのアカウントと環境が、バックエンドのファイルシステムへのアクセスを決めます。 |
| 設定 | サーバーの設定ディレクトリにある CodeNomad の設定。グローバル／プロジェクトの OpenCode 設定には、固有のネイティブな適用範囲があります。 |
| ウィンドウ | 独自のタブ、ナビゲーション、下書き、復元された表示を持ちます。ネイティブ履歴は共有され、ウィンドウごとには複製されません。 |
| デスクトップデータプロファイル | 明示的なネイティブ／クライアントストレージの選択。OpenCode セッションや、すべての共有設定を自動的に分離するものではありません。 |

ワークスペースのルートは、CodeNomad が開くフォルダーを制限しますが、エージェントのサンドボックスではありません。ホストの公開や広いツールアクセスの許可に先立ち、[セキュリティ](security.md)を確認してください。

## 作業を変更せずに監視する {#monitor-work}

ステータスパネルには、アクティブなセッションのプロバイダー使用量とネイティブのバックグラウンド Shell が表示されます。会話の状態と子のアクティビティにより、作業中、コンパクト化中、入力待ちのセッションを識別できます。バックグラウンド Shell の監視は、入力欄からの Shell リクエストの送信や、別途ホストされるターミナル SideCar の使用とは異なります。

1. 選択した会話の Location（会話を選んでいない場合は開いているワークスペース）で **ステータス → バックグラウンドシェル** を開きます。
2. 提供されているコマンド、シェル、ディレクトリ、状態、PID、終了コードを確認し、**出力を表示** で利用可能なネイティブ出力を開きます。
3. 破棄するには、実行中なら **停止して削除**、終了後なら **削除** を使用し、対象を確認します。

実行中の Shell を削除すると、そのプロセスは停止します。出力ウィンドウを閉じるだけでは停止しません。更新／再接続では、見逃した出力イベントを再構築せず、現在のネイティブ状態を読み取ります。

表示用スナップショットは、ネイティブの変更、再接続、表示時の必要に応じて更新されます。再生が保証されたログではありません。結果が不確かな場合は、変更操作を再試行する前に正規の状態を更新してください。通知やイベントを見逃したという理由だけで、再送信しないでください。
