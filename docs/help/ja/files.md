# ファイルと Git

右パネルの **ファイル** タブは、チェックアウトの閲覧、ローカルの変更、コミット履歴をまとめています。行の選択と、中央リーダーで開くことは別の操作です。

## チェックアウトを閲覧する {#browse-workspace}

1. **ファイル** を開いて **ワークスペース** を選びます。
2. 別のチェックアウトを見るには **参照するワークツリー** を選び、必要に応じてフォルダーを展開します。
3. ファイル行をクリックして選択します。目の操作で中央プレビューを開閉します。
4. 表示中のスナップショットを再確認するには **更新** を使用します。

| モード | 読み取る内容 | 会話への影響 |
| --- | --- | --- |
| ワークスペース | 閲覧中のチェックアウトのファイル | セッションの移動やブランチのチェックアウトはしません |
| 変更 | インデックスと作業ツリーの変更 | Git の変更操作は明示的な操作でのみ行います |
| コミット | ページ分割されたコミット履歴とリビジョンの内容 | 読み取り専用の履歴。チェックアウトはしません |

展開したフォルダーはモードを変えても保持されます。一覧／状態／履歴はキャッシュ済みスナップショットを使用し、関連するファイルシステム変更、アクティブ化、明示的な更新で再検証します。パネルにフォーカスしても、新しい読み取りが保証されるわけではありません。表示中のワークスペースのフォルダーは、バックエンドホスト上で作成、編集、名前変更、削除されたファイルを自動的に反映します。継続的な変更中の反映は最大 5 秒に 1 回です。折りたたんだフォルダーや他のワークツリーは、表示したときにだけ読み直します。

行の操作には **パスをコピー** があり、バックエンドのパスを開くことにクライアントが対応している場合は、**既定のアプリケーションで開く**、**フォルダーに表示**、**ファイルマネージャーで開く**、**ここでターミナルを開く** などもあります。領域が限られると、操作は **{name}のその他の操作** に移る場合があります。`{name}` にはファイル名またはフォルダー名が入ります。リモートブラウザーは、サーバーパスを端末ローカルのパスとみなせません。[リモートコントロール](remote-control.md)を参照してください。

## ソースを編集して安全に保存する {#edit-save}

1. ワークスペースのテキストファイルを目の操作で開きます。
2. Markdown では、編集用に **ソースを表示**、描画結果の閲覧用に **Markdown プレビュー** を選びます。
3. 編集して **保存** を選ぶか、エディターにフォーカスがある状態で **Ctrl/Cmd+S** を押します。
4. ファイルが外部で変更された場合は、上書き確認を読みます。**キャンセル** で、その変更を上書きせずに下書きを保持できます。

保存は、リンクされたワークツリーを含む閲覧中のチェックアウトの実ファイルに書き込みます。プロンプトの送信や、編集のステージ／コミットは行いません。保存時は、まず正規のファイルを読み直します。競合ダイアログは **ファイルはエージェントによって変更されました。上書きしますか？** と表示しますが、外部のどの書き手による変更でも、同様に慎重に扱ってください。

未保存のソース下書きは、リーダーを閉じたり切り替えたりしても、プロジェクトインスタンス、ディレクトリ、パスごとにレンダラーのメモリ内に保持されます。ファイルシステムの更新が無断で置き換えることはありません。これは永続的なファイル保存ではありません。クライアントの再起動／再読み込み前に重要な編集を保存またはコピーしてください。読み書きの失敗時も下書きは保持されます。明示的な **更新** は、未保存の編集を破棄する前に警告します。

末尾の閉じるボタンでリーダーを閉じると会話に戻り、入力欄はリーダーの下で引き続き使えます。セッション／ワークツリーの変更は、選択したリーダーをクリアしますが、下書きの保存を約束するものではありません。ブラウザープレビューを開くとリーダーが置き換わり、ファイルを開くとその表示はチャットモードに戻ります。

## 読み取り専用・範囲制限付きのプレビュー {#preview-limits}

1. 画像、バイナリファイル、過去の変更を目の操作で開きます。
2. 差分では、必要に応じて **分割表示に切り替え**／**ユニファイド表示に切り替え**、折り返し、変更のない領域の操作を使用します。
3. リーダーを閉じてチャットに戻ります。

| 内容 | 利用できる動作 |
| --- | --- |
| Markdown ソースを含むワークスペースのテキスト | 明示的な保存を伴う編集 |
| ワークスペースの画像 | 読み取り専用の画像プレビュー |
| その他のバイナリ内容 | 読み取り専用の、プレビュー不可の代替表示 |
| 変更／コミットのテキスト差分 | 読み取り専用の比較。どちら側のエディターでもありません |
| Git の画像差分 | 比較対象の正確なリビジョンからの変更前／変更後の画像 |

プレビューの読み取りには上限があります。大きい／未対応の内容は、無制限に読み込まず利用不可となる場合があります。過去の画像を現在のワークツリーファイルで代用することはありません。プレビュー失敗は、元のファイルが存在しないことを意味しません。利用可能なら適切な外部アプリで開き、プレビューのためだけにリビジョンを変更しないでください。

## ステージ、ステージ解除、コミット {#stage-commit}

1. **変更** を選び、**ステージ済みの変更** と **変更** を確認します。
2. **ファイルをステージ**／**ステージ解除**、複数行を選んだ対応操作、またはセクション間の行のドラッグを使用します。
3. **ステージ済みの変更** の上部にメッセージを入力し、**コミット** を選びます。

折りたたんだセクションのヘッダーもドロップ先になります。セクションの折りたたみやモード変更でも、その状態とコミットメッセージの下書きは保持されます。長いセクションは最初の 200 ファイルを表示し、続いて **480 件のファイルが表示されていません** のような行と **さらに 200 件を表示** を示して、次のファイルをその場で表示できます。セクションの件数は常に全体の合計で、現在のファイル、プレビュー中のファイル、選択中のファイルは表示されたままです。Shift クリックの範囲選択は表示中の行だけが対象なので、一括操作に見えていないファイルが含まれることはありません。ステージ／解除は閲覧中のワークツリーのインデックスを変更し、コミットはステージ済みの内容だけを記録します。ステージ解除は、ワークツリーの編集を破棄しません。

特にエージェントや別クライアントも書き込む場合は、コミット前にステージ済みファイルを確認してください。失敗したコミットは自動的に再実行されません。応答の消失はコミットが作成されなかった証拠ではないため、状態／履歴を更新し、エラーを確認してから再試行します。

## コミット履歴を読む {#commit-history}

1. **コミット** を選び、コミットを選択してメッセージと変更ファイルを読みます。
2. **読み込んだコミットを絞り込む…** で読み込み済みの集合を絞り込み、**以前のコミットを読み込む** で次のページを取得します。
3. 変更ファイルを目の操作で開きます。

テキスト履歴は、コミットを第 1 親と比較します（ルートコミットでは空の基準と比較）。HEAD の切り替えやセッション移動はしません。読み込み済みコミットの絞り込みは、サーバー全体の Git ログ検索ではありません。新しいコミット後に現在の履歴から始めるには更新してください。既存のページ分割は、開始時の履歴スナップショットを保持します。

## 空白と改行コード {#whitespace-line-endings}

1. **設定 → 詳細設定 → 空白のみの変更を非表示** を開きます。
2. 変更一覧から省略された未ステージの空白のみの編集を確認するには、オフにします。
3. コミット前に実際の差分とステージ済み内容を確認します。

この設定は既定でオンです。主な効果は、条件を満たす未ステージの追跡済みテキスト変更を、変更一覧、件数、選択、一括ステージ、ドラッグ操作から隠すことです。非表示のファイルは未ステージのままです。ステージ済みファイル、および未追跡、追加／削除／名前変更、バイナリのファイルは表示されます。検出失敗／未対応の場合は、推測せず表示を維持します。

Git の一覧検出は、内部の空白、CRLF のみの変更、末尾改行の追加／削除を無視できる場合があります。差分リーダーの空白比較はより限定的で、インデントと末尾の空白／タブが対象であり、すべての内部空白ではありません。ステージとコミットは、表示設定に関係なく、常に正確な内容を対象にします。

改行コードやバイトオーダーマークの違いは、行の強調ではなく事実を示す注記になる場合があります。この設定をオフにしても、すべての改行／BOM の変更や、同じ長さの末尾空白の入れ替えをエディターで描画できるわけではありません。見た目が空の差分は、バイト列が同一である証拠ではありません。

## Git を初期化する {#initialize-git}

1. リポジトリでないフォルダーで **変更** または **コミット** を開きます。
2. **Git を初期化** を選びます。確認なしで直ちに実行します。
3. プロジェクト／セッションの更新を待ち、準備ができたら明示的にステージとコミットを行います。

初期化は、明示的に開いたフォルダーに `.git` を作成し、親ディレクトリの初期化や最初のコミットの作成は行いません。バックエンドに Git がなくても、ディレクトリ専用の会話やワークスペース閲覧は可能ですが、初期化と Git 操作は利用できません。不確かな失敗では、再試行前に更新してください。初期化リクエストが自動的に再実行されることはありません。[プロジェクト](projects.md)を参照してください。
