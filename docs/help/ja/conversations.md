# 会話

CodeNomad は、OpenCode ネイティブのセッションを会話として表示し、委任した作業の階層と、次に送信する内容のための個別のコントロールを提供します。

メッセージは Markdown、コード、差分、対応するツール結果の画像を表示します。テキストのコピー、全履歴検索、音声は、埋め込まれた画像のバイト列ではなく、テキストとしての表現を使用します。**メッセージの内容** は、保存されたパーツを削除せずに表示を変えます。[履歴](history.md#operation-reference)では、表示の操作とクリーンアップの違いを説明しています。

推論とツールのヘッダーには各ステップの所要時間が表示され、実行中はリアルタイムで増えていきます。1 秒未満の所要時間は表示されません。**メッセージの内容** で **トークン** を表示している場合（プリセット **すべて** では表示されます）、各エージェントメッセージの最後のテキストの後に、トークンとコストの行が 1 つ付きます。この行は、そのメッセージと、その **この回答からツールと推論を削除** 操作の対象となるツールと推論を含むメッセージを、読み込まれた会話記録の範囲で合計したものです。展開すると推論とキャッシュの数を確認できます。ツールを実行しただけのステップには、独自の行はありません。

## 会話を探して移動する {#navigate-conversations}

1. **セッション** の行を選ぶか、**新しいセッション** で親会話を開始します。
2. 親の山形矢印を展開してサブセッションを表示します。折りたたまれた矢印は、子孫の最も緊急な状態（入力待ち、作業中、または最近完了した待機状態）を示し、そのツールチップで件数を確認できます。
3. **セッションを検索…**、**メインセッション**／**サブセッション**、ワークツリーフィルター、および **アクティビティ**、**名前**、**ワークツリー** の並べ替えで一覧を絞り込みます。
4. サイドバーの **戻る** と **進む** で、以前表示した会話を再訪します。

通常の閲覧は階層表示です。検索／フィルター結果は、各会話自身の識別情報とワークツリーを持つ平坦な項目です。新たに作業を開始したサブセッションは、アクティブな会話のファミリー配下でのみ自動表示されます。その枝を折りたたむと、現在実行中の子孫に対する自動表示は解除されます。

戻る／進むは、一覧の順序ではなく、プロジェクトタブごと、ウィンドウごとの閲覧履歴です。メモリ内に保持され、利用不可／削除済みの会話はスキップし、再起動後は復元されません。戻った後に新しい会話を選ぶと、進む先の経路が置き換わります。一方、パレットの **前のセッション**／**次のセッション** は、表示中の一覧を巡回します。

## エージェント、モデル、思考を選ぶ {#agent-model-thinking}

1. 送信前に、入力欄フッターのエージェントとモデルのセレクターを使用します。
2. モデルがバリアントを提供している場合は、**思考** の強度を選びます。**デフォルト** ではネイティブの既定値をそのまま使用します。
3. 次のプロンプトを送信し、結果を診断するときは応答のエージェント／モデルのメタデータを確認します。

新しい会話は、別のエージェントを選ばない限り、OpenCode が既定として解決するエージェント（プラグインが設定する場合もあります）で開始します。セレクターのツールチップにショートカットが表示されます。

これらは以後の送信に対する実行上の選択であり、過去の応答を編集するものではありません。タイムラインの古い箇所を読んでも、入力欄の現在の選択が過去のメタデータに置き換わることはありません。モデルの表示、お気に入り、プロバイダー接続は、[プロバイダー](providers.md)で管理します。

## 下書きと添付 {#drafts-attachments}

1. 選択した会話で入力します。会話を切り替えても、下書きは送信されず保持されます。
2. この端末のファイルには、入力欄の **その他の操作** メニューで **ファイルを添付…** を選ぶか、ドロップまたは貼り付けます。プロジェクトのファイル、エージェント、スキルの選択には `@` を入力します。
3. 添付チップを確認し、次の送信に含めないものを削除します。

| 入力 | 取得元と効果 |
| --- | --- |
| 端末からの添付 | ピッカー、ドロップ、クリップボードが、UI を実行している端末からバイト列を読み取ります。サーバーパスではありません |
| プロジェクトの `@` 参照 | ワークツリーを含め、バックエンド上の会話のプロジェクト／Location で解決されます |
| エージェントへの言及 | 過去のメッセージを変更せず、選択したエージェント参照を添付します |
| スキル | Location のスキルを名前／説明で検索し、削除可能なスキル選択を添付します |

端末のファイルは読み取り可能で、添付の上限内である必要があります。1 ファイル最大 5 MiB、10 ファイル、合計 20 MiB です。拒否されたファイルは添付されません。選択全体が成功したと思い込まず、通知を確認してください。

スキルを選ぶと、`@query` トークンが削除され、チップが追加されます。送信すると入力欄のその選択はクリアされますが、OpenCode が送信済みメッセージとともに保存した指示は消えません。過去のメッセージにもスキルのラベルが残ります。キュー内のプロンプトを編集中にスキルを削除した場合、置き換えの送信でも削除されたままになります。

デスクトップでは、送信するとキーボードフォーカスが会話に移るため、矢印、ページ送り、Space で会話をスクロールできます。文字を入力すると、その文字とともに入力欄に戻ります。**その他の操作** の **プロンプトのテキストをクリア**（既定は **Ctrl/Cmd+K**）は、入力欄の下書きを消去します。

下書きはクライアント側の作業状態であり、共有ネイティブメッセージではありません。起動時の復元で、対応する入力状態を保持できる場合はありますが、未送信の下書きや添付をバックアップと考えたり、別の端末にも表示されると想定したりしないでください。起動データを消去する前や、復元ポリシーが無効なクライアントを閉じる前に、重要なテキストを保存してください。[デスクトップ](desktop.md)を参照してください。

## コマンドとシェルモード {#commands-shell}

1. `/` を入力して検出されたカスタムコマンドを選び、引数を指定します。
2. シェルコマンドを直接実行するには、空の入力欄の先頭に `!` を入力し、**シェルモード** に入ります。
3. コマンドを送信します。実行せずにシェルモードを終了するには Escape、または空の入力欄で Backspace を使用します。

既知のスラッシュコマンド名だけが、カスタムコマンドの経路を通ります。未知の `/text` は通常のプロンプトです。カスタムコマンドはネイティブの定義を使用します。ファイル／画像の添付はそのコマンド経路では送信されず、後のプロンプト用に残ります。引数で使用する貼り付けテキストは、引数に展開されます。

シェルモードは、モデルにコマンドの提案を頼むのではなく、ネイティブのセッションシェルリクエストを実行します。実行ホスト上のファイルを変更し、プロセスを起動できます。プロファイルの環境設定は、次のプロンプト、カスタムコマンド、シェルリクエストの前に適用され、既存サービスを再起動しません。[連携](integrations.md)と [OpenCode のセットアップ](opencode.md)を参照してください。

## フォローアップの割り込み、キュー、編集 {#follow-ups}

1. **設定 → 一般** で、セッションの処理中に送信したフォローアップをキューに入れるには **送信したプロンプトをキューに入れる** をオンにします。実行中のタスクに割り込むには、オフ（既定）のままにします。
2. セッションの処理中に、その動作でフォローアップを送信します。もう一方の動作を使うには、入力欄の **その他の操作** メニューで **メッセージをキューに追加** または **今すぐ割り込む** を選ぶか、別動作の送信ショートカット（既定は Windows と Linux で **Alt+Enter**、macOS で **Cmd+Shift+Return**。[ショートカット](shortcuts.md)を参照）を使用します。
3. プロンプトキューで、項目が待機中である間に **今すぐ割り込む**、**キューへ移動**、**待機中のプロンプトを編集**、**待機中のプロンプトを削除** を使用します。

| 送信方法 | 効果 |
| --- | --- |
| 割り込み | 進行中の実行に対するネイティブの割り込み入力 |
| キュー | 後続処理のために保持されるネイティブのフォローアップ |

待機状態での通常送信は、このスイッチにかかわらず通常の即時経路を使用し、**その他の操作** の代替送信は利用できません。編集では、待機中のプロンプトと削除可能な添付が入力欄に戻ります。**編集をキャンセル** は編集フローを終了します。OpenCode が既に取り込んだプロンプトは、編集可能な待機項目ではありません。項目を削除しても、既に行われた作業は取り消されません。

キューの更新に失敗した場合は、再試行する前に現在のキューを確認します。受け付けられたことは、モデルがフォローアップを取り込んだ証拠ではなく、再接続は再送信の許可ではありません。

## /btw で補足の質問をする {#side-question}

1. 既存の会話で `/btw your question` を送るか、`/btw` で補足質問ウィンドウを開きます。
2. 回答を読み、**回答をコピー** を使用するか、待機中に **質問をキャンセル** を選びます。
3. 終わったらウィンドウを閉じます。

これは、セッションのコンテキストを使う、独立した 1 回のモデルリクエストです。ツールループの実行、操作、会話への質問／回答の追記は行いません。ファイル／画像の添付は入力欄に残り、質問で使う貼り付けテキストはテキストとして含まれます。新しい永続的な会話でも、作業を指示する別経路でもありません。

閉じると、メインセッションを中断せずに待機中の補足リクエストをキャンセルします。アクティブな会話から離れると、この一時的なウィンドウはクリアされます。必要な内容は先にコピーしてください。空の応答やエラーは、会話のメッセージにならず、このウィンドウに表示されます。

## フォーク、取り消し、失敗した実行の復旧 {#fork-errors}

1. メッセージで **このメッセージの後でフォーク** を選ぶと、元の会話を置き換えずに、その地点以降の会話を作成できます。
2. 取り消す場合は、**ここまでの変更を元に戻す（メッセージを削除）** を慎重に確認します。パレットには、段階的な取り消しのために **直前のメッセージを取り消す** と **最後のメッセージをやり直す** があります。
3. 実行に失敗した場合は、再送信する前に **セッションエラー**、応答のエラー、**送信に失敗** の詳細を確認します。

フォークは、選択した地点までの会話コンテキストをコピーします。Git ワークツリーの作成やファイルの分離は行いません。元に戻す操作は、単なる移動ではありません。続行前にファイルへの影響と取り消しの境界を確認してください。元の流れを書き換えずに別の議論をしたい場合は、フォークを使用します。

カウントダウン付きの **再試行中** 状態は、OpenCode がプロバイダーのエラーを自動で再試行していることを示します。再送信せず、完了を待つかセッションを停止してください。送信に失敗すると、新しい入力を上書きしない場合に限り、送信しようとした下書きと添付を復元します。失敗した実行でも、既にツールを実行している場合があります。再試行前に、[ファイル](files.md)、保留中の[リクエスト](permissions.md)、ネイティブのアクティビティを確認してください。**メッセージを再読み込み** や **セッションを再読み込み** は状態を読み取るもので、変更操作を繰り返す指示ではありません。**セッションを停止** は実行を中断しますが、ファイルや外部サービスの変更を巻き戻しません。
