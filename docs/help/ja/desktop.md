# デスクトップのウィンドウとデータ

## ウィンドウ、タブ、共有サービス {#windows-tabs}

1. **新しいインスタンス** で、現在のウィンドウに別のプロジェクト／ホームタブを開きます。
2. 独立したアプリウィンドウには、ネイティブの **ウィンドウ → 新規ウィンドウ**（`Ctrl+Shift+N` または `Cmd+Shift+N`）を使用します。
3. 再度起動したとき、新しいウィンドウを開くのではなく最後に使ったウィンドウにフォーカスしたい場合は、**設定 → 詳細設定** で **2 回目の起動で既存ウィンドウをフォーカス** を有効にします。

プロジェクトタブ、選択中の会話、レイアウトはウィンドウに属します。OpenCode のセッション／メッセージは共有のネイティブ OpenCode サービスに属し、別のウィンドウも同じ会話を見られます。プロジェクトタブを閉じると CodeNomad 内でそのプロジェクトが閉じられますが、セッションは OpenCode で続き、プロジェクトを開き直すと再び確認できます。[プロジェクト](projects.md)を参照してください。ウィンドウを閉じても OpenCode サービスは停止しません。ウィンドウを閉じたことを、エージェントやスケジュール済みミッションが停止した証拠にしないでください。

## 設定と起動時の復元 {#preferences-startup}

1. 設定したいウィンドウから設定を開きます。ローカルデスクトップの入口は、開いた元のプロジェクト／Location を伴って、単一のネイティブ設定ウィンドウにフォーカスします。
2. **一般 → 起動** で **前回の状態を復元** を有効／無効にします。
3. そのウィンドウの保存済みレイアウトを忘れさせるには、影響を読んでから **保存状態を消去** を使用します。

復元では、ワークスペース／SideCar のタブ、アクティブなセッション、未送信テキスト、スクロール位置、パネル、ウィンドウの配置、ズームを開き直せます。ウィンドウ単位のクライアント状態であり、ネイティブ会話データベースのコピーではありません。消去すると保存済みタブ、下書き、レイアウトが削除されますが、CodeNomad 設定や OpenCode 会話は削除されません。重要な未送信下書きは、先に別の場所へ保存してください。

設定ウィンドウは独自の復元状態を持ちません。起動の設定は、それを開いた正確なウィンドウを対象とします。そのウィンドウが閉じたり変わったりしても、利用不可／古いコントロールが無断で別のウィンドウの状態を書き換えることはありません。目的のウィンドウから設定を開き直してください。プロジェクト範囲の設定も、開いた元の Location を使用し、ない場合は利用できません。

ブラウザーとリモートの設定は埋め込み表示であり、2 つ目のネイティブ設定の所有元ではありません。ネイティブ設定を開くエラーは報告されます。代わりに隠れた埋め込み設定画面が開いたと想定しないでください。

## 明示的なデスクトップデータプロファイル {#data-profiles}

プロファイルを明示しないパッケージ版の起動は、その設定で記憶したプロファイルを再利用します。選択が記憶されていなければ、既定、`dev`、`dev-v2` の復元可能な作業を確認します。候補が 1 つなら選択し、複数なら質問し、なければ既定を使います。選択でプロファイルデータを移動、統合、削除しません。別のプロファイルを明示的に開くには、`CODENOMAD_PROFILE` を使用します。

1. 意図的なデスクトップ分離には、実行ファイルの起動前に `CODENOMAD_PROFILE` を設定します。
2. ASCII の英数字、ドット、アンダースコア、ハイフンからなる 1〜64 文字で、英数字から始まる名前を使用します。名前は小文字に正規化され、`default` または `stable` は既定プロファイルを選びます。
3. 名前付きプロファイルは **設定 → 情報 → データプロファイル** で確認します。不正な名前は、別のプロファイルを選ばずに起動を阻止します。

たとえば PowerShell で、目的のデスクトップ実行ファイルを起動する前に：

```powershell
$env:CODENOMAD_PROFILE = "review"
```

独立したサーバー設定には、起動前に `CLI_CONFIG` も別の設定ファイルへ設定します。既定は `~/.config/codenomad/config.yaml` です。プロファイル名だけでは、そのファイルや共有 OpenCode サービスは変更されません。

| デスクトップデータプロファイルで分離するもの | 自動では分離しないもの |
| --- | --- |
| ウィンドウ／タブの復元状態、未送信下書き、デスクトップの単一起動／バックエンドの範囲 | OpenCode のセッション、メッセージ、プロバイダー認証情報、実行 |
| プラットフォーム制限下で、そのプロファイルに関連するネイティブ Chromium/WebView ストレージ | 設定を共有する場合の CodeNomad 設定、音声キー、SideCar、拡張機能の有効化 |
| ホスト／プロファイル内のネイティブプレビューストレージ | 開いたプロジェクトのファイル、リモートサーバーのデータ |

macOS Tauri の範囲別プロファイルは、システムの WebKit ストレージ、ログイン、キャッシュを共有します。プロファイル名をアカウントのセキュリティ分離に使わないでください。Electron はプロファイル内にウェブデータを保存します。インストール済みバージョンや **アップデートチャネル** が別のデータプロファイルを選ぶことはありません。パッケージ化されていない開発起動は、明示指定しなければ `dev` プロファイルを使用します。

## 他の保存済みプロファイルを削除する {#delete-profiles}

1. ネイティブの **設定 → 一般 → 起動** で **その他の保存済みプロファイル** を探します。マシンに他のプロファイルがある場合にのみ表示されます。
2. 必要なら一覧を更新し、**削除…** を選んで、列挙された対象とスキップされたプロファイルを読みます。
3. 必要な下書き／ログインを保存してから確認します。再試行前に、不完全な削除の報告を確認してください。

削除は、一覧にある別設定のプロファイルも含め、他プロファイルの保存済みタブ、下書き、レイアウト、所有するウェブストレージ／キャッシュ／ログインを取り除きます。開いているプロファイル、OpenCode 会話、プロジェクトファイルは保持します。開いている、または状態不明のプロファイルはスキップします。該当する CodeNomad ウィンドウを閉じてから、明示的に更新して再試行してください。認識できない内容は広く削除せず、保持して報告します。

macOS Tauri の共有 WebKit ストアは、削除すると他プロファイルに影響するため保持します。元に戻せるクリーンアップではありません。ネイティブ会話が残っていても、削除した未送信下書きは戻りません。現在のウィンドウだけをリセットしたい場合は、より小さい操作の **保存状態を消去** を使います。

## ズームとパネルの配置 {#zoom-panels}

1. ネイティブの **表示 → 拡大**、**縮小**、**実際のサイズ** を使用します。キーボード／ホイール入力もホストの対応に従います。
2. 固定された外側のヘッダー隅にある **左パネル** と **右パネル** でパネルを切り替えます。レイアウトが対応する場合はドロワーを固定／解除します。
3. コントロールが収まらなければ、ズームを下げるかウィンドウを広げます。狭いレイアウトでは操作はメニューへ、パネルはオーバーレイへ移ります。

ローカルとリモートのメインデスクトップウィンドウは、アプリのズーム倍率で拡大した最低 390 × 600 CSS ピクセルを確保し、モニターの作業領域を上限とします。ズームインは小さすぎるウィンドウを広げる場合がありますが、ズームアウトで既に大きいウィンドウを縮めません。設定とブラウザープレビューの子ウィンドウには別のサイズ規則があります。

パネルは最低限の会話幅を残し、それより狭い場合にフローティング表示になります。会話幅が 420 CSS ピクセル未満なら、タイムラインを隠し、ヘッダー操作をオーバーフローメニューにまとめます。保存したタイムライン設定は保持されます。これらの配置変更で、プロンプト下書きやネイティブセッションは変わりません。[設定とレイアウト](settings.md)、[ブラウザープレビューと SideCar](browser-sidecars.md)を参照してください。
