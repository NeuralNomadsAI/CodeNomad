# デスクトップのウィンドウとデータ

## ウィンドウ、タブ、共有サービス {#windows-tabs}

1. **新しいインスタンス** で、現在のウィンドウに別のプロジェクト／ホームタブを開きます。
2. 独立したアプリウィンドウには、ネイティブの **ウィンドウ → 新規ウィンドウ**（`Ctrl+Shift+N` または `Cmd+Shift+N`）を使用します。
3. 再度起動したとき、新しいウィンドウを開くのではなく最後に使ったウィンドウにフォーカスしたい場合は、**設定 → 詳細設定** で **2 回目の起動で既存ウィンドウをフォーカス** を有効にします。

プロジェクトタブ、選択中の会話、レイアウトはウィンドウに属します。OpenCode のセッション／メッセージは共有のネイティブ OpenCode サービスに属し、別のウィンドウも同じ会話を見られます。プロジェクトタブを閉じると CodeNomad 内でそのプロジェクトが閉じられますが、セッションは OpenCode で続き、プロジェクトを開き直すと再び確認できます。同じプロジェクト接続を表示している別のウィンドウでもそのタブが閉じられ、通知が表示されます。同じフォルダーを別に開いたタブには影響しません。ウィンドウ全体を閉じる、終了する、再読み込みする場合は、復元のためにプロジェクト接続が保持されます。[プロジェクト](projects.md)を参照してください。ウィンドウを閉じたことを、エージェントやスケジュール済みミッションが停止した証拠にしないでください。

ネイティブのアプリケーションメニューは、ウィンドウの読み込み後に CodeNomad のインターフェース言語を使い、それまでは英語で表示されます。**ヘルプ → CodeNomad について**（macOS ではアプリケーションメニューにもあります）は、バージョン、アップデート、診断情報を含む **設定 → 情報** を開きます。

## 設定と起動時の復元 {#preferences-startup}

1. 設定したいウィンドウから設定を開きます。ローカルデスクトップの入口は、開いた元のプロジェクト／Location を伴って、単一のネイティブ設定ウィンドウにフォーカスします。
2. **一般** で **前回の状態を復元** をオンまたはオフにします。
3. そのウィンドウの保存済みレイアウトを忘れさせるには、**保存された起動状態を消去** を使用します。確認なしで直ちに適用されます。

復元では、ワークスペース／SideCar のタブ、アクティブなセッション、未送信テキスト、スクロール位置、パネル、ウィンドウの配置、ズームを開き直せます。ウィンドウ単位のクライアント状態であり、ネイティブ会話データベースのコピーではありません。消去すると保存済みタブ、下書き、レイアウトが削除されますが、CodeNomad 設定や OpenCode 会話は削除されません。重要な未送信下書きは、先に別の場所へ保存してください。

設定ウィンドウは独自の復元状態を持ちません。これらのコントロールは、それを開いたウィンドウを対象とします。そのウィンドウが閉じている場合や、起動時に設定が再表示されて不明な場合は、最後に使用したウィンドウを対象にします。別のウィンドウ向けに用意した変更が適用されることはなく、コントロールはまず新しいウィンドウの値を表示します。特定のウィンドウを設定するには、そのウィンドウから設定を開いてください。プロジェクト範囲の設定も、開いた元の Location を使用し、ない場合は利用できません。起動時に設定が再表示された場合は、そのプロジェクトが開き終わった時点で再接続します。フォルダーがまだ起動中の間や、複数のタブで開かれている場合は、目的のウィンドウから設定を開くまで利用できません。

ブラウザーとリモートの設定は埋め込み表示であり、2 つ目のネイティブ設定の所有元ではありません。ネイティブ設定を開くエラーは報告されます。代わりに隠れた埋め込み設定画面が開いたと想定しないでください。

## デスクトップデータプロファイル {#data-profiles}

1. ネイティブの **設定 → 一般** で、**前回の状態を復元** の下にある **データプロファイル** を展開します。このコンピューター上のすべてのプロファイルが、サイズ、作成日、最終使用日とともに、開いているものを先頭にして一覧表示されます。
2. 次回の起動で開くプロファイルを選択するか、**新しいプロファイル** を選び、英小文字、数字、ピリオド、ハイフン、アンダースコアを 1〜64 文字使い、英字か数字で始まる名前を入力します。
3. すぐに切り替えるには **… で再起動** を選びます。選ばなければ、選択したプロファイルは次回の起動で開きます。開いているプロファイルを再度選択すると、変更は取り消されます。

別の設定のプロファイルも一覧に表示されますが、ここでは選択できません。記憶された選択がない場合、パッケージ版の起動は既定、`dev`、`dev-v2` の各プロファイルに復元可能な作業があるか確認し、そのうち最後に使用したものを開きます。どれにもなければ既定を開きます。プロファイルを選択しても、プロファイルデータの移動、統合、削除は行われません。

実行ファイルの起動前に設定した `CODENOMAD_PROFILE` は、この選択より優先されます。その場合、**データプロファイル** はプロファイルを表示しますが、選択はできません。`default` または `stable` は既定プロファイルを選び、不正な名前は別のプロファイルを選ばずに起動を阻止します。たとえば PowerShell で、目的のデスクトップ実行ファイルを起動する前に：

```powershell
$env:CODENOMAD_PROFILE = "review"
```

独立したサーバー設定には、起動前に `CLI_CONFIG` も別の設定ファイルへ設定します。既定は `~/.config/codenomad/config.yaml` です。プロファイル名だけでは、そのファイルや共有 OpenCode サービスは変更されません。

| デスクトップデータプロファイルで分離するもの | 自動では分離しないもの |
| --- | --- |
| ウィンドウ／タブの復元状態、未送信下書き、デスクトップの単一起動／バックエンドの範囲 | OpenCode のセッション、メッセージ、プロバイダー認証情報、実行 |
| プラットフォーム制限下で、そのプロファイルに関連するネイティブ Chromium/WebView ストレージ | 設定を共有する場合の CodeNomad 設定、音声キー、SideCar、拡張機能の有効化 |
| ホスト／プロファイル内のネイティブプレビューストレージ | 開いたプロジェクトのファイル、リモートサーバーのデータ |

macOS Tauri の範囲別プロファイルは、システムの WebKit ストレージ、ログイン、キャッシュを共有します。プロファイル名をアカウントのセキュリティ分離に使わないでください。Electron はプロファイル内にウェブデータを保存します。インストール済みバージョンや **アップデートチャネル** が別のデータプロファイルを選ぶことはありません。パッケージ化されていない開発起動は、明示指定しなければ `dev` プロファイルを使用します。

## 保存済みプロファイルを削除する {#delete-profiles}

1. 上記のとおり **データプロファイル** を展開し、必要なら一覧を更新します。
2. 削除するプロファイルの削除ボタンを選びます。開いているプロファイルには削除ボタンがありません。
3. 必要な下書き／ログインを保存してから確認します。再試行前に、不完全な削除の報告を確認してください。

削除は、一覧にある別設定のプロファイルであっても、そのプロファイルの保存済みタブ、下書き、レイアウト、所有するウェブストレージ／キャッシュ／ログインを取り除きます。開いているプロファイル、OpenCode 会話、プロジェクトファイルは保持します。開いている、または状態不明のプロファイルは削除できません。該当する CodeNomad ウィンドウを閉じ、一覧を更新してから再試行してください。認識できない内容は広く削除せず、保持して報告します。

macOS Tauri の共有 WebKit ストアは、削除すると他プロファイルに影響するため保持します。元に戻せるクリーンアップではありません。ネイティブ会話が残っていても、削除した未送信下書きは戻りません。現在のウィンドウだけをリセットしたい場合は、より小さい操作の **保存された起動状態を消去** を使います。

## ズームとパネルの配置 {#zoom-panels}

1. ネイティブの **表示 → 拡大**、**縮小**、**実際のサイズ** を使用します。キーボード／ホイール入力もホストの対応に従います。
2. 固定された外側のヘッダー隅にある **左パネル** と **右パネル** でパネルを切り替えます。レイアウトが対応する場合はドロワーを固定／解除します。
3. コントロールが収まらなければ、ズームを下げるかウィンドウを広げます。狭いレイアウトでは操作はメニューへ、パネルはオーバーレイへ移ります。

ローカルとリモートのメインデスクトップウィンドウは、アプリのズーム倍率で拡大した最低 390 × 600 CSS ピクセルを確保し、モニターの作業領域を上限とします。ズームインは小さすぎるウィンドウを広げる場合がありますが、ズームアウトで既に大きいウィンドウを縮めません。設定とブラウザープレビューの子ウィンドウには別のサイズ規則があります。

パネルは最低限の会話幅を残し、それより狭い場合にフローティング表示になります。会話幅が 420 CSS ピクセル未満なら、タイムラインを隠し、ヘッダー操作をオーバーフローメニューにまとめます。保存したタイムライン設定は保持されます。これらの配置変更で、プロンプト下書きやネイティブセッションは変わりません。[設定とレイアウト](settings.md)、[ブラウザープレビューと SideCar](browser-sidecars.md)を参照してください。
