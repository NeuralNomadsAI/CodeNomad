# Установка CodeNomad

Выберите локальное настольное приложение или запустите [отдельный сервер](server.md). В обоих случаях общей нативной службой и историей владеет OpenCode.

## Загрузка настольного приложения {#desktop-downloads}

1. Откройте [последний релиз](https://github.com/NeuralNomadsAI/CodeNomad/releases/latest).
2. Выберите сборку для своей операционной системы и процессора.
3. Распакуйте ZIP либо установите/запустите пакет для платформы, затем запустите CodeNomad.

| Платформа | Релиз Electron | Релиз Tauri | Примечания |
| --- | --- | --- | --- |
| macOS | ZIP, Intel или Apple Silicon | ZIP, Intel или Apple Silicon | Встроенная среда выполнения требует macOS 13.5 или новее. |
| Windows | ZIP, x64 | Установщик, x64 | Windows 10 или новее; Tauri использует WebView2. |
| Linux | Пакет Debian, x64 | AppImage, x64 | Собрано и проверено на Ubuntu 24.04; совместимость со старыми дистрибутивами не гарантируется. |

Настольные релизы включают ресурсы среды выполнения, необходимые серверной части и установщику OpenCode, поэтому отдельно устанавливать Node.js/npm не нужно. Git не входит в комплект. Нативная автоматизация браузера поддерживается в Electron и Windows Tauri; на других платформах Tauri используется предпросмотр iframe.

Если проверенная загрузка блокируется при запуске, см. [устранение проблем платформы](troubleshooting.md#desktop-launch). Никогда не запускайте недоверенный архив только ради обхода предупреждения.

## Установка в Linux {#linux-install}

В папке с загруженным релизом подставьте его фактическую версию и имя файла:

```sh
sudo apt install ./CodeNomad-Electron-linux-x64-<version>.deb
```

Для Tauri AppImage:

```sh
chmod +x CodeNomad-Tauri-linux-x64-<version>.AppImage
./CodeNomad-Tauri-linux-x64-<version>.AppImage
```

Если FUSE недоступен, используйте режим распаковки и запуска AppImage:

```sh
./CodeNomad-Tauri-linux-x64-<version>.AppImage --appimage-extract-and-run
```

Установка Electron из пакета Debian настраивает песочницу Chromium. Не отключайте песочницу для обхода проблем установки. Для графических проблем Linux Tauri существует [целевой обходной путь WebKit](troubleshooting.md#desktop-launch).

## Требования {#requirements}

| Требование | Где должно быть доступно | Текущее требование |
| --- | --- | --- |
| OpenCode CLI | Выбранный хост выполнения, включая выбранный дистрибутив WSL, если применимо | Минимум **2.0.27**; **2.0.29** — рекомендуемая/проверенная цель. Для новых и пользовательских версий проверяются контракты, а не вводится запрет на непроверенные версии. |
| Git | `PATH` учётной записи серверной части CodeNomad | Необходим для идентификации репозитория, операций Git и worktree. |
| Node.js/npm | Хост отдельного сервера и сборки из исходников | Node.js 24 LTS; воспроизводимые сборки из исходников используют `.node-version` (**24.20.0**). Входит в ресурсы выполнения/установки настольного приложения. |
| Папка рабочего пространства | Диск, доступный серверной части | Явно открытая физическая папка, а не локальная папка устройства, предполагаемая удалённым браузером. |

В Windows установите [Git for Windows](https://gitforwindows.org/) с доступом из командной строки и сторонних приложений. Достаточно установки для одного пользователя с правом записи. В macOS/Linux следуйте [инструкциям Git для платформы](https://git-scm.com/downloads).

После изменения `PATH` полностью закройте и снова запустите настольное приложение либо перезапустите отдельную серверную часть под нужной учётной записью. Перезагрузка браузера не обновляет окружение серверной части. Git, доступный только внутри WSL, не удовлетворяет требованию Git для серверной части Windows.

Без Git можно открыть физическую папку и использовать разговоры в пределах каталога, в том числе попросить агента помочь с установкой. Операции с репозиторием/worktree недоступны; доступ к сессиям ограничен ровно этой папкой. CodeNomad сообщает агенту о доступности Git в серверной части перед запросами/пользовательскими командами и удаляет это указание после восстановления. Хост выполнения агента может отличаться от хоста серверной части, поэтому установите Git для серверной части, а не только для оболочки агента.

## Выбор OpenCode при первом запуске {#first-launch}

1. При настройке выберите совместимый существующий исполняемый файл или используйте предложенную установку OpenCode.
2. Проверьте статус среды выполнения перед открытием проекта.
3. Откройте **Настройки → OpenCode**, чтобы отдельно управлять исполняемым файлом, установкой и общей службой.

CodeNomad предпочитает совместимые исполняемые файлы из `PATH` и поддерживает явно выбранный файл. Установка/обновление CLI не перезапускает уже работающую общую службу без вашего ведома. Последствия перезапуска/перезагрузки, WSL и окружение сессии описаны в разделе [настройки OpenCode](opencode.md).

## Использование браузера {#browser-install}

Установите Node.js/npm, Git и OpenCode на серверный хост, затем следуйте [процедурам запуска сервера](server.md). Подключитесь по напечатанному адресу с настроенной аутентификацией и доверенным сертификатом. Браузеру/PWA нужна работающая серверная часть; это не автономная копия проектов.

Порты, привязки и TLS описаны в разделе [прямого доступа](remote-access.md). Для сопряжения устройства без открытия входящих портов используйте [удалённое управление](remote-control.md). Команды разработки и упаковки см. в разделе [сборки из исходников](support.md#build-from-source).
