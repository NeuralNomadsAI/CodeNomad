# Диктовка, воспроизведение и голосовой разговор

## Настройка голоса {#configure}

Откройте **Настройки → Голос**. Карточки **Диктовка**, **Воспроизведение** и **Разговор** показывают свой статус.

1. В локальном настольном приложении выберите в карточке **Диктовка** [движок устройства](#desktop-dictation). Браузер и мобильные клиенты используют только API.
2. Для диктовки через API и воспроизведения откройте **Данные доступа к API** из любой из двух карточек. Укажите **API-ключ** и при необходимости **Базовый URL**, **Модель распознавания** и **Речевая модель**. Для разных служб включите **Раздельные провайдеры для ввода и вывода**, заполните их поля и нажмите **Сохранить**.
3. В карточке **Воспроизведение** указан **Провайдер**. Установите **Голос по умолчанию**, **Режим воспроизведения** и **Формат вывода**, затем нажмите **Сохранить**.

Настройки и ключи речи принадлежат конфигурации подключённого сервера CodeNomad, не выбранному проекту или подключению провайдера OpenCode. Другие клиенты этой конфигурации используют их же. Сохранённые ключи скрыты: пустое поле сохраняет прежнее значение; **Удалить сохранённый ключ** планирует удаление при сохранении. Направление без своего эндпоинта и ключа может использовать общие настройки; отдельному эндпоинту нужен свой ключ, отдельному ключу — свой эндпоинт. При смене эндпоинта явно укажите нужный ключ и проверьте сохранённую конфигурацию; смена эндпоинта очищает сохранённый ключ этого слота вместо отправки другому хосту.

Серверная часть также может использовать `OPENAI_API_KEY` и `OPENAI_BASE_URL` как общие значения по умолчанию. Очистка сохранённого ключа не удаляет учётные данные из окружения; измените окружение серверной части и перезапустите её, если хотите убрать резервный вариант.

| Настройка | Значение / по умолчанию |
| --- | --- |
| Базовый URL | Корень совместимого с OpenAI API, по умолчанию `https://api.openai.com/v1`. Ввод использует `audio/transcriptions`; вывод — `audio/speech`. |
| Модель распознавания / модель ввода | Модель, принимаемая STT-эндпоинтом; по умолчанию `gpt-4o-mini-transcribe`. |
| Речевая модель / модель вывода | Модель, принимаемая TTS-эндпоинтом; по умолчанию `gpt-4o-mini-tts`. |
| Голос по умолчанию | Идентификатор голоса провайдера; по умолчанию `alloy`. Это не выбор голоса ОС. |
| Потоковый | По умолчанию. Начинает воспроизведение при поступлении аудио, если провайдер и браузер поддерживают формат. |
| Буферизованный | Ждёт полного аудиоответа перед воспроизведением. |
| Формат вывода | `mp3`, `wav`, `opus` или `aac`; по умолчанию `mp3`. Совместимость зависит от браузера/провайдера. |

Это запросы к настроенной службе, не гарантия реализации каждой модели, голоса или формата любым совместимым эндпоинтом.

## Проверка ввода и вывода {#test}

1. Сначала сохраните изменения эндпоинта, ключа, модели и голоса.
2. Выберите **Проверить ввод через API**, разрешите микрофон, произнесите текст, затем **Остановить запись**. Проверьте полученную расшифровку.
3. Выберите **Проверить воспроизведение** для прослушивания примера; **Остановить пример** завершает его.

Тест воспроизведения сразу использует выбранные режим и формат, а эндпоинт, ключ, модель и голос — из сохранённых настроек. **Проверить ввод через API** отправляет аудио настроенному провайдеру API независимо от движка диктовки. Сообщение в разговор не отправляется. Провайдер может взимать плату за тесты.

## Диктовка запроса {#dictate}

1. Оставьте включённым **Голосовой ввод промпта** в разделе **Голос** (он включён по умолчанию).
2. В меню **Больше действий** отметьте **Режим диктовки**. Снимите отметку с активного режима, прежде чем выбрать другой.
3. Удерживайте кнопку микрофона рядом с **Больше действий**, говорите и отпустите кнопку для расшифровки. При запросе разрешите доступ к микрофону. В совместимом удалённом окне нажатие открывает локальное управление записью.
4. Проверьте текст. Он заменяет исходное выделение, только если черновик и выделение не изменились. В противном случае перед новой диктовкой выберите **Вставить расшифровку** в обычном режиме или **Удалить расшифровку**. Диктовка не отправляет черновик.

Если API в Tauri на Linux использует резервную запись в WAV, при диктовке и проверке ввода запись останавливается через 24 секунды. Фрагмент остаётся на устройстве, пока вы не выберете **Расшифровать**, чтобы отправить его поставщику голосовых услуг, или **Отмена**, чтобы удалить его.

Сжатая запись для API тоже останавливается при достижении предельного размера. После этого доступны **Расшифровать** и **Отмена**.

### Выбор движка для настольного приложения {#desktop-dictation}

В локальном настольном приложении откройте **Настройки → Голос → Диктовка** и выберите **Движок диктовки на этом устройстве**. Выбор действует для всех проектов на этом устройстве. **Поставщик API** использует настройки подключённого сервера; для доступа к микрофону требуется защищённый контекст.

- Если сохранённый движок недоступен, выберите здесь **Hex (локальный)**, если он предлагается, или **Поставщик API**. На Mac с Intel или macOS ниже 15 используйте **Поставщик API**.
- В разделе «Голос» показано, чего не хватает для Hex, и объём загрузки по компонентам и в целом. Одно нажатие **Активировать Hex** проверяет и повторно использует совместимые файлы, загружает недостающее и выбирает готовый Hex. Следите за ходом работы там же. Можно **Отменить активацию Hex**, а когда доступно — **Возобновить активацию Hex**. При сбое или отмене остаётся прежний движок. Повторное открытие настроек, выбор готового **Hex (локальный)** или диктовка с ним не запускают загрузку.
- Hex предлагается на совместимых Windows x64/arm64, Apple Silicon с macOS 15 или новее и Linux x64/arm64 с glibc 2.36 или новее и нужными библиотеками. Intel Mac и Linux с устаревшей glibc или musl несовместимы. Движок и модели не входят в установщик CodeNomad; терминал и ключ API не нужны.

Ubuntu 24.04 удовлетворяет требованию к glibc, а Ubuntu 22.04 — нет. Hex автоматически определяет язык речи среди [языков, поддерживаемых Parakeet](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3), включая английский и французский. Список не зависит от языка приложения.

Hex загружает модель в фоновом режиме при начале записи и сохраняет её готовой к работе в течение трёх минут после последней диктовки.

Локальное распознавание работает без интернета, в том числе для проектов WSL, открытых в локальном приложении. В совместимом удалённом окне нажмите кнопку микрофона, чтобы открыть **Диктовать на этом устройстве**. Проверьте назначение и используйте кнопки записи и вставки в этом окне. В черновик вернётся только текст. Удалённому проекту по-прежнему нужно соединение с сервером.

В удалённом окне Tauri в Linux **Проверить ввод через API** проверяет голосовой API сервера, не меняя движок диктовки. Перед подтверждением каждой записи для API проверьте адрес сервера в системном диалоге доступа к микрофону. Запись использует PulseAudio или службу PulseAudio в PipeWire; указанное выше ограничение WAV в 24 секунды действует всегда.

Gemini Live и OpenAI Realtime недоступны в удалённых окнах Tauri в Linux: диктовка и проверка ввода используют встроенную запись, а WebKit блокирует прямой доступ к микрофону.

## Озвучивание сообщений {#playback}

1. Используйте **Озвучить сообщение** у сообщения или то же действие у вызова инструмента, когда TTS доступен.
2. Нажмите **Остановить воспроизведение** на том же элементе, чтобы завершить его; запуск другого чтения останавливает текущее.
3. Измените голос, режим или формат в карточке **Воспроизведение** либо модель в разделе **Данные доступа к API** и сохраните изменения.

Воспроизведение использует текстовую проекцию CodeNomad, не озвученный снимок экрана: двоичные байты/изображения и квитанции разрешений не входят в речь. Оно не выполняет запрос модели и не меняет выбранную модель OpenCode.

## Голосовой разговор {#conversation}

Gemini Live и OpenAI Realtime доступны только для сессий на сервере, который открыл это окно.

В карточке **Разговор** выберите **Движок разговора**:

- **Классический** требует только настроенного воспроизведения в поддерживаемом формате. Отметьте **Режим разговора** в меню **Больше действий**. CodeNomad озвучивает готовую сводку ответа `spoken` в активной основной сессии. Режим действует во вкладке проекта до выключения или перезагрузки.
- Для **Gemini Live** и **OpenAI Realtime** задаются отдельные **API-ключ**, **Модель** и необязательный **Голос**. Сохраните настройки выбранного провайдера. Откройте целевую сессию, выберите **Режим разговора** в меню **Больше действий**, затем **Согласиться и начать** в диалоге согласия. Разрешите доступ к микрофону.

Если провайдер стал недоступен, пока открыт диалог согласия, нажмите **Настройки голоса**, чтобы открыть карточку разговора.

Голосовая модель может читать состояние сессии, закреплённой при запуске, последний видимый ответ и недавние ошибки. У неё нет доступа к файлам. Если попросить её отправить запрос агенту, она сразу отправит его как ваше сообщение, без подтверждения на экране. [Режим разрешений разговора](permissions.md#conversation-mode) и вопросы агента действуют как обычно.

Сервер допускает один разговор в реальном времени на вошедшего пользователя, а при удалённом управлении — на сопряжённое устройство. Кнопка **Остановить** завершает аудио, оставляя расшифровку открытой. Она хранится в памяти до закрытия окна; отправленные запросы остаются сообщениями сессии. Разговор также завершается после двух минут без речи, через восемь минут в общей сложности, при смене цели, закрытии окна или разрыве соединения. Автоматического переподключения или переключения провайдера нет.

В OpenAI Realtime кнопка **Прервать ответ** останавливает воспроизведение и запрашивает отмену текущего ответа. В Gemini Live кнопка **Остановить воспроизведение** отключает звук только на этом устройстве: Gemini может продолжать формировать ответ и отправлять запросы агенту.

## Поток данных и конфиденциальность {#privacy}

При локальной диктовке звук остаётся на устройстве без переключения на API. При выборе **Поставщик API** звук идёт через сервер CodeNomad на настроенный эндпоинт распознавания. Текст синтеза идёт через сервер на эндпоинт TTS, а полученное аудио воспроизводится на клиенте. Ключи API остаются на сервере.

При использовании **Gemini Live** или **OpenAI Realtime** Google или OpenAI получает звук с микрофона, имя проекта, ветку, рабочее дерево, заголовок и состояние сессии. Провайдер также может получить текст последнего видимого ответа агента и недавние ошибки. Выбранный провайдер может взимать плату за использование с вашей учётной записи.

Пользуйтесь провайдером, которому доверяете продиктованные, озвучиваемые и передаваемые данные. Учётные данные OpenCode не дают автоматического доступа к голосовым сервисам. Прочитайте раздел [Безопасность](security.md), прежде чем открывать сервер другим пользователям.
