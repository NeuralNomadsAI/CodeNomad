# Настройка OpenCode

CodeNomad подключается к общей службе OpenCode на хосте выполнения. Выбор CLI, обновление его файлов, перезапуск службы и перезагрузка конфигурации — разные операции; ни одна не заменяет остальные.

## Выбор или установка CLI {#select-cli}

1. Откройте **Настройки → OpenCode** и используйте **Бинарник OpenCode** для выбора исполняемого файла.
2. Оставьте автоматический выбор, чтобы предпочитать PATH сервера, затем пользовательскую установку npm; либо используйте **Выбрать бинарник…** или введите путь и нажмите **Добавить**.
3. Нажмите **Проверить состояние и обновления**. Если OpenCode отсутствует, выберите **Установить и запустить OpenCode**; сначала проверьте хост и область установки.
4. Если настройка предлагает **Подключиться и продолжить**, используйте после устранения указанной проблемы.

Установка использует встроенные Node/npm для стандартной пользовательской установки, общей с другими клиентами. **Установить для пользователя и настроить PATH** меняет настройку терминала этого пользователя; после этого откройте новый терминал. Браузер подключается к серверу CodeNomad: выбор файла и исполняемого файла относится к серверу, не к устройству просмотра.

Установленный исполняемый файл и работающая служба могут иметь разные версии. Проверьте **Сведения о версиях**, не предполагая, что выбор другого файла заменил живой демон. Если установка занята или файл заблокирован, дождитесь освобождения установщиком или процессом и проверьте состояние перед повтором; не запускайте конкурирующие установщики.

## Требуемые, рекомендуемые и непроверенные версии {#versions}

| Классификация | Текущее требование | Значение |
| --- | --- | --- |
| Минимум | OpenCode **2.0.27** | Требуемая нативная среда плагинов; более старая стабильная среда не загрузит встроенные плагины. |
| Рекомендуемая | OpenCode **2.0.29** | Проверенная цель, отличная от технического минимума. |
| Непроверенная | Новая или пользовательская версия, не прошедшая полную проверку | Не отклоняется лишь из-за отсутствия тестирования; проверяются реальные API-контракты подключённой службы. |

Необходимые контракты сессий, разрешений, форм, входящих и окружения сессий тоже должны быть доступны. Одна версия исполняемого файла не доказывает их поддержку подключённой службой. Если настройка сообщает о неподдерживаемой работающей службе, выберите/установите поддерживаемый CLI и выполните явный перезапуск общей службы, когда будете готовы.

## Хост, WSL и общая служба {#execution-host}

В Windows выбранный исполняемый файл WSL работает в своём дистрибутиве. Устанавливайте/обновляйте его там и используйте пути этого дистрибутива. Подключение WSL зависит от перенаправления localhost Windows. Windows CLI и WSL CLI — не взаимозаменяемые среды выполнения.

OpenCode владеет глобальной регистрацией службы, сессиями, сообщениями и базой данных. CodeNomad не создаёт отдельную базу OpenCode для окна или проекта. Закрытие вкладки/окна или завершение серверной части CodeNomad не останавливает общий демон. **Остановить рабочее пространство** вместо этого выгружает Location и её ресурсы; см. [проекты](projects.md).

## Обновление, перезапуск и перезагрузка {#maintenance}

1. В **Настройки → OpenCode** выберите **Проверить состояние и обновления**.
2. Для замены установленных файлов CLI выберите **Обновить до OpenCode {version}**, когда предложено. Дождитесь завершения.
3. Проверьте статус работающей службы. Используйте **Перезапустить общую службу**, только если хотите активировать выбранную установку для всех подключённых клиентов.
4. Для перезапуска процесса без установки раскройте **Устранение неполадок**, выберите **Перезапустить службу OpenCode** и подтвердите.

| Действие | Область и эффект | Безопасное восстановление |
| --- | --- | --- |
| Обновить CLI | Меняет поддерживаемый установленный исполняемый файл; не перезапускает работающий демон неявно. | После сбоя проверьте установленную и работающую версии; повторяйте явно только после устранения ошибки. |
| Перезапустить службу | Заменяет общий процесс и прерывает активную работу всех подключённых клиентов OpenCode; история сессий остаётся. | Переподключитесь и проверьте разговоры и миссии по расписанию; перезапуск не означает автоматического продолжения. |
| Перезагрузить конфигурацию OpenCode | Сохраняет процесс, но пересоздаёт **все загруженные Location** для всех клиентов. Отменяет ожидающие разрешения/формы и закрывает терминалы/фоновые команды; активная работа может прерваться. | Перепроверьте ресурсы и ожидающую работу после перезагрузки. Не повторяйте запрос или изменение лишь из-за потерянного ответа. |

Используйте **Перезагрузить конфигурацию OpenCode** явно, если сохранённая конфигурация или установленный плагин остаются недоступны и прерывание допустимо. Это не безобидное обновление отображения. CodeNomad не использует старый выбранный CLI для понижения версии нового работающего демона.

## Окружение сессии {#session-environment}

1. Откройте **Настройки → Расширенные → Переменные окружения**.
2. Добавьте, измените или удалите переопределения профиля.
3. Отправьте следующий запрос, пользовательскую команду или запрос оболочки сессии через CodeNomad для применения текущего окружения к разговору.

Это настройка профиля конфигурации, применяемая на серверной стороне перед каждой отправкой. Простое открытие/чтение разговора или сохранение настроек не меняет нативную сессию. Удаление переопределения восстанавливает унаследованное значение хоста выполнения или удаляет переменную, если её там нет. Ошибка применения окружения блокирует отправку вместо использования устаревших значений.

Окружение управляет последующими локальными запусками оболочки в нативной сессии. Уже работающие процессы сохраняют окружение. Оно **не** перенастраивает провайдеров, MCP/LSP-серверы, независимые терминалы или фоновые оболочки только Location. Каждый запрос очереди не фиксирует собственное окружение, а другой клиент OpenCode может заменить окружение той же сессии. Не предполагайте, что дочерние сессии, полностью созданные внутри OpenCode, получают обновление CodeNomad при отправке.

Разрешённые переменные также передаются при запуске остановленной службы; подключение к существующему демону не меняет окружение его процесса. В WSL значения объединяются с Linux-окружением, а не Windows PATH/HOME. Изменение переопределений не перемещает базу OpenCode или регистрацию службы.

## Редактирование нативных файлов конфигурации {#configuration-files}

1. Откройте **Настройки → Файлы конфигурации** и выберите **Файл**.
2. Проверьте показанный путь, внесите правки и нажмите **Сохранить**.
3. Используйте **Перезагрузить** для повторного чтения файла; это не **Перезагрузить конфигурацию OpenCode**.

Этот редактор предоставляет только перечисленные глобальные файлы `opencode.json` и `opencode.jsonc` в каталоге `.config/opencode` **пользователя сервера CodeNomad**. Это не редактор произвольных файлов, не выбор проектной конфигурации и не гарантия чтения файла демоном WSL/с пользовательскими путями обнаружения. Проверьте цель по показанному пути; для других корней используйте инструменты самого демона.

Сохранение записывает файл как текст; оно не проверяет всю нативную конфигурацию и не перезапускает/перезагружает OpenCode. Согласуйте правки с другими клиентами: слияния внешних изменений здесь нет. Сделайте копию перед существенной заменой конфигурации. При переключении файлов или перезагрузке изменённого черновика запрашивается подтверждение его отбрасывания.

Специальные процедуры настройки описаны в разделах [Интеграции](integrations.md), [Провайдеры](providers.md), [Миссии](missions.md) и [документации OpenCode](https://opencode.ai/v2/docs/).
