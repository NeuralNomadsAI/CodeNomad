# Настройка OpenCode

## Выбор или установка CLI {#select-cli}

1. Откройте **Настройки → OpenCode** и используйте карточку **Бинарник OpenCode** под **Версия OpenCode** для выбора исполняемого файла.
2. Оставьте выбранной автоматическую запись либо раскройте **Выбрать другой бинарник…**, чтобы использовать **Выбрать бинарник…** или ввести путь и нажать **Добавить**.
3. Нажмите **Проверить состояние и обновления**. Если OpenCode отсутствует, выберите **Установить и запустить OpenCode**; сначала проверьте хост и область установки.
4. Если настройка предлагает **Подключиться и продолжить**, используйте после устранения указанной проблемы.

**Установить для пользователя и настроить PATH** меняет настройку терминала этого пользователя; после этого откройте новый терминал. Браузер подключается к серверу CodeNomad: выбор файла и исполняемого файла относится к серверу, не к устройству просмотра.

Когда первым в PATH стоит более старый OpenCode, предлагаемое действие зависит от способа его установки. Для OpenCode 1.x, установленного через npm, **Заменить OpenCode {version} на OpenCode 2** запрашивает подтверждение, удаляет этот пакет npm и устанавливает OpenCode 2 в ту же папку npm; папка данных OpenCode сохраняется, а OpenCode 2 сам импортирует беседы 1.x. Старый или неработоспособный OpenCode, установленный иначе (winget, Homebrew, вручную), никогда не изменяется: **Установить OpenCode 2 для CodeNomad** устанавливает OpenCode 2 в пользовательскую папку npm рядом с ним, и затем CodeNomad использует эту копию. Если сама эта старая команда находится в пользовательской папке npm (например, ссылка в `~/.local/bin`) или эта папка недоступна для записи, настройка вместо этого действия объясняет причину: переместите или переименуйте команду либо исправьте права на папку, затем выберите **Проверить состояние и обновления**. Команда `opencode` в терминале может по-прежнему запускать старую версию. Явно выбранный пользовательский исполняемый файл никогда не заменяется.

Карточка **Версия OpenCode** показывает **Работающая служба** отдельно, когда её версия отличается от **Установленная версия** или неизвестна. **Сведения о версиях** показывает минимальную версию и, если она отличается, рекомендуемую.

## Требуемые, рекомендуемые и непроверенные версии {#versions}

| Классификация | Текущее требование | Значение |
| --- | --- | --- |
| Минимум | OpenCode **2.4.2** | Требуется для этого выпуска CodeNomad. Беседы, сохранённые более ранними версиями, остаются доступными после обновления. |
| Рекомендуемая | OpenCode **2.4.2** | Для CodeNomad **1.2.0**. |
| Непроверенная | Новая или пользовательская версия, не прошедшая полную проверку | Не отклоняется лишь из-за отсутствия тестирования; проверяются реальные API-контракты подключённой службы. |

## Хост, WSL и общая служба {#execution-host}

В Windows выбранный исполняемый файл WSL работает в своём дистрибутиве. Устанавливайте/обновляйте его там и используйте пути этого дистрибутива. Подключение WSL зависит от перенаправления localhost Windows. Windows CLI и WSL CLI — не взаимозаменяемые среды выполнения.

Закрытие вкладки проекта закрывает этот проект в CodeNomad; сессии продолжают работать в OpenCode и снова появляются при повторном открытии проекта. Закрытие всего окна, выход или перезагрузка сохраняют подключения проектов для восстановления; ни эти действия, ни завершение серверной части не останавливают общий демон. См. [проекты](projects.md).

## Запускать при старте системы {#login-start}

В **Настройки → OpenCode** параметр **Запускать при старте системы** поручает операционной системе запускать службу OpenCode в фоне при вашем входе, даже когда CodeNomad закрыт. Он выключен, пока вы его не включите, действует со следующего входа и относится к вашей учётной записи на компьютере, где работает сервер CodeNomad. Он запускает исполняемый файл, выбранный в карточке **Бинарник OpenCode**; выбор другого нативного исполняемого файла обновляет его, иначе он продолжает запускать прежний.

| Система | Что запускает OpenCode | После сбоя |
| --- | --- | --- |
| Windows | Скрытая запланированная задача для вашей учётной записи, без пароля и прав администратора. Исполняемый файл WSL запускается в своём дистрибутиве. | Не перезапускается. |
| macOS | LaunchAgent. | Перезапускается macOS. |
| Linux | Пользовательская служба systemd, запускаемая при входе, без включения linger. | Перезапускается systemd. |

Выключение удаляет только эту задачу, LaunchAgent или службу; работающий OpenCode продолжает работать. **Недоступно в этой системе** отображается, когда сервер CodeNomad работает внутри WSL или в другой системе без запуска при входе.

## Обновление, перезапуск и перезагрузка {#maintenance}

1. В **Настройки → OpenCode** выберите **Проверить состояние и обновления**.
2. Для замены установленных файлов CLI выберите **Обновить до OpenCode {version}**, когда предложено. Дождитесь завершения.
3. Проверьте статус работающей службы. Используйте **Перезапустить общую службу**, только если хотите активировать выбранную установку для всех подключённых клиентов.
4. Для перезапуска процесса без установки раскройте **Устранение неполадок**, выберите **Перезапустить службу OpenCode** и подтвердите.

| Действие | Область и эффект |
| --- | --- |
| Обновить CLI | Меняет поддерживаемый установленный исполняемый файл; не перезапускает работающий демон неявно. |
| Перезапустить службу | Заменяет общий процесс и прерывает активную работу всех подключённых клиентов OpenCode; история сессий остаётся. |
| Перезагрузить конфигурацию OpenCode | Сохраняет процесс. Для всех подключённых клиентов отменяет ожидающие разрешения/формы, закрывает терминалы/фоновые команды и может прервать активную работу. |

Используйте **Перезагрузить конфигурацию OpenCode** (в **Устранение неполадок**, если работающая служба это поддерживает), если сохранённая конфигурация или установленный плагин остаются недоступны. Прочитайте и подтвердите предупреждение: перезагрузка может прервать активную работу всех подключённых клиентов. CodeNomad не использует старый выбранный CLI для понижения версии нового работающего демона.

## Окружение сессии {#session-environment}

1. Откройте **Настройки → Расширенные** и раскройте **Переменные окружения**.
2. Добавьте переопределения, измените их значения или удалите их; сохранённые имена доступны только для чтения, а каждое изменение сохраняется сразу.
3. Отправьте следующий запрос, пользовательскую команду или запрос оболочки сессии через CodeNomad для применения текущего окружения к разговору.

Это настройка профиля конфигурации. Простое открытие/чтение разговора или сохранение настроек не меняет нативную сессию. Удаление переопределения восстанавливает унаследованное значение хоста выполнения или удаляет переменную, если её там нет.

Окружение управляет последующими локальными запусками оболочки в нативной сессии. Уже работающие процессы сохраняют окружение. Оно **не** перенастраивает провайдеров, MCP/LSP-серверы, независимые терминалы или фоновые оболочки только Location. Каждый запрос очереди не фиксирует собственное окружение, а другой клиент OpenCode может заменить окружение той же сессии. Не предполагайте, что дочерние сессии, полностью созданные внутри OpenCode, получают обновление CodeNomad при отправке.

Разрешённые переменные также передаются при запуске остановленной службы; подключение к существующему демону не меняет окружение его процесса. В WSL значения объединяются с Linux-окружением, а не Windows PATH/HOME.

## Редактирование нативных файлов конфигурации {#configuration-files}

1. Откройте **Настройки → Файлы конфигурации** и выберите **Файл**.
2. Проверьте показанный путь, внесите правки и нажмите **Сохранить**.
3. Используйте **Перезагрузить** для повторного чтения файла; это не **Перезагрузить конфигурацию OpenCode**.

Этот редактор предоставляет только перечисленные глобальные файлы `opencode.json` и `opencode.jsonc` в каталоге `.config/opencode` **пользователя сервера CodeNomad**. Это не редактор произвольных файлов, не выбор проектной конфигурации и не гарантия чтения файла демоном WSL/с пользовательскими путями обнаружения. Проверьте цель по показанному пути; для других корней используйте инструменты самого демона.

Сохранение записывает файл как текст; оно не проверяет всю нативную конфигурацию и не перезапускает/перезагружает OpenCode. Согласуйте правки с другими клиентами: слияния внешних изменений здесь нет. Сделайте копию перед существенной заменой конфигурации. При переключении файлов или перезагрузке изменённого черновика запрашивается подтверждение его отбрасывания.

Специальные процедуры настройки описаны в разделах [Интеграции](integrations.md), [Провайдеры](providers.md), [Миссии](missions.md) и [документации OpenCode](https://opencode.ai/v2/docs/).
