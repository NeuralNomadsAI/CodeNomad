# Файлы и Git

Вкладка правой панели **Файлы** объединяет просмотр рабочей копии, локальные изменения и историю коммитов. Выбор строки отделён от открытия центрального просмотрщика.

## Просмотр рабочей копии {#browse-workspace}

1. Откройте **Файлы** и выберите **Рабочая область**.
2. Выберите **Просматриваемое рабочее дерево**, если нужна другая рабочая копия; раскрывайте папки по необходимости.
3. Нажмите строку файла для выбора. Значок глаза открывает или закрывает центральный предпросмотр.
4. Используйте **Обновить**, если видимый снимок нужно перепроверить.

| Режим | Что читает | Влияние на разговор |
| --- | --- | --- |
| Рабочая область | Файлы просматриваемой рабочей копии | Не перемещает сессию и не переключает ветку |
| Изменения | Изменения индекса и рабочего дерева | Изменения Git происходят только по явным действиям |
| Коммиты | Постраничная история коммитов и содержимое ревизий | История только для чтения; без переключения рабочей копии |

Раскрытые папки сохраняются при смене режима. Списки/статус/история используют кэшированные снимки и перепроверяются после соответствующих изменений файловой системы, активации или явного обновления; фокус на панели не гарантирует новое чтение. Видимые папки рабочей области сами подхватывают файлы, созданные, изменённые, переименованные или удалённые на серверном хосте, не чаще раза в пять секунд при непрерывной активности; свёрнутые папки и другие worktree перечитываются только при их показе.

Действия строки включают **Скопировать путь** и, если клиент умеет открывать пути серверной части, действия файлового менеджера/редактора/терминала: **Открыть в приложении по умолчанию**, **Показать в папке**, **Открыть в файловом менеджере** и **Открыть терминал здесь**. При нехватке места действия переходят в **Дополнительные действия для {name}**; `{name}` заменяется именем файла или папки. Удалённый браузер не может считать серверный путь локальным путём устройства; см. [удалённое управление](remote-control.md).

## Редактирование исходника и безопасное сохранение {#edit-save}

1. Откройте текстовый файл рабочей области значком глаза.
2. Для Markdown выберите **Показать исходник** для редактирования или **Предпросмотр Markdown** для чтения результата.
3. Внесите правки и выберите **Сохранить** либо нажмите **Ctrl/Cmd+S**, когда редактор в фокусе.
4. Если файл изменён извне, проверьте подтверждение перезаписи; **Отмена** сохраняет черновик без перезаписи этого изменения.

Сохранение записывает реальный файл в просматриваемую рабочую копию, включая связанный worktree; оно не отправляет запрос и не добавляет правку в индекс/коммит. Сначала файл повторно читается из достоверного источника. Диалог конфликта говорит **Файл был изменён агентом. Перезаписать изменения агента?**; так же внимательно относитесь к изменениям любого внешнего автора.

Несохранённые черновики исходника остаются в памяти интерфейса по экземпляру проекта, каталогу и пути при закрытии или переключении просмотрщиков. Обновления файловой системы не заменяют их незаметно. Это не долговременное файловое хранилище: сохраните или скопируйте важные правки перед перезапуском/перезагрузкой клиента. Ошибки чтения/записи сохраняют черновик. Явное **Обновить** предупреждает перед отбрасыванием несохранённых правок.

Закрытие просмотрщика кнопкой в конце возвращает к разговору; поле ввода остаётся доступным под ним. Смена сессии/worktree очищает выбранный просмотрщик, но не обещает сохранить его черновик. Открытие браузерного предпросмотра заменяет просмотрщик; открытие файла возвращает этот вид в режим чата.

## Ограниченный предпросмотр только для чтения {#preview-limits}

1. Откройте изображение, двоичный файл или историческое изменение значком глаза.
2. Для диффа используйте **Переключиться на раздельный вид** / **Переключиться на единый вид**, перенос строк и управление неизменёнными участками.
3. Закройте просмотрщик для возврата в чат.

| Контент | Доступное поведение |
| --- | --- |
| Текст рабочей области, включая исходник Markdown | Редактирование с явным сохранением |
| Изображение рабочей области | Предпросмотр изображения только для чтения |
| Другой двоичный контент | Сообщение о недоступном предпросмотре, только для чтения |
| Текстовый дифф изменений/коммитов | Сравнение только для чтения, не редактор любой из сторон |
| Дифф изображений Git | Изображения до/после из точных сравниваемых ревизий |

Чтения предпросмотра ограничены; большой/неподдерживаемый контент может быть недоступен вместо неограниченной загрузки. Исторические изображения никогда не подменяются текущим файлом worktree. Ошибка предпросмотра не означает отсутствие файла. Откройте его подходящим внешним приложением, если возможно, не меняя ревизию только ради предпросмотра.

## Подготовка, отмена подготовки и коммит {#stage-commit}

1. Выберите **Изменения** и проверьте **Подготовленные изменения** и **Изменения**.
2. Используйте **Подготовить файл** / **Убрать из staging**, выберите несколько строк для действия с выбранными файлами или перетащите строки между разделами.
3. Введите сообщение вверху **Подготовленные изменения**, затем выберите **Коммит**.

Заголовки свёрнутых разделов остаются целями перетаскивания. Сворачивание или смена режима сохраняет состояние и черновик сообщения коммита. Длинный раздел показывает первые 200 файлов, затем строку вроде **Не показано файлов: 480** с **Показать ещё 200**, чтобы раскрыть следующие на месте; счётчики разделов остаются полными итогами, а текущий, просматриваемый и выбранные файлы остаются видимыми. Диапазоны Shift+щелчка охватывают только показанные строки, поэтому массовое действие никогда не включает файл, которого вы не видите. Подготовка/отмена подготовки меняет индекс просматриваемого worktree; коммит записывает только подготовленное содержимое. Удаление из индекса не отбрасывает правку рабочего дерева.

Проверьте подготовленные файлы перед коммитом, особенно если туда также пишут агенты или другой клиент. Неудачный коммит автоматически не повторяется. Обновите статус/историю и изучите ошибку перед повтором: потерянный ответ не доказывает, что коммит не был создан.

## История коммитов {#commit-history}

1. Выберите **Коммиты** и коммит для чтения сообщения и изменённых файлов.
2. Используйте **Фильтр загруженных коммитов…** для фильтрации загруженного набора или **Загрузить предыдущие коммиты** для следующей страницы.
3. Откройте изменённый файл значком глаза.

Текстовая история сравнивает коммит с первым родителем (или пустой базой для корневого коммита). Она не переключает HEAD и не перемещает сессии. Фильтрация загруженных коммитов — не поиск по журналу Git всего сервера. Обновите для начала с текущей истории после новых коммитов; существующая пагинация сохраняет исходный снимок истории.

## Пробелы и окончания строк {#whitespace-line-endings}

1. Откройте **Настройки → Расширенные → Скрывать изменения только пробелов**.
2. Отключите параметр, если нужно проверить неиндексированные правки только пробелов, скрытые из изменений.
3. Проверьте фактический дифф и подготовленное содержимое перед коммитом.

По умолчанию настройка включена. Она главным образом скрывает подходящие неиндексированные изменения отслеживаемого текста из списка изменений, счётчиков, выбора, массовой подготовки и перетаскивания. Скрытые файлы остаются вне индекса. Подготовленные файлы видны, как и неотслеживаемые, добавленные/удалённые/переименованные и двоичные файлы. При неудачном/неподдерживаемом определении файлы остаются видимыми вместо предположений.

Определение списка Git может игнорировать внутренние пробелы, изменения только CRLF и добавленные/удалённые завершающие переводы строки. Сравнение пробелов в просмотрщике диффа уже: отступы и конечные пробелы/табуляции, а не все внутренние пробелы. Подготовка и коммит всегда работают с точным содержимым независимо от настройки отображения.

Различия окончаний строк и метки порядка байтов могут давать фактическое примечание вместо подсвеченных строк. Отключение настройки не заставит редактор отрисовать каждое изменение окончания строки/BOM или замену конечных пробелов одинаковой длины. Визуально пустой дифф не доказывает идентичность байтов.

## Инициализация Git {#initialize-git}

1. Откройте **Изменения** или **Коммиты** в папке без репозитория.
2. Выберите **Инициализировать Git**; операция выполняется сразу без подтверждения.
3. Дождитесь обновления проекта/сессий, затем явно подготовьте и закоммитьте файлы, когда будете готовы.

Инициализация создаёт `.git` в явно открытой папке; она не инициализирует родительский каталог и не создаёт первый коммит. Если в серверной части нет Git, разговоры в пределах каталога и просмотр рабочей области возможны, но инициализация и операции Git недоступны. При неопределённом сбое обновите состояние перед повтором; запрос инициализации автоматически не повторяется. См. [проекты](projects.md).
