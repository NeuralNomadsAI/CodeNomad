# Расширения панели

## Просмотр установленных и онлайн-расширений {#browse}

1. Откройте **Настроить правую панель** в полосе вкладок правой панели.
2. Раскройте **Расширения** под разделителем.
3. Используйте **Поиск расширений** для поиска в едином списке установленных дополнений и официального онлайн-каталога. Наведите указатель на запись или установите фокус для метаданных.

Просмотр метаданных каталога не загружает и не выполняет код панели автора. Каталог поддерживается в [CodeNomad Extensions](https://github.com/NeuralNomadsAI/CodeNomad-Extensions); включение в него и заявленные имена авторов — не подписи и не доказательство доверия.

## Проверка и установка без активации {#install}

1. Выберите **Установить…** у записи каталога или **Установить из ZIP…** для отдельно полученного пакета.
2. Проверьте ID пакета, автора, репозиторий, версию, API/разрешения и дайджест SHA-256. При необходимости раскройте технические подробности.
3. Проверьте издателя и, где возможно, сравните дайджест по доверенному каналу.
4. Только если доверяете коду, отметьте **Я доверяю этому пакету и его автору**, затем **Установить без активации**.

Инспекция загружает/перепроверяет выбранный пакет; код автора при этом не выполняется. Дайджест идентифицирует точные байты, не личность автора. Пакеты каталога поступают из точно объявленного ресурса релиза GitHub, не произвольного URL. Ручные пакеты — ZIP только с `manifest.json` и самодостаточным `panel.html`; неверные или неподдерживаемые пакеты отклоняются.

Установка не требует перезапуска OpenCode и никогда автоматически не даёт активацию.

## Активация и область действия {#activate-scope}

1. Вернитесь к строке дополнения над разделом **Расширения** в **Настроить правую панель**. Установленные отключённые дополнения остаются в списке.
2. Отметьте флажок для активации. Снимите тот же флажок для отключения.

Активация действует на всю конфигурацию во всех проектах, не на папку. При удалённом подключении влияет на хранилище расширений сервера, не только устройство просмотра.

Хранилище расширений — `panel-extensions/` рядом с выбранной конфигурацией CodeNomad. Отдельные настольные профили данных **не** изолируют расширения, если используют тот же каталог конфигурации. Различия см. в разделе [Настольные окна и данные](desktop.md).

**Сбросить** в настройке восстанавливает только встроенную раскладку и не включает, не отключает и не удаляет расширения.

## Замена или удаление {#replace-remove}

1. Используйте **Сменить версию…** или проверьте другой ZIP с тем же ID для замены установленного пакета.
2. Проверьте новый дайджест и разрешения, подтвердите доверие, затем установите без активации.
3. Снова активируйте обычным флажком только после решения доверять замене.
4. Для удаления используйте **Удалить…** и **Подтвердить удаление** после проверки цели.

Каждая замена отзывает активацию во всех проектах, даже при неизменном списке разрешений, и очищает сохранённые собственные настройки панели. Скрытых обновлений расширений нет. Удаление убирает пакет, настройки активации и сохранённые настройки панели, не сессии OpenCode или файлы проекта. Для восстановления после нежелательного кода сначала отключите его; переустанавливайте только проверенный доверенный пакет.

## Контекст, согласие на ресурсы и ограничения песочницы {#permissions-sandbox}

| Контракт | Что разрешает активация |
| --- | --- |
| API 1 / `session.context` | Идентификатор текущей сессии (или его отсутствие), язык и оформление интерфейса. Без текста переписки и доступа к файловой системе. |
| API 2 / `session.assets.read` плюс контекст | Явно проверенное разрешение перечислять ограниченные метаданные изображений/вложений результатов инструментов текущей сессии и читать поддерживаемые встроенные байты. Не общий доступ к переписке, файлам или URL. |
| API 3 / `repository.workItems.read` и контекст | Явно проверенное разрешение показывать ограниченные страницы issues и pull requests репозитория проекта на GitHub, GitLab или Gitea/Forgejo и открывать один из них в браузере. Это не доступ к файлам, учётным данным или сети в целом. |
| API 4 / контекст плюс одно или несколько разрешений ниже | При проверке показывается по одному предложению на каждое объявленное разрешение; активация предоставляет их все вместе, а замена отзывает их все. |
| `session.images.read` | Читать изображения, возвращённые инструментом read в отображаемом разговоре, со статусом генерации и происхождением, когда их можно проверить. |
| `session.images.prompts` (требует `session.images.read`) | Читать промпт и модель каждого изображения, созданного в разговоре «Изображения» проекта. |
| `composer.prefill` | Добавлять текст в поле ввода отображаемого разговора. Никогда не отправляет сообщение. |
| `images.conversation` | Открывать или начинать разговор «Изображения» этого проекта. |
| `opencode.designAgent` | Добавляет в OpenCode агент Design от CodeNomad и его навыки работы с изображениями, пока это расширение включено. |
| `panel.preferences` | Запоминать собственные настройки этой панели. |
| `panel.notes` | Хранить по одной заметке на каждый разговор этого проекта, показывать и удалять заметки и открывать их разговоры. Удаление расширения удаляет заметки. |
| `repository.workItems.read` | Читать имя репозитория этого проекта и его issues и pull requests на GitHub, GitLab или Gitea/Forgejo (через ваш авторизованный gh, glab или tea либо анонимно для публичных репозиториев) и открывать их в браузере. |
| `repository.worktrees.read` (требует `repository.workItems.read`) | Видеть, у каких issues и pull requests есть локальная ветка, созданная CodeNomad, и использует ли её worktree. |
| `repository.worktrees.write` (требует `repository.worktrees.read`) | Запрашивать создание ветки и worktree для issue или pull request (pull request загружается из репозитория) и перенос туда отображаемого разговора. CodeNomad каждый раз спрашивает вас. |

Доступ к ресурсам следует текущему смонтированному хосту/сессии, не выбранной автором сессии. Смена сессии, отключение или отзыв согласия аннулируют старый доступ.

Расширение с `session.images.prompts` может читать промпты, написанные вами или агентом для изображений в разговоре «Изображения», и может передать их дальше, несмотря на песочницу, поэтому предоставляйте его только авторам, которым вы их доверяете. Текст, добавленный через `composer.prefill`, остаётся в поле ввода, пока вы не измените его или не выберете **Отправить сообщение**; он никогда не начинается с команды, никогда не заканчивается незавершённым упоминанием `@` и приводит пути к изображениям обычным текстом. Отмена через Ctrl+Z (Cmd+Z в macOS) в поле ввода его не удаляет. Сохранённые настройки панели принадлежат этому профилю CodeNomad, не более 4 КиБ на расширение; при отключении расширения они сохраняются. Заметки, сохранённые через `panel.notes`, тоже принадлежат этому профилю и хранятся по проектам: их видят рабочие деревья одного репозитория, а также его клоны, чей удалённый репозиторий указывает на тот же размещённый репозиторий. Отключение или замена расширения их сохраняет, удаление — удаляет. Как и памяти агента, заметкам нужен Git, чтобы определить их проект.

Элементы берутся из удалённого репозитория `upstream` папки проекта, иначе из `origin`. CodeNomad читает их через CLI GitHub, GitLab или Gitea, в который вы уже вошли (`gh`, `glab`, `tea`), либо анонимно для публичных репозиториев, и не хранит токенов; расширение видит только имя репозитория и элементы. Анонимное чтение доступно для github.com, gitlab.com, codeberg.org и gitea.com; самостоятельно размещённая платформа читается только через CLI, в который выполнен вход на ней. Открытие элемента просит CodeNomad открыть его страницу на той же платформе в браузере, не чаще раза в секунду; другие адреса расширение открыть не может.

Связанная ветка — это ветка, созданная CodeNomad для элемента: `issue-N` от текущего коммита или `pr-N` на голове pull request, загруженной из того же remote, включая форки. Git хранит связь вместе с веткой и удаляет её вместе с ней; одноимённая ветка, созданная не CodeNomad, никогда не используется. Расширение может только попросить: CodeNomad показывает собственный диалог с названием элемента, затем при необходимости создаёт ветку и worktree и переносит туда отображаемый разговор и разговоры его субагентов. У ветки `pr-N` нет upstream; отправляйте её своей обычной командой Git.

Код автора работает в ограниченном iframe, не в доверенном процессе отображения приложения. Он не получает мост к нативному окружению/OpenCode, учётные данные, общий RPC, формы, всплывающие окна или загрузки; сетевые API и внешние ресурсы ограничены. Расширения — дополнения интерфейса, не [плагины OpenCode](integrations.md).

Песочница не изолирует процесс/CPU и не обещает безвредность одобренного кода. Враждебное расширение может нарушить работу своего процесса отображения. Устанавливайте только доверенных авторов, не передавайте секреты и отключите/удалите дополнение при неожиданном поведении.

## Создание изображений с расширением Design {#design}

Расширение **Design** — это световой стол для изображений, которые вы создаёте с агентом Design от CodeNomad в **беседе «Изображения»** проекта. Оно показывает изображения, готовит запросы в поле сообщения и оставляет каждую генерацию сообщениям, которые отправляете вы.

1. Подключите провайдера с моделью изображений. Генерация изображений включена, если её не выключили в **Настройки → Провайдеры → Изображения** ([Генерация и хранение изображений](providers.md#images)).
2. В **Настроить правую панель → Расширения** установите **Design** из каталога ([Проверка и установка без активации](#install)), проверив его разрешения ([Контекст, согласие на ресурсы и ограничения песочницы](#permissions-sandbox)), затем отметьте его флажок ([Активация и область действия](#activate-scope)).
3. Откройте панель **Design** и выберите **Открыть беседу «Изображения»**.

Пока расширение включено, CodeNomad добавляет в OpenCode свой агент Design и его навыки работы с изображениями. Ваш собственный агент `design` и ваши собственные навыки `design-*` всегда имеют приоритет; когда вы задаёте собственный агент `design`, панель показывает **Используется ваш собственный агент Design.**

### Беседа «Изображения» {#design-conversation}

У каждой папки проекта или worktree есть своя беседа «Изображения» с заголовком **Изображения**. **Открыть беседу «Изображения»** находит её или создаёт с агентом Design и моделью, которую CodeNomad выбирает для новой беседы с этим агентом, а затем показывает её с фокусом в поле сообщения; открытие ничего не отправляет. Существующая беседа «Изображения» сохраняет свою модель. **Новая беседа «Изображения»** начинает ещё одну с пустым световым столом, и панель предлагает её, когда в беседе много изображений; после этого **Открыть** показывает самую новую. Архивированные и удалённые беседы «Изображения» пропускаются.

Опишите, что вам нужно, и отправьте: агент задаёт несколько уточняющих вопросов, сообщает, сколько изображений создаст, создаёт их, перечитывает каждое и оценивает его. Изображения сохраняются в `.codenomad/design/` папки проекта. CodeNomad добавляет эту папку в локальные исключения Git репозитория (`.git/info/exclude`) и не трогает `.gitignore`; если это невозможно, панель показывает **Изображения в этом расположении могут попасть в Git.** Отмена хода убирает его изображения со светового стола, но сохраняет их файлы, а изображение, перезаписанное агентом, восстановить нельзя.

Если модель чата беседы не получает изображения, панель предупреждает, что агент не может оценить их визуально; перечитанные им изображения по-прежнему видны на световом столе.

### Световой стол {#design-light-table}

**Световой стол** показывает изображения, которые агент перечитал в открытой беседе, от новых к старым, сгруппированные по ответам. Выбранное изображение показывается крупнее, с предпросмотром **Малые размеры** в 16, 32 и 64 px; **Сравнить** ставит два изображения рядом, а **Открыть в полном размере** открывает просмотрщик. Узкую панель расширьте, чтобы сравнивать. Происхождение по цепочке (**Создано из**, **Использовано для**), а в беседе «Изображения» также промпт и модель, появляются, только когда CodeNomad может проверить, какая генерация создала изображение; иначе изображение сохраняет пиксели и помечено **происхождение не проверяется**. **Генерации** перечисляет каждую генерацию изображения с её состоянием; следите за ходом в беседе. В другой беседе панель показывает перечитанные в ней изображения без промптов и запросов и предлагает открыть беседу «Изображения».

В беседе «Изображения» кнопки **Начать с** (рецепт, например значок приложения или логотип), **Доработать**, **Варианты**, **Применить направление**, **Сохранить в проект…**, **Попросить агента показать его** и **Повторить** только добавляют редактируемый текст в поле сообщения: панель никогда не отправляет сообщение и не создаёт изображение. Действия с выбранным изображением указывают его путь относительно проекта, и указать можно только изображения проекта с проверяемым происхождением. Отредактируйте запрос и отправьте его сами. **Сохранить в проект…** просит агента скопировать изображение туда, куда вы укажете после запроса. **Изображений за ход** (от 1 до 4, по умолчанию 3) включается в запросы на создание новых изображений и хранится в сохранённых настройках панели. На телефоне панель плавающая и закрывается, когда добавляет запрос.

### Агент Design без CodeNomad {#design-without-codenomad}

Агент Design и его навыки — обычные файлы OpenCode. Чтобы использовать их в TUI OpenCode или другом клиенте без CodeNomad, скопируйте содержимое [папки контента Design](../../../packages/server/src/opencode/design/opencode/) в папку `.opencode/` проекта или в глобальную папку конфигурации OpenCode (`~/.config/opencode/`) вместе с `NOTICE.md` и лицензией. Затем выберите агента **design**; он загружает свои навыки по имени, а другие агенты используют их, только когда вы их называете.

Агент Design и его навыки адаптируют материалы [Open Design](https://github.com/nexu-io/open-design) (Apache-2.0) и [taste-skill](https://github.com/Leonxlnx/taste-skill) (MIT); `NOTICE.md` перечисляет каждый адаптированный файл. Расширение Design повторно использует код расширения MCP Assets (MIT).
