# Удалённое управление

Удалённое управление позволяет сопряжённому браузеру или настольному клиенту использовать работающую серверную часть CodeNomad без открытия входящего сетевого порта. Не нужны пароль сервера, `--host` вне loopback или VPN. Это отдельный путь от [прямых подключений](remote-access.md).

## Запуск и сопряжение {#start-and-pair}

1. На хосте откройте **Настройки → Удалённый доступ**.
2. Выберите **Запустить удалённое управление**. Дождитесь **Готово к удалённым подключениям**; первое использование может занять время для подготовки идентичности туннеля и сертификата.
3. В **Подключить другое устройство** отсканируйте QR-код или нажмите **Копировать ссылку**, затем откройте одноразовую ссылку на нужном устройстве.
4. Сохраняйте данные сайта сопряжённого браузера. Снова откройте адрес туннеля для подключения, пока серверная часть работает.

Ссылка действует **пять минут** и срабатывает **один раз**. Считайте её учётными данными: любой использовавший её может стать сопряжённым устройством. Код находится во фрагменте URL, не в строке запроса. **Создать новую ссылку сопряжения** немедленно делает предыдущую неиспользованную ссылку недействительной. Завершение серверной части отменяет ожидающую ссылку сопряжения; остановка и сбой туннеля отменяют ссылку туннеля.

В CodeNomad на другом компьютере вставьте ссылку сопряжения в поле **Настройки → Серверы → Адрес или ссылка сервера**.

Для повторного сопряжения вставьте новую ссылку в форму подключения сервера или проекта.

## Сопряжение по прямому HTTPS {#direct-https}

Если туннель заблокирован, но серверная часть доступна по доверенному HTTPS, например через обратный прокси с настоящим сертификатом, устройства могут сопрягаться по этому адресу. Подходят собственные HTTPS-адреса этой серверной части и HTTPS-источники из `CODENOMAD_ALLOWED_ORIGINS` (см. [Разрешённые источники](remote-access.md#upgrading)); имена loopback и обычный HTTP никогда не сопрягаются. Запускать удалённое управление не нужно.

1. На хосте откройте **Настройки → Удалённый доступ → Удалённое управление**.
2. В разделе **Прямое сопряжение по HTTPS** выберите **HTTPS-адрес**, если их несколько, затем **Создать ссылку сопряжения HTTPS**.
3. Откройте ссылку на устройстве, как ссылку туннеля. По ней можно перейти с другой страницы.

Для ссылки действуют те же правила (пять минут, одно использование); она заменяет любую неиспользованную ссылку, а повторяющиеся неверные коды ограничиваются. Обратный прокси должен завершать доверенный TLS, передавать исходные заголовки `Host` и `Origin` и обращаться к серверной части через loopback или защищённую сеть.

Такое устройство подключается только по своему HTTPS-адресу, никогда через туннель, а **Сопряжённые устройства** показывает этот адрес под его именем. Остановка удалённого управления не отменяет ссылку и не отключает эти устройства; доступ прекращают **Отозвать**, 30 дней без использования, предел в 32 устройства или удаление адреса из конфигурации. Браузер с отозванными или истёкшими учётными данными устройства на этом адресе не может перейти на пароль сервера: выполните сопряжение снова или очистите данные сайта, чтобы войти с паролем.

См. [доступные функции](#remote-surface), включая исключение для содержимого SideCar при прямом HTTPS-подключении. Сопряжение не даёт привилегий loopback даже через прокси на хосте.

## Управление сопряжёнными устройствами {#paired-devices}

1. На хосте вернитесь в **Настройки → Удалённый доступ → Удалённое управление**.
2. Проверьте **Сопряжённые устройства** и время **Последняя активность**. Каждое устройство названо по платформе и браузеру, с которых выполнено сопряжение, например `iPhone · Safari`.
3. Нажмите **Отозвать** для устройства, которому больше нельзя подключаться. Если появилось **Отзыв доступа ожидает сохранения**, снова нажмите **Отозвать** перед перезапуском хоста.

Отзыв завершает текущие HTTP/SSE-подключения устройства и будущий доступ. Для восстановления выполните сопряжение по новой ссылке. Устройство истекает после **30 дней без использования**. При **лимите 32 устройства** новое сопряжение заменяет устройство с самой давней активностью и закрывает его подключения.

Очистка данных сайта, смена профиля браузера или приватный режим могут потребовать нового сопряжения.

Изменение пароля прямого доступа **не** отзывает устройства. **Остановить удалённое управление** отключает туннель, но сохраняет список устройств; используйте **Отозвать**, чтобы убрать авторизацию.

### Повторное сопряжение без потери места {#re-pair}

1. Если клиент показывает **Повторно сопрягите это устройство**, оставьте эту страницу открытой.
2. На хосте создайте ссылку для исходного подключения: **Создать новую ссылку сопряжения** для туннеля или выберите исходный **HTTPS-адрес** в разделе **Прямое сопряжение по HTTPS** и нажмите **Создать ссылку сопряжения HTTPS**. Откройте ссылку в том же браузере или профиле клиента. Отдельное удалённое окно повторно использует своё хранилище.
3. Вернитесь на ожидающую страницу и нажмите **Проверить соединение**; проверка также повторяется, когда страница снова получает фокус.

Восстановление сохраняет открытую страницу и черновики; не повторяет неудачное действие. Перед повтором проверьте, сработала ли отправка, ответ или удаление. Пароль прямого доступа не восстанавливает сопряжение удалённого управления.

## Доступность и время жизни {#lifetime}

| Действие/состояние | Эффект |
| --- | --- |
| Запустить удалённое управление | Подключает эту серверную часть и запоминает выбор для будущих запусков. |
| Закрыть удалённый браузер | Не останавливает серверную часть хоста и не отзывает устройство. |
| Остановить удалённое управление | Отключает доступ через туннель и убирает автоматическое возобновление при запуске; сохраняет записи устройств. |
| Завершение серверной части / закрытие последнего настольного окна и выход из приложения | Удалённое управление становится недоступным. Общая служба OpenCode может продолжать работать, но не может предоставлять этот интерфейс через остановленную серверную часть. |
| Запуск после оставленного включённым удалённого управления | Переподключается в фоне без новой ссылки сопряжения. Установки, где его никогда не запускали, не включаются сами. |

Автовозобновление ограничено одной серверной частью на каталог конфигурации. Не запускайте конкурирующие хосты с одной конфигурацией ради дополнительной ёмкости туннеля. Для доступности после выхода из настольного приложения разверните отдельно управляемый [отдельный сервер](server.md); удалённое управление — не независимый демон.

## Доступные и недоступные поверхности {#remote-surface}

Сопряжённые устройства могут использовать обычные API проектов/разговоров, отправлять запросы, просматривать файлы и отвечать на разрешения/формы с теми же проверками принадлежности. Сопряжение даёт мощный доступ, не ссылку просмотра. Оно никогда не предоставляет loopback-привилегии, хотя туннель перенаправляет трафик внутри хоста.

| Поверхность | Через удалённое управление |
| --- | --- |
| Обычный аутентифицированный интерфейс, рабочие пространства, разговоры и SSE | Доступны сопряжённому устройству. |
| Вход/выход по паролю, изменение пароля, локальная начальная настройка токеном | Недоступны; учётные данные устройства обязательны даже при отключённой прямой аутентификации. |
| Статус удалённого управления | Читается сопряжённым устройством; управление недоступно. Запуск/остановка, создание сопряжения, список устройств и отзыв остаются на пути доступа хоста. |
| Сохранённые серверы и проксирование | Аутентифицированные удалённые клиенты могут использовать все сохранённые на хосте серверы и управлять ими, если функция и возможности хоста это разрешают. Новые пароли серверов/ссылки сопряжения требуют Удалённого управления или HTTPS, а не обычного HTTP в локальной сети. См. [сохранённые серверы](remote-access.md#saved-servers). |
| Настольные удалённые окна и их прокси | Только на хосте (`/api/remote-proxy/`). |
| Содержимое SideCar и WebSocket (`/sidecars/`) | Недоступно через туннель. Используйте loopback или включите на хосте [прямой HTTPS-доступ к SideCar](browser-sidecars.md#register-sidecar). |
| Регистрация SideCar (`/api/sidecars`) | Доступна сопряжённым устройствам и аутентифицированным клиентам с прямым подключением. |
| Содержимое веб-предпросмотра | [Открытие браузера сессии](browser-sidecars.md#session-browser) |
| Мост автоматизации | Недоступен (`/api/opencode-plugin/`). Нативные возможности рабочего стола не становятся возможностями браузера. |
| Обновления соединения до WebSocket | Доступны для веб-предпросмотра, а на сопряжённых устройствах — и для [голосовых разговоров в реальном времени](voice.md#conversation). |

Используйте loopback-подключение на хосте для прокси/WebSocket, доступных только с хоста, и управления туннелем (`/api/remote-control/`). При прямом LAN-доступе для этих операций также требуется loopback; см. [Разрешённые источники](remote-access.md#upgrading).

## Ретранслятор и конфиденциальность {#relay-privacy}

CodeNomad использует [OpenTunnel](https://github.com/anomalyco/opentunnel) и занимает один случайный маршрут на общей идентичности туннеля компьютера по умолчанию.

TLS завершается в серверной части CodeNomad. Ретранслятор передаёт шифротекст и не может читать содержимое приложения, но видит имена хостов, время соединений и объёмы трафика. Сертификат/закрытый ключ туннеля остаются на хосте. Защищайте хранилище туннеля хоста и конфигурацию CodeNomad как учётные данные; неугадываемый адрес — не авторизация.

`CODENOMAD_REMOTE_CONTROL_API` выбирает собственный API OpenTunnel; без значения используется размещённая служба. Это меняет развёртывание туннеля, не требования сопряжения и не заблокированные поверхности. Обращение с учётными данными и диагностикой см. в разделе [Безопасность](security.md).

## Политика администратора {#administrator-policy}

Администратор может отключить удалённое управление для всех пользователей компьютера: задайте переменную среды `CODENOMAD_REMOTE_CONTROL=disabled` для всей системы и перезапустите CodeNomad. Бэкенд никогда не подключает туннель, отклоняет **Запустить удалённое управление** и ссылки сопряжения и не переподключается при запуске; в настройках отображается **Отключено администратором**. Ранее сопряжённые устройства не могут подключиться и остаются в списке, чтобы их можно было отозвать. Если переменная не задана или пуста, политики нет; любое другое значение, даже из одних пробелов, не даёт бэкенду запуститься.
