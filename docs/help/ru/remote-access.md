# Прямой удалённый доступ

Прямой доступ подключается к HTTP/HTTPS-слушателям CodeNomad с паролем сервера. Он отделён от [удалённого управления](remote-control.md): сопряжению не нужны привязка к LAN или входящий порт, и ни один путь не переключается незаметно на другой.

## Выбор пути доступа {#access-paths}

| Путь | Чем вы управляете |
| --- | --- |
| Браузер на том же компьютере | Сохраните loopback-привязку; используйте напечатанный локальный URL. |
| LAN или VPN | Привяжите доступный интерфейс, ограничьте брандмауэр нужными клиентами и используйте доверенный HTTPS. VPN не настраивает слушатель CodeNomad за вас. |
| Перенаправление SSH | Оставьте серверную часть на loopback; перенаправьте её фактически напечатанный порт. Туннель защищает транспорт, но не заменяет аутентификацию CodeNomad. |
| Обратный прокси | Оставьте серверную часть на частном/loopback-интерфейсе; завершайте доверенный TLS на прокси, защитите участок до серверной части и поддерживайте длительные SSE и WebSockets, необходимые инструментам прямого доступа. |
| Удалённое управление | Сопрягите устройство с хоста; более узкая поверхность и время жизни описаны в [удалённом управлении](remote-control.md). |

Привязка не создаёт правила брандмауэра, перенаправление портов, DNS или VPN. Не публикуйте неаутентифицированный HTTP-слушатель в Интернет. Корень рабочего пространства — не защитная песочница; прочитайте [безопасность](security.md) перед открытием сервера.

## Включение прямого доступа {#enable-direct-access}

1. На хосте откройте **Настройки → Удалённый доступ** и раскройте **Прямой доступ (локальная сеть, для опытных)**.
2. В **Пароль сервера** выберите **Установить пароль** или **Изменить пароль**, введите **Новый пароль** и **Подтвердите пароль**, затем **Сохранить пароль**. Пароли, переданные при запуске, здесь менять нельзя; см. [безопасность](security.md).
3. Включите **Разрешить подключения с других IP** в **Режим прослушивания**. Прочитайте предупреждение о перезапуске и выберите **Перезапустить сейчас**, только когда готовы к временному прерыванию.
4. После перезапуска нажмите **Обновить** и проверьте **Доступные адреса**. Откройте доступный HTTPS-адрес на другом устройстве или выберите **Показать QR** на хосте и отсканируйте другим устройством, затем войдите.

Это меняет режим прямого прослушивания хоста, а не один проект и не удалённое управление. Раздел автоматически раскрывается, пока сервер слушает вне localhost. Если автоперезапуск недоступен, перезапустите CodeNomad вручную; отдельные развёртывания должны согласованно задавать `--host` при запуске. Для закрытия доступа выключите переключатель и перезапустите либо запустите CLI заново с loopback-привязкой. Это не отзывает сопряжённые устройства удалённого управления.

### Матрица привязки слушателей {#binding-matrix}

`--host` по умолчанию равен `127.0.0.1`; `localhost` нормализуется в этот адрес. Для включённых слушателей действуют следующие правила:

| Запуск/режим | Привязка HTTP | Привязка HTTPS |
| --- | --- | --- |
| Отдельный сервер, только HTTPS (по умолчанию) | Только частный loopback-слушатель | `--host` |
| Отдельный сервер, только HTTP | **`--host`**, включая LAN/подстановочный адрес | Не включён |
| Отдельный сервер, оба слушателя | `127.0.0.1` независимо от `--host` | `--host` |
| Нативная настольная серверная часть | HTTP остаётся на `127.0.0.1`, включая внутренний слушатель хоста | `--host`, когда HTTPS включён |

Конкретный LAN-адрес не обязан принимать loopback-подключения. `0.0.0.0` означает все IPv4-интерфейсы; `::` — подстановочный слушатель двух стеков. Используйте реальный доступный адрес в браузере, не подстановочный. Идентификаторы зоны IPv6 в `--host` не поддерживаются.

Для отдельного HTTPS-развёртывания задайте пароль через [начальную настройку](security.md), затем выполните:

```sh
codenomad --host 0.0.0.0 --https=true --http=false
```

Для HTTP только на loopback, например за локальным доверенным прокси:

```sh
codenomad --host 127.0.0.1 --https=false --http=true
```

Не рассчитывайте на порт 9898 или 9899: незаданные порты могут заменяться при занятости. Явный ненулевой `--https-port`, либо `--http-port` при включённом HTTP, фиксирует порт и даёт ошибку при невозможности привязки; `0` просит ОС назначить порт. Напечатанные **Local Connection URL** и **Remote Connection URL**, а также обновлённые **Доступные адреса** достоверны для данного запуска. См. полный [справочник CLI сервера](server.md).

## Политика администратора {#administrator-policy}

Администратор может зафиксировать адрес прослушивания: задайте `CODENOMAD_LOCKED_HOST` для всей системы равным адресу, который должен использовать сервер, и перезапустите CodeNomad. Он имеет приоритет над `--host`, `CLI_HOST` и **Разрешить подключения с других IP**: переключатель показывает результат, но не может его изменить. Укажите адрес интрасети, чтобы коллеги подключались через сеть компании, или `127.0.0.1`, чтобы оставить сервер на этом компьютере. Чтобы весь доступ оставался внутри сети компании, задайте также `CODENOMAD_REMOTE_CONTROL=disabled` ([удалённое управление](remote-control.md#administrator-policy)).

## Обновление {#upgrading}

После обновления войдите снова. Для псевдонима хоста, обратного прокси или отдельно размещённого интерфейса задайте в серверной части `CODENOMAD_ALLOWED_ORIGINS` с доверенными источниками интерфейса (схема, имя хоста и порт). Нативные LAN-клиенты должны передавать разрешённый заголовок `Origin` в запросах изменения данных. Его HTTPS-источники также позволяют хосту сопрягать устройства без туннеля; см. [Сопряжение по прямому HTTPS](remote-control.md#direct-https).

Используйте loopback-подключение для операций, доступных только с хоста: содержимое SideCar (`/sidecars/`) и WebSocket, управление удалённым доступом через туннель (`/api/remote-control/`), мост плагинов (`/api/opencode-plugin/`), удалённые прокси (`/api/remote-proxy/`), управление сохранёнными серверами (`/api/remote-servers/`), изменение пароля и начальная настройка токеном. Для этих операций требуется loopback даже после входа через прямой LAN-доступ. Исключение есть только для SideCars: настройка хоста **Открывать SideCars по HTTPS** открывает их содержимое и WebSocket браузерам, выполнившим вход через доверенный HTTPS-источник ([SideCars](browser-sidecars.md#register-sidecar)). Содержимое активных предпросмотров (`/previews/`) доступно через прямой LAN-доступ с действительным токеном доступа.

API регистрации `/api/sidecars` остаются доступны аутентифицированным прямым LAN-клиентам и сопряжённым устройствам. Веб-предпросмотры удалённого управления остаются доступны с токеном доступа, пока они включены на хосте.

## Настройка доверенного TLS {#tls}

### Собственный сертификат {#custom-certificates}

1. Получите сертификат, чьи Subject Alternative Names (SAN) покрывают реальное имя хоста или IP клиентов.
2. Передайте и `--tls-key <path>`, и `--tls-cert <path>` как PEM-файлы. Добавьте `--tls-ca <path>`, если нужна цепочка/набор CA.
3. Перезапустите CodeNomad и проверьте сертификат и напечатанный HTTPS-адрес с устройства клиента.

Файлы пользовательского сертификата читаются при запуске и никогда не перезаписываются CodeNomad. Вы отвечаете за продление и необходимый перезапуск для загрузки новых файлов. `--tlsSANs` настраивает генерируемые сертификаты; он не добавляет имена в переданный сертификат. Защищайте закрытые ключи и доверяйте только сертификатам с проверенной идентичностью хоста.

### Созданный локальный CA {#generated-certificates}

При включённом HTTPS без переданной пары ключ/сертификат CodeNomad создаёт локальный CA и серверный сертификат в базе конфигурации:

| Файл | Назначение |
| --- | --- |
| `tls/ca-cert.pem` | Открытый сертификат CA для безопасного распространения на администрируемые клиенты. |
| `tls/ca-key.pem` | Закрытый ключ CA; никогда не распространяйте. |
| `tls/server-cert.pem` | Серверный сертификат. |
| `tls/server-key.pem` | Закрытый ключ сервера; никогда не распространяйте. |

1. Добавьте все клиентские DNS-имена/IP через `--tlsSANs "host.example.test,192.0.2.10"`. Подстановочная привязка не обнаруживает все LAN-адреса для SAN.
2. Перезапустите серверную часть для создания/перепроверки сертификата.
3. Проверьте хост/CA по доверенному каналу, затем импортируйте **только сертификат CA** в хранилище доверия каждого нужного клиента/браузера. Альтернатива — публично доверенный сертификат или обратный TLS-прокси.

Созданный серверный сертификат действует 30 дней. При запуске сертификат обновляется, если до истечения осталось не более трёх дней, отсутствуют нужные SAN, сертификат не проходит проверки или отсутствует файл закрытого ключа. Созданный CA действует 365 дней и заменяется при истечении, непрохождении проверок сертификата или отсутствии файла закрытого ключа; замена также перевыпускает серверный сертификат. Клиенты должны доверять заменённому CA. Непрерывного продления внутри процесса нет: для длительных развёртываний организуйте осознанный перезапуск до истечения.

При предупреждении сертификата на клиенте остановитесь и проверьте имя хоста, SAN, хранилище доверия и срок. Не отключайте проверку и не превращайте обход предупреждений в процедуру развёртывания. Доверенный HTTPS также нужен удалённым функциям браузера, таким как [установка PWA и доступ к микрофону](mobile.md).

## Сохранение удалённого сервера {#saved-servers}Аутентифицированные удалённые клиенты могут использовать все сохранённые на хосте серверы и управлять ими; главная страница и **Настройки → Серверы** показывают действия, разрешённые возможностями хоста. Обычный HTTP в локальной сети отключает ввод новых паролей серверов и ссылок сопряжения: «Для ввода учётных данных используйте HTTPS или удалённое управление.» Подключения с сохранёнными учётными данными и добавление, изменение или удаление профилей без секретов остаются доступны.

Для адреса, доступного только через SSH, в разделе **Настройки → Серверы** выберите **Добавить сервер**, укажите **URL** и **Хост SSH (необязательно)**, затем нажмите **Сохранить**. Профиль сохраняется без подключения; соединение использует SSH-ретранслятор бэкенда.

Откройте **Настройки → Серверы**: вставьте адрес или ссылку сопряжения в **Адрес или ссылка сервера** либо нажмите Enter. Добавление сохраняет профиль на хосте, не открывая проект. **Изменить сервер** меняет **URL** или необязательное **Имя**; переименование с прежними URL и политикой TLS работает офлайн. **Удалить сохраненный сервер** запрашивает подтверждение, забывает соединение и сохраняет удаление; при ошибке сохранения профиль остаётся для повторной попытки. Другие соединения сохраняются.

**Пропустить проверку TLS** предлагается после ошибки сертификата для этого адреса; смена адреса сбрасывает согласие. Сопряжение всегда проверяет TLS. **Открыть** показывает проекты сервера.

**Хост SSH (необязательно)** сохраняет хост или псевдоним OpenSSH для ретранслятора бэкенда. Подсказки берутся из `~/.ssh/config` учётной записи локального бэкенда. Укажите адрес CodeNomad с точки зрения этого хоста (например, `https://127.0.0.1:9898` с фактическим портом) и нажмите **Сохранить**. Профили SSH используют ретранслятор. CodeNomad должен быть уже установлен и запущен на хосте. Локально необходимы OpenSSH, аутентификация по ключу и проверенный ключ хоста в `known_hosts`; аутентификация CodeNomad и проверка сертификатов HTTPS также действуют.

Только если `multiBackend` задан как `false`, используйте отдельные окна настольного приложения:

1. **Настройки → Удалённый доступ → Серверы** → **Подключить сервер CodeNomad**.
2. В **Подключиться к серверу** введите **Имя сервера** и **URL сервера**, используя доверенный HTTPS-origin. Оставьте **Пропустить проверку TLS для самоподписанных сертификатов.** выключенным; вместо этого настройте доверие.
3. Нажмите **Сохранить** для закладки или **Подключиться** для сохранения и открытия. Войдите на этом сервере.


Если закрыть последнее локальное окно, пока удалённые окна остаются открытыми, его вкладки сохраняются: **Окно → Новое окно** в удалённом окне или повторный запуск CodeNomad открывает его снова.

Для удалённого управления вместо этого вставьте свежую ссылку сопряжения в **URL сервера**. Закладка хранит только origin туннеля, никогда одноразовый код; повторное сопряжение после потери cookie устройства описано в [удалённом управлении](remote-control.md).

## Открыть удалённый проект во вкладке {#remote-project-tabs}

На главной странице или в новой вкладке выберите **Обзор**, затем сервер. Чтобы сохранить сервер, вставьте адрес или ссылку сопряжения. Войдите, если потребуется. Щёлкните папку для перехода в неё; нажмите Enter в поле пути или выберите **Открыть**, чтобы открыть её. Кнопка возврата открывает список серверов.

Локальные и удалённые проекты открываются в одном окне. Во время обзора в разделе **Недавние вкладки** видны проекты выбранного сервера. В общем списке у проектов, открытых здесь, показаны значок и имя сервера. Если восстановленная вкладка ждёт сервер, повторите попытку или подключитесь в самой вкладке. Черновики сохраняются.

### `--connect-server` {#connect-server}

Эта команда открывает отдельное удалённое окно при любом значении `multiBackend`. Чтобы открыть сохранённый сервер прямо из командной строки, запустите настольное приложение с `--connect-server <name>` (или `--connect-server=<name>`), указав сохранённое имя сервера или его URL `https://`. CodeNomad открывает только удалённое окно, с теми же проверками и входом, что и **Подключиться**; если CodeNomad уже запущен, сервер открывает его текущее окно, а не новое. URL, не совпадающий ни с одним сохранённым сервером, сохраняется под именем своего хоста. Значения запуска никогда не содержат учётных данных: URL с именем пользователя, паролем или кодом сопряжения отклоняется. В Windows сборка Tauri не запускается, если аргумент запуска содержит `|`; используйте URL сервера или переименуйте сервер.
