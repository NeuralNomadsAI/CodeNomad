# Устранение неполадок

Для восстановления сначала проверьте владельца неудачной операции: браузер, серверная часть CodeNomad, служба OpenCode или провайдер. Потерянный ответ не доказывает сбой изменения; перечитайте текущее состояние перед повтором.

## Проблемы запуска настольного приложения {#desktop-launch}

### Карантин macOS {#macos-quarantine}

Для релиза, загруженного из официального репозитория и проверенного вами, macOS может сообщить о повреждении приложения из-за карантина/проверок нотарификации.

1. Проверьте источник загрузки и путь установленного приложения.
2. Если приложение установлено по следующему пути, удалите атрибут карантина:

```sh
xattr -dr com.apple.quarantine /Applications/CodeNomad.app
```

3. Запустите снова; на Intel Mac также проверьте **System Settings → Privacy & Security** для решения первого запуска.

Это меняет атрибут карантина macOS у данного приложения. Не исправляет повреждённую загрузку и не делает неизвестный исполняемый файл доверенным.

### Графика Linux и FUSE {#linux-graphics}

На немедленно закрывающийся Tauri AppImage в Wayland/NVIDIA может влиять рендерер DMA-BUF/GBM WebKitGTK. Запустите загруженный AppImage с целевым переопределением окружения:

```sh
WEBKIT_DISABLE_DMABUF_RENDERER=1 ./CodeNomad-Tauri-linux-x64-<version>.AppImage
```

Electron использует Chromium и служит альтернативой на том же хосте. Если AppImage не монтируется из-за отсутствия FUSE, используйте `--appimage-extract-and-run`; см. [установку Linux](install.md#linux-install). Эти исправления не требуют отключения песочницы Electron.

## Доступность Git и рабочего пространства {#git-and-workspaces}

1. Проверьте Git в `PATH` учётной записи серверной части, не только оболочки агента.
2. При отсутствии установите Git на этом хосте/аккаунте, затем перезапустите серверную часть CodeNomad для наследования обновлённого окружения.
3. Снова откройте/обновите рабочее пространство и проверьте статус репозитория.

Разговоры в пределах каталога остаются доступны без Git; worktree и управление Git — нет. В Windows Git только внутри WSL недостаточен для серверной части Windows. Известная папка без репозитория может показывать **Инициализировать Git**; отсутствие исполняемого файла Git — другое состояние, которое надо устранить сначала. См. [требования](install.md#requirements) и [файлы](files.md).

Если принадлежность worktree или размещение разговора нельзя проверить, явно откройте физическую папку вместо произвольных путей или правок нативного хранилища. После неопределённого перемещения/удаления обновите, чтобы увидеть реальное размещение. Принудительное удаление worktree может уничтожить незакоммиченные файлы; не используйте как ремонт соединения.

## Среда OpenCode и WSL {#opencode-runtime}

1. Откройте **Настройки → OpenCode** и проверьте выбранный исполняемый файл, установленную версию и статус службы.
2. При отсутствии нужной среды используйте поддерживаемую установку/обновление. Текущий минимум: **2.0.27**; рекомендуемая/проверенная: **2.0.29**.
3. Если установленный CLI отличается от службы, явно решите, перезапускать ли общую службу.

**Перезапустить службу OpenCode** находится в **Устранение неполадок** и требует подтверждения. Прерывает активную работу всех клиентов, но сохраняет историю сессий. Перезагрузка конфигурации — отдельное действие: сохраняет процесс, но пересоздаёт загруженные Location и отменяет ожидающие вопросы/разрешения. Ни одно не является безобидным обновлением.

Для WSL проверьте нужный дистрибутив и перенаправление localhost Windows. Жизненный цикл службы работает внутри Linux; CodeNomad всё равно должен достигать её loopback-эндпоинта из Windows. Никогда не правьте регистрацию/базу службы и не посылайте сигналы угаданным PID Linux из Windows.

Пользовательская/новая версия может быть непроверенной, не будучи несовместимой. Прочитайте реальную ошибку контракта перед сменой версии. При сбое синхронизации окружения сессии исправьте окружение/подключение хоста: CodeNomad не отправит запрос без синхронизации. См. [OpenCode](opencode.md).

## Вход, TLS и прямое подключение {#login-and-tls}

| Симптом | Безопасная проверка и восстановление |
| --- | --- |
| **Войдите в CodeNomad снова** | Оставьте страницу открытой, введите имя/пароль сервера и нажмите **Войти**. Восстановление переподключается на месте для сохранения черновиков; не повторяет неудачное действие. |
| Сервер недоступен | Проверьте работу серверной части и используйте напечатанный адрес/реальный порт. Одна проверка недоступности не доказывает истечение входа. |
| Провайдер отклоняет аутентификацию | Исправьте вход провайдера через владельца; не меняйте пароль сервера CodeNomad для исправления OAuth провайдера. |
| Ошибка имени/доверия сертификата | Сверьте фактическое имя/IP с SAN и установите нужное доверие CA или действующий сертификат. Не отключайте проверку TLS. |
| Прямое подключение отклонено | Проверьте фактическую привязку HTTP/HTTPS, брандмауэр и маршрутизацию. HTTP настольного/двойного режима остаётся loopback; отдельный HTTP-only привязывается иначе. |

После восстановления аутентификации проверьте состояние перед ручным повтором неопределённого изменения. Пароли, передаваемые при запуске, нужно указывать при каждом запуске серверной части; пароль, сохранённый в настройках, сохраняется между запусками. См. [безопасность](security.md), [TLS/правила привязки](remote-access.md) и [справочник сервера](server.md).

## Сопряжение удалённого управления {#pairing}

1. На хосте откройте **Настройки → Удалённый доступ** и проверьте работу удалённого управления.
2. Создайте свежую ссылку сопряжения и откройте на нужном устройстве до истечения.
3. Если клиент показывает **Повторно сопрягите это устройство**, выполните сопряжение с хоста, затем нажмите **Проверить соединение** на клиенте.

Ссылки одноразовые и краткосрочные; пароль прямого доступа их не заменяет. Отозванные или истёкшие из-за бездействия данные требуют нового сопряжения. Закрытие последнего настольного окна останавливает серверную часть и удалённое управление; включённая служба возобновляется при следующем запуске приложения. Недоступные поверхности хоста и отзыв см. в [удалённом управлении](remote-control.md).

## Состояние провайдера, плагинов и расширений {#providers-and-addons}

| Проблема | Восстановление |
| --- | --- |
| Неверный аккаунт/квота провайдера | Проверьте выбранный нативный аккаунт и **Использование**. Показ квоты — не сумма токенов/стоимости. Обновите после неопределённой смены аккаунта; выбор может влиять на другие клиенты службы. |
| Истёкший внешний OAuth | Войдите заново через OpenCode, Claude Code или владельца данных. CodeNomad не обменивает их токены обновления. |
| Автоматическая ротация не переключает | Проверьте включение и пригодность, а также реальное исчерпание текущего аккаунта. Это политика до допуска, не переключение при сбое во время выполнения и не повтор запросов. |
| Устаревшее состояние плагина | Используйте **Обновить управление плагинами** и проверьте область/цель подсказки; активация выполнения может ждать нативного обновления. Не переключайте многократно неопределённую запись. |
| Установленное расширение отсутствует | Проверьте единственный флажок активации в настройке панели. Установка/замена оставляет отключённым до явной активации и необходимого согласия. |
| Ресурсы расширения запрещены | Подтвердите согласие API 2 на чтение ресурсов текущей смонтированной сессии. Установка расширения не разрешает чтение произвольных файлов/истории. |

См. [провайдеры](providers.md), [интеграции](integrations.md) и [расширения](extensions.md).

## История, ожидающие запросы и очистка {#history-and-requests}

Поиск всей истории не ограничен загруженными строками переписки. Фильтр скрывает контент без удаления; раздел [История](history.md) различает поиск, компактацию, техническую очистку и удаление.

При неполном восстановлении ожидающих запросов CodeNomad сохраняет известные очереди и черновики ответов, а не считает отсутствие охвата пустой очередью. После двух последовательных неполных восстановлений предупреждает обычным уведомлением; временные сбои повторяются проверкой живости. Отсрочка из-за компактации не означает отмену запроса. Сохраните черновик, проверьте подключение службы и текущее состояние запроса перед повторным ответом.

Для отменённой или частичной очистки прочитайте прогресс/квитанции перед новым удалением. Отмена не откатывает уже отправленный пакет. Не чините историю редактированием нативной базы. При неопределённости миссии используйте **Проверить статус**/обновление вместо создания ещё одного запуска или автоматического повтора работы; [миссии](missions.md) объясняют ограничения перезапуска и времени жизни.

## Логи и безопасная диагностика {#diagnostics}

1. Откройте **Информация об экземпляре** для проверки статуса; **Показать логи сервера** предоставляет доступный вывод.
2. В **Настройки → OpenCode** выбирайте нужную **Подробность логов** только при необходимости деталей. Для отдельного CodeNomad используйте [параметры логирования CLI сервера](server.md).
3. Откройте **Настройки → Информация → Диагностика** и используйте **Сообщить об ошибке**, **Скопировать в буфер обмена** или **Скачать .txt**.

Подробные логи могут раскрыть пути, вывод и данные приложения. Скройте учётные данные, ссылки сопряжения, сетевые адреса, частные пути и контент разговоров перед передачей логов/снимков. Полный отчёт диагностики включает пути/адреса; предзаполненная форма ошибки намеренно исключает их. См. [поддержку](support.md#report-a-bug).
