# नेटिभ एकीकरण

तलका स्थापना, एप्लिकेसन जडान र कन्फिगरेसन नियन्त्रण साझा स्थानीय OpenCode परियोजनाका लागि हुन्। स्पष्ट सर्भरमा प्लगइन सूची र एकीकरण स्थिति पढ्न-मात्र रहन्छ; एप्लिकेसन जडान र स्थापना त्यहाँ उपलब्ध हुँदैनन्।

CodeNomad ले OpenCode का नेटिभ MCP जडान, plugin सक्रियता, skill र custom command उपलब्ध गराउँछ। यी execution host मा चल्छन्। यी sandbox भएका [प्यानल विस्तार](extensions.md) र [SideCars](browser-sidecars.md) भन्दा फरक हुन्।

## सही नियन्त्रण रोज्नुहोस् {#integration-scopes}

| एकीकरण | कहाँ गर्ने | नियन्त्रणले बदल्ने कुरा |
| --- | --- | --- |
| MCP server | **स्थिति → MCP सर्भरहरू** | देखाइएको Location मा नेटिभ जडान; server स्थापना गर्दैन। |
| नेटिभ plugin | **स्थिति → प्लगइनहरू** | package घोषणा थप्छ वा हटाउँछ, र स्थायी **विश्वव्यापी** वा **परियोजना** सक्रियता नियम राख्छ; package plugin का लागि त्यो package को स्पष्ट जाँच वा अपडेट। |
| Skill | कम्पोजर `@` menu | कुराकानीको Location मा अर्को prompt को स्पष्ट संलग्नक। |
| Custom command | कम्पोजर `/` menu | त्यस Location का लागि OpenCode ले उपलब्ध गराएको command चलाउँछ। |

पहिले OpenCode को समर्थित कन्फिगरेसन र CLI बाट एकीकरण कन्फिगर/स्थापना गर्नुहोस्। package स्थापना, स्रोत घोषणा, नियम सक्षम, सेवा जडान र उपकरण उपलब्ध गराउनु फरक चरण हुन्। नेटिभ integration सँग OpenCode अनुमतिअन्तर्गत आफ्ना host process का अधिकार हुन्छन्; ती sandbox भएका HTML प्यानल होइनन्।

## MCP जोड्नुहोस् वा छुट्याउनुहोस् {#mcp}

1. [OpenCode MCP दस्तावेज](https://opencode.ai/v2/docs/mcp-servers/) प्रयोग गरी execution host मा MCP server कन्फिगर गर्नुहोस्।
2. परियोजनाका लागि **स्थिति → MCP सर्भरहरू** खोल्नुहोस्।
3. server छेउको switch बाट connect/disconnect गर्नुहोस्। जडान सूचक स्थिर हुन पर्खनुहोस्।

switch ले देखाइएको Location को नेटिभ connection API बोलाउँछ, उपकरण-स्थानीय installer वा प्रति-विन्डो दृश्यता प्राथमिकता होइन। त्यही Location प्रयोग गर्ने अन्य क्लाइन्टले परिवर्तन देख्न सक्छन्। disconnect ले server घोषणा हटाउँदैन वा executable uninstall गर्दैन।

server नदेखिए सक्रिय Location र नेटिभ कन्फिगरेसन जाँच्नुहोस्। जडान असफल भए server कन्फिगरेसन, आवश्यक वातावरण र नेटिभ authentication flow जाँच्नुहोस्; switch ले OAuth पूरा गर्छ नमान्नुहोस्। reconnect पछि स्थिति जाँच्नुहोस्। आवश्यक हुँदा मात्र [OpenCode सेटअप](opencode.md) का अवरोध बुझेर स्पष्ट configuration reload प्रयोग गर्नुहोस्।

## Global वा Project दायरामा plugin सक्रियता {#plugins}

1. [plugin थप्नुहोस्](#plugin-sources) वा OpenCode कन्फिगरेसनमा घोषणा गर्नुहोस्; त्यसपछि **स्थिति → प्लगइनहरू** खोल्नुहोस्।
2. स्रोत, runtime failure र configuration-target विवरण हेर्न नाममा hover/focus गर्नुहोस्।
3. **विश्वव्यापी** वा **परियोजना** सचेत रूपमा toggle गर्नुहोस्। write पर्खनुहोस् र अवस्था अस्पष्ट भए **प्लगइन नियन्त्रण ताजा गर्नुहोस्** प्रयोग गर्नुहोस्।
4. package बाट स्थापित plugin का लागि नामछेउको icon प्रयोग गर्नुहोस्। यसको menu ले ठ्याक्कै कार्य नाम दिन्छ: package को **… का अद्यावधिक जाँच्नुहोस्**, वा नयाँ संस्करण भेटिएपछि **… अद्यावधिक गर्नुहोस्**।

Global ले जोडिएको daemon को पत्ता लागेको global कन्फिगरेसन लक्षित गर्छ। Project ले सक्रिय Location भित्रको कन्फिगरेसन लक्षित गर्छ, inherited ancestor फाइल होइन। पछिको Project नियमले Global override गर्न सक्छ; Global switch ले अन्तिम Project अवस्था भएको अभिनय नगरी Global नियम नै देखाउँछ। Project नियम नभए resolved Global अवस्था inherit हुन्छ।

यी switch ले स्रोत घोषणा र असम्बन्धित कन्फिगरेसन जोगाउँदै ठ्याक्कै सक्रियता नियम थप्छन्। plugin विकल्प सम्पादन, package स्थापना वा फाइल हटाइ गर्दैनन्। built-in OpenCode plugin user सक्रियता switch मा दिइँदैनन्। लक्ष्य Global बाट सुरक्षित अलग गर्न नसके वा सक्रिय Location बाहिर जाने भए Project अक्षम हुन्छ।

package अपडेटले, यसको tooltip ले भनेझैं, त्यो package प्रयोग गर्ने हरेक Location का लागि OpenCode को साझा cache मा त्यो package बदल्छ; यसले सक्रियता नियम बदल्दैन, OpenCode पुनः सुरु गर्दैन वा कन्फिगरेसन reload गर्दैन। स्थानीय, built-in र SDK-प्रदत्त plugin को package कार्य हुँदैन। plugin ID बताउनुअघि नै असफल हुने package यसको package नामले सूचीमा रहन्छ, tooltip मा असफलता र check/update कार्यसहित, तर सक्रियता switch बिना। असफल check वा update बताइन्छ र कहिल्यै स्वतः पुनःप्रयास हुँदैन।

सतह लुकेको बेला अन्तिम snapshot राख्छ र देखाउँदा, नेटिभ परिवर्तन/reconnect र स्पष्ट refresh मा पुनःजाँच्छ। सुरक्षित नियम र live runtime उपलब्धता छोटो समय फरक हुन सक्छन्। plugin अनुपलब्ध रहिरहे **OpenCode कन्फिगरेसन पुनः लोड गर्नुहोस्** रोज्नुअघि tooltip र नेटिभ कन्फिगरेसन जाँच्नुहोस्; त्यसले यो plugin मात्र होइन सबै loaded Location प्रभावित गर्छ। बिग्रिएको कन्फिगरेसन वा समकालीन सम्पादन चुपचाप overwrite हुँदैन: समाधान, refresh र स्पष्ट retry गर्नुहोस्।

## plugin थप्नुहोस् वा हटाउनुहोस् {#plugin-sources}

1. **स्थिति → प्लगइनहरू** मा **+** खोलेर **प्लगइन थप्नुहोस्…** छान्नुहोस्।
2. npm रजिस्ट्रीको package (`name`, `name@1.2.3`, `@scope/name@^1`) वा Git रिपोजिटरी (`github:owner/repo`, `git+https://…`) लेख्नुहोस्।
3. plugin यो परियोजनामा मात्र चल्नुपर्ने नभए **विश्वव्यापी** राख्नुहोस्, अनि **थप्नुहोस्** छान्नुहोस्।
4. OpenCode ले रिपोर्ट नगरेसम्म नयाँ पङ्क्तिमा **स्थापना हुँदैछ** देखिन्छ। त्यसपछि यो switch सहितको सामान्य plugin पङ्क्ति, वा असफल पङ्क्ति बन्छ।

plugin हटाउन, यसको नाम छेउको मेनु खोलेर **विश्वव्यापी बाट हटाउनुहोस्** वा **परियोजना बाट हटाउनुहोस्** छान्नुहोस्। त्यस दायराको कन्फिगरेसन फाइलको घोषणा मात्र मेटिन्छ; यसका **विश्वव्यापी**/**परियोजना** सक्रियता नियमहरू नियमकै रूपमा रहन्छन्, र OpenCode को package cache यथावत् रहन्छ।

plugin को कोड OpenCode भित्र तपाईंको अनुमतिसहित चल्छ। त्यो फोल्डर OpenCode मा खोल्दा हरेक पटक **परियोजना** प्रविष्टि चल्छ, र OpenCode डेस्कटप एपका भाग भएका package ले ती भाग **विश्वव्यापी** बाट मात्र लोड गर्छन्; यस्तो package अन्यत्र घोषणा गरिएको छ भने tooltip ले बताउँछ। स्थानीय पथ, कन्फिगरेसन चर र plugin ID यहाँ अस्वीकार हुन्छन्: स्थानीय plugin कन्फिगरेसन फाइलमा घोषणा गर्नुहोस्। यो Location मा लागू हुने कन्फिगरेसनमा पहिल्यै घोषणा गरिएको package, संस्करण, दायरा वा रूप जे भए पनि, अस्वीकार हुन्छ।

समीक्षा गरिएको catalog को OpenCode एकीकरण (जस्तै Blender एकीकरण) स्थापना हुनुअघि नै चिनिन्छ। कुनै एपभित्र भाग भएको एकीकरण **विश्वव्यापी** मा मात्र थपिन्छ: त्यसका लागि **परियोजना** अस्वीकार हुन्छ। यसको registry package र Git build एउटै package मानिन्छन्, त्यसैले पहिल्यै घोषणा वा लोड भएको एकीकरणको दोस्रो रूप थप्दा अस्वीकार हुन्छ।

plugin को नाममा pointer वा focus राख्दा यसको संस्करण, **अपडेट उपलब्ध छ**, र असफल स्थापनामा OpenCode लगको सन्दर्भसहित त्रुटि देखिन्छ। दुई मिनेटसम्म OpenCode ले रिपोर्ट नगरेको पङ्क्तिमा **पुष्टि भएको छैन** र **प्लगइन नियन्त्रण ताजा गर्नुहोस्** कार्य देखिन्छ: plugin निष्क्रिय हुन सक्छ, वा यसको स्थापना कहिल्यै पूरा भएन ([समस्या समाधान](troubleshooting.md#providers-and-addons) हेर्नुहोस्)।

## skill जोड्नुहोस् {#skills}

1. कम्पोजरमा `@` टाइप गरी Location का उपलब्ध skill खोजेर एउटा चयन गर्नुहोस्।
2. फाइल/agent छेउको हटाउन मिल्ने संलग्नक जाँच्नुहोस्; नचाहिए पठाउनुअघि हटाउनुहोस्।
3. prompt पठाउनुहोस्। पठाइएको सन्देशसँग skill label रहन्छन्।

चयनले नेटिभ skill ID जोडेर `@query` token हटाउँछ; देखिने मस्यौदामा निर्देशन paste गर्दैन। पठाउँदा कम्पोजर चयन खाली हुन्छ, त्यस सन्देशसँग OpenCode ले सुरक्षित गरेका निर्देशन होइनन्। संलग्नक हटाउँदा पहिलेको पठाइ undo हुँदैन।

skill उपलब्धता कुराकानीको Location बाट आउँछ, global CodeNomad catalogue बाट होइन। सूची लोड नभए picker बन्द गरी फेरि खोलेर retry गर्नुहोस्; खाली भए native discovery/configuration जाँच्नुहोस्। [OpenCode skill दस्तावेज](https://opencode.ai/v2/docs/skills/) र [कुराकानी](conversations.md) हेर्नुहोस्।

## custom command चलाउनुहोस् {#commands}

1. कम्पोजरमा `/` टाइप गरी उपलब्ध नेटिभ command रोज्नुहोस्।
2. argument दिएर command अनुसार बुझाउनुअघि **एजेन्ट**, **मोडेल** र **सोचाइ** जाँच्नुहोस्।
3. acknowledgement अस्पष्ट भए बारम्बार पठाउनुको सट्टा नतिजाको कुराकानी जाँच्नुहोस्।

command सक्रिय Location का लागि OpenCode बाट पत्ता लाग्छन्। आफ्नै नेटिभ परिभाषाले execution व्यवहार रोज्न सक्छ; menu package installer वा असीमित configuration editor होइन। CodeNomad ले native custom-command पठाउनुअघि प्रोफाइल सत्र वातावरण लागू गर्छ; environment update असफल भए पठाइ रोकिन्छ। `/btw` CodeNomad को छुट्टै क्षणिक प्रश्न flow हो, सामान्य custom command होइन।

command परिभाषा र native configuration inheritance का लागि [OpenCode command दस्तावेज](https://opencode.ai/v2/docs/commands/) प्रयोग गर्नुहोस्। कन्फिगरेसन परिवर्तनपछि पहिले सम्बन्धित सतह refresh/reopen गर्नुहोस्; runtime लाई अझै चाहिँदा मात्र स्पष्ट configuration reload गर्नुहोस्। प्रदर्शन refresh गर्नकै लागि सम्भवतः admitted command replay नगर्नुहोस्।
## स्थितिमा एकीकरण खण्डहरू {#integration-sections}

**स्थिति → प्लगइनहरू** को **+** मा **एकीकरण थप्नुहोस्…** वा **प्लगइन थप्नुहोस्…** छान्न सकिन्छ। एकीकरण चयनमा समीक्षा गरिएको सूचीका स्थापना नभएका प्रविष्टि देखिन्छन्। दायरा र **स्थापना गर्नुहोस्** छान्नुहोस्: CodeNomad ले छानिएको सूची ID स्थापना गर्छ। नेटिभ एकीकरण **विश्वव्यापी मात्र** हुन्छन्। **सूची उपलब्ध छैन** मा **ताजा गर्नुहोस्** हुन्छ; **{date} को सूची** ले पुरानो भएको अन्तिम मान्य सूची जनाउँछ।

घोषणा वा लोड भएको/असफल प्लगइन भएको प्रत्येक पहिचान गरिएको एकीकरणको आफ्नै **स्थिति** खण्ड हुन्छ, निष्क्रिय वा स्थापना हुँदै गर्दा पनि। अस्पष्ट स्रोतले प्लगइनहरूमा **मापदण्ड अनुरूप छैन** देखाउँछ। प्रत्येक एकीकरणको प्लगइन पङ्क्ति अद्यावधिक, हटाउने र ताजा गर्ने कार्यसहित रहन्छ। संस्करण र प्लगइन नियन्त्रण खण्डको मुख्य भागमा हेर्न खण्ड खोल्नुहोस्; नाम र अवस्था शीर्षकमा **कागजात** र **i** छेउमा देखिइरहन्छन्। **i** पपओभरले मागअनुसार विवरण दिन्छ: Enter/Space ले खोल्छ र Escape ले बन्द गर्छ।

स्थितिको अनुकूलनबाट सबै स्थिति खण्ड लुकाउन र तानेर वा माथि/तल कुञ्जीले क्रम बदल्न सकिन्छ। दृश्यता र क्रम पुनः लोड हुँदा र एकीकरण अस्थायी रूपमा नहुँदा पनि सुरक्षित रहन्छन्। फोकस भएको खण्ड हराए फोकस प्लगइनहरूमा फर्कन्छ, वा प्लगइनहरू लुकेको भए अर्को देखिने स्थिति खण्डमा जान्छ।

सूचीबाट स्थापना, अनुप्रयोग भागको स्थापना/अद्यावधिक, जोड्ने र हटाउने कार्यमा पुष्टि चाहिन्छ। सुरुको फोकस **रद्द गर्नुहोस्** मा हुन्छ; पुष्टि कार्य 600 मिलिसेकेन्डपछि उपलब्ध हुन्छ। सक्रियता र प्लगइन अद्यावधिक सीधै चल्छन्।

## खुला अनुप्रयोग जोड्नुहोस् {#application-attachment}

अनुप्रयोगको एकीकरणबाट कागजात प्रस्ताव गर्नुहोस्, **स्थिति → एकीकरण → कुराकानी** खोल्नुहोस् र **जोड्नुहोस्…** छान्नुहोस्। यही खण्डले देखाइएको कुराकानीको जडान नियन्त्रण गर्छ। अनुप्रयोग र कागजात छान्नुहोस्, लक्षित कुराकानी र परिवर्तन चेतावनी जाँचेर **जोड्नुहोस्** बाट पुष्टि गर्नुहोस्। टाढाको जडानमा पनि अनुप्रयोग OpenCode को मेसिनमा चल्छ। WSL सहित असमर्थित होस्टमा **i** बाट मद्दत पाइन्छ।

**कुराकानी** पङ्क्तिले देखाइएको कुराकानीको जडान पढ्छ। **जडान अज्ञात छ** मा **ताजा गर्नुहोस्** हुन्छ। ताजा आधिकारिक पठनले जडान पुष्टि गर्दा **छुट्याउनुहोस्** ले **जोड्नुहोस्…** लाई प्रतिस्थापन गर्छ। एक क्लिकले थप पुष्टि बिना यही कुराकानी मात्र छुट्याउँछ; अनुप्रयोग खुला र यसको भाग स्थापित रहन्छ, अन्य कुराकानीका जडान रहन्छन्। नेटिभ परिवर्तन र पुनः जडानले अवस्था ताजा गर्छन्।

स्वीकार गरिएको कार्यको नतिजा वा त्रुटि लक्षित कुराकानी देखिइरहँदा रहन्छ; नेभिगेसनले रसिद बन्द गर्छ। हालको जडान आधिकारिक पठनअनुसार हुन्छ। उत्तर हराउँदा, समय सकिँदा वा सम्पर्क टुट्दा **अनिश्चित अवस्था** ले वास्तविक अवस्था पढ्न **ताजा गर्नुहोस्** दिन्छ। प्रदर्शन ताजा गर्न अनुरोध कहिल्यै नदोहोर्‍याउनुहोस्।

चयनमा खुला अनुप्रयोगहरू स्पष्ट रूपमा पढेपछि, सुरक्षित Q8 मेटाडेटाले उही एकीकरण र प्रमाणित कागजात लेबलका लागि चयन वा **कुराकानी** पङ्क्तिमा **फेरि जोड्नुहोस्** सुझाव दिन सक्छ, जबसम्म परियोजना, कुराकानी र जडान पुस्ता उही रहन्छन्। फेरि जोड्न स्पष्ट पुष्टि चाहिन्छ; नेभिगेसन वा डेटा अमान्य हुँदा सुझाव हट्छ। हालको जडानको आधिकारिक अवस्था एकीकरणको सत्रअनुसारको पठनबाट आउँछ।

एकीकरण खण्ड वा यसको प्लगइन पङ्क्तिबाट हटाउँदा उही घोषणा र दायरा पुष्टि प्रयोग हुन्छ। कुराकानी गणना वा स्वतः जडान छुट्याउने कामबिना हटाइन्छ।

हटाउँदा प्लगइन र ठ्याक्कै दायरा भएको चेतावनी खुल्छ। **रद्द गर्नुहोस्** मा फोकस हुन्छ; **विश्वव्यापी/परियोजनाबाट हटाउनुहोस्** 600 मिलिसेकेन्डपछि उपलब्ध हुन्छ र स्पष्ट कार्य चाहिन्छ। यसले प्रयोग गर्ने कुराकानीहरूको उपलब्धता र जडान रोक्न सक्छ; विश्वव्यापी दायराले अन्य परियोजनालाई पनि असर गर्न सक्छ। पठाउनुअघि रद्द, म्याद समाप्त वा नेभिगेसन गर्दा केही बदलिँदैन। पुष्टि गरिएको घोषणा मात्र हट्छ; नियम, क्यास, अनुप्रयोगका फाइल र सुरक्षित जडान सङ्केत रहन्छन्। कन्फिगरेसन बदलिए पुनः चयन र पुष्टि चाहिन्छ। सफलताले घोषणा हटेको जनाउँछ; रनटाइम अवस्था OpenCode को पुनः लोडसँग बदलिन्छ। उत्तर हराए फेरि प्रयास गर्नुअघि प्लगइन ताजा गरी वास्तविक कन्फिगरेसन हेर्नुहोस्। पुनः स्थापनाले उपलब्धता फर्काउन सक्छ; पुनः लोड वा जडान चाहिन सक्छ र रोकिएका कार्य फेरि सुरु नहुन सक्छन्।

## अनुप्रयोग एकीकरण स्थापना वा अद्यावधिक गर्नुहोस् {#application-installation}

**स्थिति → एकीकरण → अनुप्रयोग** मा ताजा अवस्थाले दिएमा **अनुप्रयोगमा स्थापना गर्नुहोस्…** वा **अनुप्रयोग अद्यावधिक गर्नुहोस्…** छान्नुहोस्। कुराकानी वा प्रस्ताव गरिएको कागजातबिना पनि उपलब्ध हुन्छ। अनुप्रयोग बन्द छ भने यसको भाग जाँच्न खोल्नुहोस्; **i** मा मेसिन र पूर्वसर्तका विवरण हुन्छन्।

पुष्टिमा अनुप्रयोग र स्थापनाकर्ता उपलब्ध गराउने **एकीकरण प्याकेजको संस्करण** देखिन्छ। दुवै र मेसिनसम्बन्धी चेतावनी जाँच्नुहोस्: स्थापना OpenCode चल्ने मेसिनमा हुन्छ, जुन टाढाको पनि हुन सक्छ। सुरुको फोकस **रद्द गर्नुहोस्** मा हुन्छ। अगाडि बढ्न स्पष्ट रूपमा पुष्टि गर्नुहोस्। पुष्टि गर्नुअघि परियोजना, Location वा कुराकानी बदल्दा, पुनः जडान हुँदा वा सम्बन्धित नेटिभ परिवर्तन आउँदा बाँकी स्वीकृति रद्द हुन्छ; ताजा विवरण जाँच्न कार्य फेरि खोल्नुहोस्।

खुला अनुप्रयोग मिल्दो देखिए पनि WSL मा अनुप्रयोगभित्र स्थापना सधैँ अस्वीकार हुन्छ। समर्थित मेसिनमा अनुप्रयोग खोल्नुहोस्।

नतिजाले एकीकरण स्थापना भएको, अद्यावधिक भएको, पहिले नै अद्यावधिक रहेको, अस्वीकार भएको वा असफल भएको जनाउँछ। स्थापना वा अद्यावधिकपछि अनुप्रयोग खोलेर यसको एकीकरण जाँच्नुहोस्; [खुला अनुप्रयोग जोड्नुहोस्](#application-attachment) बाट छुट्टै कुराकानी जोड्नुहोस्। स्थापनाको सफलताले स्थापना अनुरोधको नतिजा जनाउँछ; चलिरहेको अनुप्रयोगको उपलब्धता यसको स्थितिबाट थाहा हुन्छ।

अनुरोध स्वतः दोहोरिँदैनन्। अस्वीकार वा असफल भएपछि नयाँ कार्य छान्नुअघि अनुप्रयोग जाँच्नुहोस्। त्रुटिका कारण नतिजा अनिश्चित भए सो अनुरोध नदोहोर्‍याउनुहोस्: पहिले अनुप्रयोग जाँच्नुहोस्, त्यसपछि आवश्यक भए नयाँ कार्य र पुष्टि सुरु गर्नुहोस्।
