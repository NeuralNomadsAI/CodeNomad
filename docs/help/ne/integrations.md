# नेटिभ एकीकरण

CodeNomad ले OpenCode का नेटिभ MCP जडान, plugin सक्रियता, skill र custom command उपलब्ध गराउँछ। यी execution host मा चल्छन्। यी sandbox भएका [प्यानल विस्तार](extensions.md) र [SideCars](browser-sidecars.md) भन्दा फरक हुन्।

## सही नियन्त्रण रोज्नुहोस् {#integration-scopes}

| एकीकरण | कहाँ गर्ने | नियन्त्रणले बदल्ने कुरा |
| --- | --- | --- |
| MCP server | **स्थिति → MCP सर्भरहरू** | देखाइएको Location मा नेटिभ जडान; server स्थापना गर्दैन। |
| नेटिभ plugin | **स्थिति → प्लगइनहरू** | package घोषणा थप्छ वा हटाउँछ, र स्थायी **विश्वव्यापी** वा **परियोजना** सक्रियता नियम राख्छ; package plugin का लागि त्यो package को स्पष्ट जाँच वा अपडेट। |
| Skill | कम्पोजर `@` menu | कुराकानीको Location मा अर्को prompt को स्पष्ट संलग्नक। |
| Custom command | कम्पोजर `/` menu | त्यस Location का लागि OpenCode ले उपलब्ध गराएको command चलाउँछ। |

नेटिभ integration सँग OpenCode अनुमतिअन्तर्गत आफ्ना host process का अधिकार हुन्छन्; ती sandbox भएका HTML प्यानल होइनन्।

## MCP जोड्नुहोस् वा छुट्याउनुहोस् {#mcp}

1. [OpenCode MCP दस्तावेज](https://opencode.ai/v2/docs/mcp-servers/) प्रयोग गरी execution host मा MCP server कन्फिगर गर्नुहोस्।
2. परियोजनाका लागि **स्थिति → MCP सर्भरहरू** खोल्नुहोस्।
3. server छेउको switch बाट connect/disconnect गर्नुहोस्। जडान सूचक स्थिर हुन पर्खनुहोस्।

त्यही Location प्रयोग गर्ने अन्य क्लाइन्टले परिवर्तन देख्न सक्छन्। disconnect ले server घोषणा हटाउँदैन वा executable uninstall गर्दैन।

जडान असफल भए server कन्फिगरेसन, आवश्यक वातावरण र प्रमाणीकरण जाँच्नुहोस्; switch ले OAuth पूरा गर्दैन।

## Global वा Project दायरामा plugin सक्रियता {#plugins}

CodeNomad ले व्यवस्थापन गर्ने प्लगइनहरू सामान्य प्लगइन सूची र त्यसका सक्रियता, अद्यावधिक तथा हटाउने नियन्त्रणहरूबाट अलग रहन्छन्।

**CodeNomad प्लगइनहरूमा ध्यान दिनु आवश्यक छ** देखिए विवरणका लागि **i** खोल्नुहोस्। निष्क्रिय प्लगइनले **पुनः सक्रिय गर्नुहोस्** दिन्छ; प्रयोग गर्नुअघि देखाइएको कन्फिगरेसन दायरा जाँच्नुहोस्।

1. [plugin थप्नुहोस्](#plugin-sources) वा OpenCode कन्फिगरेसनमा घोषणा गर्नुहोस्; त्यसपछि **स्थिति → प्लगइनहरू** खोल्नुहोस्।
2. स्रोत, runtime failure र configuration-target विवरण हेर्न नाममा hover/focus गर्नुहोस्।
3. **विश्वव्यापी** वा **परियोजना** सचेत रूपमा toggle गर्नुहोस्। write पर्खनुहोस् र अवस्था अस्पष्ट भए **प्लगइन नियन्त्रण ताजा गर्नुहोस्** प्रयोग गर्नुहोस्।
4. package बाट स्थापित plugin का लागि नामछेउको icon प्रयोग गर्नुहोस्। यसको menu ले ठ्याक्कै कार्य नाम दिन्छ: package को **… का अद्यावधिक जाँच्नुहोस्**, वा नयाँ संस्करण भेटिएपछि **… अद्यावधिक गर्नुहोस्**।

Global ले जोडिएको daemon को पत्ता लागेको global कन्फिगरेसन लक्षित गर्छ। Project ले सक्रिय Location भित्रको कन्फिगरेसन लक्षित गर्छ, inherited ancestor फाइल होइन। पछिको Project नियमले Global override गर्न सक्छ; Global switch ले अन्तिम Project अवस्था भएको अभिनय नगरी Global नियम नै देखाउँछ। Project नियम नभए resolved Global अवस्था inherit हुन्छ।

built-in OpenCode plugin user सक्रियता switch मा दिइँदैनन्। लक्ष्य Global बाट सुरक्षित अलग गर्न नसके वा सक्रिय Location बाहिर जाने भए Project अक्षम हुन्छ।

package अपडेटले, यसको tooltip ले भनेझैं, त्यो package प्रयोग गर्ने हरेक Location का लागि OpenCode को साझा cache मा त्यो package बदल्छ; यसले सक्रियता नियम बदल्दैन, OpenCode पुनः सुरु गर्दैन वा कन्फिगरेसन reload गर्दैन। स्थानीय, built-in र SDK-प्रदत्त plugin को package कार्य हुँदैन।

## plugin थप्नुहोस् वा हटाउनुहोस् {#plugin-sources}

1. **स्थिति → प्लगइनहरू** मा **+** खोलेर **प्लगइन थप्नुहोस्…** छान्नुहोस्।
2. npm रजिस्ट्रीको package (`name`, `name@1.2.3`, `@scope/name@^1`) वा Git रिपोजिटरी (`github:owner/repo`, `git+https://…`) लेख्नुहोस्।
3. plugin यो परियोजनामा मात्र चल्नुपर्ने नभए **विश्वव्यापी** राख्नुहोस्, अनि **थप्नुहोस्** छान्नुहोस्।
4. OpenCode ले रिपोर्ट नगरेसम्म नयाँ पङ्क्तिमा **स्थापना हुँदैछ** देखिन्छ।

plugin हटाउन, यसको नाम छेउको मेनु खोलेर **विश्वव्यापी बाट हटाउनुहोस्** वा **परियोजना बाट हटाउनुहोस्** छान्नुहोस्। त्यस दायराको कन्फिगरेसन फाइलमा रहेको घोषणा र यसका सक्रियता नियमहरू मेटिन्छन्; तर plugin को अर्को घोषणा बाँकी रहँदासम्म निष्क्रिय पार्ने नियम, र अघिल्लो घोषणाले अझै परिभाषित गरेको सक्रिय पार्ने नियम रहन्छन्। आफ्नो परिभाषा गुमाउने सक्रिय पार्ने नियम यस परियोजनाको कन्फिगरेसनबाट पनि मेटिन्छ, नत्र OpenCode ले त्यही नामको registry package डाउनलोड गर्छ; त्यो CodeNomad ले सम्पादन नगर्ने फाइलमा भए हटाउने काम अस्वीकार हुन्छ। OpenCode को package cache यथावत् रहन्छ। OpenCode ले पहिचान गर्न नसकेको plugin (निष्क्रिय, वा लोड हुनुअघि असफल) का नियमहरू छुट्टै पङ्क्तिमा रहन्छन्, जसको मेनुले उही हटाउने विकल्प दिन्छ।

plugin को कोड OpenCode भित्र तपाईंको अनुमतिसहित चल्छ। त्यो फोल्डर OpenCode मा खोल्दा हरेक पटक **परियोजना** प्रविष्टि चल्छ, र OpenCode डेस्कटप एपका भाग भएका package ले ती भाग **विश्वव्यापी** बाट मात्र लोड गर्छन्; यस्तो package अन्यत्र घोषणा गरिएको छ भने tooltip ले बताउँछ। स्थानीय पथ, कन्फिगरेसन चर र plugin ID यहाँ अस्वीकार हुन्छन्: स्थानीय plugin कन्फिगरेसन फाइलमा घोषणा गर्नुहोस्। यो Location मा लागू हुने कन्फिगरेसनमा पहिल्यै घोषणा गरिएको package, संस्करण, दायरा वा रूप जे भए पनि, अस्वीकार हुन्छ।

स्थापित प्याकेजको संस्करण plugin को नामछेउमा देखिन्छ। Git plugin को विवरणमा कमिट समावेश हुन्छ; संस्करण उपलब्ध नभए नामछेउमा सात अक्षरको कमिट देखिन्छ। नाममा pointer वा focus राख्दा विवरण, **अपडेट उपलब्ध छ**, र असफल स्थापनामा OpenCode लगको सन्दर्भसहित त्रुटि देखिन्छ।

## skill जोड्नुहोस् {#skills}

1. कम्पोजरमा `@` टाइप गरी Location का उपलब्ध skill खोजेर एउटा चयन गर्नुहोस्।
2. फाइल/agent छेउको हटाउन मिल्ने संलग्नक जाँच्नुहोस्; नचाहिए पठाउनुअघि हटाउनुहोस्।
3. prompt पठाउनुहोस्। पठाइएको सन्देशसँग skill label रहन्छन्।

संलग्नक हटाउँदा पहिलेको पठाइ undo हुँदैन।

skill उपलब्धता कुराकानीको Location बाट आउँछ, global CodeNomad catalogue बाट होइन। [OpenCode skill दस्तावेज](https://opencode.ai/v2/docs/skills/) र [कुराकानी](conversations.md) हेर्नुहोस्।

## custom command चलाउनुहोस् {#commands}

1. कम्पोजरमा `/` टाइप गरी उपलब्ध नेटिभ command रोज्नुहोस्।
2. argument दिएर command अनुसार बुझाउनुअघि **एजेन्ट**, **मोडेल** र **सोचाइ** जाँच्नुहोस्।
3. acknowledgement अस्पष्ट भए बारम्बार पठाउनुको सट्टा नतिजाको कुराकानी जाँच्नुहोस्।

command सक्रिय Location का लागि OpenCode बाट पत्ता लाग्छन्। `/btw` CodeNomad को छुट्टै क्षणिक प्रश्न flow हो, सामान्य custom command होइन।

command परिभाषा र native configuration inheritance का लागि [OpenCode command दस्तावेज](https://opencode.ai/v2/docs/commands/) प्रयोग गर्नुहोस्। कन्फिगरेसन परिवर्तनपछि पहिले सम्बन्धित सतह refresh/reopen गर्नुहोस्; runtime लाई अझै चाहिँदा मात्र स्पष्ट configuration reload गर्नुहोस्। प्रदर्शन refresh गर्नकै लागि सम्भवतः admitted command replay नगर्नुहोस्।
## प्लगइनहरूमा एकीकरण {#integration-rows}

**स्थिति → प्लगइनहरू** को **+** मा **एकीकरण थप्नुहोस्…** वा **प्लगइन थप्नुहोस्…** छान्न सकिन्छ। एकीकरण चयनमा समीक्षा गरिएको सूचीका स्थापना नभएका प्रविष्टि देखिन्छन्। दायरा र **स्थापना गर्नुहोस्** छान्नुहोस्: CodeNomad ले छानिएको सूची ID स्थापना गर्छ। नेटिभ एकीकरण **विश्वव्यापी मात्र** हुन्छन्। **सूची उपलब्ध छैन** मा **ताजा गर्नुहोस्** हुन्छ; **{date} को सूची** ले पुरानो भएको अन्तिम मान्य सूची जनाउँछ।

एक्सेन्ट रङको अवस्था पङ्क्तिबाट **Blender मा स्थापना गर्नुहोस्**, **Blender अद्यावधिक गर्नुहोस्** वा देखाइएको कुराकानीलाई खुला कागजातमा **जोड्नुहोस्** छान्नुहोस् (धेरैबाट छान्न **जोड्नुहोस्…**)। साङ्लोको आइकन र कागजातले जडान जनाउँछन्; छुट्याउन छान्नुहोस्। कुराकानीको एजेन्टले पहिलो पटक एकीकरण प्रयोग गर्दा पनि कुराकानी आफैं जोडिन्छ।

पङ्क्तिको **…** मेनु जडान अवस्थाबाट सुरु हुन्छ, जस्तै **Blender: 1 खुला कागजात** वा **Blender बन्द छ**। त्यसपछि **कागजात**, **अनुप्रयोगमा स्थापना गर्नुहोस्…**, **अनुप्रयोग अद्यावधिक गर्नुहोस्…** वा **अनुप्रयोगमा पुनः स्थापना गर्नुहोस्…** ([तल हेर्नुहोस्](#application-installation)), प्याकेजको अद्यावधिक जाँच, **विश्वव्यापी बाट हटाउनुहोस्** वा **परियोजना बाट हटाउनुहोस्**, र **प्लगइन नियन्त्रण ताजा गर्नुहोस्** आउँछन्। छुट्याउन पुष्टि बिना एक क्लिक लाग्छ र यसले यो कुराकानीलाई मात्र असर गर्छ: अनुप्रयोग खुला रहन्छ, यसको भाग स्थापित रहन्छ र अन्य कुराकानीहरूको जडान रहन्छ।

सूचीबाट स्थापना, अनुप्रयोग भागको स्थापना/अद्यावधिक र हटाउन पुष्टि चाहिन्छ। **रद्द गर्नुहोस्** मा पहिले फोकस हुन्छ; पुष्टि कार्य 600 ms पछि उपलब्ध हुन्छ। सक्रियता, प्लगइन अद्यावधिक, जोड्ने र छुट्याउने काम सिधै चल्छन्।

हटाउँदा प्लगइन र ठ्याक्कै दायरा भएको चेतावनी खुल्छ। **रद्द गर्नुहोस्** मा फोकस हुन्छ; **विश्वव्यापी/परियोजनाबाट हटाउनुहोस्** 600 मिलिसेकेन्डपछि उपलब्ध हुन्छ र स्पष्ट कार्य चाहिन्छ। यसले प्रयोग गर्ने कुराकानीहरूको उपलब्धता र जडान रोक्न सक्छ; विश्वव्यापी दायराले अन्य परियोजनालाई पनि असर गर्न सक्छ। पुष्टि गरिएको घोषणा र माथि वर्णन गरिएका सक्रियता नियम मात्र हट्छन्; क्यास, अनुप्रयोगका फाइल र सुरक्षित जडान सङ्केत रहन्छन्। कन्फिगरेसन बदलिए पुनः चयन र पुष्टि चाहिन्छ।

## अनुप्रयोग एकीकरण स्थापना वा अद्यावधिक गर्नुहोस् {#application-installation}

**स्थिति → प्लगइनहरू** मा, एकीकरणको ताजा अवस्थाले कार्य दिँदा यसको अवस्था पङ्क्तिमा **Blender मा स्थापना गर्नुहोस्** वा **Blender अद्यावधिक गर्नुहोस्** छान्नुहोस्, वा यसको **…** मेनुमा **अनुप्रयोगमा स्थापना गर्नुहोस्…**, **अनुप्रयोग अद्यावधिक गर्नुहोस्…** वा **अनुप्रयोगमा पुनः स्थापना गर्नुहोस्…** छान्नुहोस्। पुनः स्थापनाले अनुप्रयोग खुला वा बन्द जे भए पनि अनुप्रयोग भाग फेरि लेख्छ। यो कुराकानी वा खुला कागजात बिना पनि उपलब्ध छ।

पुष्टिमा अनुप्रयोग र स्थापनाकर्ता उपलब्ध गराउने **एकीकरण प्याकेजको संस्करण** देखिन्छ। दुवै र मेसिनसम्बन्धी चेतावनी जाँच्नुहोस्: स्थापना OpenCode चल्ने मेसिनमा हुन्छ, जुन टाढाको पनि हुन सक्छ। सुरुको फोकस **रद्द गर्नुहोस्** मा हुन्छ। अगाडि बढ्न स्पष्ट रूपमा पुष्टि गर्नुहोस्।

खुला अनुप्रयोग मिल्दो देखिए पनि WSL मा अनुप्रयोगभित्र स्थापना सधैँ अस्वीकार हुन्छ। समर्थित मेसिनमा अनुप्रयोग खोल्नुहोस्।

स्थापना वा अद्यावधिकपछि अनुप्रयोग खोलेर यसको एकीकरण जाँच्नुहोस्।

त्रुटिका कारण नतिजा अनिश्चित भए सो अनुरोध नदोहोर्‍याउनुहोस्: पहिले अनुप्रयोग जाँच्नुहोस्, त्यसपछि आवश्यक भए नयाँ कार्य र पुष्टि सुरु गर्नुहोस्।
