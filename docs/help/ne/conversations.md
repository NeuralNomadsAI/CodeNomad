# कुराकानी

CodeNomad ले नेटिभ OpenCode सत्रलाई कुराकानीका रूपमा देखाउँछ, प्रत्यायोजित कामको पदानुक्रम र अर्को पटक पठाउने कुराका छुट्टै नियन्त्रणसहित।

सन्देशले Markdown, code, diff र समर्थित उपकरण-नतिजा छवि देखाउँछन्। पाठ प्रतिलिपि, पूर्ण-इतिहास खोज र वाचनले embedded छविका byte होइन पाठ projection प्रयोग गर्छन्। **सन्देशको सामग्री** ले सुरक्षित अंश नमेटी दृश्यता बदल्छ; [इतिहास](history.md#operation-reference) ले प्रदर्शन नियन्त्रण र सफाइ छुट्याउँछ।

तर्क र उपकरणका header ले हरेक चरणमा लागेको समय देखाउँछन्, चलिरहँदा प्रत्यक्ष गन्दै; एक सेकेन्डभन्दा कम अवधि देखाइँदैन। **सन्देशको सामग्री** मा **टोकन** देखाइएको बेला (**सबै** प्रिसेटले देखाउँछ), हरेक agent सन्देश आफ्नो अन्तिम पाठपछि एउटा token र लागत पङ्क्तिमा टुङ्गिन्छ। त्यो पङ्क्तिले लोड भएको transcript भित्र, त्यो सन्देश र यसको **यस जवाफबाट उपकरण र तर्क हटाउनुहोस्** कार्यले समेट्ने उपकरण र तर्क भएका सन्देशहरू जोड्छ; तर्क र cache गणनाका लागि यसलाई विस्तार गर्नुहोस्। उपकरण मात्र चलाएका चरणको आफ्नै पङ्क्ति हुँदैन।

## कुराकानी खोज्नुहोस् र आवागमन गर्नुहोस् {#navigate-conversations}

1. **सत्रहरू** अन्तर्गतको row चयन गर्नुहोस्, वा parent कुराकानी सुरु गर्न **नयाँ सत्र** प्रयोग गर्नुहोस्।
2. उप-सत्र हेर्न parent को chevron विस्तार गर्नुहोस्। संक्षिप्त chevron ले descendants को सबैभन्दा जरुरी अवस्था देखाउँछ: इनपुट चाहिने, काम गरिरहेको, वा भर्खरै सकिएको (निष्क्रिय); यसको tooltip ले तिनको गणना देखाउँछ।
3. सूची साँघुरो बनाउन **सत्रहरू खोज्नुहोस्...**, **मुख्य सत्रहरू** / **उप-सत्रहरू**, worktree filter र **गतिविधि**, **नाम** वा **वर्कट्री** क्रम प्रयोग गर्नुहोस्।
4. पहिले देखेका कुराकानीमा फर्कन sidebar का **पछाडि** र **अगाडि** प्रयोग गर्नुहोस्।

सामान्य ब्राउज पदानुक्रममा हुन्छ; खोज/filter नतिजा हरेक कुराकानीको आफ्नै पहिचान र worktree सहित सपाट प्रविष्टि हुन्छन्। नयाँ काम गर्ने उप-सत्र सक्रिय कुराकानीको परिवारमुनि मात्र स्वतः देखिन्छ। त्यो branch संक्षिप्त गर्दा अहिले चलिरहेका descendants का लागि स्वचालित देखाइ खारेज हुन्छ।

Back/Forward प्रति-परियोजना-ट्याब, प्रति-विन्डो भ्रमण इतिहास हो, सूची क्रम होइन। यो memory मा रहन्छ, अनुपलब्ध/मेटिएका कुराकानी छोड्छ र पुनःसुरुवातपछि फर्किँदैन। पछाडि गएपछि नयाँ कुराकानी चयन गर्दा अगाडिको मार्ग बदलिन्छ। प्यालेटका **अघिल्लो सत्र** / **अर्को सत्र** ले भने देखिएको सूची घुमाउँछन्।

## Agent, Model र Thinking रोज्नुहोस् {#agent-model-thinking}

1. पठाउनुअघि कम्पोजर footer का agent र model selector प्रयोग गर्नुहोस्।
2. मोडेलमा variant भए **सोचाइ** प्रयास चयन गर्नुहोस्; **पूर्वनिर्धारित** ले नेटिभ default प्रयोग गर्छ।
3. अर्को prompt पठाउनुहोस् र नतिजाको निदान गर्दा जवाफको agent/model metadata जाँच्नुहोस्।

तपाईंले अर्को नरोजेसम्म, नयाँ कुराकानी OpenCode ले आफ्नो पूर्वनिर्धारितका रूपमा resolve गर्ने agent बाट सुरु हुन्छ, जुन plugin ले सेट गर्न सक्छ। selector का tooltip ले तिनका shortcut देखाउँछन्।

यी पछिका पठाइका कार्यान्वयन चयन हुन्, अघिल्ला जवाफको सम्पादन होइनन्। पुरानो timeline अंश पढ्दा कम्पोजरका हालका चयन ऐतिहासिक metadata ले बदल्दैन। मोडेल दृश्यता, मनपर्ने र प्रदायक जडान [प्रदायक](providers.md) मा व्यवस्थापन हुन्छन्।

## मस्यौदा र संलग्नक {#drafts-attachments}

1. चयन गरिएको कुराकानीमा लेख्नुहोस्। कुराकानी बदल्दा मस्यौदा पठाउनुको सट्टा रहिरहन्छ।
2. यस उपकरणका फाइलका लागि कम्पोजरको **थप कार्यहरू** मेनुमा **फाइल संलग्न गर्नुहोस्…** रोज्नुहोस्, वा drop वा paste गर्नुहोस्; अथवा परियोजना फाइल, agent वा skill चयन गर्न `@` टाइप गर्नुहोस्।
3. संलग्नक chip समीक्षा गरी अर्को पठाइमा नचाहिने हटाउनुहोस्।

| इनपुट | स्रोत र असर |
| --- | --- |
| उपकरण संलग्नक | picker, drop वा clipboard ले UI चलिरहेको उपकरणबाट byte पढ्छ; यो सर्भर मार्ग होइन |
| परियोजना `@` reference | ब्याकएन्डमा कुराकानीको परियोजना/Location भित्र worktree समेत resolve हुन्छ |
| Agent mention | विगतका सन्देश बदल्नुको सट्टा चयन गरिएको agent reference जोड्छ |
| Skill | Location का skill नाम/विवरणबाट खोजी हटाउन मिल्ने skill चयन जोड्छ |

उपकरण फाइल पढ्न मिल्ने र संलग्नक सीमाभित्र हुनुपर्छ: प्रत्येक बढीमा 5 MiB, 10 फाइल र कुल 20 MiB। अस्वीकृत फाइल जोडिँदैन; सबै चयन सफल भयो नभनी सूचना समीक्षा गर्नुहोस्।

skill रोज्दा `@query` token हटेर chip थपिन्छ। पठाउँदा कम्पोजरको चयन खाली हुन्छ, पठाइएको सन्देशसँग OpenCode ले सुरक्षित गरेका निर्देशन होइनन्। ऐतिहासिक सन्देशमा skill label रहन्छन्। लामको prompt सम्पादन गर्दा skill हटाए प्रतिस्थापन पठाइमा पनि हटेकै रहन्छ।

डेस्कटपमा पठाउँदा keyboard focus कुराकानीमा सर्छ, त्यसैले arrow, paging र Space ले यसलाई scroll गर्छन्; कुनै अक्षर टाइप गर्दा त्यही अक्षरसहित कम्पोजरमा फर्किन्छ। **थप कार्यहरू** मा रहेको **प्रम्प्ट पाठ सफा गर्नुहोस्** (पूर्वनिर्धारित **Ctrl/Cmd+K**) ले कम्पोजरको मस्यौदा खाली गर्छ।

मस्यौदा क्लाइन्टको कामचलाउ अवस्था हुन्, साझा नेटिभ सन्देश होइनन्। startup restoration ले समर्थित कम्पोजर अवस्था राख्न सक्छ, तर नपठाइएको मस्यौदा वा संलग्नकलाई backup नमान्नुहोस् वा अर्को उपकरणमा देखिन्छ नठान्नुहोस्। startup डेटा खाली गर्नुअघि वा restore नीति बन्द भएको क्लाइन्ट बन्द गर्नुअघि महत्त्वपूर्ण पाठ बचत गर्नुहोस्; [डेस्कटप](desktop.md) हेर्नुहोस्।

## आदेश र Shell मोड {#commands-shell}

1. `/` टाइप गरी भेटिएको custom command चयन गर्नुहोस्, त्यसपछि argument दिनुहोस्।
2. प्रत्यक्ष shell आदेशका लागि खाली कम्पोजरको सुरुमा `!` टाइप गरी **शेल मोड** मा जानुहोस्।
3. आदेश पठाउनुहोस्। नचलाइकन Shell मोड छोड्न Escape, वा खाली field मा Backspace प्रयोग गर्नुहोस्।

चिनिएका slash-command नाम मात्र custom-command मार्गबाट जान्छन्; अज्ञात `/text` सामान्य prompt हो। custom command ले आफ्नै नेटिभ परिभाषा प्रयोग गर्छ। फाइल/छवि संलग्नक यो मार्गबाट पठाइँदैनन् र पछिको prompt का लागि रहन्छन्; argument मा प्रयोग गरिएको pasted पाठ argument भित्र resolve हुन्छ।

Shell मोडले नेटिभ सत्र shell अनुरोध चलाउँछ, मोडेललाई आदेश सुझाउन माग्दैन। यसले कार्यान्वयन होस्टमा फाइल बदल्न र प्रक्रिया सुरु गर्न सक्छ। प्रोफाइल वातावरण सेटिङ अर्को prompt, custom command वा shell अनुरोधअघि लागू हुन्छन्; विद्यमान सेवा पुनः सुरु गर्दैनन्। [एकीकरण](integrations.md) र [OpenCode सेटअप](opencode.md) हेर्नुहोस्।

## फलो-अप निर्देशन, लाम र सम्पादन {#follow-ups}

1. सत्र व्यस्त हुँदा पठाइएका फलो-अप लाममा राख्न **सेटिङहरू → सामान्य** मा **पठाइएका प्रम्प्टहरू लाममा राख्नुहोस्** खोल्नुहोस्; चलिरहेको कामलाई निर्देशन दिन यसलाई बन्दै (पूर्वनिर्धारित) छोड्नुहोस्।
2. सत्र व्यस्त हुँदा त्यही व्यवहारमा फलो-अप पठाउनुहोस्। अर्को व्यवहारका लागि कम्पोजरको **थप कार्यहरू** मेनुमा **सन्देश लाममा राख्नुहोस्** वा **अहिले पठाउनुहोस्** रोज्नुहोस्, वा वैकल्पिक-send shortcut प्रयोग गर्नुहोस् (पूर्वनिर्धारित Windows र Linux मा **Alt+Enter**, macOS मा **Cmd+Shift+Return**; [सर्टकट](shortcuts.md) हेर्नुहोस्)।
3. prompt लाममा प्रविष्टि अझै pending हुँदा **अहिले पठाउनुहोस्**, **लाममा सार्नुहोस्**, **लामको प्रम्प्ट सम्पादन गर्नुहोस्** वा **लामको प्रम्प्ट हटाउनुहोस्** प्रयोग गर्नुहोस्।

| वितरण | असर |
| --- | --- |
| निर्देशन | चलिरहेको कार्यान्वयनका लागि नेटिभ steering input |
| लाम | पछिको processing का लागि रोकिएको नेटिभ फलो-अप |

निष्क्रिय अवस्थामा सामान्य पठाइले त्यो switch जे भए पनि सामान्य तत्काल मार्ग प्रयोग गर्छ, र **थप कार्यहरू** को विकल्प उपलब्ध हुँदैन। सम्पादनले pending prompt र हटाउन मिल्ने संलग्नक कम्पोजरमा फर्काउँछ; **सम्पादन रद्द गर्नुहोस्** ले सम्पादन छोड्छ। OpenCode ले खपत गरिसकेको prompt अब सम्पादनयोग्य pending प्रविष्टि हुँदैन। प्रविष्टि हटाउँदा भइसकेको काम उल्टिँदैन।

लाम अपडेट असफल भए फेरि प्रयासअघि जीवित लाम जाँच्नुहोस्। admission ले मोडेलले फलो-अप खपत गरेको प्रमाण दिँदैन, र पुनःजडानले फेरि पठाउने अनुमति दिँदैन।

## /btw बाट छेउको प्रश्न सोध्नुहोस् {#side-question}

1. विद्यमान कुराकानीमा `/btw your question` पठाउनुहोस्, वा छेउको प्रश्न विन्डो खोल्न `/btw` पठाउनुहोस्।
2. उत्तर पढ्नुहोस्, **उत्तर प्रतिलिपि गर्नुहोस्** प्रयोग गर्नुहोस्, वा pending हुँदा **प्रश्न रद्द गर्नुहोस्** रोज्नुहोस्।
3. सकिएपछि विन्डो बन्द गर्नुहोस्।

यो सत्र सन्दर्भ प्रयोग गर्ने एउटै छुट्टै मोडेल अनुरोध हो। यसले tool loop चलाउँदैन, कार्य गर्दैन वा प्रश्न/उत्तर कुराकानीमा थप्दैन। फाइल/छवि संलग्नक कम्पोजरमै रहन्छन्; प्रश्नमा प्रयोग गरिएको pasted पाठ पाठकै रूपमा समावेश हुन्छ। यो नयाँ टिकाउ कुराकानी वा काम पठाउने वैकल्पिक तरिका होइन।

बन्द गर्दा मुख्य सत्र नरोकी pending छेउको अनुरोध रद्द हुन्छ। सक्रिय कुराकानी छोड्दा यो क्षणिक विन्डो खाली हुन्छ; चाहिने कुरा पहिले प्रतिलिपि गर्नुहोस्। खाली/त्रुटि जवाफ transcript सन्देश नभई यहीं देखिन्छन्।

## Fork, undo र असफल run पुनःप्राप्ति {#fork-errors}

1. सन्देशमा **यो सन्देशपछि फोर्क गर्नुहोस्** रोजेर मूल नबदली त्यस बिन्दुपछिको कुराकानी बनाउनुहोस्।
2. undo का लागि **यहाँ सम्मका परिवर्तनहरू फिर्ता लिनुहोस् (सन्देशहरू मेटाउँछ)** ध्यान दिएर समीक्षा गर्नुहोस्। प्यालेटले staged undo का लागि **अन्तिम सन्देश फिर्ता लिनुहोस् (Undo)** र **अन्तिम सन्देश फेरि गर्नुहोस्** दिन्छ।
3. कार्यान्वयन असफल भए फेरि पठाउनुअघि **सत्र त्रुटि**, जवाफ त्रुटि र **पठाउन असफल** विवरण जाँच्नुहोस्।

fork ले चयनित बिन्दुसम्म कुराकानी सन्दर्भ प्रतिलिपि गर्छ; Git worktree बनाउँदैन वा फाइल अलग गर्दैन। revert केवल नेभिगेसन होइन। अघि बढ्नुअघि फाइल असर र undo सीमा समीक्षा गर्नुहोस्; मूल मार्ग नलेखी वैकल्पिक छलफल चाहिँदा fork प्रयोग गर्नुहोस्।

countdown सहितको **पुन: प्रयास गर्दै** अवस्थाको अर्थ OpenCode आफैं प्रदायक त्रुटि पुनः प्रयास गर्दैछ; फेरि पठाउनुको सट्टा पर्खनुहोस् वा सत्र रोक्नुहोस्। नयाँ टाइपिङ नमेटिने भए असफल पठाइले प्रयास गरिएको मस्यौदा र संलग्नक फर्काउँछ। असफल run ले उपकरण चलाइसकेको हुन सक्छ: पुनःप्रयासअघि [फाइल](files.md), pending [अनुरोध](permissions.md) र नेटिभ गतिविधि जाँच्नुहोस्। **सन्देशहरू फेरि लोड गर्नुहोस्** वा **सत्र पुन: लोड गर्नुहोस्** ले अवस्था पढ्छ; परिवर्तन दोहोर्‍याउने निर्देशन होइनन्। **सत्र रोक्नुहोस्** ले कार्यान्वयन रोक्छ, फाइल वा बाह्य सेवाका परिवर्तन rollback गर्दैन।
