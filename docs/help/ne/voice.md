# आवाज input र playback

## आवाजको API कन्फिगर गर्नुहोस् {#configure}

1. **सेटिङहरू → आवाज** खोल्नुहोस्। **वाचन (Speech)** card ले कुराकानीको model provider बाट स्वतन्त्र OpenAI-compatible server-side adapter प्रयोग गर्छ।
2. **API कुञ्जी**, ऐच्छिक **आधार URL**, **ट्रान्सक्रिप्शन मोडेल**, **वाचन मोडेल (TTS)** र **पूर्वनिर्धारित आवाज** भर्नुहोस्।
3. input र output लाई फरक सेवा चाहिँदा **इनपुट र आउटपुटका लागि छुट्टाछुट्टै प्रदायक** सक्षम गरी input/output key, base URL र model field भर्नुहोस्।
4. **प्लेब्याक मोड** र **आउटपुट ढाँचा**, अनि **बचत गर्नुहोस्** (नबचाइएका परिवर्तन हुँदा उपलब्ध) रोज्नुहोस्। परीक्षणअघि परीक्षण बटनछेउको अवस्था, **कन्फिगर गरियो**, **आंशिक रूपमा कन्फिगर** वा **API कुञ्जी हराइरहेको छ**, जाँच्नुहोस्; save असफल भए **बचत गर्न असफल भयो** देखिन्छ।

speech सेटिङ र key जोडिएको CodeNomad server configuration का हुन्, चयनित परियोजना वा OpenCode provider connection का होइनन्। साझा गर्ने अन्य क्लाइन्टले पनि प्रयोग गर्छन्। सुरक्षित key लुकाइन्छ: खाली key field ले सुरक्षित मान राख्छ; **बचत गरिएको कुञ्जी सफा गर्नुहोस्** ले बचत गर्दा हटाउने तय गर्छ। आफ्नै endpoint र key दुवै नभएको दिशाले साझा सेटिङ प्रयोग गर्न सक्छ; छुट्टै endpoint लाई आफ्नै key र छुट्टै key लाई आफ्नै endpoint चाहिन्छ। endpoint बदल्दा अभिप्रेत key स्पष्ट दिनुहोस् र सुरक्षित कन्फिगरेसन जाँच्नुहोस्; अर्को host मा पठाउनुको सट्टा endpoint परिवर्तनले त्यस slot को सुरक्षित key हटाउँछ।

backend ले साझा default का लागि `OPENAI_API_KEY` र `OPENAI_BASE_URL` पनि प्रयोग गर्न सक्छ। सुरक्षित key खाली गर्दा environment-provided credential हट्दैन; fallback हटाउन चाहनुहुन्छ भने backend वातावरण बदलेर पुनः सुरु गर्नुहोस्।

| सेटिङ | अर्थ / default |
| --- | --- |
| Base URL | OpenAI-compatible API root, default `https://api.openai.com/v1`। input ले `audio/transcriptions`; output ले `audio/speech` प्रयोग गर्छ। |
| Transcription model / Input model | STT endpoint ले स्वीकार्ने model; default `gpt-4o-mini-transcribe`। |
| Speech model / Output model | TTS endpoint ले स्वीकार्ने model; default `gpt-4o-mini-tts`। |
| Default voice | प्रदायक voice identifier; default `alloy`। OS voice picker होइन। |
| Streaming | पूर्वनिर्धारित। provider र browser ले चयनित format समर्थन गर्दा audio आउनासाथ playback सुरु हुन्छ। |
| Buffered | बजाउनुअघि पूरा audio response पर्खन्छ। |
| Output format | `mp3`, `wav`, `opus` वा `aac`; default `mp3`। अनुकूलता browser/provider अनुसार फरक हुन्छ। |

यी कन्फिगर सेवामा अनुरोध हुन्, हरेक compatible endpoint ले हरेक model, voice वा format समर्थन गर्छ भन्ने प्रत्याभूति होइन।

## input र output परीक्षण {#test}

1. पहिले endpoint, key, model र voice परिवर्तन बचत गर्नुहोस्।
2. **इनपुट परीक्षण** रोजेर microphone अनुमति दिनुहोस्, बोल्नुहोस्, अनि **रेकर्डिङ रोक्नुहोस्**। फर्किएको transcription जाँच्नुहोस्।
3. नमूना सुन्न **प्लेब्याक परीक्षण गर्नुहोस्** रोज्नुहोस्; **नमूना रोक्नुहोस्** ले अन्त्य गर्छ।

playback परीक्षणले चयनित मोड/format तुरुन्त प्रयोग गर्छ, तर endpoint, key, model र voice सुरक्षित सेटिङबाट आउँछन्। input परीक्षणले कुराकानी prompt पठाउँदैन। परीक्षणले पनि कन्फिगर speech provider लाई audio/text पठाउँछन् र शुल्क लाग्न सक्छ।

## बोलेर prompt लेख्नुहोस् {#dictate}

1. **आवाज** मा **प्रम्प्ट ध्वनि इनपुट** सक्षम नै राख्नुहोस् (पूर्वनिर्धारित रूपमा यो चालू हुन्छ)।
2. कम्पोजरमा **थप कार्यहरू → श्रुतलेखन** रोज्नुहोस् र माइक्रोफोनको अनुमति दिनुहोस्। **श्रुतलेखन: आवाज सेटिङ खोल्नुहोस्** देखिए त्यहीँ इन्जिन छान्नुहोस् वा सेटअप गर्नुहोस् र मस्यौदामा फर्कनुहोस्।
3. पाठ निकाल्न **रेकर्डिङ रोक्नुहोस् र ट्रान्सक्राइब गर्नुहोस्** रोज्नुहोस्। रेकर्डिङ त्याग्न **श्रुतिलेखन रद्द गर्नुहोस्** रोज्नुहोस्। कुराकानी फेर्दा वा कम्पोजर बन्द गर्दा पनि श्रुतलेखन रद्द हुन्छ।
4. पाठ हेर्नुहोस्। मस्यौदा र चयन नबदलिएको भए मात्र यसले सुरुको चयन बदल्छ। नत्र **प्रतिलेख घुसाउनुहोस्** वा **प्रतिलेख हटाउनुहोस्** रोज्नुहोस्। श्रुतलेखनले मस्यौदा पठाउँदैन।

Linux मा Tauri चलाउँदा API ले वैकल्पिक WAV मोड प्रयोग गरेमा, बोलेर लेख्ने र इनपुट परीक्षण गर्ने दुवैमा रेकर्डिङ २४ सेकेन्डमा रोकिन्छ। अडियो आवाज सेवा प्रदायकलाई पठाउन **प्रतिलेखन गर्नुहोस्** वा हटाउन **रद्द गर्नुहोस्** रोज्दासम्म यही यन्त्रमा रहन्छ।

### डेस्कटपमा इन्जिन छान्नुहोस् {#desktop-dictation}

स्थानीय डेस्कटप एपमा **प्राथमिकताहरू → आवाज** खोलेर **यो उपकरणको श्रुतलेखन इन्जिन** छान्नुहोस्। छनोट यस उपकरणका सबै परियोजनामा लागू हुन्छ; **वाचन (Speech)** कार्डले जोडिएको सर्भरको API सेट गर्छ। ब्राउजर र मोबाइलले सेट गरिएको API प्रदायक प्रयोग गर्छन् र माइक्रोफोनका लागि सुरक्षित सन्दर्भ चाहिन्छ।

- **स्थानीय प्रणाली वाणी पहिचान** ले अपरेटिङ सिस्टमको श्रुतलेखन प्यानल नखोली CodeNomad भित्रै काम गर्छ। Windows वा macOS मा एपको भाषासँग मिल्ने स्थानीय इन्जिन स्थापित हुनुपर्छ। Linux मा वा इन्जिन वा भाषा उपलब्ध नभए Hex विकल्प देखिएमा प्रयोग गर्नुहोस्।
- आवाजमा Hex का लागि बाँकी भाग र हरेक भागको तथा कुल डाउनलोड आकार देखिन्छ। **Hex सक्रिय गर्नुहोस्** एकपटक थिच्दा मिल्ने फाइल जाँचेर पुनः प्रयोग गरिन्छ, बाँकी डाउनलोड हुन्छ र तयार भएपछि Hex छानिन्छ। प्रगति त्यहीँ हेर्नुहोस्। रोक्न **Hex सक्रिय गर्ने काम रद्द गर्नुहोस्** र उपलब्ध हुँदा **Hex सक्रिय गर्ने काम जारी राख्नुहोस्** रोज्नुहोस्। असफल भए वा रद्द गरे पहिलेको इन्जिन नै छानिएको रहन्छ। सेटिङ फेरि खोल्दा, तयार **Hex (स्थानीय)** छान्दा वा त्यसबाट श्रुतलेखन गर्दा अर्को डाउनलोड सुरु हुँदैन।
- मिल्ने Windows x64/arm64, macOS 15 वा नयाँ भएको Apple Silicon, र glibc 2.36 वा नयाँ तथा आवश्यक लाइब्रेरी भएको Linux x64/arm64 मा Hex विकल्प आउँछ। Intel Mac र पुरानो glibc वा musl भएको Linux मिल्दैन। इन्जिन र मोडेल CodeNomad को इन्स्टलरभन्दा छुट्टै छन्; टर्मिनल वा API साँचो चाहिँदैन।

Ubuntu 24.04 ले glibc को आवश्यकता पूरा गर्छ, तर Ubuntu 22.04 ले गर्दैन। Hex ले अङ्ग्रेजी र फ्रेन्चसहित [Parakeet ले समर्थन गर्ने भाषाहरू](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3) बाट बोलिएको भाषा स्वतः पहिचान गर्छ। यो सूची एपको भाषाबाट स्वतन्त्र छ।

स्थानीय वाणी पहिचानले यसै उपकरणको माइक्रोफोन प्रयोग गर्छ र अफलाइन चल्छ, स्थानीय एपमा खोलिएका WSL परियोजनामा पनि। मिल्ने रिमोट विन्डोमा **श्रुतलेखन** रोज्दा **यही उपकरणमा बोलेर लेख्नुहोस्** भन्ने स्थानीय विन्डो खुल्छ। देखाइएको गन्तव्य जाँचेर **ध्वनि इनपुट सुरु गर्नुहोस्**, **रेकर्डिङ रोक्नुहोस् र ट्रान्सक्राइब गर्नुहोस्** र **प्रतिलेख घुसाउनुहोस्** रोज्नुहोस्। पाठ मात्र मस्यौदामा फर्कन्छ। रिमोट परियोजनालाई भने सर्भर जडान चाहिन्छ।

Linux को रिमोट Tauri विन्डोमा **इनपुट परीक्षण** ले बोलेर लेख्ने इन्जिन नफेरी सर्भरको आवाज API जाँच्छ। API का लागि हरेक रेकर्डिङ पुष्टि गर्नुअघि माइक्रोफोनको अनुमति माग्ने संवादमा सर्भरको ठेगाना जाँच्नुहोस्। रेकर्डिङले PulseAudio वा PipeWire को PulseAudio सेवा प्रयोग गर्छ र माथि भनिएको WAV को २४ सेकेन्डको सीमा सधैँ लागू हुन्छ।

## सन्देश वाचन {#playback}

1. TTS उपलब्ध हुँदा सन्देशमा **सन्देश वाचन गर्नुहोस्**, वा tool call मा उही कार्य प्रयोग गर्नुहोस्।
2. अन्त्य गर्न उही नियन्त्रणमा **वाचन रोक्नुहोस्** प्रयोग गर्नुहोस्; अर्को वाचन सुरु गर्दा हालको रोकिन्छ।
3. पछिका अनुरोधका लागि **वाचन (Speech)** मा सुरक्षित voice, model, mode वा format बदल्नुहोस्।

playback ले CodeNomad को text projection प्रयोग गर्छ, screenshot को वर्णन होइन: binary/image byte र permission receipt speech सामग्री होइनन्। prompt चलाउँदैन वा चयनित OpenCode model बदल्दैन।

स्वचालित conversation speech का लागि कम्पोजरको **थप कार्यहरू** मेनुमा **कुराकानी मोड सक्षम गर्नुहोस्** प्रयोग गर्नुहोस्; यो त्यही परियोजना ट्याबमा लागू हुन्छ र reload पछि रहँदैन। यो चालू हुँदा, तपाईंले पठाउने हरेक prompt सँग CodeNomad ले agent लाई जवाफ छोटो fenced `spoken` सारांशबाट सुरु गर्न भन्छ। सक्रिय मुख्य सत्रमा त्यो पूरा भएको block मात्र पढिन्छ; हरेक reply वा subagent को स्वचालित वाचन होइन। **कुराकानी मोड अक्षम गर्नुहोस्** ले लाम रोक्छ र सारांश माग्न छोड्छ। microphone input सुरु गर्दा पनि सक्रिय conversation speech रोकिन्छ। कुराकानी मोडका लागि समर्थित ढाँचामा प्लेब्याक कन्फिगर गरिएको हुनुपर्छ।

## डेटा प्रवाह र गोपनीयता {#privacy}

स्थानीय श्रुतलेखनमा अडियो उपकरणमै रहन्छ र API मा सर्दैन। **API प्रदायक** छान्दा माइक्रोफोनको अडियो CodeNomad सर्भर हुँदै प्रतिलेखन सेवामा पुग्छ। वाचन गर्न छानिएको पाठ त्यही सर्भर हुँदै TTS सेवामा पुग्छ; फर्किएको अडियो क्लाइन्टमा बज्छ। API साँचो सर्भरमै रहन्छ।

बोलिएको वा पढिने सामग्रीका लागि विश्वासिलो सेवा प्रयोग गर्नुहोस्। OpenCode को प्रमाणपत्रले वाणी सेवामा स्वतः पहुँच दिँदैन। साँचो वा सेवा परिवर्तन भविष्यका अनुरोधमा मात्र लागू हुन्छ। सर्भर अरूलाई उपलब्ध गराउनुअघि [सुरक्षा](security.md) हेर्नुहोस्।
