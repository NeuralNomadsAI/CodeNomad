# श्रुतलेखन, प्लेब्याक र आवाजमा कुराकानी

## आवाज सेट गर्नुहोस् {#configure}

**प्राथमिकताहरू → आवाज** खोल्नुहोस् (ब्राउजर वा रिमोट विन्डोमा **सेटिङहरू → आवाज**)। **श्रुतलेखन**, **प्लेब्याक** र **कुराकानी** कार्डमा तिनको अवस्था देखिन्छ।

1. स्थानीय डेस्कटप एपमा **श्रुतलेखन** अन्तर्गत [उपकरणको इन्जिन](#desktop-dictation) छान्नुहोस्। ब्राउजर र मोबाइलले API मात्र प्रयोग गर्छन्।
2. API बाट श्रुतलेखन र प्लेब्याक गर्न दुईमध्ये कुनै कार्डबाट **API प्रमाणीकरण विवरण** खोल्नुहोस्। **API कुञ्जी** र आवश्यक भए **आधार URL**, **ट्रान्सक्रिप्शन मोडेल** र **वाचन मोडेल (TTS)** भर्नुहोस्। अलग सेवा चाहिँदा **इनपुट र आउटपुटका लागि छुट्टाछुट्टै प्रदायक** चालू गरी सम्बन्धित विवरण भर्नुहोस् र **बचत गर्नुहोस्** थिच्नुहोस्।
3. **प्लेब्याक** ले **प्रदायक** देखाउँछ। **पूर्वनिर्धारित आवाज**, **प्लेब्याक मोड** र **आउटपुट ढाँचा** रोजेर **बचत गर्नुहोस्** थिच्नुहोस्।

speech सेटिङ र key जोडिएको CodeNomad server configuration का हुन्, चयनित परियोजना वा OpenCode provider connection का होइनन्। साझा गर्ने अन्य क्लाइन्टले पनि प्रयोग गर्छन्। सुरक्षित key लुकाइन्छ: खाली key field ले सुरक्षित मान राख्छ; **बचत गरिएको कुञ्जी सफा गर्नुहोस्** ले बचत गर्दा हटाउने तय गर्छ। आफ्नै endpoint र key दुवै नभएको दिशाले साझा सेटिङ प्रयोग गर्न सक्छ; छुट्टै endpoint लाई आफ्नै key र छुट्टै key लाई आफ्नै endpoint चाहिन्छ। endpoint बदल्दा अभिप्रेत key स्पष्ट दिनुहोस् र सुरक्षित कन्फिगरेसन जाँच्नुहोस्; अर्को host मा पठाउनुको सट्टा endpoint परिवर्तनले त्यस slot को सुरक्षित key हटाउँछ।

backend ले साझा default का लागि `OPENAI_API_KEY` र `OPENAI_BASE_URL` पनि प्रयोग गर्न सक्छ। सुरक्षित key खाली गर्दा environment-provided credential हट्दैन; fallback हटाउन चाहनुहुन्छ भने backend वातावरण बदलेर पुनः सुरु गर्नुहोस्।

| सेटिङ | अर्थ / default |
| --- | --- |
| Base URL | OpenAI-compatible API root, default `https://api.openai.com/v1`। input ले `audio/transcriptions`; output ले `audio/speech` प्रयोग गर्छ। |
| Transcription model / Input model | STT endpoint ले स्वीकार्ने model; default `gpt-4o-mini-transcribe`। |
| Speech model / Output model | TTS endpoint ले स्वीकार्ने model; default `gpt-4o-mini-tts`। |
| Default voice | प्रदायक voice identifier; default `alloy`। OS voice picker होइन। |
| Streaming | पूर्वनिर्धारित। provider र browser ले चयनित format समर्थन गर्दा audio आउनासाथ playback सुरु हुन्छ। |
| Buffered | बजाउनुअघि पूरा audio response पर्खन्छ। |
| Output format | `mp3`, `wav`, `opus` वा `aac`; default `mp3`। अनुकूलता browser/provider अनुसार फरक हुन्छ। |

यी कन्फिगर सेवामा अनुरोध हुन्, हरेक compatible endpoint ले हरेक model, voice वा format समर्थन गर्छ भन्ने प्रत्याभूति होइन।

## input र output परीक्षण {#test}

1. पहिले endpoint, key, model र voice परिवर्तन बचत गर्नुहोस्।
2. **API इनपुट परीक्षण** रोजेर microphone अनुमति दिनुहोस्, बोल्नुहोस्, अनि **रेकर्डिङ रोक्नुहोस्**। फर्किएको transcription जाँच्नुहोस्।
3. नमूना सुन्न **प्लेब्याक परीक्षण गर्नुहोस्** रोज्नुहोस्; **नमूना रोक्नुहोस्** ले अन्त्य गर्छ।

प्लेब्याक परीक्षणले रोजेको मोड र ढाँचा तुरुन्त प्रयोग गर्छ, तर endpoint, key, model र voice सुरक्षित सेटिङबाट आउँछन्। जुनसुकै श्रुतलेखन इन्जिन रोजे पनि **API इनपुट परीक्षण** ले सेट गरिएको API प्रदायकलाई अडियो पठाउँछ। यसले कुराकानीमा प्रम्प्ट पठाउँदैन। प्रदायकले परीक्षणको शुल्क लिन सक्छ।

## बोलेर prompt लेख्नुहोस् {#dictate}

1. **आवाज** मा **प्रम्प्ट ध्वनि इनपुट** सक्षम नै राख्नुहोस् (पूर्वनिर्धारित रूपमा यो चालू हुन्छ)।
2. **थप कार्यहरू** मा **श्रुतलेखन मोड** मा चिन्ह लगाउनुहोस्। अर्को मोड छान्नुअघि सक्रिय मोडको चिन्ह हटाउनुहोस्।
3. **थप कार्यहरू** छेउको माइक्रोफोन थिचेर बोल्नुहोस् र पाठ बनाउन छोड्नुहोस्। आवश्यक परे माइक्रोफोनको अनुमति दिनुहोस्। मिल्ने रिमोट विन्डोमा क्लिक गर्दा स्थानीय रेकर्डिङ नियन्त्रण खुल्छ।
4. पाठ हेर्नुहोस्। मस्यौदा र चयन नबदलिएको भए मात्र यसले सुरुको चयन बदल्छ। नत्र फेरि श्रुतलेखन गर्नुअघि सामान्य मोडमा **प्रतिलेख घुसाउनुहोस्** वा **प्रतिलेख हटाउनुहोस्** रोज्नुहोस्। श्रुतलेखनले मस्यौदा पठाउँदैन।

Linux मा Tauri चलाउँदा API ले वैकल्पिक WAV मोड प्रयोग गरेमा, बोलेर लेख्ने र इनपुट परीक्षण गर्ने दुवैमा रेकर्डिङ २४ सेकेन्डमा रोकिन्छ। अडियो आवाज सेवा प्रदायकलाई पठाउन **प्रतिलेखन गर्नुहोस्** वा हटाउन **रद्द गर्नुहोस्** रोज्दासम्म यही यन्त्रमा रहन्छ।

API का लागि सङ्कुचित रेकर्डिङ पनि आकारको सीमामा रोकिन्छ। त्यसपछि **प्रतिलेखन गर्नुहोस्** वा **रद्द गर्नुहोस्** रोज्न सक्नुहुन्छ।

### डेस्कटपमा इन्जिन छान्नुहोस् {#desktop-dictation}

स्थानीय डेस्कटप एपमा **प्राथमिकताहरू → आवाज → श्रुतलेखन** खोलेर **यो उपकरणको श्रुतलेखन इन्जिन** छान्नुहोस्। छनोट यस उपकरणका सबै परियोजनामा लागू हुन्छ। **API प्रदायक** ले जोडिएको सर्भरको सेटिङ प्रयोग गर्छ र माइक्रोफोनका लागि सुरक्षित सन्दर्भ चाहिन्छ।

- सुरक्षित गरिएको इन्जिन उपलब्ध छैन भने यहाँ **Hex (स्थानीय)** उपलब्ध भए त्यसलाई वा **API प्रदायक** छान्नुहोस्। Intel Mac वा macOS 15 भन्दा पुरानो संस्करणमा **API प्रदायक** प्रयोग गर्नुहोस्।
- आवाजमा Hex का लागि बाँकी भाग र हरेक भागको तथा कुल डाउनलोड आकार देखिन्छ। **Hex सक्रिय गर्नुहोस्** एकपटक थिच्दा मिल्ने फाइल जाँचेर पुनः प्रयोग गरिन्छ, बाँकी डाउनलोड हुन्छ र तयार भएपछि Hex छानिन्छ। प्रगति त्यहीँ हेर्नुहोस्। रोक्न **Hex सक्रिय गर्ने काम रद्द गर्नुहोस्** र उपलब्ध हुँदा **Hex सक्रिय गर्ने काम जारी राख्नुहोस्** रोज्नुहोस्। असफल भए वा रद्द गरे पहिलेको इन्जिन नै छानिएको रहन्छ। सेटिङ फेरि खोल्दा, तयार **Hex (स्थानीय)** छान्दा वा त्यसबाट श्रुतलेखन गर्दा अर्को डाउनलोड सुरु हुँदैन।
- मिल्ने Windows x64/arm64, macOS 15 वा नयाँ भएको Apple Silicon, र glibc 2.36 वा नयाँ तथा आवश्यक लाइब्रेरी भएको Linux x64/arm64 मा Hex विकल्प आउँछ। Intel Mac र पुरानो glibc वा musl भएको Linux मिल्दैन। इन्जिन र मोडेल CodeNomad को इन्स्टलरभन्दा छुट्टै छन्; टर्मिनल वा API साँचो चाहिँदैन।

Ubuntu 24.04 ले glibc को आवश्यकता पूरा गर्छ, तर Ubuntu 22.04 ले गर्दैन। Hex ले अङ्ग्रेजी र फ्रेन्चसहित [Parakeet ले समर्थन गर्ने भाषाहरू](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3) बाट बोलिएको भाषा स्वतः पहिचान गर्छ। यो सूची एपको भाषाबाट स्वतन्त्र छ।

रेकर्डिङ सुरु गर्दा Hex ले पृष्ठभूमिमा आफ्नो मोडेल लोड गर्छ र अन्तिम डिक्टेसनपछि तीन मिनेटसम्म तयार राख्छ।

स्थानीय वाणी पहिचान अफलाइन चल्छ, स्थानीय एपमा खोलिएका WSL परियोजनामा पनि। मिल्ने रिमोट विन्डोमा माइक्रोफोन क्लिक गरेर **यही उपकरणमा बोलेर लेख्नुहोस्** खोल्नुहोस्। गन्तव्य जाँचेर त्यस विन्डोका रेकर्डिङ र पाठ घुसाउने नियन्त्रण प्रयोग गर्नुहोस्। पाठ मात्र मस्यौदामा फर्कन्छ। रिमोट परियोजनालाई भने सर्भर जडान चाहिन्छ।

Linux को रिमोट Tauri विन्डोमा **API इनपुट परीक्षण** ले बोलेर लेख्ने इन्जिन नफेरी सर्भरको आवाज API जाँच्छ। API का लागि हरेक रेकर्डिङ पुष्टि गर्नुअघि माइक्रोफोनको अनुमति माग्ने संवादमा सर्भरको ठेगाना जाँच्नुहोस्। रेकर्डिङले PulseAudio वा PipeWire को PulseAudio सेवा प्रयोग गर्छ र माथि भनिएको WAV को २४ सेकेन्डको सीमा सधैँ लागू हुन्छ।

Linux का रिमोट Tauri विन्डोमा Gemini Live र OpenAI Realtime उपलब्ध छैनन्। यी विन्डोले बोलेर लेख्न र इनपुट परीक्षण गर्न स्थानीय रेकर्डर प्रयोग गर्छन्, र WebKit ले माइक्रोफोनमा सीधा पहुँच रोक्छ।

## सन्देश वाचन {#playback}

1. TTS उपलब्ध हुँदा सन्देशमा **सन्देश वाचन गर्नुहोस्**, वा tool call मा उही कार्य प्रयोग गर्नुहोस्।
2. अन्त्य गर्न उही नियन्त्रणमा **वाचन रोक्नुहोस्** प्रयोग गर्नुहोस्; अर्को वाचन सुरु गर्दा हालको रोकिन्छ।
3. आवाज, मोड वा ढाँचा **प्लेब्याक** मा र मोडेल **API प्रमाणीकरण विवरण** मा बदलेर बचत गर्नुहोस्।

playback ले CodeNomad को text projection प्रयोग गर्छ, screenshot को वर्णन होइन: binary/image byte र permission receipt speech सामग्री होइनन्। prompt चलाउँदैन वा चयनित OpenCode model बदल्दैन।

## आवाजमा कुराकानी {#conversation}

Gemini Live र OpenAI Realtime यो विन्डो खोल्ने सर्भरका सत्रहरूमा मात्र उपलब्ध छन्।

**कुराकानी** कार्डमा **कुराकानी इन्जिन** छान्नुहोस्:

- **परम्परागत** का लागि समर्थित ढाँचामा प्लेब्याक मात्र सेट गर्नुपर्छ। **थप कार्यहरू** मा **कुराकानी मोड** मा चिन्ह लगाउनुहोस्। CodeNomad ले सक्रिय मुख्य सत्रको जवाफको पूरा `spoken` सारांश पढ्छ। चिन्ह नहटाएसम्म वा पृष्ठ फेरि नखोलेसम्म यो परियोजना ट्याबमा लागू हुन्छ।
- **Gemini Live** र **OpenAI Realtime** का आ-आफ्नै **API कुञ्जी**, **मोडेल** र ऐच्छिक **आवाज** छन्। छानेको प्रदायकको सेटिङ बचत गर्नुहोस्। लक्षित सत्र खोलेर **थप कार्यहरू** मा **कुराकानी मोड** छान्नुहोस् र प्रदायकको सहमति संवाद देखिँदा **सहमत भएर सुरु गर्नुहोस्** थिच्नुहोस्। माइक्रोफोनको अनुमति दिनुहोस्।

सहमति संवाद खुला हुँदा प्रदायक अनुपलब्ध भएमा, **ध्वनि सेटिङ** रोजेर कुराकानीको कार्ड खोल्नुहोस्।

आवाज मोडेलले सुरुमा तोकिएको सत्रको अवस्था, देखिएको पछिल्लो जवाफ र हालैका त्रुटि पढ्न सक्छ। यसले फाइल खोल्न सक्दैन। एजेन्टलाई अनुरोध पठाउन भन्नुभयो भने यसले स्क्रिनमा पुष्टि नमागी तपाईंको सन्देशका रूपमा सिधै पठाउँछ। [कुराकानीको अनुमति मोड](permissions.md#conversation-mode) र एजेन्टका प्रश्न यथावत् लागू हुन्छन्।

सर्भरले साइन इन गरेको प्रत्येक प्रयोगकर्तालाई, वा Remote Control मा जोडी बनाइएको प्रत्येक उपकरणलाई, एकपटकमा एउटा मात्र प्रत्यक्ष कुराकानी गर्न दिन्छ। **रोक्नुहोस्** थिच्दा आवाज बन्द हुन्छ र प्रतिलेख खुलै रहन्छ। विन्डो बन्द नहुँदासम्म प्रतिलेख मेमोरीमा रहन्छ; एजेन्टलाई पठाइएका अनुरोध सत्रका सन्देशका रूपमा रहन्छन्। दुई मिनेटसम्म नबोलेमा, कुल आठ मिनेट पुगेमा, लक्षित सत्र बदलिएमा, विन्डो बन्द गरेमा वा जडान टुटेमा कुराकानी रोकिन्छ। आफैँ फेरि जडान हुँदैन र अर्को प्रदायकमा सर्दैन।

OpenAI Realtime मा **जवाफ रोक्नुहोस्** ले प्लेब्याक रोक्छ र हालको जवाफ रद्द गर्न अनुरोध गर्छ। Gemini Live मा **प्लेब्याक रोक्नुहोस्** ले यस उपकरणमा आवाज मात्र बन्द गर्छ। Gemini ले जवाफ तयार गरिरहन र एजेन्टलाई अनुरोध पठाउन सक्छ।

## डेटा प्रवाह र गोपनीयता {#privacy}

स्थानीय श्रुतलेखनमा अडियो उपकरणमै रहन्छ र API मा सर्दैन। **API प्रदायक** छान्दा माइक्रोफोनको अडियो CodeNomad सर्भर हुँदै प्रतिलेखन सेवामा पुग्छ। वाचन गर्न छानिएको पाठ त्यही सर्भर हुँदै TTS सेवामा पुग्छ; फर्किएको अडियो क्लाइन्टमा बज्छ। API साँचो सर्भरमै रहन्छ।

**Gemini Live** वा **OpenAI Realtime** चलाउँदा Google वा OpenAI ले माइक्रोफोनको अडियो, परियोजनाको नाम, ब्रान्च, वर्कट्री, सत्रको शीर्षक र अवस्था पाउँछ। देखिएको पछिल्लो जवाफको पाठ र हालैका त्रुटि पनि प्रदायकलाई पठाउन सकिन्छ। सेवाको शुल्क छानेको प्रदायकको खातामा लाग्न सक्छ।

तपाईंले बोलेको, पढ्न लगाएको वा साझा गरेको सामग्रीका लागि विश्वासिलो प्रदायक प्रयोग गर्नुहोस्। OpenCode का पहुँच विवरणले आवाज सेवामा स्वतः पहुँच दिँदैनन्। सर्भर अरूलाई उपलब्ध गराउनुअघि [सुरक्षा](security.md) हेर्नुहोस्।
