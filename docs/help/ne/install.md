# CodeNomad स्थापना गर्नुहोस्

स्थानीय डेस्कटप होस्ट रोज्नुहोस् वा [स्वतन्त्र सर्भर](server.md) चलाउनुहोस्। दुवै अवस्थामा साझा नेटिभ सेवा र इतिहास OpenCode को स्वामित्वमा हुन्छन्।

## डेस्कटप डाउनलोड {#desktop-downloads}

1. [नवीनतम रिलिज](https://github.com/NeuralNomadsAI/CodeNomad/releases/latest) खोल्नुहोस्।
2. आफ्नो अपरेटिङ सिस्टम र प्रोसेसरसँग मिल्ने build रोज्नुहोस्।
3. ZIP निकाल्नुहोस् वा प्लेटफर्म प्याकेज स्थापना/चलाउनुहोस्, त्यसपछि CodeNomad सुरु गर्नुहोस्।

| प्लेटफर्म | Electron रिलिज | Tauri रिलिज | प्लेटफर्म टिप्पणी |
| --- | --- | --- | --- |
| macOS | ZIP, Intel वा Apple Silicon | ZIP, Intel वा Apple Silicon | समावेश गरिएको रनटाइमका लागि macOS 13.5 वा पछिको आवश्यक छ। |
| Windows | ZIP, x64 | Installer, x64 | Windows 10 वा पछिको; Tauri ले WebView2 प्रयोग गर्छ। |
| Linux | Debian प्याकेज, x64 | AppImage, x64 | Ubuntu 24.04 मा build र परीक्षण गरिएको; पुराना वितरणसँग अनुकूलता सुनिश्चित छैन। |

डेस्कटप रिलिजमा ब्याकएन्ड र OpenCode installer लाई चाहिने रनटाइम स्रोत समावेश छन्, त्यसैले प्रयोग गर्न छुट्टै Node.js/npm स्थापना चाहिँदैन। Git समावेश छैन। नेटिभ ब्राउजर स्वचालन Electron र Windows Tauri मा समर्थित छ; अन्य Tauri प्लेटफर्मले iframe पूर्वावलोकन प्रयोग गर्छन्।

प्रमाणित डाउनलोड सुरु गर्दा रोकिएमा [प्लेटफर्म समस्या समाधान](troubleshooting.md#desktop-launch) हेर्नुहोस्। चेतावनी छल्नकै लागि अविश्वसनीय archive कहिल्यै नचलाउनुहोस्।

## Linux मा स्थापना {#linux-install}

डाउनलोड गरिएको रिलिज भएको फोल्डरबाट यसको वास्तविक संस्करण र फाइल नाम राख्नुहोस्:

```sh
sudo apt install ./CodeNomad-Electron-linux-x64-<version>.deb
```

Tauri AppImage का लागि:

```sh
chmod +x CodeNomad-Tauri-linux-x64-<version>.AppImage
./CodeNomad-Tauri-linux-x64-<version>.AppImage
```

FUSE उपलब्ध नभए AppImage को extraction-and-run मोड प्रयोग गर्नुहोस्:

```sh
./CodeNomad-Tauri-linux-x64-<version>.AppImage --appimage-extract-and-run
```

Electron Debian स्थापनाले Chromium sandbox कन्फिगर गर्छ। स्थापना समस्याको उपायका रूपमा sandbox अक्षम नगर्नुहोस्। Linux Tauri graphics समस्याका लागि [लक्षित WebKit उपाय](troubleshooting.md#desktop-launch) छ।

## आवश्यकता {#requirements}

| आवश्यकता | कहाँ उपलब्ध हुनुपर्छ | हालको आवश्यकता |
| --- | --- | --- |
| OpenCode CLI | चयन गरिएको कार्यान्वयन होस्ट, लागू भए चयन गरिएको WSL वितरणसमेत | न्यूनतम **2.1.2**; **2.1.4** सिफारिस/योग्यता जाँच गरिएको लक्ष्य हो। नयाँ वा अनुकूलित संस्करणलाई परीक्षण नभएको भन्दै निषेध नगरी contract जाँच गरिन्छ। |
| Git | CodeNomad ब्याकएन्ड खाताको `PATH` | रिपोजिटरी पहिचान, Git कार्य र worktree का लागि आवश्यक। |
| Node.js/npm | स्वतन्त्र सर्भर र स्रोत-build होस्ट | Node.js 24 LTS; पुनरुत्पादनयोग्य स्रोत build ले `.node-version` (**24.20.0**) प्रयोग गर्छन्। डेस्कटप रनटाइम/स्थापना स्रोतमा समावेश। |
| कार्यस्थान फोल्डर | ब्याकएन्डले पहुँच गर्न सक्ने डिस्क | स्पष्ट रूपमा खोलिएको भौतिक फोल्डर, रिमोट ब्राउजरले अनुमान गरेको उपकरण-स्थानीय फोल्डर होइन। |

Windows मा command-line/third-party पहुँच सक्षम गरेर [Git for Windows](https://gitforwindows.org/) स्थापना गर्नुहोस्। प्रयोगकर्ताले लेख्न सक्ने per-user स्थापना पर्याप्त छ। macOS/Linux मा [Git का प्लेटफर्म निर्देशन](https://git-scm.com/downloads) प्रयोग गर्नुहोस्।

`PATH` बदलेपछि डेस्कटप एप पूर्ण रूपमा बन्द गरी फेरि सुरु गर्नुहोस्, वा अभिप्रेत खातामा स्वतन्त्र ब्याकएन्ड पुनः सुरु गर्नुहोस्। ब्राउजर reload गर्दा ब्याकएन्ड वातावरण अद्यावधिक हुँदैन। WSL भित्र मात्र उपलब्ध Git ले Windows ब्याकएन्डको Git आवश्यकता पूरा गर्दैन।

Git नभए पनि भौतिक फोल्डर खोलेर डाइरेक्टरी-मात्र कुराकानी गर्न सकिन्छ, एजेन्टसँग स्थापना सहायता माग्नसमेत। रिपोजिटरी/worktree कार्य उपलब्ध हुँदैनन्; सत्र पहुँच त्यही फोल्डरमा सीमित रहन्छ। CodeNomad ले prompt/custom command अघि एजेन्टलाई ब्याकएन्ड Git उपलब्धताबारे बताउँछ र पुनःस्थापनापछि त्यो सूचना हटाउँछ। एजेन्टको कार्यान्वयन होस्ट ब्याकएन्ड होस्टभन्दा फरक हुन सक्छ, त्यसैले एजेन्टको shell मा मात्र होइन ब्याकएन्डका लागि Git स्थापना गर्नुहोस्।

## पहिलो सुरुवातमा OpenCode चयन गर्नुहोस् {#first-launch}

1. सेटअपमा अनुकूल विद्यमान executable रोज्नुहोस् वा दिइएको OpenCode स्थापना कार्य प्रयोग गर्नुहोस्।
2. परियोजना खोल्नुअघि रनटाइम स्थिति प्रमाणित गर्नुहोस्।
3. executable, स्थापना र साझा सेवा छुट्टाछुट्टै व्यवस्थापन गर्न **प्राथमिकताहरू → OpenCode** मा फर्कनुहोस्।

CodeNomad ले `PATH` का अनुकूल executable प्राथमिकता दिन्छ र स्पष्ट चयन गरिएको executable पनि समर्थन गर्छ। `PATH` ले पुरानो OpenCode सुरु गर्छ भने, सेटअपले npm बाट स्थापित OpenCode 1.x लाई पुष्टिपछि प्रतिस्थापन गर्ने, वा अर्कै तरिकाले गरिएको स्थापनाको छेउमा CodeNomad का लागि OpenCode 2 स्थापना गर्ने प्रस्ताव गर्छ, जुन स्थापनालाई यसले कहिल्यै बदल्दैन; [OpenCode सेटअप](opencode.md#select-cli) हेर्नुहोस्। CLI स्थापना/अपडेटले चलिरहेको साझा सेवा चुपचाप पुनः सुरु गर्दैन। पुनःसुरुवात/reload का असर, WSL र सत्र वातावरणका लागि [OpenCode सेटअप](opencode.md) हेर्नुहोस्।

## सट्टामा ब्राउजर प्रयोग गर्नुहोस् {#browser-install}

सर्भर होस्टमा Node.js/npm, Git र OpenCode स्थापना गरी [सर्भर सुरु गर्ने प्रक्रिया](server.md) प्रयोग गर्नुहोस्। छापिएको ठेगाना, कन्फिगर गरिएको प्रमाणीकरण र विश्वसनीय प्रमाणपत्रबाट जोडिनुहोस्। ब्राउजर/PWA लाई चलिरहेको ब्याकएन्ड चाहिन्छ; यो परियोजनाको अफलाइन प्रतिलिपि होइन।

पोर्ट, binding र TLS का लागि [प्रत्यक्ष पहुँच](remote-access.md) प्रयोग गर्नुहोस्। inbound पोर्ट नखोली उपकरण जोड्न [Remote Control](remote-control.md) प्रयोग गर्नुहोस्। विकास र प्याकेजिङ आदेशका लागि [स्रोत build](support.md#build-from-source) हेर्नुहोस्।
