# फाइल र Git

दायाँ प्यानलको **फाइलहरू** ट्याबले checkout ब्राउज, स्थानीय परिवर्तन र commit इतिहास एकै ठाउँमा दिन्छ। row चयन गर्नु र त्यसको केन्द्रीय reader खोल्नु फरक हुन्।

## checkout ब्राउज गर्नुहोस् {#browse-workspace}

1. **फाइलहरू** खोलेर **कार्यक्षेत्र** रोज्नुहोस्।
2. अर्को checkout चाहिँदा **हेर्ने कार्यवृक्ष** चयन गर्नुहोस्; आवश्यक फोल्डर विस्तार गर्नुहोस्।
3. फाइल row क्लिक गरेर चयन गर्नुहोस्। केन्द्रीय पूर्वावलोकन खोल्न वा बन्द गर्न त्यसको eye कार्य प्रयोग गर्नुहोस्।
4. देखिएको snapshot पुनःजाँच गर्न **रिफ्रेस** प्रयोग गर्नुहोस्।

| मोड | पढ्ने कुरा | कुराकानीमा असर |
| --- | --- | --- |
| कार्यक्षेत्र | ब्राउज गरिएको checkout का फाइल | सत्र सार्ने वा branch checkout हुँदैन |
| परिवर्तन | index र working-tree परिवर्तन | स्पष्ट कार्यबाट मात्र Git परिवर्तन हुन्छ |
| कमिट | पृष्ठबद्ध commit इतिहास र revision सामग्री | पढ्न-मात्र इतिहास; checkout हुँदैन |

मोड बदल्दा विस्तारित फोल्डर रहन्छन्। सूची/स्थिति/इतिहासले cached snapshot प्रयोग गर्छन् र सम्बन्धित filesystem परिवर्तन, सक्रियता वा स्पष्ट रिफ्रेसपछि पुनःजाँच्छन्; प्यानल focus गर्नु नयाँ read को प्रत्याभूति होइन। देखिने Workspace फोल्डरले backend host मा बनाइएका, सम्पादित, नाम बदलिएका वा मेटिएका फाइल आफैं पत्ता लगाउँछन्, लगातार गतिविधिमा बढीमा पाँच सेकेन्डमा एक पटक; संक्षिप्त फोल्डर र अन्य worktree तपाईंले देखाउँदा मात्र फेरि पढिन्छन्।

row कार्यमा **मार्ग (Path) प्रतिलिपि गर्नुहोस्** र क्लाइन्टले ब्याकएन्ड मार्ग खोल्न समर्थन गर्दा **पूर्वनिर्धारित अनुप्रयोगमा खोल्नुहोस्**, **फोल्डरमा देखाउनुहोस्**, **फाइल व्यवस्थापकमा खोल्नुहोस्** र **यहाँ टर्मिनल खोल्नुहोस्** जस्ता file-manager/editor/terminal कार्य छन्। ठाउँ सीमित भए कार्य **{name} का लागि थप कार्यहरू** मा जान सक्छन्; `{name}` को ठाउँमा फाइल वा फोल्डर नाम आउँछ। रिमोट ब्राउजरले सर्भर मार्गलाई स्थानीय उपकरण मार्ग मान्न सक्दैन; [Remote Control](remote-control.md) हेर्नुहोस्।

## स्रोत सम्पादन र सुरक्षित बचत {#edit-save}

1. eye कार्यबाट Workspace पाठ फाइल खोल्नुहोस्।
2. Markdown मा सम्पादनका लागि **स्रोत देखाउनुहोस्**, वा rendered रूप पढ्न **Markdown पूर्वावलोकन** रोज्नुहोस्।
3. सम्पादन गरी **बचत** रोज्नुहोस्, वा editor मा focus हुँदा **Ctrl/Cmd+S** थिच्नुहोस्।
4. फाइल बाहिर बदलिएको भए overwrite पुष्टि समीक्षा गर्नुहोस्; त्यो परिवर्तन नमेटी आफ्नो मस्यौदा राख्न **रद्द गर्नुहोस्** रोज्नुहोस्।

बचतले linked worktree समेत ब्राउज गरिएको checkout को वास्तविक फाइल लेख्छ; prompt पठाउँदैन वा सम्पादन stage/commit गर्दैन। बचतले पहिले आधिकारिक फाइल फेरि पढ्छ। conflict संवादले **फाइल एजेन्टद्वारा परिमार्जन गरिएको थियो। एजेन्टका परिवर्तनहरू अधिलेखन (Overwrite) गर्ने?** भन्छ; कुनै पनि बाह्य लेखकको परिवर्तनलाई उत्तिकै सावधानीले लिनुहोस्।

reader बन्द वा बदलिए पनि dirty स्रोत मस्यौदा परियोजना instance, directory र path अनुसार renderer memory मा रहन्छन्। filesystem रिफ्रेसले चुपचाप तिनलाई बदल्दैन। यो टिकाउ फाइल भण्डारण होइन: क्लाइन्ट restart/reload अघि महत्त्वपूर्ण सम्पादन बचत वा प्रतिलिपि गर्नुहोस्। read/write असफल हुँदा मस्यौदा रहन्छ। स्पष्ट **रिफ्रेस** ले नबचाइएका सम्पादन हटाउनुअघि चेतावनी दिन्छ।

पछाडिको close बटनले reader बन्द गर्दा कुराकानीमा फर्किन्छ; कम्पोजर reader मुनि उपलब्ध रहन्छ। सत्र/worktree बदल्दा चयनित reader खाली हुन्छ, मस्यौदा बचत हुने वाचा होइन। ब्राउजर पूर्वावलोकन खोल्दा reader बदलिन्छ; फाइल खोल्दा त्यो दृश्य chat मोडमा फर्किन्छ।

## पढ्न-मात्र र सीमित पूर्वावलोकन {#preview-limits}

1. eye कार्यबाट छवि, binary फाइल वा ऐतिहासिक परिवर्तन खोल्नुहोस्।
2. diff मा आवश्यकअनुसार **Split view मा जानुहोस्** / **Unified view मा जानुहोस्**, word wrap र अपरिवर्तित-क्षेत्र नियन्त्रण प्रयोग गर्नुहोस्।
3. chat मा फर्कन reader बन्द गर्नुहोस्।

| सामग्री | उपलब्ध व्यवहार |
| --- | --- |
| Markdown स्रोतसमेत Workspace पाठ | स्पष्ट Save सहित सम्पादनयोग्य |
| Workspace छवि | पढ्न-मात्र छवि पूर्वावलोकन |
| अन्य binary सामग्री | पढ्न-मात्र अनुपलब्ध-पूर्वावलोकन fallback |
| Changes/Commits पाठ diff | पढ्न-मात्र तुलना, कुनै पक्षको editor होइन |
| Git छवि diff | ठ्याक्कै तुलना गरिएका revision का Before/After छवि |

पूर्वावलोकन read सीमित छन्; ठूलो/असमर्थित सामग्री असीमित लोड हुनुको सट्टा अनुपलब्ध हुन सक्छ। ऐतिहासिक छविमा हालको worktree फाइल प्रतिस्थापन हुँदैन। पूर्वावलोकन असफल हुनु मूल फाइल छैन भन्ने होइन। उपलब्ध भए उपयुक्त बाह्य अनुप्रयोगमा फाइल खोल्नुहोस्, पूर्वावलोकन पाउनकै लागि revision नबदल्नुहोस्।

## Stage, unstage र commit {#stage-commit}

1. **परिवर्तनहरू** रोजी **Staged परिवर्तनहरू** र **परिवर्तनहरू** जाँच्नुहोस्।
2. **फाइल स्टेज गर्नुहोस्** / **फाइल अनस्टेज गर्नुहोस्** प्रयोग गर्नुहोस्, चयनित-फाइल कार्यका लागि धेरै row छान्नुहोस्, वा खण्डबीच row तान्नुहोस्।
3. **Staged परिवर्तनहरू** को माथि सन्देश लेखी **कमिट गर्नुहोस्** रोज्नुहोस्।

संक्षिप्त खण्ड header पनि drop target रहन्छन्। खण्ड संक्षिप्त गर्दा वा मोड बदल्दा तिनको अवस्था र commit-सन्देश मस्यौदा रहन्छ। लामो खण्डले पहिले 200 फाइल देखाउँछ, त्यसपछि **480 फाइलहरू देखाइएका छैनन्** जस्तो पङ्क्ति र अर्को फाइलहरू त्यहीँ देखाउन **थप 200 देखाउनुहोस्** आउँछ; खण्डको गणना पूर्ण कुल नै रहन्छ, र हालको, पूर्वावलोकन गरिएको र चयन गरिएका फाइल देखिइरहन्छन्। Shift-click दायराले देखिएका row मात्र समेट्छ, त्यसैले bulk कार्यमा तपाईंले नदेखेको फाइल कहिल्यै पर्दैन। staging/unstaging ले ब्राउज गरिएको worktree को index बदल्छ; commit ले staged सामग्री मात्र अभिलेख गर्छ। unstaging ले worktree सम्पादन खारेज गर्दैन।

commit अघि staged फाइल समीक्षा गर्नुहोस्, विशेष गरी agent वा अर्को क्लाइन्टले पनि त्यहाँ लेख्दा। असफल commit स्वतः दोहोरिँदैन। पुनःप्रयासअघि स्थिति/इतिहास रिफ्रेस गरी त्रुटि जाँच्नुहोस्, किनकि जवाफ हराउनु commit बनेन भन्ने प्रमाण होइन।

## commit इतिहास पढ्नुहोस् {#commit-history}

1. **कमिटहरू** रोजी commit चयन गरेर सन्देश र बदलिएका फाइल पढ्नुहोस्।
2. लोड भएका समूह छान्न **लोड भएका कमिटहरू छान्नुहोस्…**, वा अर्को पृष्ठ ल्याउन **पुराना कमिटहरू लोड गर्नुहोस्** प्रयोग गर्नुहोस्।
3. eye कार्यबाट बदलिएको फाइल खोल्नुहोस्।

पाठ इतिहासले commit लाई पहिलो parent सँग (वा root commit का लागि खाली आधारसँग) तुलना गर्छ। HEAD बदल्दैन वा सत्र सार्दैन। लोड भएका commit छान्नु सर्भरभरको Git log खोज होइन। नयाँ commit पछि हालको इतिहासबाट सुरु गर्न रिफ्रेस गर्नुहोस्; विद्यमान pagination ले सुरुवाती इतिहास snapshot राख्छ।

## whitespace र line ending {#whitespace-line-endings}

1. **सेटिङहरू → उन्नत → खाली ठाउँ मात्रका परिवर्तनहरू लुकाउनुहोस्** खोल्नुहोस्।
2. Changes बाट हटाइएका unstaged whitespace-मात्र सम्पादन हेर्नुपरे यो बन्द गर्नुहोस्।
3. commit अघि वास्तविक diff र staged सामग्री समीक्षा गर्नुहोस्।

यो सेटिङ default मा चालू छ। यसको मुख्य असर योग्य unstaged tracked पाठ परिवर्तनलाई Changes सूची, count, selection, bulk staging र drag कार्यबाट लुकाउनु हो। लुकेका फाइल unstaged नै रहन्छन्। staged फाइल र untracked, added/deleted/renamed तथा binary फाइल देखिइरहन्छन्। असफल/असमर्थित detection ले अनुमान नगरी फाइल देखाउँछ।

Git को सूची detection ले बीचको whitespace, CRLF-मात्र परिवर्तन र थपिएका/हटाइएका अन्तिम newline बेवास्ता गर्न सक्छ। diff reader को whitespace तुलना साँघुरो छ: indentation र पछाडिका space/tab, सबै बीचका whitespace होइन। प्रदर्शन प्राथमिकता जे भए पनि Stage र Commit ले ठ्याक्कै सामग्रीमा काम गर्छन्।

line-ending र byte-order-mark भिन्नताले highlighted line को सट्टा तथ्यात्मक टिप्पणी दिन सक्छ। सेटिङ बन्द गर्दा पनि editor ले सबै line-ending/BOM परिवर्तन वा समान लम्बाइका trailing-whitespace साटफेर देखाउँदैन। दृश्यतः खाली diff समान byte को प्रमाण होइन।

## Git सुरु गर्नुहोस् {#initialize-git}

1. रिपोजिटरी नभएको फोल्डरमा **परिवर्तनहरू** वा **कमिटहरू** खोल्नुहोस्।
2. **Git सुरु गर्नुहोस्** रोज्नुहोस्; पुष्टिबिना तुरुन्त चल्छ।
3. परियोजना/सत्र रिफ्रेस पर्खेर तयार हुँदा स्पष्ट stage र commit गर्नुहोस्।

सुरुवातले स्पष्ट खोलिएको फोल्डरमा `.git` बनाउँछ; parent डाइरेक्टरी initialize गर्दैन वा पहिलो commit बनाउँदैन। ब्याकएन्डमा Git नभए directory-only कुराकानी र Workspace ब्राउज सम्भव रहन्छन्, तर initialization र Git कार्य उपलब्ध हुँदैनन्। असफलता अनिश्चित भए पुनःप्रयासअघि रिफ्रेस गर्नुहोस्; कुनै initialization अनुरोध स्वतः दोहोरिँदैन। [परियोजना](projects.md) हेर्नुहोस्।
