# परियोजना र worktree

परियोजना ट्याबले CodeNomad लाई ब्याकएन्ड कम्प्युटरको फोल्डरसँग जोड्छ। ट्याब खोल्नु, checkout ब्राउज गर्नु र कुराकानी परिवार सार्नु फरक कार्य हुन्।

## परियोजना खोल्नुहोस् {#open-project}

1. गृह पृष्ठ खोल्न **नयाँ उदाहरण** (`+`) क्लिक गर्नुहोस्।
2. **फोल्डरहरू ब्राउज गर्नुहोस्** रोजी ब्याकएन्ड फोल्डर चयन गरेर खोल्नुहोस्; वा **भर्खरका फोल्डरहरू** अन्तर्गतको प्रविष्टि रोज्नुहोस्।
3. रिपोजिटरी प्रतिलिपिका लागि **Git Repo क्लोन गर्नुहोस्** रोजी **रिपोजिटरी URL** र **गन्तव्य फोल्डर** भर्नुहोस्, अनि **क्लोन गर्नुहोस्**।

रिमोट सर्भर ब्राउज गर्नु त्यस सर्भरको फाइल प्रणाली ब्राउज गर्नु हो, आफ्नो फोन वा ल्यापटपको होइन। परियोजना खोल्दा प्रत्येक ट्याबको छुट्टै OpenCode daemon बन्दैन। कुराकानी नेटिभ OpenCode सत्र हुन्; तिनको आयु ट्याबको आयु होइन।

क्लोनले गन्तव्यमा रिपोजिटरी लेख्छ। **यदि पहिले नै अवस्थित छ भने पहिले गन्तव्य फोल्डर हटाउनुहोस्।** विनाशकारी छ: त्यहाँका सबै सामग्री मेट्न मिल्दा मात्र सक्षम गर्नुहोस्। अनिश्चित भए नयाँ गन्तव्य प्रयोग गर्नुहोस्। क्लोन असफल भयो भन्दै विद्यमान परियोजना नमेट्नुहोस्; फेरि प्रयासअघि देखाइएको गन्तव्य र त्रुटि जाँच्नुहोस्।

भर्खरका प्रविष्टि shortcut हुन्। **कार्यस्थान पुन: नामकरण गर्नुहोस्** ले देखिने नाम बदल्छ; **भर्खरको सूचीबाट हटाउनुहोस्** ले shortcut हटाउँछ, फाइल वा कुराकानी होइन। recent परियोजनाको पङ्क्ति रोज्दा नयाँ ट्याब खुल्छ। विद्यमान ट्याबमा फर्कन **खुला परियोजनामा जानुहोस्** प्रयोग गर्नुहोस्।

## नयाँ-इन्स्ट्यान्स launcher प्रयोग गर्नुहोस् {#new-instance-launcher}

1. `+` लामो थिच्नुहोस् वा right-click गर्नुहोस्; त्यहाँ keyboard focus हुँदा **Alt+Down**, **Shift+F10** वा Menu key प्रयोग गर्नुहोस्।
2. भर्खरका परियोजना खोज्नुहोस्, वा **ब्राउज…**, **अस्थायी** वा **क्लोन…** चयन गर्नुहोस्।

सामान्य क्लिकले अझै पूर्ण गृह पृष्ठ खोल्छ। launcher shortcut हो, व्यवस्थापन सतह होइन: recent परियोजनाको नाम बदल्न/हटाउन र सर्भर bookmark व्यवस्थापन गर्न गृह पृष्ठ प्रयोग गर्नुहोस्। Escape ले launcher बन्द गरी `+` मा focus फर्काउँछ।

## ट्याब बन्द गरेर परियोजना बन्द गर्नुहोस् {#close-stop}

1. ट्याबको close बटन वा कमाण्ड प्यालेटको **ट्याब बन्द गर्नुहोस्** प्रयोग गर्नुहोस्।
2. यसले त्यो ट्याबको परियोजना CodeNomad मा बन्द गर्छ र CodeNomad ले त्यो जडान पछ्याउन छोड्छ। सत्र OpenCode मा चलिरहन्छन्।
3. Browse वा Recents बाट फोल्डर फेरि खोल्दा ती सत्र फेरि भेटिन्छन्।

| कार्य | दायरा र असर | यसले नगर्ने काम |
| --- | --- | --- |
| ट्याब बन्द | त्यो ट्याबको CodeNomad परियोजना जडान | परियोजना फाइल वा इतिहास मेट्दैन; OpenCode सत्र वा साझा सेवा रोक्दैन |
| सत्र रोक्ने | चयन गरिएको कुराकानीको कार्यान्वयन | परियोजना बन्द वा इतिहास मेट्दैन |

उही फोल्डरको अर्को ट्याबको छुट्टै जडानमा असर पर्दैन। उही जडान अर्को विन्डोमा पनि देखाइएको छ भने त्यहाँको ट्याब पनि बन्द हुन्छ र सूचना देखिन्छ। CodeNomad ले OpenCode Location हटाउँदैन। कार्यान्वयन अन्त्य गर्न सम्बन्धित सत्र स्पष्ट रोक्नुहोस्। साझा-सेवा मर्मत [OpenCode सेटअप](opencode.md) मा छ।

## अस्थायी कार्यस्थान {#temporary-workspaces}

1. launcher मा **अस्थायी** वा गृह पृष्ठमा **नयाँ अस्थायी उदाहरण** रोज्नुहोस्।
2. खाली CodeNomad-व्यवस्थित फोल्डरमा काम गर्नुहोस्; Git स्वतः सुरु हुँदैन।
3. ट्याब बन्द गर्दा **राख्नुहोस्**, **हटाउनुहोस्** वा **रद्द गर्नुहोस्** रोज्नुहोस्। ट्याब menu मा **परियोजनाको रूपमा राख्नुहोस्** पनि छ।

| चयन | असर | पुनःप्राप्ति |
| --- | --- | --- |
| राख्ने | फोल्डर र कुराकानी राख्छ, अस्थायी स्थिति हटाएर recent परियोजना थप्छ | Recents बाट फेरि खोल्नुहोस्; फोल्डर सर्दैन |
| हटाउने | अस्थायी कार्यस्थानका कुराकानी र फाइल मेट्छ | Undo छैन; चाहिने कुरा पहिले अन्तै बचत गर्नुहोस् |
| रद्द | अस्थायी कार्यस्थान खुलै राख्छ | काम जारी राख्नुहोस् वा पछि निर्णय गर्नुहोस् |

कुराकानी, फाइल वा नपठाइएको मस्यौदा नभएको अछुतो अस्थायी ट्याब बन्द गर्दा चुपचाप हटाइन्छ। खुला अस्थायी ट्याब सामान्य startup restoration मा समावेश हुन्छन्, तर बन्द अस्थायी फोल्डर फेरि सुरु गर्न गृह पृष्ठमा छुट्टै सूची छैन।

कुराकानी चलिरहेको वा फोल्डर अर्को ट्याब/विन्डोमा खुला हुँदा Discard अस्वीकार हुन्छ। पहिले run रोक्नुहोस् र अरू दृश्य बन्द गर्नुहोस्। हटाइ असफल भए अस्थायी नै रहन्छ: parent डाइरेक्टरी हातैले मेट्नुको सट्टा बताइएको समस्या समाधान गरी फेरि प्रयास गर्नुहोस्।

## worktree चयन वा सिर्जना {#select-create-worktree}

1. parent कुराकानी खोलेर कम्पोजर worktree selector प्रयोग गर्नुहोस्। साँघुरो लेआउटमा यो तीर-मात्र नियन्त्रण हुन्छ।
2. पत्ता लागेको विद्यमान worktree चयन गर्नुहोस्, वा **+ Worktree सिर्जना गर्नुहोस्** रोज्नुहोस्।
3. सिर्जनाका लागि **नाम** भरेर **Worktree सिर्जना गरी प्रयोग गर्नुहोस्** रोज्नुहोस्।

CodeNomad ले OpenCode बाट worktree पत्ता लगाई खोलिएको रिपोजिटरीकै हो भनी जाँच्छ। नयाँ branch नाम चयन गरिएको checkout को HEAD बाट सुरु हुन्छ। विद्यमान branch नामले त्यस branch को हालको revision प्रयोग गर्छ; अर्को ठाउँमा checkout भएको branch लाई Git ले अस्वीकार गर्न सक्छ। worktree ले default `.codenomad/worktrees` स्थान प्रयोग गर्छन्। commit नभएका परिवर्तन मूल checkout मै रहन्छन्; सिर्जनाले नयाँ worktree मा तिनको प्रतिलिपि गर्दैन।

कम्पोजर selector ले parent कुराकानी र सबै तहका descendants लाई प्रमाणित परिवारका रूपमा सार्छ। उप-सत्रले यो selector स्वतन्त्र बदल्न सक्दैन। सक्रिय सत्रले कार्य रोक्छन्: परिवारलाई सकिन दिनुहोस् वा पहिले कार्यान्वयन रोक्नुहोस्। अर्को move माग्नुअघि अघिल्लो टुङ्गिन पर्खनुहोस्; त्रुटि भए फेरि प्रयासअघि ताजा कुराकानी/worktree अवस्था जाँच्नुहोस्।

यसको विपरीत [फाइल](files.md) को **हेर्ने कार्यवृक्ष** ले प्यानलले पढ्ने checkout मात्र बदल्छ। कुराकानी सार्दैन, branch switch गर्दैन वा अर्को shell आदेश चल्ने ठाउँ बदल्दैन।

## worktree हटाउनुहोस् {#remove-worktree}

1. कम्पोजर worktree सूचीमा हटाउन मिल्ने branch worktree का लागि **Worktree मेटाउनुहोस्** प्रयोग गर्नुहोस्।
2. लक्ष्य फोल्डर समीक्षा गर्नुहोस्। स्थानीय परिवर्तन गुमाउन नमिलेसम्म **बलपूर्वक मेटाउनुहोस् (स्थानीय परिवर्तनहरू खारेज गर्नुहोस्)** बन्द राख्नुहोस्।
3. मेटाइ पुष्टि गरी परिणामी inventory जाँच्नुहोस्।

मेटाइले worktree को स्थानीय फोल्डर हटाउँछ। Git को मुख्य checkout हटाउन मिल्ने लक्ष्य होइन। CodeNomad ले प्रभावित कुराकानी परिवार मूल checkout मा फर्काएर तिनको स्थान प्रमाणित गरेपछि worktree हटाउँछ; सक्रिय सत्रले हटाइ रोक्न सक्छन्। मेटाइ commit नभएका फाइलको archive वा backup होइन।

Git ले modified/untracked फाइलका कारण अस्वीकार गरे ती जोगाउनुहोस् वा सफा गरेर पुनःप्रयास गर्नुहोस्। बलपूर्वक मेटाइले ती स्पष्ट रूपमा नष्ट गर्छ। डाइरेक्टरी lock भए त्यसलाई प्रयोग गर्ने टर्मिनल, editor, watcher र background प्रक्रिया बन्द गर्नुहोस्। record हराए worktree रिफ्रेस गरी पुनःप्रयासअघि मार्ग जाँच्नुहोस्। निदान साझा गर्न त्रुटि संवादले **Sanitized प्रतिलिपि गर्नुहोस्** दिन्छ; sanitized पाठ पनि पहिले समीक्षा गर्नुहोस्।

## Git सुरु वा त्यसबिना काम गर्नुहोस् {#initialize-git}

1. Git उपलब्ध सामान्य फोल्डरका लागि **फाइलहरू → परिवर्तनहरू** वा **कमिटहरू** खोल्नुहोस्।
2. **Git सुरु गर्नुहोस्** रोज्नुहोस्। यसले थप पुष्टिबिना तुरुन्त काम गर्छ।
3. परियोजना metadata र कुराकानी ताजा हुन पर्खनुहोस्; CodeNomad बाहिर Git सुरु गरिएको भए **रिफ्रेस** प्रयोग गर्नुहोस्।

सुरुवातले स्पष्ट खोलिएको फोल्डरमा रिपोजिटरी बनाउँछ, त्यसको parent मा होइन। यसले commit गर्दैन। असफल भए सन्देश जाँचेर पुनःप्रयासअघि रिफ्रेस गर्नुहोस्: अनिश्चित जवाफ स्वतः दोहोरिँदैन।

ब्याकएन्डले Git चलाउन नसके स्पष्ट खोलिएको फोल्डरका लागि directory-only मोडमा कुराकानी र सीमित फाइल ब्राउज उपलब्ध रहन्छन्। worktree कार्य र Git सुरुवातका लागि त्यही ब्याकएन्डमा Git चाहिन्छ। [स्थापना](install.md) र [फाइल](files.md) हेर्नुहोस्।
