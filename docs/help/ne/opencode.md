# OpenCode सेटअप

## CLI चयन वा स्थापना {#select-cli}

1. **सेटिङहरू → OpenCode** खोलेर executable चयन गर्न **OpenCode संस्करण** मुनिको **OpenCode बाइनरी** card प्रयोग गर्नुहोस्।
2. स्वचालित प्रविष्टि चयनमै राख्नुहोस्, वा **अर्को बाइनरी छान्नुहोस्…** खोलेर **बाइनरीको लागि ब्राउज गर्नुहोस्...** प्रयोग गर्नुहोस् अथवा मार्ग भरी **थप्नुहोस्** रोज्नुहोस्।
3. **स्थिति र अपडेट जाँच गर्नुहोस्** प्रयोग गर्नुहोस्। OpenCode नभए **OpenCode स्थापना गरी सुरु गर्नुहोस्** रोज्नुहोस्; पहिले होस्ट र स्थापना दायरा समीक्षा गर्नुहोस्।
4. सेटअपले **जडान गरी जारी राख्नुहोस्** दिए बताइएको समस्या समाधानपछि प्रयोग गर्नुहोस्।

**प्रयोगकर्ताका लागि स्थापना गरी PATH मिलाउनुहोस्** ले त्यस प्रयोगकर्ताको terminal सेटअप बदल्छ; त्यसपछि नयाँ terminal खोल्नुहोस्। ब्राउजर CodeNomad सर्भरसँग जोडिन्छ: यसको file picker र executable चयन त्यस सर्भरका हुन्, ब्राउज गर्ने उपकरणका होइनन्।

PATH मा पुरानो OpenCode पहिले आउँदा दिइने कार्य त्यो कसरी स्थापना गरिएको थियो भन्नेमा निर्भर हुन्छ। npm बाट स्थापित OpenCode 1.x का लागि **OpenCode {version} लाई OpenCode 2 ले प्रतिस्थापन गर्नुहोस्** ले पुष्टि माग्छ, त्यो npm package हटाउँछ र उही npm फोल्डरमा OpenCode 2 स्थापना गर्छ; OpenCode डेटा फोल्डर राखिन्छ, र OpenCode 2 ले 1.x कुराकानी आफैं import गर्छ। अर्कै तरिकाले (winget, Homebrew, हातैले) स्थापित पुरानो वा प्रयोग गर्न नमिल्ने OpenCode कहिल्यै बदलिँदैन: **CodeNomad का लागि OpenCode 2 स्थापना गर्नुहोस्** ले त्यसको छेउमा user npm फोल्डरमा OpenCode 2 स्थापना गर्छ, र त्यसपछि CodeNomad ले त्यही प्रतिलिपि प्रयोग गर्छ। यदि त्यो पुरानो आदेश आफैं user npm फोल्डरमा छ (जस्तै `~/.local/bin` मा link), वा त्यो फोल्डरमा लेख्न सकिँदैन भने, setup ले यो कार्य देखाउनुको सट्टा कारण बताउँछ: आदेश सार्नुहोस् वा पुनः नामकरण गर्नुहोस्, वा फोल्डरको अनुमति सच्याउनुहोस्, त्यसपछि **स्थिति र अपडेट जाँच गर्नुहोस्** रोज्नुहोस्। terminal को `opencode` आदेशले अझै पुरानो संस्करण सुरु गर्न सक्छ। स्पष्ट चयन गरिएको custom executable कहिल्यै प्रतिस्थापन हुँदैन।

**OpenCode संस्करण** कार्डमा **चलिरहेको सेवा** को संस्करण **स्थापित संस्करण** भन्दा फरक वा अज्ञात हुँदा छुट्टै देखिन्छ। **संस्करणका विवरण** मा न्यूनतम संस्करण र त्यसबाट फरक भए सिफारिस गरिएको संस्करण देखिन्छ।

## होस्ट, WSL र साझा-सेवा दायरा {#execution-host}

Windows मा चयनित WSL executable रोजिएको वितरणभित्र चल्छ। त्यहीं स्थापना/अपडेट गर्नुहोस् र त्यस वितरणभित्र अर्थपूर्ण मार्ग प्रयोग गर्नुहोस्। WSL जडान Windows localhost forwarding मा निर्भर छ। Windows CLI र WSL CLI साट्न मिल्ने कार्यान्वयन वातावरण होइनन्।

परियोजना ट्याब बन्द गर्दा त्यो परियोजना CodeNomad मा बन्द हुन्छ; सत्र OpenCode मा चलिरहन्छन् र परियोजना फेरि खोल्दा देखिन्छन्। पूरै विन्डो बन्द गर्दा, एप बन्द गर्दा वा reload गर्दा परियोजना जडान पुनर्स्थापनाका लागि राखिन्छन्; ती कार्य वा ब्याकएन्ड बन्द हुँदा पनि साझा daemon रोकिँदैन। [परियोजना](projects.md) हेर्नुहोस्।

## स्टार्टअपमा सुरु गर्नुहोस् {#login-start}

**सेटिङहरू → OpenCode** मा **स्टार्टअपमा सुरु गर्नुहोस्** ले तपाईं साइन इन गर्दा अपरेटिङ सिस्टमलाई OpenCode सेवा पृष्ठभूमिमा सुरु गर्न लगाउँछ, CodeNomad बन्द भए पनि। तपाईंले सक्रिय नगरेसम्म यो बन्द रहन्छ, अर्को साइन इनदेखि लागू हुन्छ र CodeNomad सर्भर चलाउने कम्प्युटरमा तपाईंको खातामा लागू हुन्छ। यसले **OpenCode बाइनरी** card मा चयन गरिएको executable सुरु गर्छ; अर्को नेटिभ executable चयन गर्दा यो अद्यावधिक हुन्छ, नत्र अघिल्लै सुरु गरिरहन्छ।

| प्रणाली | OpenCode के ले सुरु गर्छ | क्र्यासपछि |
| --- | --- | --- |
| Windows | तपाईंको खाताका लागि लुकेको scheduled task, पासवर्ड वा प्रशासक अधिकार बिना। WSL executable आफ्नो distribution भित्र सुरु हुन्छ। | फेरि सुरु हुँदैन। |
| macOS | एउटा LaunchAgent। | macOS ले फेरि सुरु गर्छ। |
| Linux | लगइनमा सुरु हुने systemd प्रयोगकर्ता सेवा, linger सक्रिय नगरी। | systemd ले फेरि सुरु गर्छ। |

बन्द गर्दा त्यो task, LaunchAgent वा सेवा मात्र हटाइन्छ; चलिरहेको OpenCode चलिरहन्छ। CodeNomad सर्भर WSL भित्र वा लगइन सुरु नभएको अर्को प्रणालीमा चल्दा **यो प्रणालीमा उपलब्ध छैन। ** देखिन्छ।

## अपडेट, पुनःसुरुवात वा reload {#maintenance}

1. **सेटिङहरू → OpenCode** मा **स्थिति र अपडेट जाँच गर्नुहोस्** रोज्नुहोस्।
2. स्थापित CLI फाइल बदल्न उपलब्ध हुँदा **OpenCode {version} मा अद्यावधिक गर्नुहोस्** रोजी सकिन पर्खनुहोस्।
3. चलिरहेको सेवाको स्थिति समीक्षा गर्नुहोस्। हरेक जोडिएको क्लाइन्टका लागि चयनित स्थापना सक्रिय गर्न चाहँदा मात्र **साझा सेवा पुनः सुरु गर्नुहोस्** प्रयोग गर्नुहोस्।
4. केही स्थापना नगरी प्रक्रिया पुनःसुरुवात गर्न **समस्या समाधान** विस्तार गरी **OpenCode सेवा पुनः सुरु गर्नुहोस्** रोजेर पुष्टि गर्नुहोस्।

| कार्य | दायरा र असर |
| --- | --- |
| CLI अपडेट | समर्थित स्थापित executable बदल्छ; चलिरहेको daemon स्वतः पुनः सुरु गर्दैन। |
| सेवा पुनःसुरुवात | साझा प्रक्रिया बदल्छ र सबै जोडिएका OpenCode क्लाइन्टको सक्रिय काम रोक्छ; सत्र इतिहास रहन्छ। |
| OpenCode कन्फिगरेसन reload | प्रक्रिया राख्छ। सबै जडित क्लाइन्टका pending अनुमति/Form रद्द र terminal/background command बन्द गर्छ; सक्रिय काम रोकिन सक्छ। |

सुरक्षित कन्फिगरेसन वा स्थापित plugin अझै अनुपलब्ध हुँदा **OpenCode कन्फिगरेसन पुनः लोड गर्नुहोस्** (चलिरहेको सेवाले समर्थन गर्दा **समस्या समाधान** अन्तर्गत) प्रयोग गर्नुहोस्। चेतावनी पढेर पुष्टि गर्नुहोस्: पुनः लोड गर्दा सबै जडित क्लाइन्टको सक्रिय काम रोकिन सक्छ। CodeNomad ले पुरानो चयनित CLI बाट नयाँ चलिरहेको daemon downgrade गर्दैन।

## सत्र वातावरण {#session-environment}

1. **सेटिङहरू → उन्नत** खोली **वातावरण चरहरू (Environment Variables)** विस्तार गर्नुहोस्।
2. मान थप्नुहोस्, सम्पादन गर्नुहोस् वा हटाउनुहोस्। सुरक्षित गरिएका नाम पढ्न मात्र मिल्छ। Rune मा चर छान्नुहोस्, त्यसको मान सम्पादन गर्नुहोस् र **सुरक्षित गर्नुहोस्** रोज्नुहोस्।
3. त्यस कुराकानीमा हालको वातावरण लागू गर्न CodeNomad बाट अर्को prompt, custom command वा session shell अनुरोध पठाउनुहोस्।

यो configuration-profile सेटिङ हो। कुराकानी खोल्नु/पढ्नु वा सेटिङ बचतले नेटिभ सत्र बदल्दैन। override हटाउँदा execution host को inherited मान फर्कन्छ, वा त्यहाँ नभए हट्छ।

वातावरणले त्यस नेटिभ सत्रका पछिल्ला स्थानीय shell सुरुवात नियन्त्रण गर्छ। चलिरहेका प्रक्रियाले आफ्नै वातावरण राख्छन्। यसले provider, MCP/LSP server, स्वतन्त्र terminal वा Location-मात्र background shell पुनःकन्फिगर **गर्दैन**। queued prompt ले प्रत्येकको आफ्नै वातावरण capture गर्दैनन्, र अर्को OpenCode क्लाइन्टले उही सत्र वातावरण बदल्न सक्छ। पूर्णतः OpenCode भित्र बनेका child सत्रले CodeNomad को send-time update पाउँछन् भनेर नमान्नुहोस्।

रोकिएको सेवा सुरु गर्दा अनुमत variable पनि पठाइन्छन्; विद्यमान daemon मा जोडिँदा यसको process environment बदलिँदैन। WSL मा मान Linux execution environment सँग मिसिन्छन्, Windows PATH/HOME सँग होइन।

## नेटिभ कन्फिगरेसन फाइल सम्पादन {#configuration-files}

1. **सेटिङहरू → कन्फिग फाइलहरू** खोली **फाइल** चयन गर्नुहोस्।
2. देखाइएको मार्ग जाँचेर सम्पादन गरी **बचत गर्नुहोस्** रोज्नुहोस्।
3. फाइल फेरि पढ्न **पुन: लोड गर्नुहोस्** प्रयोग गर्नुहोस्; यो **OpenCode कन्फिगरेसन पुनः लोड गर्नुहोस्** होइन।

यो editor ले सूचीकृत global `opencode.json` र `opencode.jsonc` फाइल मात्र देखाउँछ, जुन **CodeNomad सर्भर प्रयोगकर्ताको** `.config/opencode` डाइरेक्टरीमुनि छन्। यो मनपरी-file editor, Project-config selector वा WSL/custom-discovery daemon ले त्यो फाइल पढ्छ भन्ने प्रत्याभूति होइन। लक्ष्य प्रमाणित गर्न देखाइएको मार्ग प्रयोग गर्नुहोस्; अरू root का लागि daemon कै tooling प्रयोग गर्नुहोस्।

बचतले पाठका रूपमा फाइल लेख्छ; पूर्ण नेटिभ कन्फिगरेसन जाँच वा OpenCode restart/reload गर्दैन। अरू क्लाइन्टसँग सम्पादन समन्वय गर्नुहोस्: यस सतहमा external-change merge छैन। ठूलो कन्फिगरेसन बदल्नुअघि प्रतिलिपि राख्नुहोस्। dirty मस्यौदा हुँदा फाइल बदल्न वा reload गर्नाले खारेज गर्ने हो कि सोध्छ।
