# सेटिङ र लेआउट

## सेटिङ खोलेर दायरा चिनाउनुहोस् {#open-settings}

1. ट्याब पट्टी (macOS डेस्कटप एपमा शीर्षक पट्टी) वा गृह पृष्ठको **सेटिङहरू खोल्नुहोस्** gear बाट **सेटिङहरू** खोल्नुहोस्। मोडेल selector को **प्रदायकहरू व्यवस्थापन गर्नुहोस्**, Missions प्यानलको gear वा सूचना इतिहासको **सेटिङहरू** gear जस्ता shortcut ले सम्बन्धित खण्ड सोझै खोल्छन्।
2. खण्ड चयन गर्नुहोस्। स्थानीय Electron र Tauri विन्डोले एउटै नेटिभ Preferences विन्डो खोल्छन् वा focus गर्छन्; ब्राउजर र रिमोट दृश्यले embedded सेटिङ स्क्रिन प्रयोग गर्छन्।
3. छोड्नुअघि सेटिङको दायरा र **बचत गर्नुहोस्** कार्य जाँच्नुहोस्।

धेरैजसो चयन तुरुन्त लागू हुन्छन्, Mission preferences समेत, जसले हरेक परिवर्तन गर्दागर्दै सुरक्षित गर्छ। speech, custom palette रङ र कन्फिग फाइलहरूमा स्पष्ट **बचत गर्नुहोस्** रहन्छ। असफल save परिवर्तन लागू भएको पुष्टि होइन; पुनःप्रयासअघि सम्बन्धित खण्ड खोल्नुहोस् वा refresh गर्नुहोस्। व्याख्या सेटिङको शीर्षकछेउको **i** पछाडि हुन्छ: त्यसमा hover वा focus गर्नुहोस्, वा touch screen मा tap गर्नुहोस्।

**तथ्याङ्क** ले खोलिएको फोल्डर मात्र होइन, पूरै जोडिएको OpenCode सेवा (सबै परियोजना, स्वतन्त्र clone र उप-सत्र) लाई पछिल्ला 7, 30, 90 वा 365 दिनका लागि समेट्छ। यसलाई खुला परियोजना चाहिन्छ र यसले OpenCode ले अभिलेख गरेका token र लागत देखाउँछ, provider invoice वा subscription allowance होइन; refresh हुँदै गर्दा अघिल्ला सुरक्षित कुल देखिन सक्छन्। plan quota Status को **प्रयोग** खण्डमा पर्छन्।

प्रदर्शन प्राथमिकता बदल्दा OpenCode restart वा prompt replay हुँदैन। native configuration, सेवा मर्मत र credential का छुट्टै असर छन्: [OpenCode सेटअप](opencode.md), [प्रदायक](providers.md) र [एकीकरण](integrations.md) हेर्नुहोस्।

## भाषा र रूप {#language-appearance}

1. **सामान्य** मा **भाषा** चयन गर्नुहोस्: अंग्रेजी, स्पेनी, फ्रान्सेली, रूसी, जापानी, सरलीकृत चिनियाँ, हिब्रू, जर्मन, नेपाली वा टर्किश।
2. **रङ योजना** मा **मोड** रोज्नुहोस्: **स्वतः**, **अँध्यारो** वा **उज्यालो**। Auto ले अपरेटिङ सिस्टम पछ्याउँछ।
3. देखिएको रूपको palette रोज्नुहोस्। light र dark चयन छुट्टाछुट्टै सुरक्षित हुन्छन्; Auto ले मिल्दो प्रयोग गर्छ।
4. custom रङका लागि swatch र **सुरक्षित गर्नुहोस्** प्रयोग गर्नुहोस्; **रिसेट गर्नुहोस्** ले built-in palette का रङ फर्काउँछ। छुट्टै palette नाम दिन **नयाँ**, र आफूले बनाएको palette हटाउन **मेटाउनुहोस्** प्रयोग गर्नुहोस्।

कुराकानी restart नगरी UI अद्यावधिक हुन्छ। हिब्रूमा right-to-left लेआउट हुन्छ; code र प्राविधिक मान आफ्नै दिशामा पढ्न मिल्छन्। भाषा चयनले interface पाठ बदल्छ, विद्यमान सन्देश वा agent निर्देशनको भाषा होइन। CodeNomad विन्डो लोड भएपछि नेटिभ डेस्कटप menu interface भाषामा बदलिन्छन्।

रङ पढ्न गाह्रो भए built-in palette रोज्नुहोस् वा सम्पादित palette reset गर्नुहोस्। palette बदल्दा नबचाइएका रङ सम्पादन त्याग्न सोध्न सक्छ; कुराकानी मस्यौदा त्याग्दैन।

## प्यानल र Status खण्ड {#panels-status}

1. प्यानल देखाउन/लुकाउन बाहिरी header कुनाका **बायाँ प्यानल** र **दायाँ प्यानल**, वा **View** menu का सम्बन्धित item प्रयोग गर्नुहोस्।
2. दायाँ प्यानलमा **दायाँ प्यानल अनुकूलन गर्नुहोस्** खोल्नुहोस्। built-in ट्याब र Status खण्ड रोज्न checkbox प्रयोग गर्नुहोस्; कम्तीमा एउटा Status खण्ड देखिइरहन्छ।
3. क्रम बदल्न right-panel ट्याब तान्नुहोस्। built-in लेआउट चयन फर्काउन **रिसेट गर्नुहोस्** प्रयोग गर्नुहोस्।

Status मा token जानकारी, Yolo मोड, provider Usage, background shell, MCP र Plugins छन्। खण्ड लुकाउँदा सेवा अक्षम वा अनुमति खारेज हुँदैन। साँघुरो लेआउटमा प्यानल कुराकानी खुम्च्याउनुको सट्टा माथि तैरिन्छन्; एउटा floating प्यानल खोल्दा अर्को बन्द हुन्छ।

built-in लेआउट विन्डो लेआउट हो, परियोजना परिवर्तन होइन। विस्तार checkbox फरक छन्: तिनले कन्फिगरेसन प्रयोग गर्ने सबै परियोजनामा code सक्रिय गर्छन्। **रिसेट गर्नुहोस्** ले विस्तार सहमति बदल्दैन। [प्यानल विस्तार](extensions.md) हेर्नुहोस्।

## Transcript विवरण र कम्पोजर आकार {#transcript-composer}

1. transcript विवरण default रोज्न **च्याट** खोल्नुहोस्। preset **केही नदेखाउने**, **न्यूनतम**, **सन्तुलित** र **सबै** हुन्; व्यक्तिगत परिवर्तनले **अनुकूलित** बनाउँछन्।
2. thinking, निदान, tool input, token, प्रणाली सन्देश र हरेक tool प्रकारका लागि प्रत्येक row को **पूर्वनिर्धारित अवस्था** (**लुकेको**, **संकुचित (Collapsed)** वा **विस्तार गरिएको (Expanded)**) सेट गर्नुहोस्, वा यिनै चयन साझा गर्ने कुराकानीको **सन्देशको सामग्री** popup प्रयोग गर्नुहोस्।
3. **सामान्य** मा आवश्यकअनुसार **सन्देश समयरेखा देखाउनुहोस्**, **उपकरण कलका diff हरू विभाजित गर्नुहोस्** र **पठाइएका प्रम्प्टहरू लाममा राख्नुहोस्** (सत्र काम गर्दै गर्दा पठाइएका prompt लाई निर्देशन दिनुको सट्टा लाममा राख्छ) छान्नुहोस्।
4. resize नियन्त्रणबाट कम्पोजरको आकार बदल्नुहोस्; लामो मस्यौदा field भित्र scroll हुन्छ।

timeline मा कुराकानीमा देखिने प्रत्येक जवाफ, reasoning, tool, compaction र system context का लागि उही क्रममा एउटा marker हुन्छ। marker ले **सन्देशको सामग्री** पछ्याउँछन्: त्यहाँ tool प्रकार, reasoning वा system सन्देश लुकाउँदा pending अनुमति भएको tool बाहेक तिनका marker पनि लुक्छन्, र **केही नदेखाउने** ले सबै tool marker लुकाउँछ। दृश्यता र expansion सेटिङले प्रस्तुति मात्र बदल्छन्। सुरक्षित tool/reasoning हटाउँदैनन् वा model context compact गर्दैनन्। विनाशकारी कार्यका लागि [इतिहास र सफाइ](history.md) हेर्नुहोस्।

कम्पोजर उचाइ software keyboard समेत देखिने कुराकानीअनुसार हुन्छ: न्यूनतम 8%, 44 px floor सहित, अधिकतम 60%। हातैले मिलाएको उचाइ अनुपातमा सम्झिन्छ; साँघुरो चौडाइ र लामो पाठले सीमा बढाउँदैनन्। विस्तारित अनुमति/प्रश्नले सुरक्षित उचाइ वा मस्यौदा नबदली अस्थायी कम्पोजर सानो बनाउँछ। resize फर्काउन अनुरोध collapse वा settle गर्नुहोस्।

## सूचना र badge {#notifications}

1. **सूचनाहरू** खोल्नुहोस्। हरेक प्रकारको सूचना कहाँ देखिन्छ छान्नुहोस्: **स्क्रिनमा** (अस्थायी बबल), **इतिहास** (ट्याब पट्टीको, macOS डेस्कटप एपमा शीर्षक पट्टीको, bell को सूचना इतिहासमा रहन्छ) र **प्रणाली** (operating-system सूचना)।
2. **प्रणाली** बाकस छान्दा आवश्यक भए अनुमति माग्छ। **प्रणाली सूचनाहरू** अन्तर्गत, अनुमति नभएसम्म **अनुरोध** ले फेरि माग्छ।
3. यो विन्डो देखिँदा पनि प्रणाली सूचना राख्न **एप फोकसमा हुँदा पनि सूचित गर्नुहोस्** सक्षम गर्नुहोस्।

पूर्वनिर्धारित रूपमा **एउटा सत्र तपाईंको जवाफ पर्खिरहेको छ** र **एउटा सत्र सकियो** प्रणालीमा मात्र जान्छन्, ताकि क्षणिक सत्र अवस्था इतिहासमा नथुप्रिऊन्; यी subagent होइन मुख्य सत्रसँग सम्बन्धित छन्, र तपाईं आफैंले रोकेको सत्र घोषणा गरिँदैन। तालिकाले जे भने पनि त्रुटि सधैं स्क्रिन र इतिहासमा देखिन्छन्, र छोटा प्रगति सन्देश स्क्रिनमा मात्र रहन्छन्।

ब्राउजर/OS अनुमति उपकरण र application origin को हो; सुरक्षित प्राथमिकताले अस्वीकार override गर्न सक्दैन। रोकिएको भए ब्राउजर वा OS सेटिङमा सूचना सक्षम गरी फर्कनुहोस्। असमर्थित वातावरणमा **प्रणाली** स्तम्भ अक्षम रहन्छ।

इतिहासमा पठाइएका सूचना मात्र गन्ने bell/history unread count ले ब्राउजर favicon dot र नेटिभ application badge चलाउँछ। नेटिभ badge ले live main विन्डोको कुल दिन्छन्; चलिरहेका सत्रको count वा OS सूचना पुगेको प्रमाण होइनन्। यस सुविधाले PWA launcher badge दिँदैन।

## उन्नत विकल्प {#advanced}

1. **उन्नत** खोल्नुहोस्।
2. चाहिएका विकल्प मात्र छान्नुहोस् वा हटाउनुहोस्; हरेक परिवर्तन CodeNomad preferences बाट बचत हुन्छ। सत्र execution environment बदल्न अन्त्यमा रहेको संक्षिप्त **वातावरण चरहरू (Environment Variables)** समूह विस्तार गर्नुहोस्।
3. अनुमानले साझा सेवा restart नगरी नतिजाको दृश्य वा अर्को पठाइ जाँच्नुहोस्।
