# 文件与 Git

右侧面板的**文件**标签页集成了检出目录浏览、本地更改和提交历史。选择一行与打开其中央阅读器是独立操作。

## 浏览检出目录 {#browse-workspace}

1. 打开**文件**并选择**工作区**。
2. 需要其他检出目录时选择**浏览工作树**；按需展开文件夹。
3. 点击文件行选择它。使用眼睛操作打开或关闭中央预览。
4. 需要重新检查可见快照时，使用**刷新**。

| 模式 | 读取内容 | 对对话的影响 |
| --- | --- | --- |
| 工作区 | 所浏览检出目录中的文件 | 不移动会话或检出分支 |
| 更改 | 索引和工作树更改 | 只有显式操作才会修改 Git |
| 提交 | 分页提交历史和修订内容 | 只读历史；不检出 |

切换模式会保留已展开文件夹。列表/状态/历史使用缓存快照，并在相关文件系统变化、激活或显式刷新后重新验证；聚焦面板并不保证重新读取。可见的工作区文件夹会自行反映后端主机上新建、编辑、重命名或删除的文件，在持续活动期间最多每五秒更新一次；折叠的文件夹和其他工作树只会在你显示它们时重新读取。

行操作包括**复制路径**，以及在客户端支持打开后端路径时可用的文件管理器/编辑器/终端操作，如**使用默认应用打开**、**在文件夹中显示**、**在文件管理器中打开**和**在此处打开终端**。空间不足时，操作可能移入 **{name}的更多操作**；文件或文件夹名替换 `{name}`。远程浏览器不能假定服务器路径就是本地设备路径；参阅[远程控制](remote-control.md)。

## 编辑源码并安全保存 {#edit-save}

1. 使用眼睛操作打开工作区文本文件。
2. 对 Markdown，选择**显示源码**进行编辑，或选择 **Markdown 预览**阅读渲染结果。
3. 编辑后选择**保存**，或在编辑器获得焦点时按 **Ctrl/Cmd+S**。
4. 如果文件已被外部修改，请检查覆盖确认；选择**取消**可保留草稿而不覆盖该更改。

保存会写入所浏览检出目录中的实际文件，包括关联工作树；不会发送提示词，也不会暂存/提交编辑。保存前会重新读取权威文件。冲突对话框显示**文件已被智能体修改。是否覆盖智能体的更改？**；请同样谨慎对待任何外部写入者的更改。

关闭或切换阅读器时，未保存源码草稿按项目实例、目录和路径保留在渲染器内存中。文件系统刷新不会静默替换它们。这不是持久文件存储：重启/重新加载客户端前，请保存或复制重要编辑。读写失败会保留草稿。显式**刷新**在丢弃未保存编辑前会发出警告。

使用阅读器末尾的关闭按钮可返回对话；输入框仍可在下方使用。更改会话/工作树会清除所选阅读器，并不保证保存其草稿。打开浏览器预览会替换阅读器；打开文件会让该视图返回聊天模式。

## 只读和有界预览 {#preview-limits}

1. 使用眼睛操作打开图片、二进制文件或历史更改。
2. 对差异视图，按需使用**切换到分栏视图** / **切换到统一视图**、自动换行和未更改区域控件。
3. 关闭阅读器返回聊天。

| 内容 | 可用行为 |
| --- | --- |
| 工作区文本，包括 Markdown 源码 | 可编辑，需显式保存 |
| 工作区图片 | 只读图片预览 |
| 其他二进制内容 | 只读的预览不可用后备界面 |
| 更改/提交文本差异 | 只读比较，不能编辑任一侧 |
| Git 图片差异 | 来自精确比较修订的前/后图片 |

预览读取有大小边界；大型/不受支持的内容可能不可用，而不是无限加载。历史图片绝不会用当前工作树文件替代。预览失败不代表底层文件不存在。可用时请用合适的外部应用打开文件，不要仅为获得预览而更改其修订。

## 暂存、取消暂存和提交 {#stage-commit}

1. 选择**更改**，检查**已暂存的更改**和**更改**。
2. 使用**暂存文件** / **取消暂存**、选择多行执行对应的所选文件操作，或在两个区域之间拖动行。
3. 在**已暂存的更改**顶部输入消息，然后选择**提交**。

折叠的区域标题仍可接收拖放。折叠区域或更改模式会保留其状态和提交消息草稿。较长的区域会先显示前 200 个文件，随后显示一行如 **480 个文件未显示**，并提供**再显示 200 个**以就地显示后续文件；区域计数始终为完整总数，当前、正在预览和已选择的文件会保持显示。Shift 点击选择的范围只涵盖已显示的行，因此批量操作绝不会包含你看不到的文件。暂存/取消暂存修改所浏览工作树中的索引；提交只记录已暂存内容。取消暂存不会丢弃工作树编辑。

提交前请检查已暂存文件，尤其当智能体或其他客户端也在写入该位置时。失败的提交不会自动重放。重试前请刷新状态/历史并检查错误，因为丢失回复不代表未创建提交。

## 阅读提交历史 {#commit-history}

1. 选择**提交**，再选择一条提交阅读消息和更改文件。
2. 使用**筛选已加载的提交…**筛选已加载集合，或使用**加载更早的提交**获取下一页。
3. 使用眼睛操作打开更改文件。

文本历史将提交与其第一个父提交比较（根提交则与空基线比较）。不会切换 HEAD 或移动会话。筛选已加载提交不是服务器范围的 Git 日志搜索。新提交出现后，刷新可从当前历史重新开始；已有分页保留其起始历史快照。

## 空白与行尾 {#whitespace-line-endings}

1. 打开**设置 → 高级 → 隐藏仅空白的更改**。
2. 如需查看从更改中省略的、未暂存的纯空白编辑，请关闭它。
3. 提交前检查实际差异和已暂存内容。

此设置默认开启。主要作用是从更改列表、计数、选择、批量暂存和拖动操作中隐藏符合条件的、未暂存的受跟踪文本修改。隐藏文件仍未暂存。已暂存文件保持可见，未跟踪、新增/删除/重命名和二进制文件也保持可见。检测失败/不受支持时会保留文件可见，而非猜测。

Git 的列表检测可以忽略内部空白、仅 CRLF 的更改以及新增/移除的末尾换行。差异阅读器的空白比较范围较窄：缩进和尾随空格/制表符，而非所有内部空白。无论显示偏好如何，暂存和提交始终作用于精确内容。

行尾和字节顺序标记的差异可能以事实说明呈现，而不高亮行。关闭此设置无法让编辑器绘制每一种行尾/BOM 更改或每一种等长尾随空白替换。视觉上空的差异不代表字节相同。

## 初始化 Git {#initialize-git}

1. 在非仓库文件夹中打开**更改**或**提交**。
2. 选择**初始化 Git**；它会立即运行，无需确认。
3. 等待项目/会话刷新，准备好后显式暂存和提交。

初始化会在显式打开的文件夹中创建 `.git`；不会初始化父目录或创建首次提交。如果后端缺少 Git，仍可使用仅目录对话和工作区浏览，但初始化和 Git 操作不可用。失败结果不确定时，请先刷新再重试；初始化请求不会自动重放。参阅[项目](projects.md)。
