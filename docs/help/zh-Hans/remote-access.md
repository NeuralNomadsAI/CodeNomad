# 直接远程访问

直接访问使用服务器密码连接 CodeNomad 的 HTTP/HTTPS 监听器。它与[远程控制](remote-control.md)分开：配对不需要局域网绑定或入站端口，两条路径都不会静默回退到另一条。

## 选择访问路径 {#access-paths}

| 路径 | 需要管理的内容 |
| --- | --- |
| 同机浏览器 | 保持回环绑定；使用打印的本地 URL。 |
| 局域网或 VPN | 绑定可达接口，将防火墙限制到目标客户端，并使用可信 HTTPS。VPN 不会替你配置 CodeNomad 监听器。 |
| SSH 转发 | 保持后端回环绑定；转发其实际打印端口。隧道保护传输，但不替代 CodeNomad 认证。 |
| 反向代理 | 保持后端位于私有/回环接口；在代理终止可信 TLS，保护上游链路，并支持长期 SSE 及直接访问工具所需的 WebSocket。 |
| 远程控制 | 从主机配对设备；其较窄界面和生命周期参阅[远程控制](remote-control.md)。 |

绑定不会创建防火墙规则、端口转发、DNS 或 VPN。不要向互联网发布未认证 HTTP 监听器。工作区根目录不是安全沙箱；公开服务器前阅读[安全](security.md)。

## 启用直接访问 {#enable-direct-access}

1. 在主机打开**设置 → 远程访问**，展开**直接访问（局域网，高级）**。
2. 在**服务器密码**下选择**设置密码**或**修改密码**，输入**新密码**和**确认密码**，然后选择**保存密码**。运行时提供的密码不能在此更改；参阅[安全](security.md)。
3. 在**监听模式**下开启**允许其他 IP 连接**。阅读重启警告，只有准备好接受临时中断时才选择**立即重启**。
4. 重启后使用**刷新**，检查**可访问地址**。在另一设备打开可达 HTTPS 地址，或在主机选择**显示二维码**并用另一设备扫描，然后登录。

这更改主机直接监听模式，而非单个项目，也不影响远程控制。服务器监听范围超出 localhost 时，折叠区域自动打开。不能自动重启时，请手动重启 CodeNomad；独立部署必须一致地设置启动时 `--host`。移除暴露时，关闭开关并重启，或用回环绑定重启 CLI。这不会撤销已配对远程控制设备。

### 监听器绑定矩阵 {#binding-matrix}

`--host` 默认为 `127.0.0.1`；`localhost` 会规范化为该地址。以下规则适用于已启用监听器：

| 启动/模式 | HTTP 绑定到 | HTTPS 绑定到 |
| --- | --- | --- |
| 独立，仅 HTTPS（默认） | 仅私有回环监听器 | `--host` |
| 独立，仅 HTTP | **`--host`**，包括局域网/通配地址 | 未启用 |
| 独立，双监听器 | `127.0.0.1`，不受 `--host` 影响 | `--host` |
| 原生桌面后端 | HTTP 监听器始终在 `127.0.0.1`，包括宿主内部监听器 | 启用 HTTPS 时为 `--host` |

具体局域网地址不一定接受回环连接。`0.0.0.0` 表示所有 IPv4 接口；`::` 是双栈通配监听器。浏览器中使用实际可达地址，不要使用通配地址。`--host` 不支持 IPv6 区域标识符。

独立 HTTPS 部署请通过[初始化流程](security.md)设置密码，然后运行：

```sh
codenomad --host 0.0.0.0 --https=true --http=false
```

仅回环 HTTP，例如位于本地可信代理之后：

```sh
codenomad --host 127.0.0.1 --https=false --http=true
```

不要假定端口是 9898 或 9899：省略端口时，繁忙会回退。显式非零的 `--https-port`，或启用 HTTP 时的 `--http-port`，会固定端口，无法绑定则失败；`0` 请求操作系统分配。本次运行以打印的 **Local Connection URL**、**Remote Connection URL** 和刷新的**可访问地址**为准。参阅完整[服务器 CLI 参考](server.md)。

## 管理员策略 {#administrator-policy}

管理员可以固定监听地址：在系统范围将 `CODENOMAD_LOCKED_HOST` 设置为服务器必须使用的地址，然后重启 CodeNomad。它优先于 `--host`、`CLI_HOST` 和 **允许其他 IP 连接**；该开关会显示结果，但无法更改。使用内网地址可让同事通过公司网络访问服务器，使用 `127.0.0.1` 则仅限本机。若要让所有访问都留在公司网络内，还需设置 `CODENOMAD_REMOTE_CONTROL=disabled`（[远程控制](remote-control.md#administrator-policy)）。

## 升级 {#upgrading}

升级后请重新登录。使用主机名别名、反向代理或单独托管的界面时，请在后端设置 `CODENOMAD_ALLOWED_ORIGINS`，列出可信的界面来源（协议、主机名和端口）。局域网原生客户端必须在修改请求中提供允许的 `Origin` 请求头。其 HTTPS 来源还允许主机在没有隧道的情况下配对设备；参阅[通过直接 HTTPS 配对](remote-control.md#direct-https)。

仅限主机的操作需要回环连接：SideCar 内容（`/sidecars/`）及 WebSocket、远程控制管理（`/api/remote-control/`）、插件桥接（`/api/opencode-plugin/`）、远程代理（`/api/remote-proxy/`）、已保存服务器管理（`/api/remote-servers/`）、密码更改和令牌初始化。即使通过局域网直接访问并已登录，这些操作也要求回环连接。只有 SideCars 例外：主机的**通过 HTTPS 打开 SideCars**设置会向通过可信 HTTPS 来源登录的浏览器开放其内容和 WebSocket（[SideCars](browser-sidecars.md#register-sidecar)）。持有有效能力令牌时，活动预览内容（`/previews/`）可通过局域网直接访问。

`/api/sidecars` 注册 API 仍可供已认证的局域网直连客户端和已配对设备使用。远程控制网页预览在主机启用时，仍可通过其能力令牌访问。

## 配置可信 TLS {#tls}

### 提供自己的证书 {#custom-certificates}

1. 获取证书，其主体备用名称（SAN）须覆盖客户端实际使用的主机名或 IP。
2. 同时提供 PEM 格式的 `--tls-key <path>` 和 `--tls-cert <path>`。部署需要 CA 链/证书包时，添加 `--tls-ca <path>`。
3. 重启 CodeNomad，从客户端设备验证证书及打印的 HTTPS 地址。

自定义证书文件在启动时读取，CodeNomad 绝不重写。续期及加载续期文件所需重启由你负责。`--tlsSANs` 配置生成的证书，无法为提供的证书添加名称。保护私钥，只信任已验证主机身份的证书。

### 使用生成的本地 CA {#generated-certificates}

启用 HTTPS 且未提供密钥/证书对时，CodeNomad 会在配置根目录下创建本地 CA 和服务器证书：

| 文件 | 用途 |
| --- | --- |
| `tls/ca-cert.pem` | 公共 CA 证书，可安全分发给你管理的客户端。 |
| `tls/ca-key.pem` | CA 私钥；绝不分发。 |
| `tls/server-cert.pem` | 服务器证书。 |
| `tls/server-key.pem` | 服务器私钥；绝不分发。 |

1. 使用 `--tlsSANs "host.example.test,192.0.2.10"` 添加每个面向客户端的 DNS 名/IP。通配绑定不会发现所有局域网地址并加入 SAN。
2. 重启后端以生成/重新检查证书。
3. 通过可信渠道验证主机/CA，然后向每个目标客户端/浏览器信任库导入**仅 CA 证书**。也可使用公开受信任证书或 TLS 反向代理。

生成的服务器证书有效 30 天。启动时会在距离过期三天内、缺少必需 SAN、证书检查失败或私钥文件缺失时续期。生成的 CA 有效 365 天，会在过期、证书检查失败或私钥文件缺失时替换；替换也会重新签发服务器证书。客户端必须信任替换 CA。进程内不会持续续期：长期运行部署请在过期前安排明确重启。

客户端报告证书警告时，请停止并检查主机名、SAN、信任库和有效期。不要禁用验证，也不要将点击绕过警告作为部署流程。远程浏览器功能，如 [PWA 安装和麦克风访问](mobile.md)，也要求可信 HTTPS。

## 保存远程服务器 {#saved-servers}

实验性 `multiBackend` 默认关闭，没有可见的启用控件。启用后，已认证的远程客户端可以使用和管理主机保存的所有服务器；主页和**设置 → 服务器**根据主机提供的能力显示可用操作。普通 LAN HTTP 会禁用新的服务器密码和配对链接输入：“请使用 HTTPS 或远程控制输入凭据。”使用已保存凭据的连接，以及添加、编辑或删除不含机密信息的配置仍然可用。

对于只能通过 SSH 访问的目标，在实验性的 **设置 → 服务器** 中选择 **添加服务器**，输入 **URL** 和 **SSH 主机（可选）**，然后点击 **保存**。配置可离线保存；连接时使用后端的 SSH 中继。

启用实验性多后端设置后，请使用**设置 → 服务器**：将地址或配对链接粘贴到**服务器地址或链接**，或按 Enter 添加。添加只在主机保存配置，不会打开项目。**编辑服务器**可修改 **URL** 或可选的**名称**；URL 和 TLS 策略相同时，离线也能改名。**删除已保存服务器**会请求确认，忘记该配置的连接后保存删除操作；保存失败时保留配置以便重试。其他连接保持可用。

该地址的证书验证失败后才会提供**跳过 TLS 验证**；更换地址会清除同意。配对始终验证 TLS。**打开**可浏览服务器的项目。以下步骤适用于默认模式。

启用实验性多后端功能后，**SSH 主机（可选）**可为后端中继保存 OpenSSH 主机或别名。建议来自本地后端运行账户的 `~/.ssh/config`。请输入从该主机访问的 CodeNomad 地址（例如使用实际端口的 `https://127.0.0.1:9898`），然后选择**保存**。SSH 配置使用中继；用于打开直连服务器窗口的**连接**按钮对此类配置禁用。该主机上的 CodeNomad 必须已安装并运行。本地需要 OpenSSH、密钥认证以及 `known_hosts` 中已验证的主机密钥；CodeNomad 认证和 HTTPS 证书检查仍然适用。

1. 在桌面主页选择**连接 CodeNomad 服务器**。空的**服务器**标签页和**设置 → 远程访问 → 服务器**中也有同一按钮。
2. 在**连接到服务器**中，输入**服务器名称**和使用可信 HTTPS 来源的**服务器 URL**。不要勾选**为自签名证书跳过 TLS 验证。**；应建立信任。
3. 选择**保存**添加书签，或选择**连接**保存并打开。在该服务器上登录。

在主页的**服务器**标签页中选择已保存的服务器即可再次打开它。书签属于此 CodeNomad 配置，而非远程服务器项目。保存 URL 不会启动服务器或授予访问。**删除已保存服务器**移除书签，而非远程对话、后端或凭据。

要直接从命令行打开已保存的服务器，请使用服务器的保存名称或其 `https://` URL，以 `--connect-server <name>`（或 `--connect-server=<name>`）启动桌面应用。CodeNomad 只打开远程窗口，检查和登录与**连接**相同；如果 CodeNomad 已在运行，则由其当前窗口打开，而不是新建窗口。未匹配任何已保存服务器的 URL 会以其主机名保存。启动值绝不携带凭据：包含用户名、密码或配对码的 URL 会被拒绝。在 Windows 上，如果启动参数包含 `|`，Tauri 版本会拒绝启动；请改用服务器的 URL，或重命名该服务器。

在远程窗口仍打开时关闭最后一个本地窗口，会保留其标签页：在远程窗口中使用 **窗口 → 新建窗口**，或再次启动 CodeNomad，即可重新打开它。

使用远程控制时，改为将新配对链接粘贴到**服务器 URL**。书签仅保留隧道来源，绝不保留一次性配对码；设备 cookie 丢失后的重新配对请参阅[远程控制](remote-control.md)。
