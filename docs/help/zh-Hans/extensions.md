# 面板扩展

## 浏览已安装和在线扩展 {#browse}

1. 在右侧面板标签栏中打开**自定义右侧面板**。
2. 展开分隔线下方的**扩展**。
3. 使用**搜索扩展**搜索已安装附加组件和官方在线目录组成的单一列表。悬停或聚焦条目查看元数据。

每次打开自定义弹出框时，折叠区域都默认关闭。已安装和在线条目按扩展 ID 合并；没有单独的管理窗口或已安装/在线模式。浏览目录元数据不会下载或执行作者的面板代码。目录维护于 [CodeNomad Extensions](https://github.com/NeuralNomadsAI/CodeNomad-Extensions)；收录及声明的作者姓名并非签名或信任证明。

目录不可用时，已安装扩展和**从 ZIP 安装…**仍可使用。刷新可重试发现。折叠或关闭弹出框会放弃待处理检查/确认界面；不会静默安装任何内容。

## 检查并安装但不启用 {#install}

1. 在目录条目上选择**安装…**，或对另行获得的软件包选择**从 ZIP 安装…**。
2. 检查软件包 ID、作者、仓库、版本、API/权限和 SHA-256 摘要。需要时展开技术详情。
3. 验证发布者，并在可用时通过可信渠道比较摘要。
4. 只有信任代码时，才选择**我信任此软件包及其作者**，然后选择**安装但不启用**。

检查会下载/重新验证所选软件包；不会执行作者代码。摘要标识精确字节，而非作者身份。目录软件包来自精确声明的 GitHub 发行版资源，而非任意 URL。手动软件包是仅包含 `manifest.json` 和自包含 `panel.html` 的 ZIP；无效或不受支持的软件包会被拒绝。

安装无需重启 OpenCode，且绝不自动授予激活权限。验证失败、冲突或存储操作失败不意味着允许以不同字节重试。新一次安装尝试前请重新检查软件包。

## 激活并了解范围 {#activate-scope}

1. 返回**自定义右侧面板**中**扩展**折叠区域上方的附加组件行。已安装但禁用的组件仍在该列表中。
2. 勾选复选框激活。取消同一复选框即可禁用。

该复选框是唯一激活控件：没有额外管理器开关或按窗口的可见性开关。激活作用于整个配置下的所有项目，而非按文件夹生效。远程连接时，它影响服务器已安装扩展存储，而非仅影响查看设备。

扩展存储是所选 CodeNomad 配置旁的 `panel-extensions/`。如果不同桌面数据配置文件使用同一配置目录，它们**不会**隔离扩展。反过来，打开不同配置也不代表获准运行安装在其他位置的附加组件。区别请参阅[桌面窗口与数据](desktop.md)。

启用的面板可在选中时挂载；隐藏可能清除其临时界面状态。禁用会撤销激活。自定义中的**重置**只恢复内置布局，不会启用、禁用或卸载扩展。

## 替换或移除 {#replace-remove}

1. 使用**更换版本…**，或检查同 ID 的另一个 ZIP，替换已安装软件包。
2. 检查新摘要和权限，确认信任，然后安装但不启用。
3. 只有决定信任替换版本后，才通过普通复选框重新激活。
4. 卸载时，检查目标后使用**移除…**和**确认移除**。

每次替换都会撤销所有项目中的激活，即使权限列表未变，并清除面板自身已保存的设置。验证/冲突/存储失败会保留已安装软件包。扩展不会静默更新。移除会删除软件包、其激活设置及已保存的面板设置，而非 OpenCode 会话或项目文件。出现不想要的代码时，先禁用；只重新安装已验证可信的软件包。

## 上下文、资源同意和沙箱限制 {#permissions-sandbox}

| 契约 | 激活允许的内容 |
| --- | --- |
| API 1 / `session.context` | 当前会话标识符（或无）、界面语言和外观。无对话文本或文件系统访问。 |
| API 2 / `session.assets.read` 加上下文 | 显式审查过的权限，用于列出有界的当前会话工具结果图片/附件元数据，并读取受支持的嵌入字节。不提供通用对话、文件或 URL 访问。 |
| API 3 / `repository.workItems.read` 及上下文 | 经明确审查的权限：分页列出项目仓库在 GitHub、GitLab 或 Gitea/Forgejo 上的 issue 和 pull request（页数有上限），并在浏览器中打开其中一项。这不是文件、凭据或一般网络访问。 |
| API 4 / 上下文加以下一项或多项权限 | 审查时每项声明的权限显示一句说明；激活会一并授予全部权限，替换会全部撤销。 |
| `session.images.read` | 读取所显示对话中 read 工具返回的图像，并在可验证时附带生成状态和来源谱系。 |
| `session.images.prompts`（需要 `session.images.read`） | 读取项目“图像”对话中生成的每张图像的提示词和模型。 |
| `composer.prefill` | 向所显示对话的输入框添加文本。绝不会发送消息。 |
| `images.conversation` | 打开或开始此项目的“图像”对话。 |
| `opencode.designAgent` | 在此扩展启用期间，将 CodeNomad 的 Design 智能体及其图像技能添加到 OpenCode。 |
| `panel.preferences` | 记住此面板自身的设置。 |

资源访问跟随当前挂载的宿主/会话，而非作者选择的会话。本地/远程引用可能列为不可用；资源 API 不获取任意远程 URL 或打开本地文件。切换会话、断开连接或撤销同意会使旧访问失效。

在 API 4 中，图像读取同样跟随所显示的对话，且只显示智能体读回该对话的图像。拥有 `session.images.prompts` 的扩展可以读取您或智能体在“图像”对话中为图像编写的提示词，并且尽管有沙箱，仍可能将其转交他人，因此只应授予您愿意托付这些内容的作者。由 `composer.prefill` 添加的文本会留在输入框中，直到您编辑它或选择**发送消息**；它绝不会以命令开头，绝不会以未完成的 `@` 提及结尾，并以纯文本引用图像路径。在输入框中用 Ctrl+Z（macOS 上为 Cmd+Z）撤销不会移除它。已保存的面板设置属于此 CodeNomad 配置，每个扩展最多 4 KiB；禁用扩展会保留它们。

这些条目来自项目文件夹的 `upstream` 远程仓库，否则来自 `origin`。CodeNomad 使用您已登录的 GitHub、GitLab 或 Gitea CLI（`gh`、`glab`、`tea`）读取它们，公开仓库可匿名读取，且不存储任何令牌；扩展只能看到仓库名称和条目。匿名读取仅适用于 github.com、gitlab.com、codeberg.org 和 gitea.com；自托管平台只能通过已登录该平台的 CLI 读取。打开条目时，CodeNomad 会在浏览器中打开该条目在同一平台上的页面，每秒最多一次；扩展无法打开其他地址。

作者代码在受限 iframe 中运行，而非可信应用渲染器。它无法获得原生/OpenCode 桥接、凭据访问、通用 RPC、表单、弹出窗口或下载；网络 API 和外部资源受限。扩展是界面附加组件，而非 [OpenCode 插件](integrations.md)。

沙箱不是进程/CPU 隔离，也不保证获批代码无害。恶意扩展可能干扰其渲染器。只安装可信作者的扩展，不提供秘密，行为异常时禁用/移除组件。

## 使用 Design 扩展创建图像 {#design}

**Design** 扩展是一个看片台，用于查看你在项目的**图像对话**中与 CodeNomad 的 Design 智能体一起创建的图像。它显示图像、在消息框中准备请求，而每次生成都由你发送的消息触发。

1. 连接一个提供图像模型的提供商。除非已在**设置 → 提供商 → 图像**中关闭，图像生成默认开启（[图像生成与存储](providers.md#images)）。
2. 在**自定义右侧面板 → 扩展**中，先审查它的权限（[上下文、资源同意和沙箱限制](#permissions-sandbox)），再从目录安装 **Design**（[检查并安装但不启用](#install)），然后勾选它的复选框（[激活并了解范围](#activate-scope)）。
3. 打开 **Design** 面板，选择**打开图像对话**。

扩展启用期间，CodeNomad 会将它的 Design 智能体及图像技能添加到 OpenCode。你自己的 `design` 智能体和你自己的 `design-*` 技能始终优先；当你提供自己的 `design` 智能体时，面板显示**正在使用你自己的 Design 代理。**缺少图像生成、图像模型或 Design 智能体时，面板也会说明。

### 图像对话 {#design-conversation}

每个项目文件夹或 worktree 都有自己的图像对话，标题为**图像**。**打开图像对话**会找到它，或使用 Design 智能体以及 CodeNomad 为该智能体的新对话选择的模型创建它，然后显示该对话并将焦点放在消息框中；打开不会发送任何内容。已有的图像对话保留自己的模型。**新建图像对话**会以空的看片台开始另一个对话；当一个对话包含大量图像时，面板会建议这样做，之后**打开**会显示最新的对话。已归档和已删除的图像对话会被跳过。

描述你的需要并发送：智能体会问几个确定方向的问题，说明将生成几张图像，生成它们，再逐张读回并评估。图像保存在项目文件夹的 `.codenomad/design/` 中。CodeNomad 会将该文件夹加入仓库的本地 Git 排除规则（`.git/info/exclude`），不改动 `.gitignore`；无法加入时，面板显示**此位置的图像可能会出现在 Git 中。**撤销一轮会把它的图像从看片台移除，但保留文件；被智能体覆盖的图像无法恢复。智能体请求约 1K 像素的图像，但提供商可能返回更大的图像，同时生成多张大图可能占用共享 OpenCode 服务的大量内存。

如果使用 Design 智能体的图像对话中缺少该智能体，消息框会显示**Design 智能体不可用**并阻止发送：选择**使用默认智能体**，或重新启用 Design 扩展。如果对话的聊天模型无法接收图像，面板会提示智能体无法从视觉上评估它们；它读回的图像仍会显示在看片台上。

### 看片台 {#design-light-table}

**看片台**显示智能体在当前对话中读回的图像，从新到旧，按回复分组。选中图像会放大显示，并在**小尺寸**中提供 16、32 和 64 px 预览；**比较**将两张图像并排放置，**查看原图**打开查看器。面板较窄时，请加宽后再比较。谱系（**生成自**、**用于**）以及图像对话中的提示词和模型，仅在 CodeNomad 能验证图像由哪次生成产生时显示；否则图像保留像素并标记为**来源无法验证**。**生成记录**列出每次图像生成及其状态；请在对话中跟进进度。在其他对话中，面板显示该对话中读回的图像，不含提示词和请求，并提供打开图像对话的入口。

在图像对话中，**从模板开始**（例如应用图标或标志等方案）、**优化**、**变体**、**应用方向**、**保存到项目…**、**请代理显示它**和**重试**只会在消息框中添加可编辑的文本：面板从不发送消息，也从不生成图像。针对所选图像的操作会以相对于项目的路径引用该图像，且只能引用来源可验证的项目图像。编辑请求后由你自己发送。**保存到项目…**会请智能体把图像复制到你在请求后输入的目标位置。**每轮图像数**（1 到 4，默认 3）会包含在生成新图像的请求中，并保存在面板的已存设置里。在手机上，面板以浮动方式显示，添加请求后会关闭。

### 不使用 CodeNomad 时使用 Design 智能体 {#design-without-codenomad}

Design 智能体及其技能是普通的 OpenCode 文件。要在没有 CodeNomad 的情况下于 OpenCode TUI 或其他客户端中使用，请将 [Design 内容文件夹](../../../packages/server/src/opencode/design/opencode/)中的内容复制到项目的 `.opencode/` 文件夹或全局 OpenCode 配置文件夹（`~/.config/opencode/`），并将 `NOTICE.md` 和许可证一同保留。然后选择 **design** 智能体；它按名称加载自己的技能，其他智能体只有在你点名时才会使用这些技能。

Design 智能体及其技能改编了 [Open Design](https://github.com/nexu-io/open-design)（Apache-2.0）和 [taste-skill](https://github.com/Leonxlnx/taste-skill)（MIT）的材料；`NOTICE.md` 列出了每个改编的文件。Design 扩展复用了 MCP Assets 扩展的代码（MIT）。
