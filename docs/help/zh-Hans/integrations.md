# 原生集成

CodeNomad 提供 OpenCode 的原生 MCP 连接、插件激活、技能和自定义命令。这些在执行主机上运行，与沙箱[面板扩展](extensions.md)和 [SideCar](browser-sidecars.md) 分开。

## 选择正确的控件 {#integration-scopes}

| 集成 | 操作位置 | 控件更改的内容 |
| --- | --- | --- |
| MCP 服务器 | **状态 → MCP 服务器** | 显示 Location 的原生连接；不会安装服务器。 |
| 原生插件 | **状态 → 插件** | 添加或移除软件包声明，并设置持久的**全局**或**项目**激活规则；对于软件包插件，可显式检查或更新该软件包。 |
| 技能 | 输入框 `@` 菜单 | 显式附加到对话 Location 中的下一条提示词。 |
| 自定义命令 | 输入框 `/` 菜单 | 运行 OpenCode 为该 Location 提供的命令。 |

请先使用 OpenCode 支持的配置和 CLI 配置/安装集成。安装软件包、声明来源、启用规则、连接服务和使工具可用是独立步骤。原生集成拥有其宿主进程权限，并受 OpenCode 权限约束；它们不是沙箱 HTML 面板。

## 连接或断开 MCP {#mcp}

1. 按 [OpenCode MCP 文档](https://opencode.ai/v2/docs/mcp-servers/)在 OpenCode 执行主机上配置 MCP 服务器。
2. 打开项目的**状态 → MCP 服务器**。
3. 使用服务器旁的开关连接或断开。等待连接指示器稳定。

开关针对报告的 Location 调用原生连接 API，不是设备本地安装程序，也不是按窗口的可见性偏好。使用该 Location 的其他客户端可以观察到连接更改。断开不会移除服务器声明或卸载其可执行文件。

若未显示服务器，请验证活动 Location 及其原生配置。连接失败时，请检查服务器配置、所需环境和原生认证流程；不要假定开关能完成 OAuth。重新连接后再次检查状态。仅在必要时显式重新加载配置，并注意 [OpenCode 设置](opencode.md)中描述的中断影响。

## 在全局或项目范围激活插件 {#plugins}

1. [添加插件](#plugin-sources)或在 OpenCode 配置中声明；然后打开**状态 → 插件**。
2. 悬停或聚焦名称，检查来源、运行时失败和配置目标详情。
3. 有意识地切换**全局**或**项目**。等待写入完成，状态不明时使用**刷新插件控件**。
4. 对于从软件包安装的插件，使用其名称旁的图标。其菜单会写明确切操作：**检查 … 的更新**，或在发现较新版本后**更新 …**。

全局以所连接守护进程发现的全局配置为目标。项目以活动 Location 内的配置为目标，而非继承的祖先文件。后续项目规则可以覆盖全局；全局开关仍显示全局规则，而不会假装是最终项目状态。没有项目规则时，项目继承解析后的全局状态。

这些开关追加精确激活规则，同时保留来源声明和无关配置。不会编辑插件选项、安装软件包或移除文件。内置 OpenCode 插件不会作为用户激活开关提供。项目目标无法安全地与全局分离，或会超出活动 Location 时，项目控件会禁用。

软件包更新会在 OpenCode 的共享缓存中更改该软件包，影响所有使用它的 Location，其工具提示中也会说明这一点；它不会更改激活规则、重启 OpenCode 或重新加载配置。本地、内置和 SDK 提供的插件没有软件包操作。在报告插件 ID 之前就加载失败的软件包会按软件包名称列出，其工具提示中包含失败信息，并提供检查/更新操作，但没有激活开关。检查或更新失败会被报告，且绝不会自动重试。

界面隐藏时保留上次快照，并在显示时、原生更改/重新连接后及显式刷新时重新验证。已保存规则与实时运行时可用性可能短暂不同。插件持续不可用时，先检查工具提示和原生配置，再选择**重新加载 OpenCode 配置**；该操作影响所有已加载 Location，而非仅此插件。格式错误的配置或并发编辑不会被静默覆盖：请解决、刷新后显式重试。

## 添加或移除插件 {#plugin-sources}

1. 在**状态 → 插件**中选择**添加插件**（**刷新插件控件**旁的加号图标）。
2. 输入 npm 注册表中的软件包（`name`、`name@1.2.3`、`@scope/name@^1`）或 Git 仓库（`github:owner/repo`、`git+https://…`）。
3. 除非插件只应在此项目中运行，否则保持**全局**，然后选择**添加**。
4. 观察到声明后，本地提交的添加操作显示**正在安装**，从最初请求起最多两分钟，直到 OpenCode 报告运行状态。之后它会变成带开关的普通行或失败的行。重新加载后或缺少充分的本地依据时显示**未确认**；延迟响应绝不会重新开始两分钟计时。

要移除插件，请打开其名称旁的菜单，选择**从全局移除**或**从项目移除**。只会删除该范围配置文件中的声明；其**全局**/**项目**规则，无论启用还是停用，均原样保留，OpenCode 的软件包缓存也保持不变。

插件代码会以你的权限在 OpenCode 中运行。每次在 OpenCode 中打开该文件夹时，**项目**条目都会运行；带有 OpenCode 桌面应用部分的软件包只从**全局**加载这些部分，若此类软件包在其他位置声明，提示会说明这一点。此处拒绝本地路径、配置变量和插件 ID：请在配置文件中声明本地插件。已在适用于此 Location 的配置中声明的软件包会被拒绝，无论其版本、范围或形式如何。

已审核目录中的 OpenCode 集成（例如 Blender 集成）在安装前即可识别。在应用程序内带有部分的集成只能添加到**全局**：对它拒绝**项目**。它的注册表软件包和 Git 构建算作同一个软件包，因此添加已声明或已加载集成的另一种形式会被拒绝。

将指针悬停或聚焦到插件名称上，可查看其版本、**有可用更新**，以及安装失败时带有 OpenCode 日志编号的错误。两分钟后 OpenCode 仍未报告的行会显示**未确认**，并提供**刷新插件控件**操作：插件可能已停用，或其安装从未完成（参见[故障排除](troubleshooting.md#providers-and-addons)）。

## 附加技能 {#skills}

1. 在输入框输入 `@`，搜索 Location 可用技能并选择一个。
2. 在文件/智能体旁检查其可移除附件；如果不打算使用，请在发送前移除。
3. 发送提示词。技能标签会保留在已发送消息中。

选择会附加原生技能 ID 并移除 `@query` 标记；不会将指令粘贴到可见草稿。发送会清除输入框选择，而非 OpenCode 随该消息已存储的指令。移除附件无法撤销先前发送。

技能可用性来自对话的 Location，而非全局 CodeNomad 技能目录。列表无法加载时，关闭并重新打开选择器重试；为空时检查原生发现/配置。参阅 [OpenCode 技能文档](https://opencode.ai/v2/docs/skills/)和[对话](conversations.md)。

## 运行自定义命令 {#commands}

1. 在输入框输入 `/` 并选择可用原生命令。
2. 提供参数，并根据该命令需要在提交前检查**智能体**、**模型**和**思考**。
3. 如果确认不明确，请检查生成的对话，而非反复提交。

命令由 OpenCode 针对活动 Location 发现。其自身的原生定义可以选择执行行为；菜单不是软件包安装程序或无限制配置编辑器。CodeNomad 会在提交原生自定义命令前应用配置文件的会话环境；环境更新失败会阻止发送。`/btw` 是 CodeNomad 独立的临时提问流程，而非普通自定义命令。

命令定义和原生配置继承请使用 [OpenCode 命令文档](https://opencode.ai/v2/docs/commands/)。配置更改后，先刷新/重新打开相关界面；仅当运行时仍需要时才显式重新加载配置。切勿仅为刷新显示而重放可能已接纳的命令。
## 连接已打开的应用 {#application-attachment}

从应用的集成功能中提供文档，然后在会话标题栏（或更多操作菜单）或插件行菜单中选择 **连接已打开的应用…**。仅当活动的原生集成报告了可用连接时才显示此操作。选择应用和文档，检查目标会话及修改警告，然后选择 **确认连接**。初始焦点位于取消。应用运行在 OpenCode 所在的机器上，包括远程连接。不受支持的主机（包括不受支持的 WSL）会显示帮助而非连接操作。

会话标题栏在宽屏和窄屏布局中均持续显示包含应用名称和文档标签的绑定指示器。它读取当前显示会话的绑定状态。未确认的状态显示 **绑定未知**；确认没有绑定时，指示器隐藏。只有最新的权威读取确认该确切会话已连接时，才提供 **断开此会话**。其他客户端可能更改绑定，因此原生变化和重新连接会刷新此状态。

操作提交后，只要目标会话仍在显示，原生变化和重新连接均会保留其结果或错误。连接和断开完成消息是描述已完成请求的本地操作回执。绑定指示器及断开操作的可用性由该会话最新的权威状态决定。导航会关闭回执。

保存的 Q8 元数据仅提供重新连接建议：只有存在相同集成和标签的可用连接时，选择器才提供 **重新连接**，且需要明确确认。当前绑定的权威信息来自集成针对该会话的读取。

插件会在目录不可用时显示提示，或在目录过期时显示最后一个有效目录及获取时间。刷新插件以重试。

移除前的警告会列出插件和确切范围。初始焦点位于 **取消**；**从全局/项目移除** 在 600 毫秒后可用，且需要明确操作。移除可能中断使用该插件的对话中的可用性和连接；全局范围也可能影响其他项目。提交前取消、过期或切换页面不会产生更改。仅移除确认的声明，保留规则、缓存、应用文件及保存的连接提示。配置变化后须重新选择并确认。成功表示声明已移除，运行状态随后由 OpenCode 重新加载更新。如果响应丢失，请先刷新插件核实实际配置，再重新尝试。重新安装可能恢复可用性，但可能需要重新加载或重新附加，中断的操作可能无法继续。

要重新安装已移除的目录集成：

1. 刷新插件，根据当前原生配置和运行状态，确认其声明和已加载插件均不存在。必要时显式选择**重新加载 OpenCode 配置**，然后再次刷新。
2. 打开 **Intégrations**，选择集成，再次选择**安装**。原生应用集成仅使用**全局**范围。检查当前详情并重新确认。
3. OpenCode 原生重新加载后，刷新插件并检查实际激活状态和运行时可用性。OpenCode 的原生声明顺序与保留的规则共同决定最终激活状态；必要时请有意识地调整。检查每个对话的绑定和中断的操作，必要时显式重新连接，再发起新请求。

## 安装或更新应用集成 {#application-installation}

在 **状态 → 插件** 中，打开该集成自身的行菜单，选择 **安装应用集成…** 或 **更新应用集成…**。当活动原生集成的最新状态要求安装或更新时，会显示此操作。无需会话或已提供的文档也可使用。

确认对话框会显示应用名称，以及提供安装程序的 **集成包版本**。请核对两者和机器警告：安装运行在 OpenCode 所在的机器上，该机器可能是远程机器。初始焦点位于 **取消**。必须明确确认才能继续。确认前切换项目、Location 或会话，重新连接，或收到相关原生变化，都会取消待定授权；请重新打开操作以核对最新详情。

WSL 始终拒绝应用内安装，即使已打开的应用看起来兼容。请在受支持的机器上打开应用。

结果会报告集成已安装、已更新、已是最新版本、被拒绝或失败。安装或更新后，请打开应用并检查其集成；通过 [连接已打开的应用](#application-attachment) 单独连接会话。安装成功描述的是安装请求的结果；应用是否实际可用由应用状态反映。

请求绝不会自动重试。被拒绝或失败后，请先检查应用，再选择新操作。如果错误导致结果不确定，请勿重复该请求：先检查应用，再根据需要发起新操作并重新确认。
