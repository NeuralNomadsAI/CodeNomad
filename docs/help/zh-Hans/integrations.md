# 原生集成

CodeNomad 提供 OpenCode 的原生 MCP 连接、插件激活、技能和自定义命令。这些在执行主机上运行，与沙箱[面板扩展](extensions.md)和 [SideCar](browser-sidecars.md) 分开。

## 选择正确的控件 {#integration-scopes}

| 集成 | 操作位置 | 控件更改的内容 |
| --- | --- | --- |
| MCP 服务器 | **状态 → MCP 服务器** | 显示 Location 的原生连接；不会安装服务器。 |
| 原生插件 | **状态 → 插件** | 添加或移除软件包声明，并设置持久的**全局**或**项目**激活规则；对于软件包插件，可显式检查或更新该软件包。 |
| 技能 | 输入框 `@` 菜单 | 显式附加到对话 Location 中的下一条提示词。 |
| 自定义命令 | 输入框 `/` 菜单 | 运行 OpenCode 为该 Location 提供的命令。 |

原生集成拥有其宿主进程权限，并受 OpenCode 权限约束；它们不是沙箱 HTML 面板。

## 连接或断开 MCP {#mcp}

1. 按 [OpenCode MCP 文档](https://opencode.ai/v2/docs/mcp-servers/)在 OpenCode 执行主机上配置 MCP 服务器。
2. 打开项目的**状态 → MCP 服务器**。
3. 使用服务器旁的开关连接或断开。等待连接指示器稳定。

使用该 Location 的其他客户端可以观察到连接更改。 断开不会移除服务器声明或卸载其可执行文件。

连接失败时，请检查服务器配置、所需环境和认证；开关不会完成 OAuth。

## 在全局或项目范围激活插件 {#plugins}

CodeNomad 管理的插件不显示在普通插件列表中，也不提供列表中的激活、更新和移除控件。

出现 **CodeNomad 插件需要处理** 时，打开 **i** 查看详情。已禁用的插件提供 **重新启用**；使用前请检查显示的配置范围。

1. [添加插件](#plugin-sources)或在 OpenCode 配置中声明；然后打开**状态 → 插件**。
2. 悬停或聚焦名称，检查来源、运行时失败和配置目标详情。
3. 有意识地切换**全局**或**项目**。等待写入完成，状态不明时使用**刷新插件控件**。
4. 对于从软件包安装的插件，使用其名称旁的图标。其菜单会写明确切操作：**检查 … 的更新**，或在发现较新版本后**更新 …**。

全局以所连接守护进程发现的全局配置为目标。项目以活动 Location 内的配置为目标，而非继承的祖先文件。后续项目规则可以覆盖全局；全局开关仍显示全局规则，而不会假装是最终项目状态。没有项目规则时，项目继承解析后的全局状态。

内置 OpenCode 插件不会作为用户激活开关提供。 项目目标无法安全地与全局分离，或会超出活动 Location 时，项目控件会禁用。

软件包更新会在 OpenCode 的共享缓存中更改该软件包，影响所有使用它的 Location，其工具提示中也会说明这一点；它不会更改激活规则、重启 OpenCode 或重新加载配置。 本地、内置和 SDK 提供的插件没有软件包操作。

## 添加或移除插件 {#plugin-sources}

1. 在**状态 → 插件**中打开 **+**，选择**添加插件…**。
2. 输入 npm 注册表中的软件包（`name`、`name@1.2.3`、`@scope/name@^1`）或 Git 仓库（`github:owner/repo`、`git+https://…`）。
3. 除非插件只应在此项目中运行，否则保持**全局**，然后选择**添加**。
4. 在 OpenCode 报告之前，新行显示**正在安装**。

要移除插件，请打开其名称旁的菜单，选择**从全局移除**或**从项目移除**。会删除该范围配置文件中的声明及其激活规则；但在插件仍有其他声明时保留禁用规则，并保留前面的声明仍然定义的启用规则。会失去定义的启用规则也会从本项目的配置中删除，否则 OpenCode 会下载同名的注册表软件包；若该规则位于 CodeNomad 不编辑的文件中，则拒绝移除。OpenCode 的软件包缓存保持不变。OpenCode 无法识别的插件（已禁用，或加载前失败）的规则会留在单独一行，其菜单提供同样的移除操作。

插件代码会以你的权限在 OpenCode 中运行。每次在 OpenCode 中打开该文件夹时，**项目**条目都会运行；带有 OpenCode 桌面应用部分的软件包只从**全局**加载这些部分，若此类软件包在其他位置声明，提示会说明这一点。此处拒绝本地路径、配置变量和插件 ID：请在配置文件中声明本地插件。已在适用于此 Location 的配置中声明的软件包会被拒绝，无论其版本、范围或形式如何。

已安装软件包的版本显示在插件名称旁。Git 插件的详情包含提交；若版本不可用，名称旁会显示七位提交标识。将指针悬停或聚焦到名称上，可查看详情、**有可用更新**，以及安装失败时带有 OpenCode 日志编号的错误。

## 附加技能 {#skills}

1. 在输入框输入 `@`，搜索 Location 可用技能并选择一个。
2. 在文件/智能体旁检查其可移除附件；如果不打算使用，请在发送前移除。
3. 发送提示词。技能标签会保留在已发送消息中。

移除附件无法撤销先前发送。

技能可用性来自对话的 Location，而非全局 CodeNomad 技能目录。 参阅 [OpenCode 技能文档](https://opencode.ai/v2/docs/skills/)和[对话](conversations.md)。

## 运行自定义命令 {#commands}

1. 在输入框输入 `/` 并选择可用原生命令。
2. 提供参数，并根据该命令需要在提交前检查**智能体**、**模型**和**思考**。
3. 如果确认不明确，请检查生成的对话，而非反复提交。

命令由 OpenCode 针对活动 Location 发现。 `/btw` 是 CodeNomad 独立的临时提问流程，而非普通自定义命令。

命令定义和原生配置继承请使用 [OpenCode 命令文档](https://opencode.ai/v2/docs/commands/)。配置更改后，先刷新/重新打开相关界面；仅当运行时仍需要时才显式重新加载配置。切勿仅为刷新显示而重放可能已接纳的命令。
## 插件中的集成 {#integration-rows}

**状态 → 插件**中的 **+** 提供**添加集成…**和**添加插件…**。集成选择器列出已审核目录中尚未安装的条目。选择范围和**安装**后，CodeNomad 按所选目录 ID 安装。原生集成**仅全局**可用。**目录不可用**提供**刷新**；**{date} 的目录**表示使用已过期的最后一个有效目录。

通过强调色状态行**安装到 Blender**、**更新 Blender**，或将当前对话**连接**到打开的文档（多个文档时用**连接…**选择）。链条图标和文档表示已连接；选择即可分离。对话的代理第一次使用该集成时，对话也会自动连接。

该行的 **…** 菜单以连接状态开头，例如 **Blender:1 个打开的文档**或 **Blender 已关闭**。随后提供**文档**、**安装到应用…**、**更新应用…**或**重新安装到应用…**（[见下文](#application-installation)）、软件包更新检查、**从全局移除**或**从项目移除**以及**刷新插件控件**。分离只需单击一次，无需确认，并且只影响此对话：应用保持打开，其组件保持安装，其他对话保留各自的连接。

从目录安装、安装或更新应用组件以及移除都需要确认。**取消**首先获得焦点；确认操作在 600 毫秒后可用。启用、插件更新、连接和分离会直接执行。

移除前的警告会列出插件和确切范围。 初始焦点位于 **取消**；**从全局/项目移除** 在 600 毫秒后可用，且需要明确操作。 移除可能中断使用该插件的对话中的可用性和连接；全局范围也可能影响其他项目。 仅移除确认的声明及上述激活规则，保留缓存、应用文件及保存的连接提示。 配置变化后须重新选择并确认。

## 安装或更新应用集成 {#application-installation}

在**状态 → 插件**中，当集成的最新状态提供该操作时，在其状态行中选择**安装到 Blender** 或**更新 Blender**，或在其 **…** 菜单中选择**安装到应用…**、**更新应用…**或**重新安装到应用…**。无论应用打开还是关闭，重新安装都会重写应用组件。没有对话或打开的文档时也可使用。

确认对话框会显示应用名称，以及提供安装程序的 **集成包版本**。 请核对两者和机器警告：安装运行在 OpenCode 所在的机器上，该机器可能是远程机器。 初始焦点位于 **取消**。 必须明确确认才能继续。

WSL 始终拒绝应用内安装，即使已打开的应用看起来兼容。请在受支持的机器上打开应用。

安装或更新后，请打开应用并检查其集成。

如果错误导致结果不确定，请勿重复该请求：先检查应用，再根据需要发起新操作并重新确认。
