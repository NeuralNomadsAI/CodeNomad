# 问题与权限

原生问题、Form 和权限请求在紧邻输入框上方的中断停靠区中回答，而非在待处理的对话工具卡片内回答。

## 找到请求并检查来源 {#request-dock}

1. 选择标有**需要输入** / **需要权限**的对话，或点击项目请求徽章就地打开停靠区。
2. 展开或回答前，阅读请求类型、对话标题和来源。
3. 有多个待处理请求时，使用**上一个请求** / **下一个请求**。仅在想导航到来源时使用**查看会话**。

| 来源 | 含义与行为 |
| --- | --- |
| 打开的对话 | 其请求可正常展开 |
| 带**来自 …** 父级信息的子智能体 | 打开对话的递归后代属于本地上下文；父级来源保持可见 |
| 其他对话 | 最初显示紧凑预览；显式展开后可回答，无需离开当前对话 |
| 项目请求 / 服务请求 | Form 可能没有所属对话；不会显示虚构的对话链接 |

新到请求不会替换正在编辑的请求或导航离开。队列刷新时仍选择同一请求；箭头到达末端不会循环。处理完成后，另一个无关对话的请求仍保持紧凑，直到你将其打开。

**收起请求**只隐藏正文；不会拒绝、取消或回答任何内容。展开编辑器会暂时将输入框缩至最小高度，但不改变其保存的尺寸或草稿。请求内容独立于固定回答操作滚动。

## 回答问题和 Form {#answer-questions-forms}

1. 展开目标请求，填写字段或选择提供的选项。
2. 当选择字段允许自定义答案时，会显示额外的文本框：在其中输入自己的答案来代替所提供的选项（或为多选字段添加自定义值）。回答所有必答问题。
3. 选择**提交**；只有确实打算执行原生取消时，才对问题或 Form 使用**取消**。

部分答案和拒绝草稿会在运行中的客户端内跨队列刷新和对话导航保留。它们不是已提交决定，也不保证在清除客户端数据后恢复。回答失败后仍可编辑；重试前检查待处理请求。CodeNomad 不会自动重放回答。

有些 Form 提供**打开外部表单**，用于浏览器流程。请遵循请求说明并返回检查状态，不要将打开页面视为成功回答。任意提供商/认证 Form 不一定是对话产物。

已完成的原生问题工具会在历史中显示问题、所选答案、选项描述和原样自定义文本。**其他选项**保留未选择的其他选项。这些已完成结果与实时停靠区不同。

## 批准或拒绝权限 {#permission-decisions}

1. 阅读请求的操作、资源和所有**请求的 Diff**。检查哪个对话会收到决定。
2. 可选地输入反馈，解释拒绝原因或更安全的替代方案。
3. 选择**仅允许一次**、**始终允许**或**拒绝**。

| 选择 | 原生影响 | 安全边界 |
| --- | --- | --- |
| 仅允许一次 | 批准本次权限请求 | 不会全面批准无关的后续操作 |
| 始终允许 | 在适用会话上下文内，对匹配请求发送原生持久批准选择 | 不是 CodeNomad 全局或操作系统全局信任开关；请检查授权的资源/模式 |
| 拒绝 | 拒绝请求，可附反馈 | 不会撤销此请求之前执行的工作 |

批准权限可能立即放行工具执行。它不是试运行。当请求内容无法验证时，差异/读取边界和来源身份检查可能阻止批准；请刷新并检查实际请求，不要凭假设批准另一项操作。

如果其他客户端处理了请求，它可能从此处消失。超时或回答失败无法证明原生服务是否接受决定：请等待待处理请求协调更新停靠区，再作下一次明确选择。模糊回复绝不会显示成虚构的已确认决定。

## 阅读权限回执 {#permission-receipts}

1. 即使原生工具卡片隐藏，也可在关联对话内容旁查找**权限决定**。
2. 对没有源消息的决定，打开**会话权限决定**。
3. 使用**加载更多决定**继续，读取失败后使用**重试**。

回执记录已知请求/资源、确认的决定以及可用理由/来源。**在 CodeNomad 中作出的决定**、**自动 · Yolo** 和**原生决定**区分观察到的来源；原生处理完成不代表用户在此窗口点击过。

回执是只读 CodeNomad 注释，而非原生消息或权限规则编辑器。它们不包含在原生完整历史搜索、消息复制和导出中。无法重建 CodeNomad 离线时错过的决定，也不会用成功工具结果代替缺失回执。删除会话会移除其回执。

## Yolo 模式与会话族范围 {#yolo-mode}

1. 选择对话并打开**状态 → Yolo 模式**。
2. 仅在整个会话族都可接受自动批准权限时启用。
3. 开展进一步不可信工作前禁用；检查待处理请求和已运行工具。

尽管控件提及一个会话，其有效范围是解析出的会话族根及后代：从子会话启用/禁用会影响该会话族。原生分叉视为自身的根。这不是对每个项目或独立对话的全局批准。

Yolo **仅批准权限**。它不会回答问题或 Form、提供缺失信息、保证执行成功或绕过后端归属检查。自动批准由 CodeNomad 后端执行：后端仍活动时，仅关闭一个窗口不足以禁用它；后端停止后无法继续批准请求。会话族设置会持久保存，并在再次加载工作区时恢复。

关闭 Yolo 不会撤销已接受决定或回滚文件/网络影响。请检查**自动 · Yolo** 回执，必要时显式停止执行。带人工关卡的自动化请参阅[任务](missions.md)。

## 恢复缺失或过时请求 {#request-recovery}

1. 检查连接指示器，重新连接同一后端/项目。
2. 让恢复流程协调待处理原生请求；覆盖不完整时会保留已知请求和草稿。
3. 如果出现**未能完整恢复问题和权限请求**警告，它会列出项目、原因、文件夹和受影响的会话。请解决该原因（例如已删除的工作树，或在此项目之外工作的会话）；下一次恢复会自动重试。

恢复不会仅为枚举请求而加载每个不活动工作树。不完整响应不是权威的空队列，警告也不意味着允许重复提示词、回答或批准。重新加载配置可能取消原生 Form/权限；不要将它作为常规请求刷新按钮。参阅[故障排查](troubleshooting.md)和 [OpenCode 设置](opencode.md)。
