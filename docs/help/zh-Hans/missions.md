# 任务

任务将目标、协调者对话、子任务及结果保存在一起。入口在右侧的**任务**面板。

任务不可用时，**OpenCode 设置**会为缺失或运行失败的插件打开服务恢复设置。服务器的本地任务桥接不可用时，**服务器诊断**会打开“设置 → 信息”中的诊断报告。

## 显示或隐藏任务 {#activation}

在**自定义右侧面板**中勾选**任务**可显示标签页，取消勾选并确认可隐藏标签页。此操作也会在已连接的 OpenCode 服务器的全局配置中写入 `codenomad.missions` 或 `-codenomad.missions`。项目规则可覆盖全局规则。停用不会删除或暂停任何内容，但可能错过计划运行。如果写入失败，标签页会保持所选的显示或隐藏状态。**重置**只更改布局。**状态 → 插件**不会针对这条精确的全局停用规则发出警告；其他停用方式仍提供**重新启用**。

## 创建任务 {#create}

远程连接使用相同的表单和控件。建议使用 HTTPS 保护网络通信。

选择**创建任务**后，表单会替代任务树，直到创建或取消。创建确认后会选中任务；创建被拒绝后，表单仍可编辑。

您可以在项目的任何对话中，包括子代理或计划执行中，请代理准备独立的一次性或计划任务。其对话保持不变，默认创建新的协调者对话。请保持负责该项目的 CodeNomad 后端可用。**自动启动**授权新任务的首次启动；恢复时读取原始结果。代理还可以列出、查看、启动、暂停、停止、恢复、立即运行、检查、编辑和删除项目内的任何计划，包括您在编辑器中创建的计划。所有操作遵循相同的修订和执行准入检查，并保留明确关闭计划功能的设置。未确认的操作保留原始请求，仅通过读取状态进行恢复。

### 配置 {#saved-briefs}

代理可以从项目所属的任何对话中读取项目内的所有任务，包括您创建的任务。只读视图涵盖子任务、结果、清理、计划执行和来源选项；浏览不会启动或重试工作。

代理还可以诊断计划功能、在保留明确 OFF 设置的前提下准备配置，以及使用原始请求继续已确认的部分编辑。

**配置**可载入保存的目标、备注、剧本、代理／模型和任务会话选择，其名称成为可编辑的标题。请检查填入的字段。

代理可以读取、保存、替换或重命名、删除及修复配置，也能保存现有任务的指令。它们还可以修改全局或剧本专用的代理配置与任务会话默认值、恢复继承、重置无效偏好，并修改删除任务对话的偏好。配置库和这些偏好适用于该 CodeNomad 配置档案的所有项目。项目子代理深度支持 1–10 或**继承**，包括修复空配置块。每次修改都会核对上次读取的值，并保留其后用户所做的编辑。

底部取消、创建旁的**保存配置**用于保存可复用配置，不会创建或启动任务。计划与自动启动分别设置。齿轮打开偏好设置和配置库；删除配置会保留现有任务和对话。

要替换已保存的配置，请使用其名称并选择**替换**。如果有多个同名配置，请先加载要替换的配置。在配置库还有空间时，使用新名称会保存为独立副本。

### 目标、标题和备注 {#mission-instructions}

对于一次性 Mission，代理也可以启动、恢复、在当前步骤结束后暂停、立即中断、停止、编辑、删除、在失败后恢复协调，以及请求缺失报告或进展更新。这也包括您创建的 Mission，并遵守与面板相同的准入和修订检查。除非明确指定其他选项，删除操作会采用您的托管会话删除偏好。未确认的控制和清理保留原始身份；代理会先读取已保存状态，再明确继续已确认的部分操作。

**目标**说明所需结果及验证方法。**标题**是树中的名称；空白任务会取目标的第一句话，最多 60 个字符，之后可修改。**备注**可选，用于传给代理的背景、约束或补充指令。

### 选项和剧本 {#playbooks}

**剧本**选择协调者的工作方法；角色与步骤见[剧本](playbooks.md)。原生权限仍然适用。提交、推送、拉取请求和修改问题跟踪器，必须在目标或备注中明确要求该项操作。

### 委派和深度 {#profiles}

**任务会话**选择协调者下的原生子代理或独立会话。两者都遵守 OpenCode 的权限和嵌套限制。

**子代理深度**影响项目中的所有 OpenCode 对话。 选择**继承**或 1–10 会立即保存。 有效深度及权限取决于读取到的配置。

子代理深度信息会在 **OpenCode 配置文件：** 下显示实际配置来源。

保存项目深度还会允许子代理在该深度内继续委派，并在支持的情况下优先于其他配置文件中的 General 限制。 **继承**会移除添加的规则。 保存不会重新加载 OpenCode，也不改变正在运行的对话。

### 代理和模型 {#agents-models}

展开**代理和模型**，按角色编辑代理／模型／思考三列；折叠后的摘要仍显示请求的选择。初始值来自偏好设置，在表单中的修改只用于此任务。

齿轮可设置全部任务或某一剧本的默认值，修改会立即保存。模型列表跟随对话选择器的可见性与收藏设置；列表外已保存的选择仍会保留。

**比较两个模型**要求 A、B 不同，仅思考级别不同不算。未另选时，裁判使用协调者的模型；使用 A 或 B 作为裁判可能产生偏差。

基于日历的计划要求为协调者及剧本中的每个角色明确指定代理和模型。

### 自动启动 {#automatic-start}

**自动启动**位于计划之外，默认关闭。关闭时创建暂停的任务，之后用 ▶ 启动；开启时在创建确认后请求启动，并执行通常的检查和自动计划准备。

### 使用 /goal 保持协调器持续运行 {#coordinator-goal}

**使用 /goal 保持协调器持续运行**适用于一次性任务，默认关闭。开启后，启动任务会为协调器启用 OpenCode `/goal`，暂停或继续任务会同步暂停或继续该目标，完成或停止任务则会清除它。若任务运行期间 OpenCode 重启，任务会自动恢复因重启而暂停的目标（开启 OpenCode 自动化时，即使关闭 CodeNomad 也能恢复），同时保持手动暂停、停滞或达到轮次上限的暂停状态不变。实时状态与操作显示在任务概览中。

## 计划 {#daily-schedules}

带有重复时间或事件的任务在列表中始终只占一行：每次启动都会在同一个协调者会话中取代上一次启动，并在上一次仍处于活动状态时等待。其详情显示**启动条件**、**期望状态**、下次唤醒或检查、**已启动轮次**和**历史运行**（最近 20 次启动）。关闭**自动启动**时，它以暂停状态创建。**编辑所选任务**会重新打开创建表单，下一次启动使用您保存的内容。**删除所选任务…**会先移除它的计划。 没有启动在进行时，工具栏中的 ▶ 和 ⏸ 会继续或暂停其计划，■ 会永久停止该计划并将任务保留在列表中；启动进行期间，它们控制该次启动，⋯ 菜单可暂停或继续计划。

### 条件 {#native-scheduling}

**i** 按钮打开[计划帮助](missions.md#native-scheduling)。

首个条件是**一次，现在**。**添加条件**添加下一项；选择类型，用 × 删除，或用把手重排。聚焦把手后可用 Alt+上／下。

可选一次现在、每 N 小时、每天、选定星期、每月某日和 cron。时间遵循保存的时区；与系统不同才显示时区字段。没有指定日期的月份会跳过。一次现在以启动时刻为准，只有一次机会，条件可能消耗机会而不启动。需要 OpenCode 服务和执行主机可用。

启动或恢复时，会在项目的 OpenCode 配置中自动准备计划功能。明确的 OFF 设置会保留：如有**打开计划设置**操作，可打开负责该设置的文件；**i** 可显示来源或环境详情。

### 事件和组合 {#scheduling-conditions}

选择**仓库活动 → 事件**，再在同一卡片中填写可选筛选条件。Git 提交与自动检测到的 GitHub、GitLab 或 Gitea 仓库事件共用一个菜单，检测方式与 Contribute 相同：先 `upstream`，再 `origin`。三者都支持新建 PR/MR、已合并 PR/MR 和新建 Issue，并可按**作者（可选）**筛选，包括 `dependabot[bot]`。选择事件会固定其仓库；已保存条件保留原目标。

检查使用 OpenCode 主机上的 `gh`、`glab` 或 `tea`，CodeNomad 关闭后也能运行；公共仓库可以匿名读取。 自托管服务需要已登录该主机的 CLI。 **github.com** 还通过已登录的 `gh` 提供账号通知与 Dependabot 告警，需要[通知访问权](https://docs.github.com/en/rest/activity/notifications)或[告警读取权](https://docs.github.com/en/rest/dependabot/alerts)。 通知保留已读状态；告警包括已修复或忽略的项目。 已保存通知的 **GitHub 仓库**留空时覆盖整个账号。 首次启动建立基准。

事件可跟随其他计划或一次性任务成功、本地提交、新消息或明确列出的项目文件。 请在相应条件内选择来源。 搜索不区分大小写，包括带变音符号的字母。 搜索期间，无论当前页是否已有匹配项，都需在选择器中点击**加载更多来源**继续。 为新消息选定的对话也会为运行提供上下文。 更改条件类型会清空其来源。 编辑时保留已保存的对话上下文。

**或**连接相邻时间或相邻事件。**如果**使时间后的事件成为条件：自上次成功运行后至少一个发生变化。**否则**使事件后的时间成为后备：从其上一个时段或启用以来，上方条件未启动过运行才执行。后续事件约束该后备。

开头的触发事件每 15 分钟检查一次。 首次启动建立基准，成功推进基准，失败保留基准。 运行不会重叠。

### 计数和历史 {#scheduling-limits}

**协调者会话**默认在每次执行时使用**新会话**。 选择时间或事件后，**现有会话**可选择本项目中同一执行 Location 的根对话。 每次执行会使用配置的代理和模型在其中继续，并保留对话记录、标题及权限。 任务控制也会影响其中已有的工作。 每次执行的结果和日志在历史中分别保留。 该对话必须使用协调者的代理、模型和思考：否则保存会被拒绝，而启动时若发现它们已更改，则使用另一个会话。

你可以请代理使用它当前的根对话来准备计划。每次执行都会等到该对话空闲后再开始。

选中的计划显示状态、下次唤醒／检查、已启动／成功次数及历史。保留最近 30 个结果，累计计数仍在。已获准的立即运行也计数。表单无法表示的保存规则保留到显式替换；编辑前检查结束条件和次数限制。

在**关注的对话**中点击**添加对话**并选择对话，即时任务也可使用。启动前可更改选择，或点击 × 移除。

选择**本地分支有新提交**可监视本地 Git 引用；选择**远程分支有新提交**后，输入分支名（例如 `dev`）。检查直接读取检测到的远程仓库，无需在本地执行 fetch。两次检查之间的多个提交只触发一次执行。

## 任务树和结果 {#tracking}

箭头展开子任务；单击行选择任务或子任务，其操作留在页头。无子任务则无箭头。筛选仅针对已加载条目。一次性与周期任务同列一表，按最近活动排序；正在运行的计划执行排在最前。

眼睛切换中央摘要并跟随选择。打开对话进入对应协调者或子任务。⋯ 菜单提供适用的更新、打断、保存配置和编辑操作。

选择、展开的部分和阅读器属于各自的项目标签页，并随其恢复。同一文件夹的多个标签页可以阅读不同报告，或在一个标签页保留报告，在另一个标签页显示对话、文件或网页预览。打开或关闭阅读器只会更改当前标签页；任务工作和完成结果的已读确认在窗口内保持共享。

接近列表末尾会自动加载更多任务和子任务。子任务加载失败时，使用**重试**继续。

### 颜色和状态 {#status-colours}

旗帜显示任务状态，箭头显示子任务的待关注状态；重复任务使用循环图标。红色等待回答，黄色表示观察到工作。强调色暂停符号表示在工作中途暂停的任务，橙色暂停符号表示已暂停的计划（继续之前不会启动任何内容），橙色警告三角形表示中断。绿色表示待查看的任务、子任务或成功运行。

强调色图标下方的小型静止中性色横线表示**等待计划运行**：下一次唤醒已确认。强调色随调色板变化。单独的强调色图标表示已准备或尚未启动。已查看的完成结果、已停止的计划和**状态未确认**显示为中性色；请阅读状态文字。

选择任务、点击／扫过绿色子任务图标，或使用箭头菜单中的**标为已读**可确认结果。对于**成功运行待查看**，在活动窗口中明确选择重复任务行，或使用**标为已读**。计划仍启用时图标恢复等待状态，否则恢复中性色。已选中行收到的新结果保持未读。撤回子任务会保留历史。

### 问题和决策 {#questions}

协调者应先自行解决能解决的事项，再询问剩余决策、同意或凭据。请在中断面板回答。探索区分协调者决策与用户回答；独立会话将决策写入备注。参见[剧本](playbooks.md)。

### 进度说明 {#briefings}

里程碑说明是协调者的判断。 通过 ⋯ 请求更新后在摘要中阅读。

## 上下文和结果 {#context-flow}

新任务与新运行有独立计划。 将有用的过往结果写入目标或备注。

### 搜索以前的对话 {#context-search}

CodeNomad 运行时，代理可搜索项目保存的对话。过往结论重要时请明确要求搜索；完整上下文不会自动继承。

## 关闭和重启 {#lifetime}

关闭 CodeNomad 不会停止原生工作。原生计划可在服务／主机可用时继续；正常日历在服务重启后恢复。显式暂停、停止和不确定结果仍阻止启动。

部分协调和恢复操作需要 CodeNomad 服务器。

正在运行的一次性任务在没有 CodeNomad 窗口打开该项目时，仍会继续分配子任务并送达其报告。在 CodeNomad 中更改的环境变量和权限设置会在项目打开后重新应用于这些对话。

## 暂停、停止和未确认操作 {#controls-recovery}

一次性任务暂停会让当前步骤结束，不启动新步骤；立即打断会请求即时中断。停止是终止操作，需要确认。暂停计划会关闭未来启动并请求中断当前运行。工具效果可能继续。

保留原始未确认请求：只要原生计划视图或编辑器保持打开，CodeNomad 就会自动重新读取直到确认，并仅对准确记录的部分准备自动重试。出现时，一次性任务控制请使用 **检查状态**，普通一次性创建请使用 **刷新任务地图**，不要另发替代操作。原生计划在其 **更多操作** 菜单中提供 **检查状态**。

## 编辑、删除和对话清理 {#cleanup}

子任务对话清理是一次性任务的选项。删除原生计划会保留其对话。

⋯ 中的编辑打开相同表单。 首次启动前可改未锁定的准备字段，之后仅在允许时改指令和备注。 锁定字段说明原因。

删除前先停止工作。 一次性任务直接移除。 删除计划先关闭未来启动。 删除子任务对话的偏好仅适用于合格对话；协调者、复用／共享或无法验证归属的对话保留。 清理显示剩余工作和显式重试。
