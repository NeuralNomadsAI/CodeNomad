# 任务

保存的字段过大时，选择 **分页读取原始 JSON**。**上一页** 和 **下一页** 读取精确且有界的片段；集合变化后，重试会从第一页重新开始。

选择器每次加载50条任务摘要；使用 **加载更多** 继续浏览。搜索仅筛选已加载的任务。只有选中的任务或阅读器指定的目标才加载详情。清理记录、活动和请求分别显示加载数量及继续加载控件。即使已观察多个独立窗口，未读取的执行者和请求仍为未知。概览中的 **读取已保存字段** 可精确分页查看执行者、报告、历史、回执及扩展元数据。读取失败时保留上次显示；重试重新读取该窗口，集合变化时从首个窗口开始。读取不会启动工作。历史完成状态只按持久化项目完成计数器初始化一次；新完成的任务在显示前仍为未读。

任务将持久项目计划与原生 OpenCode 对话结合。协调者规划并委派；任务树记录依赖和结果。已保存计划、已接纳输入和观察到的执行是不同事实。

## 先创建，再显式启动 {#create}

1. 打开右侧面板的**任务**，选择**创建任务**。在你创建或取消之前，表单会替代任务列表和所选任务的任务节点。
2. 填写**任务要做什么？**，检查从首句预填的**标题**（最多 60 个字符）。
3. 对于**一次，立即执行**和**无条件**，保持**计划**折叠；也可展开以选择频率、条件和可选限制。创建计划工作前，请检查**保存的时区（IANA）**和预览。
4. 展开**选项**，设置**剧本**、**备注**、**代理和模型**、**任务会话**、项目的**子会话嵌套深度**、已保存简述及可选关注对话。选择**比较两个模型**时，**模型 A** 和**模型 B** 选择器会显示在主表单中。
5. 选择**创建**。选择暂停的条目并检查，准备好后使用 ▶ **开始**。立即无条件工作会启动一个任务；延迟、重复或有条件策略会启用原生计划。

**创建会保存已暂停的任务。**只有点击播放才会启动工作或启用原生日历；创建或保存简述会保留共享服务监管偏好。创建属于所选项目/Location，并记录请求的配置和任务会话策略。验证信息显示在相应字段旁；若拒绝信息说明未发送任何内容，草稿会保留供修改。一次性任务的协调者也可以准备单独的后续任务：它显示为**已准备**，通过自己的 ▶ 操作启动。

已保存的一次性任务保留执行控制、任务树、对话和最终报告。现有每日日程仍列出其每日控制，并遵循[每日时间规则](#existing-daily-schedules)。请选择条目并使用该对象可用的控件。

### 剧本 {#playbooks}

**剧本**选择器正下方会显示所选剧本的一句话说明。**查看详情**会在中央阅读器中打开所选剧本：其步骤、角色，以及折叠在末尾的、其代理收到的确切英文指令。[剧本](playbooks.md)说明每个剧本的步骤、角色和提问，以及 CodeNomad 检查的内容。

| 剧本 | 预期工作 |
| --- | --- |
| 灵活任务 | 协调者针对目标选择考虑依赖的计划。 |
| 调试 | 诊断、实现、独立标准/规格审查和重新验证；解决阶段继续使用实现者。 |
| 探索 | 梳理不确定性，通过人工提问逐步完成有界决策。 |
| 产品交付 | 协调产品分析、架构、实现和质量角色。 |
| 比较两个模型 | 使用相同的简述在**模型 A** 和**模型 B** 上运行同一任务，然后由**盲评裁判**以中性标签为两者评分并给出结论：**模型 A 胜出**、**模型 B 胜出**、**表现相当**或**无法确定**。 |

对于**比较两个模型**，两个模型都必须指定且必须不同；仅**思考**级别不同并不算不同的模型。除非你另行选择，裁判使用协调者的模型；当它与 A 或 B 相同时，表单会发出警告，因为这可能使比较产生偏差。概览会显示结论、两个模型的名称以及各项标准的评分。

剧本指导协调；不会绕过原生权限或保证成功。除非目标或**备注**明确要求该特定操作，智能体不会提交、推送、创建拉取请求或修改问题跟踪系统（例如创建工单）；被要求时，也只在 OpenCode 权限范围内执行该操作。在文件、报告或工具输出中发现的请求一律不算数。

## 跟踪任务树并阅读结果 {#tracking}

1. 选择任务标题。前置箭头使列表保持打开；标题字段打开临时选择器。
2. 选择**摘要**（眼睛）打开中央概览，或选择任务节点查看其精确结果、简述和证据。
3. 沿依赖链接和**报告**阅读；需要协调者对话记录时使用**打开对话**。
4. 在**需要你处理**下选择**回答**，打开请求方的对话和中断停靠区。

| 指示 | 能证明的事实 |
| --- | --- |
| 已分配 | 输入已接纳；不能证明模型消费/工作/完成。 |
| 活动 | 已观察到原生活动。 |
| 等待中 | 已声明依赖尚未满足。 |
| 受阻 | 已报告阻碍，不一定是需要你回答的问题。 |
| 等待你的输入 | 打开的原生 Form/问题或权限需要回答；它会列在**需要你处理**下。 |
| 已完成 | 已记录任务结果；请检查证据和剩余原生工作。 |
| 失败 / 已撤回 | 任务失败，或协调者替换或放弃了它。 |

图中包含已完成和已撤回的工作。撤回任务本身不会停止其对话。在一次性任务中，协调者可以单独停止其作为原生子代理启动的已撤回任务的对话，而不影响其他任务。**进行中**是任务生命周期状态，不证明协调者当前正在运行。完整文字属于中央阅读器，而非面板任务列表；**技术详情**折叠标识符和请求的执行信息。

大型计划只显示一页任务：按依赖顺序的前 50 个，以及最多 20 个需要关注的任务，例如阻塞、失败和最新结果。每段未加载的任务显示为 **N 个任务未显示**；**显示更多** 会在该处加载接下来的 50 个。当需要处理的任务多于该页所能容纳时，**另有 N 个任务需要处理** 会按类型给出此任务的计数，**显示这些任务** 会加载这些任务。虚线短段标出未显示的依赖或后续任务，任务阅读器中的依赖链接会先加载对应任务。任务阅读器显示其最新结果；**N 个更早的结果未显示** 提供 **全部显示**，用于加载完整历史。无法加载任务或报告时，阅读器会说明；**重试** 会重新加载。

任务页只有在完整接收后才会显示。读取失败或内容更改时，会保留上次显示的任务。如果读取期间列表发生变化，请先**刷新**，再**重试**；该页将从头重新读取。缺少一部分内容并不代表任务或请求不存在，重试读取也不会启动工作。如果 Missions 插件无法提供页面，请在重新连接或重新加载插件后重试。

### 颜色与已中断的任务 {#status-colours}

任务标记、任务节点图标和列表的前置箭头使用与会话列表相同的颜色：颜色只显示此刻需要你处理的内容。

| 颜色 | 含义 |
| --- | --- |
| 红色 | 需要你回答；显示在 **需要你处理** 下。 |
| 黄色，闪烁 | 工作正在进行。 |
| 橙色 | 任务已暂停或已中断，并提供继续它的操作。 |
| 绿色 | 你在此窗口中尚未打开的已完成任务；一旦选中它就恢复为中性。 |
| 蓝色 | 已准备的任务，像已撰写的提示词一样等待启动。 |

其余一切都是中性的，包括已完成和失败的任务节点：结果体现在状态文字和图标中。列表折叠时，其箭头取其他任务的红色、黄色和绿色中最紧急的颜色；与折叠的会话一样，橙色和蓝色只显示在各自的行上。

当协调者未作结论就停止、且没有其他内容在运行时，任务为 **已中断**。显示为 **失败** 的任务也可以恢复。两种情况下，工具栏的第一个按钮都会变为 **恢复中断的任务**：它请协调者根据已保存的计划和结果重新评估，并先重新打开失败的任务。协调者不会将一次性任务以失败结束：当没有你就无法推进时，会在 **需要你处理** 下向你提问。只有你可以停止任务。

### 问题与决定 {#questions}

只有协调者会向你提问。任务及其启动的子代理会把未决问题连同选项、证据和建议交回给协调者。提问前，协调者会先尝试自行解决：阅读项目、查找资料、让某个任务进行调查，或采用易于撤销的默认做法并记录为假设。它只询问自己无法决定的事项：你的同意、凭据、难以撤销的选择，或目标未确定的产品决策。它会把待回答的问题合并到 **需要你处理** 下的一个表单中，并先启动无关的工作。

在**探索**中，决策任务会准备一份摘要，由协调者处理每个决定：证据充分且选择易于撤销时自行决定，把问题留在**备注**中以后处理，或者向你提问。使用**原生子代理**时，决策任务的结果会注明由谁决定：

| 标签 | 含义 |
| --- | --- |
| **协调者的决定** | 协调者未询问你就作出了决定；结果会显示其理由，以及它提供的撤销说明（如有）。如需更改，请通过**打开对话**给协调者写消息。 |
| **你的回答** | 你在 CodeNomad 中断停靠区回答了这个问题。 |

只有你在中断停靠区给出的回答才算作**你的回答**；智能体不能代你回答。使用**原生子代理**时，每个决策问题都以它所决定的唯一一项决定的标签结尾，例如 `[decision choose-seam 3fa9c21b]`。多个决定一起询问时，每个决定都是带有自己标签的单独问题；同时提到两个决定的问题哪一个都不决定。使用**独立会话**时，协调者改为把每个结果记录在**备注**中，并注明是它还是你作出的决定。在**产品交付**中，已准确描述行为变更的目标视为已批准的规格；否则协调者会合并待批准事项，请你批准。

### 简报与更新请求 {#briefings}

协调者会收到指令，在初始计划后、任务结算后、等待人工时及最终报告前发布项目简报。这是撰写的评估，而非实时活动计数器或保证定期发送的心跳。地图自简报发布后发生变化时，会有提示。

使用工具栏下的**请求更新**获取协调者新评估，然后阅读**摘要**。**已请求更新…**表示请求待处理，而非已回答。**发送未确认**不授权自动重发：请先打开协调者对话，再另行提出新请求。这是普通原生输入，不是只读沙箱；协调者保留正常权限。

## 上下文如何在任务中流转 {#context-flow}

任务图是任务共享的持久记忆。它保存目标和**备注**、每个任务节点及其**任务简报**、依赖（**依赖于 …**）和状态、为已完成工作记录的**报告**（摘要、**证据**、**建议的后续步骤**以及可能有的**结构化报告**）、协调者的简报和**计划变更**。OpenCode 随项目保存它，因此它在对话和重启之后依然存在；任务控制台显示它，恢复也从它继续。每个参与者获得其中确定的一部分：

| 参与者 | 获得的内容 |
| --- | --- |
| 协调者 | 每个轮次都获得目标、备注和剧本指令。需要时随时读取完整任务图；其已存储的对话保留它读过的每个结果，而 OpenCode 可能会[压缩](history.md#compact-session)其模型上下文。 |
| 任务节点（**原生子代理**） | 协调者在普通 OpenCode 子代理调用中传递的分配：目标、该节点的标题和简述、角色指令及其依赖的任务节点。协调者可以附加上下文，例如之前的结果。 |
| 任务节点（**独立会话**） | 同样的分配，作为其自身对话中的一条消息。每个轮次它还会获得目标、备注和自己未完成的分配，并且可以读取完整任务图。 |
| 任务节点启动的辅助智能体 | 其父级在调用中写入的内容。剧本要求每个父级把辅助智能体所需的范围、约束和安全规则传递下去。 |

结果沿同一路径返回。原生子代理把结果返回给启动它的对话（通常是协调者），由协调者将其记录为该任务节点的报告。独立会话自行记录报告，CodeNomad 将报告摘要作为消息送达协调者。

后续任务节点通过两种方式利用先前的工作。依赖决定工作顺序：协调者在某个节点所依赖的任务节点完成后才启动它，并把相关结果写入简述或附在分配旁；独立会话也可以在任务图中读取这些报告。若要继续某个已完成任务节点自己的对话，协调者会声明一个复用该对话的后续任务节点：后续节点在那里以该对话的当前上下文继续，OpenCode 可能已对其进行[压缩](history.md#compact-session)，而更早的细节仍保留在其已存储历史中，可供搜索。调试剧本就是这样把两份审查交回实现者的。使用**独立会话**时，协调者也可以把任务节点分配给现有的主对话，该对话保留自己的上下文，包括与之无关的先前工作。除此之外，任务节点从自己的分配开始于新对话，其他节点的对话记录通过协调者或搜索到达它。在**比较两个模型**中，裁判的分配和上下文不包含目标和备注；其简述包含匿名化的输出。

每个计划轮次都以自己的协调者和任务图开始，使用已保存的指令和冻结的输入。关注的对话提供有界的新增用户和助手文本；成功轮次结束后，其已处理消息游标才会推进。先前轮次保留在计划历史中。轮次内启动的对话可以读取该轮次的任务图。新的一次性任务拥有单独的任务图：请将需要延续的结果写入其目标或**备注**，或请协调者用这些上下文准备后续任务。

### 搜索以往对话 {#context-search}

CodeNomad 运行期间，项目中的每个智能体对话（包括任务协调者和任务节点）都可以使用 CodeNomad 的会话搜索工具（`codenomad.session_search`，通过 OpenCode 的 Code Mode 使用）。它在该对话所属项目文件夹的已保存对话中搜索，排序方式与**整个工作区**[搜索](history.md#full-history-search)相同，返回带有每个对话标题和标识符的简短摘录，以及读取完整对话的方法。原生工具权限照常适用。智能体会在自行决定时，或在目标、备注或你的消息提出要求时进行搜索，例如查找以往任务或任务节点得出的结论。CodeNomad 关闭期间执行的计划轮次在没有此工具的情况下工作。

## 配置、委派和深度 {#profiles}

保存深度时会在项目配置中保留已启用的原生计划。项目中明确设置的 `schedules:false` 仍保持关闭；移除深度会保留计划设置。保存原生设置前，必须先解决 JSON 与 JSONC 文件并存的冲突。

1. 使用任务齿轮或**设置 → 任务**编辑**新任务默认设置**。
2. 在**应用范围**下选择**所有任务**或某个剧本，然后设置**任务会话**，并在**代理和模型**下为每个角色设置一行（先是协调者，然后是该剧本的各个角色）。每项选择都会立即保存；没有保存按钮。
3. 在剧本范围中，各行显示标有**全局**的全局值。更改某个字段会以这些值为起点自定义该角色；其还原图标会重新使用全局值。**重置**（需确认）只清除所显示范围的代理和模型。
4. 创建时使用**选项 → 代理和模型**指定请求的配置；**使用已保存的默认设置**会恢复已保存的配置。
5. 原生递归限制请在此处或创建时的**选项**中编辑**子会话嵌套深度 → 为项目指定的深度**。按 Enter 或离开字段会保存已更改的有效值；**继承**会立即保存；Escape 会放弃未保存的值。

| 设置 | 范围与影响 |
| --- | --- |
| 新任务默认设置 | 配置范围的默认值，仅适用于**新建**任务；剧本例外覆盖通用默认值。 |
| 智能体 / 模型 / 思考 | 随创建记录的协调者/角色请求选择；不会为满足后续工作静默切换繁忙参与者。计划轮次使用已保存的请求配置；编辑会应用于后续轮次。 |
| 原生子代理 | 任务会话在协调者下使用原生 subagent/all 智能体。 |
| 独立会话 | 声明的任务会话使用 primary/all 智能体和独立对话；不禁用内部原生辅助智能体。 |
| 子会话嵌套深度 | 该处**全部** OpenCode 对话的项目配置，而非仅任务。留空为继承：**继承**会移除项目覆盖设置，以及因此变空或只剩全局**图像只存储一次**值的 `experimental` 块。OpenCode 将项目的 `experimental` 块作为整体读取，因此其中保留的其他实验性设置仍会遮蔽全局深度。OpenCode 内置的 **General** 子代理默认无法启动子代理，因此其对话从不嵌套：保存任意项目深度时，还会在同一文件中添加一条规则，允许子代理在该深度内启动自己的子代理，并优先于其他配置文件中对 General 的限制（深度为 1 时，OpenCode 的深度上限仍会阻止嵌套）；**继承**会将其移除。在 **OpenCode 有效深度** 下方，编辑器会说明 General 子代理能否嵌套。如果项目以旧格式定义 General，且 `permission` 为单个值，或已同时设置 `task` 和 `subagent`，则只保存深度，编辑器会予以提示：请自行在该文件中允许 General 启动子代理。保存不会重新加载 OpenCode 或更改运行中的对话。 |

**原生默认值**与**全局**不同：前者请求 OpenCode 自身的默认值，后者继承全局选择；在剧本范围中选择原生默认值仍是显式例外。会检查目录可用性；请求的配置不证明对话当前实际使用的配置。两种任务模式下，内部辅助调用仍受原生权限和配置深度约束。

每个**模型**列表显示的内容与对话的**模型**选择器相同，名称一致并按提供商分组：不包含已隐藏的模型；启用仅收藏筛选时，也不包含其他模型（参见[模型可见性、收藏和思考](providers.md#models)）。不支持工具的模型同样不包含。列表之外的已保存模型仍保持选中。选择器当前无法提供的已保存模型标记为**不可用**：它不在项目当前的目录中、已弃用或不支持工具。

被拒绝或未确认的选择绝不会重新发送：会重新显示已存储的值，只有在无法读取这些值时才会出现**重新加载**。如果深度更改未确认，你的值会保留；请先使用**刷新项目深度**，再进行其他更改。不要将 **OpenCode 有效深度未知**解释为零或禁用。

## 复用已保存简述 {#saved-briefs}

1. 创建时展开**选项 → 从已保存的简述开始**，选择已保存简述。
2. **创建**前检查复制的目标、备注、剧本、配置和委派。
3. 使用**另存为简述**为可复用草稿命名。选中的一次性任务（包括已完成任务）也提供**另存为简述**。

简述保存指令和请求选择，不保存任务计划、结果、对话、日程时钟或执行权限。加载只填入普通创建草稿；不会启动或安排任何工作。移除简述会保留现有任务/对话。**设置 → 任务 → 已保存的简述**管理资料库；如果资料库无法读取，**重置已保存的模板库**（需确认）移除的是已保存简述，而非执行。日程本身没有另存为简述操作。

## 计划、补跑和关注对话 {#daily-schedules}

### 原生计划 {#native-scheduling}

标签旁的 **i** 图标提供选项说明：悬停、用键盘聚焦或轻触即可查看。

在创建或编辑时展开**计划**。**频率**提供以下选项：

| 选项 | 时间安排 |
| --- | --- |
| 一次，立即执行 | 点击播放时启动一次，可选条件按下文说明检查。 |
| 一次，指定日期 | 保存的 IANA 时区中的一个日期和时间；点击播放时已过去的日期会被拒绝。 |
| 一次，延迟执行 | 以分钟或小时为单位的正整数时长，从点击播放时开始。 |
| 固定间隔 | 至少 15 分钟；首次唤醒在点击播放一个间隔后。 |
| 每天 | 保存时区中的一个当地民用时间。 |
| 指定星期几 | 在勾选的星期几的同一时间。 |
| 每天多次 | 最多八个独立时间点，例如 09:15 和 17:45；重复时间共用一个轮次。 |
| 每月指定日 | 在每月 1–31 日的选定时间；没有该日期的月份会跳过。 |
| 高级（cron） | 原生 cron 表达式，最多每分钟一次。 |

**后续时段（最多5个）**根据已保存时区和假定的播放时间提供预览。有条件时，**后续检查（最多5个）**预览检查时间；轮次取决于已核实的变化。未更改的已保存间隔保留其原生相位。已暂停或未知的相位会显示为不可用，直到可以读取其原生状态。延迟和间隔使用经过时长；民用日历遵循已保存时区和 OpenCode 的夏令时规则。显示的日期是推算值，受服务和主机可用性限制。

故障后，原生计划最多补跑一个轮次，然后回到未来时段。它使用已记录的原生到期时段，该时段可能早于后来错过的时段。每天多个时间点共用这一次补跑和同一防重叠保护。另一个轮次启动前，未解决的轮次会以其原始对话和消息标识进行核对。恢复显式暂停的重复计划时，使用下一个未来时段；暂停的一次性计划可以延迟到达一次。

### 条件和来源 {#scheduling-conditions}

选择一个可选**条件**及其**此项目中的来源**：**另一计划执行成功**、**本地分支有新提交**、**一次性任务成功完成**、**关注的对话有新消息**或**指定文件发生变化**。只使用条件时，保留**一次，立即执行**：原生检查每 15 分钟运行一次，直到其唯一轮次启动。结合日历时，仅在该日历的时段检查条件。重复条件可在出现新的合格变化后再次启动轮次。

首次播放建立起始参照。继续会保留此参照，包括暂停后观察到的变化。成功来源要求经过验证的成功结果和已结算的原生会话族。分支检查使用本地提交及其祖先关系，不从远程获取。对话检查等待完整、稳定的新消息，并排除技术唤醒及该轮次自己的对话。文件使用最多 128 个明确指定的项目相对路径，每行一个；递归模式和链接路径会被拒绝。来源缺失、已移动、不明确或超出容量时，会说明原因并阻止准入。检查之间的变化必须在来源中留下持久痕迹才能被检测到。

同时观察到的变化会合并。轮次会冻结已观察到的来源证据；成功结算会将该快照标记为已处理，后续变化留待下一次检查。失败轮次会保留来源检查点，并要求人工干预。**选项**下的**关注的对话（可选）**单独提供上下文，与选择对话消息条件相互独立。

### 结束限制和计数 {#scheduling-limits}

持续重复时将限制留空。**最后允许的时段**和**首次播放后多少小时为最后时段（可选）**限定合格时段；最早的限制生效。时长从首次播放开始，暂停期间继续计时。结束前记录的时段可能在长时间故障后延迟到达。已接纳的轮次可以持续观察，直到获得结果。

**最多启动次数**是所有时间点和**立即运行**共用的总数。协调者的首次输入被接纳时，轮次计数一次，包括后来失败的轮次。检查、未变化的条件和被拒绝的唤醒不占名额；准入不确定时会占住名额，等待核对。一次性策略最多允许一个轮次。已用名额在编辑和重启后仍会保留；未更改的结束限制保留首次播放的起算点和绝对结束时段。更改上限会改变整个生命周期的总额度；总额度等于或低于已用次数时，计划结束。编辑器会说明，更改频率可能在保存时开始新的间隔相位。

选中的原生计划显示**期望状态**、**原生日历**、**下次唤醒**或**下次检查**、带有**自 … 起记录**的**检查次数**、**已启动轮次**、**成功轮次**、结束限制和**历史运行**。通过**打开对话**阅读过去的轮次。**计划已结束**描述计划的结束；请单独检查轮次结果。结果保留最新 30 条；累计计数在此窗口之外仍会保留。**加载更多 Mission**加载下一页已保存对象。

列表仅在已配置时显示条件和结束限制，仅在有条件时显示**检查次数**。

### 现有每日日程 {#existing-daily-schedules}

现有每日日程使用已保存的 IANA 时区和当地民用时间。每次运行都有自己的协调者和任务图；选择当前任务树或过去的日期/结果，即可在中央阅读结果。其历史保留 30 个结果。以下每日规则适用于这些条目：

| 情况 | 调度行为 |
| --- | --- |
| 错过多个到期日 | 仅运行晚于已结算每日标记的最新到期日，不为每个错过日期积压运行。 |
| 夏令时向前跳的缺口 | 推进到之后第一个有效分钟；日末缺口会跨越日期边界。 |
| 重复时钟小时 | 使用第一次出现的时间；不会创建第二次每日运行。 |
| 整个民用日期被跳过 | 该日没有运行。 |
| 时钟后拨 | 不会让已处理日期再次到期。 |
| 现有运行仍待处理 | 不会与新的每日运行重叠。 |

创建时间也限制符合条件的每日工作。现有每日条目提供**立即运行**时，它会在待处理运行保护下启动单独的手动运行，并保留每日时钟。显示的下次时间是推算值，受服务和主机可用性限制。

**关注的对话（可选）**从选定对话添加有界上下文。只有完成的运行才推进已处理消息游标；失败/中断运行不会静默消费该上下文。若指令加上下文超出容量，请缩短指令或移除关注对话，而非假定会读取无限历史。

## 生命周期与服务重启 {#lifetime}

**技术详情**旁的 **i** 说明技术活动及费用。在**设置 → OpenCode**中，监管状态和错误保持可见，常规说明收纳在 **i** 中。

对于原生计划，展开**技术详情**可查看其**主载体**和**协调载体**、各自的原生日历，以及任何**清理等待协调**状态。这些技术会话不提供消息输入操作，也不会出现在普通会话或来源选择器中。技术唤醒、标题和上下文压缩使用本地模型，不向提供商发送 HTTP 请求；原生事件和统计仍可能包含这些活动，而实际轮次仍产生正常的模型费用。上下文压缩在保持会话和日历标识不变的同时，限制所处理的上下文。已存储的原生消息和事件可能持续增长，直到显式清理已结束的计划；保留的 30 条 Mission 结果与之分开。深度控件和**计划**会在路径可用时通过**OpenCode 配置文件：**显示该路径；深度控件会另行标明其**项目写入目标**。

| 组件 | 关闭意味着什么 |
| --- | --- |
| CodeNomad 项目标签页 | 在 CodeNomad 中关闭该项目；不停止原生工作或 OpenCode 服务，重新打开即可再次找到会话。 |
| 整个窗口、退出应用或重新加载渲染器 | 保留项目连接以便恢复；不停止原生工作或 OpenCode 服务。 |
| CodeNomad 后端 | 不停止 OpenCode。运行中的一次性任务会继续：其协调者、原生子代理任务和任务工具都在 OpenCode 中运行。向独立会话分配任务并将其报告送达协调者、协调者准备的任务、停止已撤回任务的对话、恢复以及任务控制台需要等待后端；OpenCode 服务重启后继续一次性任务也是如此。 |
| 已启用的原生计划 | 在执行主机和服务可用时，持久化的 OpenCode 日历会唤醒其项目并执行轮次，即使 CodeNomad 界面和后端都已关闭。 |
| OpenCode 服务重启 — 健康的原生计划 | 健康且期望状态为运行的计划会自动恢复其日历。新准入之前，会以原始标识核对待处理工作。 |
| 现有每日日程 | 服务存活期间，即使 CodeNomad 关闭，其插件时钟也会运行。服务重启后，它处于**已中断**；显式**继续**会核对待处理运行并重新启用每日时钟。 |

对于原生计划，显式暂停、停止、失败工作和不确定结果会在重启后保留准入屏障。检查保留的轮次和原始请求；提供时使用**检查本次运行**或**刷新已保存的请求**，然后仅在状态允许时**继续**。原生继续执行会以其现有标识进行观察。已证实的失败或无报告结束需要人工恢复；证据不完整时，轮次仍不确定。绝不要通过重启来重复已开始的工具效果。

[保持 OpenCode 运行](opencode.md#service-supervision)会单独监管执行主机上的共享服务。除非已保存关闭偏好，否则首次播放任务会启用此功能；创建暂停的任务会保留此选择。关闭监管后，OpenCode 继续运行，但不会自动重新启动。Windows、macOS 和 WSL 受登录边界限制；原生 Linux 使用用户 linger，并受权限限制。睡眠、休眠、WSL 空闲生命周期和外部主机控制都会限制可用性；请独立于计划检查监管状态。

任务可在桌面应用和独立的 CodeNomad [服务器](server.md)上运行。面板显示**任务控制台不可用**时，其消息会指出原因：

| 原因 | 处理方法 |
| --- | --- |
| OpenCode 工作区尚未就绪 | 重新连接项目，然后刷新。 |
| OpenCode 尚未加载任务插件 | 稍后刷新；如果问题仍然存在，请在**设置 → OpenCode** 中使用**重新加载 OpenCode 配置**。 |
| OpenCode 无法加载任务插件 | 在插件列表中查看其错误，修复后刷新。 |
| CodeNomad 服务器无法打开其本地任务连接（127.0.0.1） | 检查服务器日志；重新加载 OpenCode 无济于事。 |

## 暂停、停止和不确定结果 {#controls-recovery}

1. 选择条目，操作前检查当前状态和对话。
2. 使用暂停图标作可恢复暂停，或使用停止图标并确认作终止停止。一次性任务提示为**暂停任务**和**永久停止任务**；日程提示会指明日程。
3. 结果未确认时，使用**检查状态** / **检查控制状态**读取已有结果。不要以替换操作绕过不确定性。
4. 对一次性操作，标题栏的**刷新并重新发送未确认的操作**会先检查状态，仅在你显式点击时重发仍未确认的同一精确操作。

一次性暂停会让进行中的工作先完成：协调者及其子代理完成当前步骤、不再开始新工作然后停止，期间面板显示**正在暂停：进行中的步骤正在完成。** **立即中断**则会立即停止它们：中断任务原生会话族并挂起协调。停止同样会中断，还会取消排队的会话族输入/交付，且为终止状态。中断有边界：**部分子代理可能仍在运行。**表示其中有一项不完整。检查保留结果并使用其显式重试，而非假定所有 Shell/工具影响已取消。继续会告知协调者哪些内容被暂停或中断；由它决定如何继续工作。

原生计划的**暂停**会关闭未来准入，并请求中断已接纳的轮次；**继续**会在重新启用前核对现有工作。**停止…**为终止操作。**立即运行**使用相同的待处理保护和已启动轮次额度，同时保留日历。**检查本次运行**核对原始轮次。请保留未确认的操作并使用**刷新已保存的请求**；被动刷新和重新连接会保留此请求。已开始的工具效果可能在中断后继续。

现有每日条目保留每日**暂停**、**停止…**、**继续**、**立即运行**和**检查本次运行**控件。暂停和停止会取消其时钟，并请求中断已注册的根对话，包括独立专家。请检查其原生会话族以及任何部分中断结果。临时每日检查失败会显示警告并重试；丢失的用户控制回复仍关联其原始请求。已停止的条目保持终止状态。

对于空闲但无报告的一次性协调者，主 ▶ 操作可验证并恢复；任务符合条件时有针对性的缺失报告恢复。恢复先检查原生活动、后代和等待；活动未知时拒绝接纳。不会重放分配或替换计划。打开对话以解决未完成问题、权限、Shell 或后台工作。

**创建**未确认时，窗口保留已提交请求并禁用该项目进一步创建；工作树删除可能仍被阻止。刷新只读取状态。关闭/重新打开编辑器不能修复。重新加载窗口前检查任务列表：重新加载会清除本地锁，**不证明创建失败**。不要在重新加载或重启后盲目创建重复任务。

## 编辑、删除和清理对话 {#cleanup}

如果表单仍在加载时目标或备注发生变化，它会提示任务在你打开后已更改，而不会填入它们；选择**重新打开**以编辑当前版本。

轮次之间，若没有轮次或未解决的控制请求占用对象，暂停或运行中的原生计划可编辑标题、指令、备注、请求的配置、任务会话模式、来源、日历和限制。暂停的计划仍保持暂停；已启用的计划会在继续之前核对日历。保存会保留过去的结果、已处理的来源、启动计数和首次播放的起算点；未更改的结束限制保留其绝对结束时段。

已接纳的轮次期间，只有指令和备注遵循活动文本编辑契约：更改记录在该轮次历史中，并保存供未来轮次使用。现有子任务、简述、配置和执行标识保持准入时的值。结构字段在轮次结算前保持锁定，暂停后也是如此。只要创建过任何子任务，剧本就保持锁定，包括已完成或已撤回的子任务。准入或控制不确定，或完整性证据不足时，结构编辑保持只读。创建与编辑使用同一套日历校验；预览会将修改后的最后允许时段应用到已保存的下次唤醒，包括延迟到达的唤醒。

本地分支来源包含没有worktree的分支，仅读取本地引用。选择器最多支持200个本地分支；列表更大时来源会显示为不可用。可启用原生计划时，**开始**和**继续**会显示准确的配置路径并请求同意。原生计划未启用时，**立即运行**会禁用并显示原因；请在 OpenCode 配置中启用 `experimental.schedules`，然后刷新。启用响应丢失时，会保留原始请求以核对回执。

首次 Play 前，可以保留**选项**中的关注对话并改回立即无条件启动。Play 会读取并冻结完整、稳定的消息前缀（每个来源最多32条消息，启动输入总计不超过16,384个字符）。来源缺失、已移动或超出容量时，将说明原因并阻止启动。重试会保留原始冻结上下文和启动标识。

读取回执确认准备工作仅部分完成后，会显示**重试**。点击会再次检查同一回执，仅继续原始保存的更改，并保持任务暂停。

新准备的任务首次启动前，可以编辑标题、指令、备注、工作流程、请求的智能体/模型/思考设置、任务会话模式和**计划**。可以在即时、延迟、重复和有条件启动之间切换，并保留同一个任务。保存会保持暂停并准备一个新的空协调者，同时保留初始对话。只有 Play 才会开始工作或启用计划。启动后，指令和备注遵循活动任务的编辑规则。如果保存尚未确认，**刷新已保存的请求**只读取原始结果；部分准备工作阻止启动、文本编辑和删除时，请保留同一请求。

对可编辑的一次性任务或原生计划使用**编辑所选任务**。阅读锁定字段旁的说明。发生修订冲突时，选择**重新加载当前配置**，再打开**用于比较的旧草稿**，检查保留的草稿后再保存。现有每日日程保留其专属工具栏控件。

对于原生计划，**删除所选任务…**会先禁用未来轮次，再移除条目。对话和结果会保留；等待核对的清理仍显示在**技术详情**中。请保留未确认的删除，并刷新其原始请求。

1. 对不再需要的一次性任务，选择**删除所选任务…**并检查确认内容。
2. 确认前可选中**同时删除为此任务创建的专家会话**。
3. 查看**会话清理**中的已移除/保留/待处理数量。提供重试时，只重试剩余的已记录清理。

删除任务不同于停止；请先停止并检查剩余工作。协调者和复用对话会保留。共享、移动、有子会话或无法验证归属的专家也可能保留。部分清理不会回滚，也不会在后台静默完成。即使会话清理显示待处理 0，任务卡片也可能在删除仍待确认时消失。请继续使用原来的**重试**操作，直到删除得到确认；它会保留相同的删除请求和选项。概览阅读器保留最近 20 次已完成的清理。删除任务会释放其在项目中的存储：较早删除的任务会自动清除。
