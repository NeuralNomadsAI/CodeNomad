# קבצים ו־Git

הלשונית **קבצים** בלוח הימני משלבת עיון בעותק עבודה, שינויים מקומיים והיסטוריית קומיטים. בחירת שורה נפרדת מפתיחת הקורא המרכזי שלה.

## עיון בעותק עבודה {#browse-workspace}

1. פתחו **קבצים** ובחרו **סביבת עבודה**.
2. בחרו **עץ עבודה לעיון** כשאתם רוצים עותק עבודה אחר; הרחיבו תיקיות לפי הצורך.
3. לחצו על שורת קובץ לבחירתה. השתמשו בפעולת העין שלה לפתיחת התצוגה המרכזית או לסגירתה.
4. השתמשו ב־**רענן** אם יש לבדוק מחדש את תמונת המצב הגלויה.

| מצב | מה נקרא | השפעה על השיחה |
| --- | --- | --- |
| סביבת עבודה | קבצים בעותק העבודה שבו מעיינים | ללא העברת סשן או מעבר לענף |
| שינויים | שינויים באינדקס ובעץ העבודה | שינויי Git מתבצעים רק בפעולות מפורשות |
| קומיטים | היסטוריית קומיטים בדפים ותוכני גרסאות | היסטוריה לקריאה בלבד; ללא מעבר גרסה |

תיקיות מורחבות נשמרות במעבר בין מצבים. רשימות/מצב/היסטוריה משתמשים בתמונות מצב ממטמון ומאמתים מחדש לאחר שינויי מערכת קבצים רלוונטיים, הפעלה או רענון מפורש; מיקוד הלוח אינו מבטיח קריאה חדשה. תיקיות גלויות בסביבת העבודה קולטות מעצמן קבצים שנוצרו, נערכו, ששמם שונה או שנמחקו במארח שרת הקצה, לכל היותר פעם בחמש שניות בזמן פעילות רציפה; תיקיות מכווצות ו־worktrees אחרים נקראים מחדש רק כשאתם מציגים אותם.

פעולות שורה כוללות **העתק נתיב**, וכשהלקוח תומך בפתיחת נתיבי שרת קצה, פעולות מנהל קבצים/עורך/מסוף כגון **פתיחה באמצעות יישום ברירת המחדל**, **הצגה בתיקייה**, **פתיחה במנהל הקבצים** ו־**פתיחת מסוף כאן**. פעולות עשויות לעבור ל־**פעולות נוספות עבור {name}** כשהמקום מוגבל; שם הקובץ או התיקייה מחליף את `{name}`. דפדפן מרוחק אינו יכול להניח שנתיב שרת הוא נתיב מקומי למכשיר; ראו [שליטה מרחוק](remote-control.md).

## עריכת מקור ושמירה בטוחה {#edit-save}

1. פתחו קובץ טקסט מסביבת העבודה בפעולת העין שלו.
2. ל־Markdown, בחרו **הצג מקור** לעריכה, או **תצוגת Markdown** לקריאת התוצאה המעוצבת.
3. ערכו ובחרו **שמור**, או לחצו **Ctrl/Cmd+S** כשהעורך ממוקד.
4. אם הקובץ השתנה חיצונית, בדקו את אישור הדריסה; בחרו **בטל** לשמירת הטיוטה בלי לדרוס את השינוי.

שמירה כותבת את הקובץ בפועל בעותק העבודה שבו מעיינים, לרבות worktree מקושר; היא אינה שולחת קלט או מעבירה את העריכה ל־staging/מבצעת commit. השמירה קוראת תחילה מחדש את הקובץ המוסמך. חלון ההתנגשות אומר **הקובץ שונה על ידי הסוכן. לדרוס את שינויי הסוכן?**; התייחסו באותה זהירות לשינויים של כל כותב חיצוני.

טיוטות מקור ששונו נשמרות בזיכרון תהליך התצוגה לפי מופע פרויקט, תיקייה ונתיב כאשר קוראים נסגרים או מוחלפים. רענוני מערכת הקבצים אינם מחליפים אותן בשקט. זה אינו אחסון קבצים מתמשך: שמרו או העתיקו עריכות חשובות לפני הפעלה מחדש/טעינה מחדש של הלקוח. כשלי קריאה/כתיבה משמרים את הטיוטה. **רענן** מפורש מזהיר לפני השלכת עריכות שלא נשמרו.

סגירת הקורא בכפתור הסגירה שבקצהו מחזירה לשיחה; שדה הקלט נשאר זמין מתחת לקורא. החלפת סשן/worktree מנקה את הקורא שנבחר, לא מבטיחה שמירת טיוטתו. פתיחת תצוגת דפדפן מחליפה את הקורא; פתיחת קובץ מחזירה אותה תצוגה למצב צ׳אט.

## תצוגות מוגבלות ולקריאה בלבד {#preview-limits}

1. פתחו תמונה, קובץ בינארי או שינוי היסטורי בפעולת העין.
2. בהבדלים, השתמשו ב־**עבור לתצוגה מפוצלת** / **עבור לתצוגה מאוחדת**, בגלישת שורות ובפקדי אזורים ללא שינוי לפי הצורך.
3. סגרו את הקורא כדי לחזור לצ׳אט.

| תוכן | התנהגות זמינה |
| --- | --- |
| טקסט מסביבת העבודה, לרבות מקור Markdown | ניתן לעריכה עם שמירה מפורשת |
| תמונה מסביבת העבודה | תצוגת תמונה לקריאה בלבד |
| תוכן בינארי אחר | תצוגת חלופה לקריאה בלבד המציינת שתצוגה מקדימה אינה זמינה |
| הבדלי טקסט בשינויים/קומיטים | השוואה לקריאה בלבד, לא עורך לאף צד |
| הבדלי תמונות ב־Git | תמונות לפני/אחרי מהגרסאות המדויקות המושוות |

קריאות תצוגה מקדימה מוגבלות; תוכן גדול/לא נתמך עשוי להיות לא זמין במקום להיטען ללא גבול. תמונות היסטוריות לעולם אינן מוחלפות בקובץ הנוכחי בעץ העבודה. כשל תצוגה אינו אומר שהקובץ עצמו חסר. פתחו את הקובץ ביישום חיצוני מתאים כשזמין, בלי לשנות את גרסתו רק כדי להשיג תצוגה מקדימה.

## העברה ל־staging, הוצאה ממנו ו־commit {#stage-commit}

1. בחרו **שינויים** ובדקו **שינויים שנשמרו ל-staging** ו־**שינויים**.
2. השתמשו ב־**העבר ל-staging** / **הוצא מ-staging**, בחרו מספר שורות לפעולת הקבצים הנבחרים המתאימה, או גררו שורות בין הסעיפים.
3. הזינו הודעה בראש **שינויים שנשמרו ל-staging**, ואז בחרו **בצע commit**.

כותרות סעיפים מכווצים נשארות יעדי שחרור בגרירה. כיווץ סעיפים או החלפת מצבים משמרים את מצבם ואת טיוטת הודעת ה־commit. סעיף ארוך מציג את 200 הקבצים הראשונים שלו, ואחריהם שורה כגון **480 קבצים לא מוצגים** עם **הצג עוד 200** לחשיפת הבאים במקומם; ספירות הסעיפים נשארות סכומים מלאים, והקבצים הנוכחי, המוצג בתצוגה מקדימה והנבחרים נשארים מוצגים. טווחי Shift-לחיצה מכסים שורות מוצגות בלבד, כך שפעולה מרוכזת לעולם אינה כוללת קובץ שאינכם רואים. העברה ל־staging/הוצאה ממנו משנה את האינדקס ב־worktree שבו מעיינים; commit מתעד רק תוכן ב־staging. הוצאה מ־staging אינה משליכה את העריכה בעץ העבודה.

בדקו קבצים ב־staging לפני commit, במיוחד כשסוכנים או לקוח אחר כותבים שם גם הם. commit שנכשל אינו נשלח שוב אוטומטית. רעננו מצב/היסטוריה ובדקו את השגיאה לפני ניסיון חוזר, כי תשובה שאבדה אינה הוכחה שלא נוצר commit.

## קריאת היסטוריית קומיטים {#commit-history}

1. בחרו **קומיטים** ובחרו commit לקריאת הודעתו והקבצים שהשתנו בו.
2. השתמשו ב־**סינון קומיטים שנטענו…** לסינון הקבוצה הטעונה, או ב־**טעינת קומיטים קודמים** לאחזור דף נוסף.
3. פתחו קובץ שהשתנה בפעולת העין שלו.

היסטוריית טקסט משווה את ה־commit להורה הראשון שלו (או לבסיס ריק ב־commit שורש). היא אינה מעבירה HEAD או מזיזה סשנים. סינון קומיטים טעונים אינו חיפוש יומן Git בכל השרת. רעננו כדי להתחיל מההיסטוריה הנוכחית לאחר קומיטים חדשים; דפדוף קיים שומר את תמונת ההיסטוריה שממנה התחיל.

## רווחים וסיומות שורה {#whitespace-line-endings}

1. פתחו **הגדרות → מתקדם → הסתר שינויים של רווחים בלבד**.
2. כבו זאת אם עליכם לבדוק עריכות של רווחים בלבד שלא נמצאות ב־staging והושמטו משינויים.
3. בדקו את ההבדלים בפועל ואת התוכן ב־staging לפני commit.

ההגדרה מופעלת כברירת מחדל. השפעתה העיקרית היא הסתרת שינויים מתאימים בקובצי טקסט במעקב שאינם ב־staging מרשימת השינויים, הספירות, הבחירה, ההעברה המרוכזת ל־staging ופעולות הגרירה. קבצים מוסתרים נשארים מחוץ ל־staging. קבצים ב־staging נשארים גלויים, וכך גם קבצים לא במעקב, קבצים שנוספו/נמחקו/ששמם שונה וקבצים בינאריים. זיהוי שנכשל/אינו נתמך משאיר קבצים גלויים במקום לנחש.

זיהוי הרשימה של Git יכול להתעלם מרווחים פנימיים, משינויי CRLF בלבד ומשורות חדשות סופיות שנוספו/הוסרו. השוואת הרווחים בקורא ההבדלים צרה יותר: הזחה ורווחים/טאבים בסוף, לא כל הרווחים הפנימיים. Stage ו־Commit תמיד פועלים על התוכן המדויק, ללא תלות בהעדפת התצוגה.

הבדלים בסיומות שורה ובסימן סדר בתים עשויים להפיק הערה עובדתית במקום שורות מודגשות. כיבוי ההגדרה אינו יכול לגרום לעורך לצייר כל שינוי סיומת שורה/BOM או כל החלפת רווחים בסוף באותו אורך. הבדל ריק חזותית אינו הוכחה לבתים זהים.

## אתחול Git {#initialize-git}

1. פתחו **שינויים** או **קומיטים** בתיקייה שאינה מאגר.
2. בחרו **אתחול Git**; הוא רץ מיד ללא אישור.
3. המתינו לרענון הפרויקט/הסשן, ואז העבירו ל־staging ובצעו commit במפורש כשתהיו מוכנים.

אתחול יוצר `.git` בתיקייה שנפתחה במפורש; אינו מאתחל תיקיית הורה או יוצר commit ראשון. אם Git חסר בשרת הקצה, שיחות מוגבלות לתיקייה ועיון בסביבת העבודה עדיין אפשריים, אך אתחול ופעולות Git אינם זמינים. בכשל לא ודאי, רעננו לפני ניסיון חוזר; אף בקשת אתחול אינה נשלחת שוב אוטומטית. ראו [פרויקטים](projects.md).
