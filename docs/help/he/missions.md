# משימות

משימות מצמידות תוכנית פרויקט מתמשכת לשיחות מקוריות של OpenCode. המתאם מתכנן ומאציל; עץ המטלות מתעד תלויות ותוצאות. תוכנית שמורה, קלט שהתקבל להרצה והרצה שנצפתה הן עובדות שונות.

## יצירה ואז הפעלה מפורשת {#create}

1. פתחו **משימות** בלוח הימני ובחרו **יצירת משימה**. הטופס מחליף את רשימת המשימות ואת המטלות של המשימה שנבחרה עד שתיצרו או תבטלו.
2. מלאו **מה המשימה צריכה לעשות?** ובדקו **כותרת**, הממולאת מראש מהמשפט הראשון (עד 60 תווים).
3. השאירו את **תזמון** מקופל עבור **פעם אחת, מיד** ו־**ללא תנאי**, או הרחיבו אותו לבחירת תדירות, תנאי ומגבלות לפי הצורך. בדקו את **אזור זמן שמור (IANA)** ואת התצוגה המקדימה לפני יצירת עבודה מתוזמנת.
4. הרחיבו **אפשרויות** עבור **מדריך**, **הערות**, **סוכנים ומודלים**, **שיחות משימות**, **עומק הקינון של תתי־סשנים** של הפרויקט, תקצירים שמורים ושיחות במעקב לפי בחירה. עם **השוואת שני מודלים**, הבוררים **מודל A** ו־**מודל B** מופיעים בטופס הראשי.
5. בחרו **יצירה**. בחרו את הרשומה המושהית, בדקו אותה ואז השתמשו ב־▶ **התחלה** כשתהיו מוכנים. עבודה מיידית ללא תנאי מתחילה משימה אחת; מדיניות דחויה, חוזרת או מותנית מפעילה תזמון מקורי.

**יצירה שומרת משימה מושהית.** רק פעולת ההפעלה מפעילה עבודה ולוחות זמנים מקוריים; יצירה או שמירת תקציר משמרות את העדפת ההשגחה על השירות המשותף. היצירה שייכת לפרויקט/ל־Location שנבחרו ומתעדת את הפרופילים המבוקשים ואת מדיניות שיחות המטלות. האימות מופיע לצד השדה המתאים; סירוב שמציין שלא נשלח דבר שומר את הטיוטה לתיקון. מתאם חד־פעמי יכול גם להכין משימת המשך נפרדת: היא מופיעה כ־**מוכנה** ומתחילה מפעולת ▶ שלה.

משימות חד־פעמיות שמורות שומרות על בקרות ההפעלה, עץ המשימות, השיחות והדוחות הסופיים שלהן. לוחות זמנים יומיים קיימים נשארים ברשימה עם הבקרות היומיות ועם [כללי התזמון היומי](#existing-daily-schedules). בחרו את הרשומה והשתמשו בבקרות הזמינות לאותו אובייקט.

### מדריכי עבודה {#playbooks}

הבורר **מדריך** מציג ישירות מתחתיו תיאור במשפט אחד של המדריך שנבחר. **הצגת פרטים** פותח את המדריך שנבחר בקורא המרכזי: השלבים, התפקידים ובסוף, במצב מקופל, ההנחיות המדויקות באנגלית שהסוכנים שלו מקבלים. [מדריכי עבודה](playbooks.md) מסביר את השלבים, התפקידים והשאלות של כל מדריך, ומה CodeNomad בודק.

| מדריך עבודה | העבודה המיועדת |
| --- | --- |
| משימה גמישה | המתאם בוחר תוכנית מודעת־תלויות למטרה. |
| ניפוי תקלות | אבחון, מימוש, סקירת תקנים/מפרט נפרדת ואימות חדש; פתרון ממשיך את שיחת המממש. |
| חקירה | ממפה אי־ודאויות ופועלת דרך החלטות תחומות עם שאלות לאדם. |
| אספקת מוצר | מתאמת תפקידי ניתוח מוצר, ארכיטקטורה, מימוש ואיכות. |
| השוואת שני מודלים | מריצה את אותה מטלה עם תיאורים זהים על **מודל A** ועל **מודל B**, ואז **שופט עיוור** נותן ציון לשניהם תחת תוויות ניטרליות ומוסר פסק דין: **מודל A מנצח**, **מודל B מנצח**, **שקולים** או **ללא מסקנה**. |

ב־**השוואת שני מודלים**, שני המודלים נדרשים וחייבים להיות שונים; רמת **חשיבה** שונה בלבד אינה מודל שונה. אלא אם תבחרו שופט, הוא משתמש במודל של המתאם; הטופס מזהיר כשהוא זהה ל־A או ל־B, דבר שעלול להטות את ההשוואה. הסקירה מציגה את פסק הדין, את שמות שני המודלים ואת הציונים לפי קריטריון.

המדריך מנחה תיאום; הוא אינו עוקף אישורים מקוריים או מבטיח הצלחה. סוכנים אינם מבצעים commit או push, אינם פותחים pull request ואינם משנים מערכות מעקב תקלות (למשל ליצירת כרטיסים), אלא אם המטרה או ה**הערות** מבקשות במפורש את הפעולה המסוימת הזו; אז הם מבצעים רק אותה, במסגרת ההרשאות של OpenCode. בקשה שנמצאה בקבצים, בדוחות או בפלט של כלי לעולם אינה נחשבת.

## מעקב אחר העץ וקריאת תוצאות {#tracking}

1. בחרו את כותרת המשימה. החץ המוביל משאיר את רשימתה פתוחה; שדה הכותרת פותח בורר זמני.
2. בחרו **סיכום** (עין) לסקירה המרכזית, או בחרו צומת מטלה לתוצאה, לתיאור ולראיות המדויקים שלו.
3. עקבו אחר קישורי תלויות ו־**דוחות**; השתמשו ב־**פתיחת השיחה** למתאם כשנחוץ לכם התמליל שלו.
4. תחת **נדרשת תגובתך**, בחרו **מענה** לפתיחת שיחת הגורם המבקש ואזור הבקשות.

| מחוון | מה הוא מוכיח |
| --- | --- |
| הוקצתה | קלט התקבל להרצה; צריכת המודל/עבודה/השלמה אינן מוכחות. |
| פעילה | נצפתה פעילות מקורית. |
| ממתינה | התלויות המוצהרות עדיין לא התקיימו. |
| חסומה | דווח מכשול, לא בהכרח שאלה עבורכם. |
| ממתינה לתשובתך | טופס/שאלה מקוריים פתוחים או הרשאה דורשים תשובה; הם מופיעים תחת **נדרשת תגובתך**. |
| הושלמה | נרשמה תוצאת מטלה; בדקו את ראיותיה וכל עבודה מקורית שנותרה. |
| נכשלה / הוסרה | המטלה נכשלה, או שהמתאם החליף אותה או נטש אותה. |

הגרף כולל עבודה שהושלמה והוצאה מהתוכנית. הוצאת מטלה מהתוכנית אינה עוצרת כשלעצמה את שיחתה. במשימה חד־פעמית, המתאם יכול לעצור בנפרד את השיחות של מטלה שהוסרה ושהוא הפעיל כתת־סוכן מקורי, בלי לגעת במטלות אחרות. **בתהליך** הוא מצב מחזור החיים של המשימה, לא הוכחה שהמתאם שלה פועל כרגע. טקסט מלא שייך לקורא המרכזי, לא לרשימת המטלות בלוח; **פרטים טכניים** מכווץ מזהים ומידע הרצה מבוקש.

תוכנית גדולה מציגה עמוד אחד של המשימות שלה: 50 הראשונות לפי סדר התלויות ועד 20 שדורשות תשומת לב, כמו חסימות, כשלים והתוצאות החדשות ביותר. כל רצף של משימות שלא נטענו מופיע בתור **N משימות לא מוצגות**; **הצג עוד** טוען שם את 50 הבאות. כשיותר משימות דורשות תשומת לב ממה שהעמוד מכיל, **N משימות נוספות דורשות תשומת לב** מציג את ספירות המשימה לפי סוג, ו**הצג אותן** טוען את המשימות האלה. קו מקווקו מסמן תלות או משימה תלויה שאינה מוצגת, וקישור תלות בקורא של משימה טוען קודם את המשימה שלו. הקורא של משימה מציג את התוצאות החדשות ביותר שלה; **N תוצאות קודמות לא מוצגות** מציע **הצג הכול**, שטוען את כל ההיסטוריה שלה. כשאי אפשר לטעון משימה או דוח, הקורא מציין זאת; **ניסיון נוסף** טוען שוב.

דפי משימות מוצגים רק לאחר שהתקבלו במלואם. קריאה שנכשלה או השתנתה משאירה את המשימות האחרונות שהוצגו. אם הרשימה משתנה במהלך הקריאה, בחרו **רענון** ואז **ניסיון נוסף**; הדף נקרא שוב מההתחלה. חלק חסר לעולם אינו מוכיח שמשימה או בקשה אינן קיימות, וניסיון חוזר לקריאה אינו מתחיל עבודה. אם תוסף המשימות אינו יכול לספק את הדף, נסו שוב לאחר התחברות מחדש או טעינת התוסף מחדש.

### צבעים ומשימות שנקטעו {#status-colours}

סימוני המשימות, סמלי המטלות והחץ של הרשימה משתמשים בצבעים של רשימת השיחות: הצבע מציג רק את מה שדורש אתכם עכשיו.

| צבע | משמעות |
| --- | --- |
| אדום | מצופה מכם תשובה; היא מופיעה תחת **נדרשת תגובתך**. |
| צהוב, מהבהב | מתבצעת עבודה. |
| כתום | המשימה מושהית או נקטעה, ויש פעולה להמשך שלה. |
| ירוק | משימה שהושלמה ועדיין לא פתחתם בחלון הזה; היא חוזרת לניטרלית ברגע שבוחרים בה. |
| כחול | משימה מוכנה, שממתינה להפעלה כמו הנחיה שנוסחה. |

כל השאר ניטרלי, כולל מטלות שהושלמו או נכשלו: התוצאות מופיעות בטקסט המצב ובסמלים. כשהרשימה מכווצת, החץ שלה מקבל את הדחוף ביותר מבין אדום, צהוב וירוק במשימות האחרות; כמו בשיחות מכווצות, כתום וכחול מוצגים רק בשורות שלהן.

משימה **נקטעה** כשהמתאם שלה עצר בלי לסכם, ושום דבר אחר אינו פועל. גם משימה שמוצגת כ**נכשלה** ניתנת לחידוש. בשני המקרים הכפתור הראשון בסרגל הכלים הופך ל**שחזור משימה שנקטעה**: הוא מבקש מהמתאם להעריך מחדש על סמך התוכנית והתוצאות השמורות, ומשימה שנכשלה נפתחת מחדש קודם. מתאם אינו מסיים משימה חד־פעמית ככישלון: כששום דבר אינו יכול להתקדם בלעדיכם, הוא שואל אתכם שאלה תחת **נדרשת תגובתך**. רק אתם עוצרים משימה.

### שאלות והחלטות {#questions}

רק המתאם שואל אתכם שאלות. המטלות ותתי־הסוכנים שהן מפעילות מחזירים אליו את השאלות הפתוחות שלהם, עם האפשרויות, הראיות והמלצה. לפני שהוא שואל, המתאם מנסה להכריע בעצמו: הוא קורא את הפרויקט, מחפש מידע, מטיל על מטלה לבדוק, או בוחר ברירת מחדל שקל לבטל ורושם אותה כהנחה. הוא שואל רק את מה שאינו יכול להכריע: הסכמתכם, פרטי גישה, בחירות שיקר לבטל או החלטות מוצר שהמטרה משאירה פתוחות. הוא מאגד את השאלות הממתינות בטופס אחד תחת **נדרשת תגובתך** ומפעיל קודם את העבודה שאינה תלויה בהן.

ב**מסע חקר**, מטלות ההחלטה מכינות סיכום והמתאם מכריע בכל החלטה: הוא מחליט בעצמו כשהראיות מספיקות והבחירה קלה לביטול, שומר את השאלה ב**הערות** להמשך, או שואל אתכם. עם **תת־סוכנים מקוריים**, תוצאת מטלת ההחלטה מציינת מי החליט:

| תווית | משמעות |
| --- | --- |
| **החלטת המתאם** | המתאם החליט בלי לשאול אתכם; התוצאה מציגה את הנימוק שלו וכל הנחיה לביטול שסיפק. כדי לשנות זאת, כתבו למתאם דרך **פתיחת השיחה**. |
| **התשובה שלכם** | עניתם על שאלה זו באזור הבקשות של CodeNomad. |

רק תשובה שאתם נותנים באזור הבקשות נחשבת **התשובה שלכם**; סוכן אינו יכול לענות במקומכם. עם **תת־סוכנים מקוריים**, כל שאלת החלטה מסתיימת בתג של ההחלטה היחידה שהיא מכריעה, למשל `[decision choose-seam 3fa9c21b]`. כששואלים כמה החלטות יחד, כל אחת היא שאלה נפרדת עם תג משלה; שאלה שמציינת שתי החלטות אינה מכריעה באף אחת מהן. עם **שיחות עצמאיות**, המתאם רושם במקום זאת כל תוצאה ב**הערות** ומציין אם הוא או אתם החלטתם. ב**אספקת מוצר**, מטרה שכבר מתארת במדויק את שינוי ההתנהגות נחשבת למפרט מאושר; אחרת המתאם מבקש מכם לאשר אותו, ומאגד אישורים ממתינים.

### עדכוני מצב ובקשות עדכון {#briefings}

המתאם מונחה לפרסם עדכון מצב לפרויקט אחרי התוכנית הראשונית, אחרי השלמת מטלות, כשהוא ממתין לאדם ולפני הדוח הסופי. זו הערכה כתובה, לא מונה פעילות חי או אות חיים תקופתי מובטח. הודעה מציינת כשהמפה השתנתה מאז העדכון.

השתמשו ב־**בקשת עדכון** מתחת לסרגל הכלים להערכה חדשה מהמתאם, ואז קראו **סיכום**. **עדכון התבקש…** אומר שהבקשה ממתינה, לא שנענתה. **השליחה לא אושרה** אינו מתיר שליחה אוטומטית מחדש: פתחו את שיחת המתאם לפני הגשת בקשה חדשה ונפרדת. זהו קלט מקורי רגיל, לא ארגז חול לקריאה בלבד; המתאם שומר את הרשאותיו הרגילות.

## איך הקשר עובר בתוך משימה {#context-flow}

מפת המשימה היא הזיכרון המשותף והמתמשך של המשימה. היא מכילה את המטרה ואת ה־**הערות**, כל מטלה עם **תדריך המשימה** שלה, התלויות שלה (**תלויה ב-**) והמצב שלה, את ה־**דוחות** שנרשמו לעבודה שהסתיימה (סיכום, **ראיות**, **הצעדים הבאים המומלצים** ו־**דוח מובנה** אם יש), את עדכוני המצב של המתאם ואת ה־**שינויים בתוכנית**. OpenCode שומר אותה עם הפרויקט, ולכן היא שורדת שיחות והפעלות מחדש; בקרת המשימה מציגה אותה, והתאוששות ממשיכה ממנה. כל משתתף מקבל חלק מוגדר ממנה:

| משתתף | מה הוא מקבל |
| --- | --- |
| מתאם | את המטרה, ההערות והוראות מדריך העבודה בכל תור. הוא קורא את המפה כולה בכל פעם שהוא צריך; השיחה השמורה שלו שומרת כל תוצאה שקרא, ואילו OpenCode עשוי [לסכם](history.md#compact-session) את הקשר המודל שלו. |
| מטלה (**תת־סוכנים מקוריים**) | ההקצאה שלה, שהמתאם מעביר בקריאה רגילה לתת־סוכן של OpenCode: המטרה, הכותרת והתיאור של המטלה, הוראות התפקיד שלה והמטלות שהיא תלויה בהן. המתאם יכול להוסיף לצידה הקשר, כגון תוצאות קודמות. |
| מטלה (**שיחות עצמאיות**) | אותה הקצאה, כהודעה בשיחה משלה. בכל תור היא מקבלת גם את המטרה, ההערות וההקצאות הפתוחות שלה, והיא יכולה לקרוא את המפה כולה. |
| עוזרים שמטלה מפעילה | מה שההורה שלהם כותב בקריאה. מדריכי העבודה מנחים כל הורה להעביר את התחום, האילוצים וכללי הבטיחות שהעוזרים שלו צריכים. |

התוצאות חוזרות באותה דרך. תת־סוכן מקורי מחזיר את התוצאה שלו לשיחה שהפעילה אותו, בדרך כלל המתאם, שרושם אותה כדוח של המטלה. שיחה עצמאית רושמת דוח משלה, ו־CodeNomad מוסר את הסיכום שלו למתאם כהודעה.

מטלה מאוחרת יותר נשענת על עבודה קודמת בשתי דרכים. התלויות קובעות את סדר העבודה: המתאם מתחיל מטלה כשהמטלות שהיא תלויה בהן הושלמו, ומכניס את התוצאות הרלוונטיות לתיאור או לצד ההקצאה; שיחות עצמאיות יכולות גם לקרוא את הדוחות האלה במפה. כדי להמשיך את השיחה עצמה של מטלה שהסתיימה, המתאם מצהיר על מטלת המשך שעושה בה שימוש חוזר: מטלת ההמשך ממשיכה שם עם ההקשר הנוכחי של אותה שיחה, ש־OpenCode אולי [סיכם](history.md#compact-session), ואילו פרטים מוקדמים יותר נשארים בהיסטוריה השמורה שלה לחיפוש. כך מדריך ניפוי התקלות מחזיר את שתי הסקירות למממש. עם **שיחות עצמאיות**, המתאם יכול גם להקצות מטלה לשיחה ראשית קיימת, ששומרת על ההקשר שלה, כולל עבודה קודמת שאינה קשורה. אחרת, מטלה מתחילה בשיחה חדשה מההקצאה שלה, והתמליל של מטלה אחרת מגיע אליה דרך המתאם או דרך חיפוש. ב־**השוואת שני מודלים**, ההקצאה וההקשר של השופט משמיטים את המטרה ואת ההערות; התיאור שלו מכיל את התוצרים האנונימיים.

כל הרצה מתוזמנת מתחילה עם מתאם ומפת משימה משלה, באמצעות ההוראות השמורות והקלטים המוקפאים שלה. שיחות במעקב מספקות טקסט חדש ומוגבל של המשתמש והעוזר; סמני הצריכה שלהן מתקדמים לאחר הרצה מוצלחת. הרצות קודמות נשארות בהיסטוריית התזמון. שיחות שהופעלו בתוך הרצה יכולות לקרוא את המפה שלה. למשימה חד־פעמית חדשה יש מפה נפרדת: שימו תוצאות שברצונכם להעביר הלאה במטרה שלה או ב־**הערות**, או בקשו מהמתאם להכין משימת המשך עם ההקשר הזה.

### חיפוש בשיחות קודמות {#context-search}

כל עוד CodeNomad פועל, לכל שיחת סוכן בפרויקט, כולל מתאמי משימות ומטלות, יש את כלי חיפוש הסשנים של CodeNomad (`codenomad.session_search`, שמשמש דרך Code Mode של OpenCode). הוא מחפש בשיחות השמורות של תיקיית הפרויקט של השיחה באותו דירוג כמו [החיפוש](history.md#full-history-search) ב־**כל סביבת העבודה**, ומחזיר קטעים קצרים עם הכותרת והמזהה של כל שיחה, וגם דרך לקרוא שיחה שלמה. חלות הרשאות הכלים המקוריות. סוכן מחפש כשהוא מחליט לעשות זאת או כשהמטרה, ההערות או ההודעה שלכם מבקשות זאת, למשל כדי לברר למה הגיעה משימה או מטלה קודמת. הרצה מתוזמנת שמתבצעת כש־CodeNomad סגור עובדת בלי הכלי הזה.

## פרופילים, האצלה ועומק {#profiles}

שמירת עומק משמרת תזמונים מקוריים פעילים בתצורת הפרויקט. הגדרת `schedules:false` מפורשת בפרויקט נשארת כבויה; הסרת העומק משמרת את הגדרת התזמון. יש לפתור התנגשות בין קובצי JSON ו־JSONC לפני שמירת הגדרות מקוריות.

1. השתמשו בגלגל השיניים של משימות או ב־**הגדרות → משימות** לעריכת **ברירות מחדל למשימות חדשות**.
2. תחת **החלה על**, בחרו **כל המשימות** או מדריך אחד, ואז הגדירו את **שיחות משימות**, ותחת **סוכנים ומודלים** שורה אחת לכל תפקיד (המתאם, ואז תפקידי המדריך). כל בחירה נשמרת מיד; אין כפתור שמירה.
3. בהיקף של מדריך, השורות מציגות את הערכים הגלובליים המסומנים **גלובלי**. שינוי שדה מתאים אישית את אותו תפקיד החל מהם; סמל השחזור שלו חוזר להשתמש בערכים הגלובליים. **איפוס** (לאחר אישור) מנקה רק את הסוכנים והמודלים של ההיקף המוצג.
4. ביצירה, השתמשו ב־**אפשרויות → סוכנים ומודלים** לפרופילים מבוקשים מסוימים; **שימוש בברירות המחדל השמורות** משחזר את השמורים.
5. למגבלות רקורסיה מקורית, ערכו את **עומק הקינון של תתי־סשנים → עומק שנקבע לפרויקט**, כאן או תחת **אפשרויות** ביצירה. לחיצה על Enter או יציאה מהשדה שומרות ערך תקין ששונה; **ירושה** שומרת מיד; Escape משליך ערך שלא נשמר.

| הגדרה | היקף והשפעה |
| --- | --- |
| ברירות מחדל למשימות חדשות | ברירות מחדל לכל התצורה למשימות **חדשות** בלבד; חריג מדריך גובר על ברירת המחדל הכללית. |
| סוכן / מודל / חשיבה | בחירות מתאם/תפקיד מבוקשות המתועדות ביצירה; גורם עסוק אינו מוחלף בשקט כדי להתאים לעבודה מאוחרת יותר. הרצות מתוזמנות משתמשות בפרופילים המבוקשים השמורים שלהן; עריכות חלות על הרצות עתידיות. |
| תת־סוכנים מקוריים | סשני מטלות משתמשים בסוכני subagent/all מקוריים תחת המתאם. |
| סשנים עצמאיים | סשני מטלות מוצהרים משתמשים בסוכני primary/all ובשיחות עצמאיות; הדבר אינו משבית עוזרים מקוריים פנימיים. |
| עומק הקינון של תתי־סשנים | תצורת פרויקט ל־**כל** שיחות OpenCode שם, לא רק למשימות. ריק יורש: **ירושה** מסירה את העקיפה של הפרויקט ואת בלוק `experimental` שהיא משאירה ריק או רק עם הערך הגלובלי של **שמירת תמונות פעם אחת**. OpenCode קורא את בלוק `experimental` של הפרויקט כמכלול, ולכן הגדרות ניסיוניות אחרות שנשארות בו עדיין מסתירות את העומק הגלובלי. כברירת מחדל, תת-הסוכן המובנה **General** של OpenCode אינו יכול להפעיל תתי-סוכנים, ולכן השיחות שלו אף פעם אינן מקוננות: שמירת עומק פרויקט כלשהו מוסיפה לאותו קובץ גם כלל שמאפשר לתתי-סוכנים להפעיל תתי-סוכנים משלהם עד לעומק הזה וגובר על ההגבלות של General מקובצי הגדרות אחרים (בעומק 1, מגבלת העומק של OpenCode עדיין מונעת קינון), ו**ירושה** מסירה אותו. מתחת ל**עומק OpenCode אפקטיבי**, העורך מציין אם תתי-הסוכנים General יכולים לקנן. אם הפרויקט מגדיר את General בתבנית הישנה עם ערך `permission` יחיד, או עם `task` ו-`subagent` שכבר מוגדרים, נשמר רק העומק והעורך מציין זאת: אפשרו בעצמכם תתי-סוכנים עבור General בקובץ זה. שמירה אינה טוענת מחדש את OpenCode או משנה שיחות פועלות. |

**ברירת מחדל מקורית** ו־**גלובלי** שונות: הראשונה מבקשת את ברירות המחדל של OpenCode עצמו, השנייה יורשת את הבחירה הגלובלית; בחירת ברירות מחדל מקוריות בהיקף של מדריך נשארת חריג מפורש. זמינות הקטלוג נבדקת; פרופיל מבוקש אינו הוכחה לפרופיל ששיחה משתמשת בו כרגע. אישורים מקוריים והעומק המוגדר עדיין שולטים בקריאות לעוזרים פנימיים בשני מצבי המטלות.

כל רשימת **מודל** מציגה את מה שמציג בורר **מודל** של השיחה, באותם שמות ומקובצת לפי ספק: מודלים מוסתרים אינם מופיעים, ובזמן שסינון למועדפים בלבד פעיל גם שאר המודלים אינם מופיעים (ראו [נראות מודלים, מועדפים וחשיבה](providers.md#models)). גם מודלים ללא תמיכה בכלים אינם מופיעים. מודל שמור שאינו ברשימה נשאר נבחר. **לא זמין** מסמן מודל שמור שהבורר אינו יכול להציע כעת: הוא חסר בקטלוג הנוכחי של הפרויקט, הוצא משימוש או אינו תומך בכלים.

בחירה שנדחתה או שלא אושרה לעולם אינה נשלחת שוב: הערכים השמורים מוצגים שוב, ו־**טעינה מחדש** מופיעה רק כשאי אפשר לקרוא אותם. אם שינוי עומק אינו מאושר, הערך שלכם נשמר; השתמשו ב־**רענון עומק הפרויקט** לפני שינוי נוסף. אל תפרשו **עומק OpenCode האפקטיבי אינו ידוע** כאפס או כמושבת.

## שימוש חוזר בתקציר שמור {#saved-briefs}

1. ביצירה, הרחיבו **אפשרויות → להתחיל מתקציר** ובחרו את התקציר השמור.
2. בדקו את המטרה, ההערות, המדריך, הפרופילים וההאצלה שהועתקו לפני **יצירה**.
3. השתמשו ב־**שמירה כתקציר** למתן שם לטיוטה לשימוש חוזר. משימה חד־פעמית שנבחרה, לרבות משימה שהסתיימה, מציעה גם **שמירה כתקציר**.

תקצירים שומרים הוראות ובחירות מבוקשות, לא תוכניות מטלות, תוצאות, שיחות, שעוני לוח זמנים או סמכות הרצה. טעינת תקציר ממלאת טיוטת יצירה רגילה; היא אינה מתחילה או מתזמנת דבר. הסרת תקציר משאירה משימות/שיחות קיימות. **הגדרות → משימות → תיאורים שמורים** מנהל את הספרייה; אם הספרייה הופכת לבלתי קריאה, **איפוס הספרייה השמורה** (לאחר אישור) מסיר תקצירים שמורים, לא הרצות. ללוחות הזמנים עצמם אין פעולת שמירה כתקציר.

## תזמון, השלמת פערים ושיחות במעקב {#daily-schedules}

### תזמון מקורי {#native-scheduling}

הרחיבו **תזמון** ביצירה או בעריכה. **תדירות** מציעה:

| בחירה | מועד |
| --- | --- |
| פעם אחת, מיד | הפעלה אחת בעת ההפעלה, עם תנאי לפי בחירה שנבדק כמתואר להלן. |
| פעם אחת, בתאריך מסוים | תאריך ושעה שמורים באזור IANA; תאריך שכבר חלף בעת ההפעלה נדחה. |
| פעם אחת, לאחר השהיה | משך שלם וחיובי בדקות או בשעות, שמתחיל בהפעלה. |
| במרווח קבוע | לפחות 15 דקות; ההתעוררות הראשונה היא מרווח אחד לאחר ההפעלה. |
| מדי יום | שעה אזרחית אחת באזור השמור. |
| בימי שבוע נבחרים | שעה אחת בימי השבוע המסומנים. |
| כמה פעמים ביום | עד שמונה שעות עצמאיות, כגון 09:15 ו־17:45; שעות כפולות חולקות הרצה אחת. |
| ביום מסוים בכל חודש | יום 1–31 בשעה שנבחרה; חודשים ללא אותו יום מדולגים. |
| מתקדם (cron) | ביטוי cron מקורי, לכל היותר פעם בדקה. |

**המועדים הבאים (עד חמישה)** מציגים תצוגה מקדימה לפי האזור השמור ושעת ההפעלה המשוערת. עם תנאי, **הבדיקות הבאות (עד חמש)** מציגות בדיקות; הרצה תלויה בשינוי מאומת. מרווח שמור שלא השתנה שומר על המופע המקורי שלו. מופע מושהה או לא ידוע מוצג כלא זמין עד שניתן לקרוא את מצבו המקורי. השהיות ומרווחים משתמשים בזמן שחלף; לוחות שנה אזרחיים פועלים לפי האזור השמור וכללי שעון הקיץ של OpenCode. התאריכים המוצגים הם תחזיות הכפופות לזמינות השירות והמארח.

לאחר השבתה, התזמון המקורי מבצע לכל היותר הרצת השלמה אחת לפני חזרה למועדים עתידיים. הוא משתמש במועד המקורי המתועד שהגיע זמנו, שעשוי להיות מוקדם ממועדים מאוחרים יותר שהוחמצו. כמה שעות יומיות חולקות את השלמת הפערים ואת אותה הגנה מחפיפה. הרצה שלא הוסדרה מתואמת לפי זהויות השיחה וההודעה המקוריות שלה לפני שהרצה נוספת יכולה להתחיל. חידוש חזרה שהושהתה במפורש משתמש במועד העתידי הבא שלה; הרצה חד־פעמית מושהית יכולה להגיע פעם אחת, באיחור.

### תנאים ומקורות {#scheduling-conditions}

בחרו **תנאי** אחד לפי הצורך ואת ה־**מקור בפרויקט זה** שלו: **הצלחה של תזמון אחר**, **קומיטים חדשים בענף מקומי**, **משימה חד־פעמית מסתיימת בהצלחה**, **הודעה חדשה בשיחה במעקב** או **שינוי בקבצים מפורשים**. לתנאי לבדו, השאירו **פעם אחת, מיד**: בדיקות מקוריות מתבצעות כל 15 דקות עד שההרצה היחידה מתחילה. עם לוח זמנים, התנאי נבדק במועדיו. תנאים חוזרים יכולים להפעיל שוב לאחר שינויים חדשים שעומדים בדרישות.

ההפעלה הראשונה קובעת את נקודת הייחוס ההתחלתית. המשך משמר אותה, כולל שינויים שנצפו לאחר השהיה. מקורות הצלחה דורשים תוצאה מוצלחת מאומתת ומשפחה מקורית שהוסדרה. בדיקות ענפים משתמשות בקומיטים מקומיים ובקשרי האבות שלהם ללא משיכה מרחוק. בדיקות שיחה ממתינות להודעות חדשות שלמות ויציבות ומחריגות התעוררויות טכניות ואת השיחות של ההרצה עצמה. קבצים משתמשים בעד 128 נתיבים מפורשים יחסיים לפרויקט, אחד בכל שורה; תבניות רקורסיביות ונתיבים מקושרים נדחים. מקור חסר, מועבר, עמום או חורג מהקיבולת חוסם קבלה להרצה עם הסבר. כדי לזהות שינויים בין בדיקות, נדרשת עקבה מתמשכת במקור.

שינויים שנצפו יחד מקובצים. הרצה מקפיאה את ראיות המקור שנצפו; סיום מוצלח צורך את תמונת המצב הזו ומשאיר שינויים מאוחרים יותר לבדיקה עתידית. הרצה שנכשלה שומרת את נקודת הביקורת של המקור שלה ודורשת התערבות. **שיחות במעקב (לא חובה)** תחת **אפשרויות** מספקות הקשר בנפרד מבחירת תנאי של הודעה בשיחה.

### סיום וספירות {#scheduling-limits}

השאירו מגבלות ריקות לחזרה מתמשכת. **המועד האחרון המותר** ו־**המועד האחרון לאחר מספר שעות זה מההפעלה הראשונה (רשות)** מגבילים מועדים זכאים; הגבול המוקדם קובע. המשך מתחיל בהפעלה הראשונה וממשיך להימדד בזמן השהיה. מועד שתועד לפני הסיום עשוי להגיע באיחור לאחר השבתה ארוכה. הרצה שכבר התקבלה נשארת זמינה למעקב עד לתוצאתה.

**מספר מרבי של ריצות שהתחילו** הוא סך משותף לכל השעות ול־**הרצה עכשיו**. הרצה נספרת פעם אחת כשהקלט הראשון של המתאם שלה מתקבל, גם אם היא נכשלת בהמשך. בדיקות, תנאים שלא השתנו והתעוררויות שנדחו אינם צורכים מקום; קבלה לא ודאית מחזיקה את מקומה עד להתאמה. מדיניות חד־פעמית מאפשרת לכל היותר הרצה אחת. מקומות שנצרכו נשמרים בעריכות ובהפעלות מחדש; מגבלות סיום שלא השתנו שומרות על נקודת המוצא בהפעלה הראשונה ועל מועד הסיום המוחלט. שינוי המספר המרבי משנה את הסך לכל משך החיים; סך השווה למספר שנצרך או נמוך ממנו מסיים את התזמון. שינוי תדירות עשוי להתחיל מופע מרווח חדש בשמירה, כפי שהעורך מסביר.

התזמון המקורי הנבחר מציג **מצב רצוי**, **לוח זמנים מקורי**, **ההתעוררות הבאה** או **הבדיקה הבאה**, **בדיקות** עם **במעקב מאז**, **הרצות שהופעלו**, **הרצות שהצליחו**, את סיומו ואת **הרצות קודמות**. קראו הרצה קודמת דרך **פתיחת השיחה**. **התזמון הסתיים** מתאר את סיום התזמון; בדקו בנפרד את תוצאת ההרצה. התוצאות שומרות את 30 הרשומות האחרונות; הספירות הכוללות נשמרות מעבר לחלון הזה. **טעינת משימות נוספות** טוענת את העמוד הבא של האובייקטים השמורים.

### לוחות זמנים יומיים קיימים {#existing-daily-schedules}

לוחות זמנים יומיים קיימים משתמשים באזור IANA ובשעה האזרחית השמורים. לכל הרצה מתאם ומפת משימה משלה; בחרו את עץ המטלות הנוכחי שלה או תאריך/תוצאה קודמים כדי לקרוא את התוצאה במרכז. ההיסטוריה השמורה שלהם מכילה 30 תוצאות. כללי היומיום הבאים חלים על רשומות אלה:

| מצב | התנהגות התזמון |
| --- | --- |
| מספר ימים שמועדם חל הוחמצו | מריץ רק את היום האחרון שמועדו חל ומאוחר מסמן היום שהושלם, לא צבר לכל יום שהוחמץ. |
| פער במעבר לשעון קיץ | מתקדם לדקה התקינה הראשונה שאחריו; פער בסוף היום מתקדם מעבר לגבול היום. |
| שעה שחוזרת בשעון | משתמש בהופעה הראשונה; אינו יוצר הרצה יומית שנייה. |
| יום אזרחי שדולג בשלמותו | אין הרצה לאותו יום. |
| השעון זז לאחור | אינו הופך יום שכבר עובד ליום שהגיע מועדו שוב. |
| הרצה קיימת עדיין ממתינה | אינו חופף אותה עם הרצה יומית חדשה. |

גם זמן היצירה מגביל עבודה יומית זכאית. **הרצה עכשיו**, כשהיא מוצעת ברשומה יומית קיימת, מתחילה הרצה ידנית נפרדת בכפוף להגנה מפני הרצה ממתינה ומשמרת את השעון היומי שלה. השעה הבאה המוצגת היא תחזית הכפופה לזמינות השירות והמארח.

**שיחות במעקב (לא חובה)** מוסיף הקשר מוגבל משיחות שנבחרו. רק הרצה שהושלמה מקדמת את סמני ההודעות שעובדו שלהן; הרצה שנכשלה/נקטעה אינה צורכת בשקט את ההקשר הזה. אם ההוראות וההקשר יחד חורגים מהקיבולת, קצרו הוראות או הסירו שיחות במעקב במקום להניח שנקראת היסטוריה ללא גבול.

## משך חיים והפעלות שירות מחדש {#lifetime}

בתזמון מקורי, הרחיבו את **פרטים טכניים** כדי לזהות את ה־**נשא ראשי** וה־**נשא התאמה** שלו, את לוחות הזמנים המקוריים שלהם וכל מצב **ניקוי ממתין להתאמה**. שיחות טכניות אלה אינן מציעות פעולת כתיבת הודעה ואינן מופיעות בבוררי השיחות והמקורות הרגילים. התעוררויות טכניות, כותרות ודחיסת הקשר משתמשות במודל המקומי ללא בקשות HTTP לספקים; אירועים וסטטיסטיקות מקוריים עדיין עשויים לכלול אותם, בעוד שההרצות בפועל שומרות על עלויות המודל הרגילות שלהן. דחיסת ההקשר מגבילה את ההקשר המעובד תוך שמירה על זהות השיחה ולוח הזמנים. הודעות ואירועים מקוריים מאוחסנים עשויים להצטבר עד לניקוי מפורש של תזמון שהסתיים; 30 תוצאות המשימה הנשמרות הן נפרדות. בקרת העומק ו־**תזמון** מציגות את מסמך **הבלוק הניסיוני שבתוקף**; בקרת העומק מסמנת בנפרד את **יעד הכתיבה של הפרויקט**.

| רכיב | משמעות סגירתו |
| --- | --- |
| לשונית פרויקט CodeNomad | סוגרת את הפרויקט ב־CodeNomad; סשנים מקוריים ממשיכים ב־OpenCode. פתחו את הפרויקט מחדש כדי למצוא אותם שוב. |
| חלון שלם, יציאה מהיישום או טעינה מחדש של תהליך התצוגה | משמרים את חיבורי הפרויקטים לשחזור; אינם עוצרים עבודה מקורית או את שירות OpenCode. |
| שרת הקצה של CodeNomad | אינו עוצר את OpenCode. משימה חד־פעמית פעילה ממשיכה: המתאם שלה, המטלות שלה כתת־סוכנים מקוריים וכלי המשימה פועלים ב־OpenCode. הקצאת מטלות לסשנים עצמאיים ומסירת הדוחות שלהם למתאם, משימות שהמתאם מכין, עצירת השיחות של מטלה שהוצאה מהתוכנית, התאוששות ובקרת המשימה ממתינות לשרת הקצה, וכך גם המשך של משימה חד־פעמית אחרי הפעלה מחדש של שירות OpenCode. |
| תזמון מקורי מופעל | לוחות זמנים מתמשכים של OpenCode מעירים את הפרויקט ומבצעים הרצות כשהממשק ושרת הקצה של CodeNomad סגורים, כל עוד מארח ההרצה והשירות זמינים. |
| הפעלה מחדש של שירות OpenCode — תזמון מקורי תקין | תזמון תקין שמצבו הרצוי הוא ״פועל״ מחדש את לוח הזמנים שלו אוטומטית. עבודה ממתינה מתואמת לפי זהויותיה המקוריות לפני קבלה חדשה. |
| לוח זמנים יומי קיים | שעון התוסף שלו פועל כש־CodeNomad סגור כל עוד השירות חי. הפעלה מחדש של השירות משאירה אותו במצב **נקטע**; **המשך** מפורש מתאם את ההרצה הממתינה שלו ומפעיל שוב את שעונו היומי. |

בתזמונים מקוריים, השהיה ועצירה מפורשות, עבודה שנכשלה ותוצאות לא ודאיות משמרות את מחסומי הקבלה שלהן לאחר הפעלה מחדש. בדקו את ההרצה שנשמרה ואת הבקשה המקורית; השתמשו ב־**בדיקת ההרצה** או ב־**רענון הבקשה השמורה** כשמוצעות, ואז ב־**המשך** רק כשהמצב מאפשר זאת. המשך מקורי נצפה תחת זהותו הקיימת. כישלון מוכח או סיום ללא דוח דורשים התאוששות אנושית; ראיות לא שלמות משאירות את ההרצה לא ודאית. לעולם אל תשתמשו בהפעלה מחדש כדי לנסות שוב השפעות כלים שכבר החלו.

[השארת OpenCode פועל](opencode.md#service-supervision) משגיחה בנפרד על השירות המשותף במארח ההרצה שלו. ההפעלה הראשונה של משימה מפעילה אותה אלא אם שמרתם כיבוי; יצירת משימה מושהית משמרת את הבחירה הזו. כיבויה משאיר את OpenCode פועל ללא הפעלה מחדש אוטומטית. Windows, macOS ו־WSL משתמשים בגבול הכניסה; Linux מקורי משתמש בהשארת שירותי המשתמש פועלים, בכפוף להרשאות. שינה, תרדמה, משך החיים של WSL במצב סרק ושליטה במארח חיצוני מגבילים זמינות; בדקו את מצב ההשגחה בנפרד מהתזמון.

משימות פועלות עם יישומי שולחן העבודה ועם [שרת](server.md) CodeNomad עצמאי. כשהלוח מציג **בקרת המשימה אינה זמינה**, ההודעה שלו מציינת את הסיבה:

| סיבה | מה לעשות |
| --- | --- |
| סביבת העבודה של OpenCode אינה מוכנה | חברו מחדש את הפרויקט, ואז רעננו. |
| OpenCode לא טען את תוסף המשימות | רעננו בעוד רגע; אם המצב נמשך, השתמשו ב־**טעינה מחדש של תצורת OpenCode** ב־**הגדרות → OpenCode**. |
| OpenCode לא הצליח לטעון את תוסף המשימות | קראו את השגיאה שלו ברשימת התוספים, ואז רעננו לאחר שתוקנה. |
| שרת CodeNomad לא הצליח לפתוח את חיבור המשימות המקומי שלו (127.0.0.1) | בדקו את יומן השרת; טעינה מחדש של OpenCode לא תעזור. |

## השהיה, עצירה ותוצאות לא ודאיות {#controls-recovery}

1. בחרו את הרשומה ובדקו את מצבה הנוכחי ואת השיחה לפני פעולה.
2. השתמשו בסמל ההשהיה לעצירה שניתן לחדש, או בסמל העצירה ובאישור לעצירה סופית. עצות הריחוף החד־פעמיות הן **השהיית משימה** ו־**עצירת משימה לצמיתות**; עצות לוחות זמנים מציינות את לוח הזמנים.
3. אם התוצאה אינה מאושרת, השתמשו ב־**בדיקת מצב** / **בדיקת מצב הבקרה** לקריאת התוצאה הקיימת. אל תוציאו פעולה חלופית כדי לעקוף אי־ודאות.
4. לפעולות חד־פעמיות, **רענון ושליחה מחדש של הפעולה שלא אושרה** בכותרת בודק תחילה מצב ושולח מחדש רק את אותה פעולה מדויקת שעדיין אינה מאושרת, בעקבות לחיצה מפורשת שלכם.

השהיה חד־פעמית מאפשרת לעבודה הנוכחית להסתיים: המתאם ותתי-הסוכנים שלו משלימים את השלב שבו הם נמצאים, אינם מתחילים דבר חדש ועוצרים, בזמן שהלוח מציג **בהשהיה: השלבים הפעילים מסתיימים.** **הפסקה עכשיו** עוצר אותם מיד במקום זאת: הוא קוטע את המשפחה המקורית של המשימה ומשהה תיאום. עצירה גם קוטעת, מבטלת קלטים/מסירות בתור של המשפחה והיא סופית. הקטיעות מוגבלות: **ייתכן שחלק מתתי-הסוכנים עדיין פועלים.** אומר שאחת מהן אינה שלמה. בדקו את התוצאה שנשמרה והשתמשו בניסיון החוזר המפורש שלה במקום להניח שכל השפעות המעטפת/הכלים בוטלו. חידוש מודיע למתאם מה הושהה או נקטע; הוא מחליט כיצד להמשיך את העבודה.

**השהיה** בתזמון מקורי סוגרת קבלה עתידית ומבקשת קטיעה של הרצה שהתקבלה; **המשך** מתאם עבודה קיימת לפני הפעלה מחדש של התזמון. **עצירה…** היא סופית. **הרצה עכשיו** משתמשת באותה הגנה מפני הרצה ממתינה ובאותה מכסת הרצות שהופעלו, תוך שמירת לוח הזמנים. **בדיקת ההרצה** מתאמת את ההרצה המקורית. שמרו פעולה שלא אושרה והשתמשו ב־**רענון הבקשה השמורה**; רענון פסיבי וחיבור מחדש משמרים אותה. השפעות כלים שכבר החלו עשויות להימשך לאחר קטיעה.

רשומות יומיות קיימות שומרות את בקרותיהן היומיות: השהיה, עצירה, המשך, הרצה עכשיו ובדיקת ההרצה. השהיה/עצירה מבטלות את שעונן ומבקשות קטיעה של שורשים רשומים, כולל מומחים עצמאיים. בדקו את משפחותיהם המקוריות וכל תוצאת קטיעה חלקית. כשלי בדיקה יומית זמניים נבדקים שוב עם האזהרה המוצגת; תשובת בקרת משתמש שאבדה נשארת צמודה לבקשתה המקורית. רשומה שנעצרה נשארת סופית.

למתאם חד־פעמי הנמצא בסרק ללא הדוח שלו, פעולת ▶ הראשית יכולה לאמת ולהתאושש; למטלות יש התאוששות ממוקדת לדוח חסר כשזכאיות. ההתאוששות בודקת תחילה פעילות מקורית, צאצאים והמתנות; פעילות לא ידועה מסרבת לקבלה להרצה. היא אינה שולחת מחדש הקצאות או מחליפה את התוכנית. פתחו שיחות כדי לפתור שאלות, אישורים, מעטפות או עבודת רקע שנותרו.

אם **יצירה** אינה מאושרת, החלון שומר את הבקשה שנשלחה ומשבית יצירה נוספת לאותו פרויקט; מחיקת worktree עשויה להישאר מעוכבת. רענון רק קורא מצב. סגירת העורך ופתיחתו מחדש אינן מתקנות זאת. לפני טעינת החלון מחדש, בדקו את רשימת המשימות: טעינה מחדש מנקה את הנעילה המקומית, **לא הוכחה שהיצירה נכשלה**. אל תיצרו בעיוורון כפילות לאחר טעינה מחדש או הפעלה מחדש.

## עריכה, מחיקה וניקוי שיחות {#cleanup}

אם המטרה או ההערות משתנות בזמן שהטופס עדיין נטען, הוא מציין שהמשימה השתנתה מאז שפתחתם אותה במקום למלא אותן; בחרו **פתיחה מחדש** כדי לערוך את הגרסה הנוכחית.

בין הרצות, אפשר לערוך בתזמון מקורי מושהה או פועל את הכותרת, ההוראות, ההערות, הפרופילים המבוקשים, מצב שיחות המטלות, המקורות, לוח הזמנים והמגבלות, כשאין הרצה או בקרה לא מוסדרת שמחזיקות את האובייקט. תזמון מושהה נשאר מושהה; תזמון מופעל מתאם את לוח הזמנים שלו לפני ההמשך. שמירה משמרת תוצאות קודמות, מקורות שנצרכו, מספר הרצות שהופעלו ואת נקודת המוצא בהפעלה הראשונה; מגבלות סיום שלא השתנו שומרות על מועד הסיום המוחלט שלהן.

במהלך הרצה שהתקבלה, רק הוראות והערות כפופות לחוזה עריכת הטקסט הפעיל: שינויים נרשמים בהיסטוריה שלה ונשמרים להרצות עתידיות. מטלות, תקצירים, פרופילים וזהויות ביצוע קיימים שומרים את הערכים שהתקבלו להפעלה. שדות מבניים נשארים נעולים עד להסדרת ההרצה, גם לאחר השהיה. מדריך נשאר נעול מרגע שנוצרה מטלה כלשהי, כולל מטלות שהושלמו או הוסרו. קבלה/בקרה לא ודאיות או ראיות לא שלמות לתקינות הנתונים משאירות עריכה מבנית לקריאה בלבד. יצירה ועריכה משתמשות באותו אימות לוח זמנים; התצוגה המקדימה מחילה את המועד האחרון המותר שנערך על ההתעוררות הבאה השמורה, גם כשהיא מאוחרת.

מקור הענפים המקומיים כולל ענפים ללא worktree וקורא רק הפניות מקומיות. הבורר תומך בעד 200 ענפים מקומיים; במלאי גדול יותר המקור מוצג כלא זמין. **התחלה** ו**המשך** מבקשים הסכמה עם נתיבי התצורה המדויקים כשההפעלה זמינה. **הרצה עכשיו** נשארת מושבתת עם הסבר כשהתזמון המקורי כבוי; יש להפעיל `experimental.schedules` בתצורת OpenCode ואז לרענן. תשובת הפעלה שאבדה שומרת על הבקשה המקורית לבדיקת האישור שלה.

לפני Play הראשון אפשר לחזור להפעלה מיידית ללא תנאי ולשמור את השיחות שבמעקב ב**אפשרויות**. Play קורא ומקפיא את רצף ההודעות השלם והיציב שלהן (עד 32 הודעות לכל מקור, במסגרת קלט הפעלה של 16,384 תווים). מקור חסר, שהועבר או שחורג מהקיבולת חוסם את ההפעלה עם הסבר. ניסיון חוזר שומר את ההקשר המוקפא ואת זהות ההפעלה המקורית.

כאשר קריאת האישור מאשרת הכנה חלקית, מופיע **ניסיון נוסף**. הלחיצה בודקת שוב את אותו אישור וממשיכה רק את השינוי המקורי שנשמר, כשהמשימה נשארת מושהית.

לפני ההפעלה הראשונה של משימה חדשה שהוכנה, אפשר לערוך כותרת, הוראות, הערות, ספר מהלכים, סוכנים/מודלים/חשיבה מבוקשים, מצב שיחות המשימות ו**תזמון**. אפשר לעבור בין הפעלה מיידית, דחויה, חוזרת ומותנית תוך שמירה על אותה משימה. שמירה משאירה אותה מושהית ומכינה מתאם חדש וריק; השיחה המקורית נשמרת. רק Play מתחיל עבודה או מפעיל תזמון. לאחר ההפעלה, ההוראות וההערות כפופות לכללי העריכה של המשימה הפעילה. אם השמירה לא אושרה, **רענון הבקשה השמורה** קורא את התוצאה המקורית; שמרו על אותה בקשה כל עוד הכנה חלקית חוסמת הפעלה, עריכת טקסט ומחיקה.

השתמשו ב־**עריכת המשימה שנבחרה** במשימה חד־פעמית או בתזמון מקורי הניתנים לעריכה. קראו את ההסברים לצד השדות הנעולים. בהתנגשות גרסאות, בחרו **טעינת ההגדרות הנוכחיות מחדש**, ואז פתחו **טיוטה קודמת להשוואה** כדי לבדוק את הטיוטה שנשמרה לפני שמירה נוספת. לוחות זמנים יומיים קיימים שומרים את הבקרות שבסרגל הכלים שלהם.

בתזמון מקורי, **מחיקת המשימה שנבחרה…** משביתה הרצות עתידיות לפני הסרת הרשומה. השיחות והתוצאות נשמרות; ניקוי שממתין להתאמה נשאר גלוי ב־**פרטים טכניים**. שמרו מחיקה שלא אושרה ורעננו את בקשתה המקורית.

1. למשימה חד־פעמית שכבר אינה נחוצה, בחרו **מחיקת המשימה שנבחרה…** ובדקו את האישור.
2. אפשר לסמן **למחוק גם שיחות מומחים שנוצרו עבור משימה זו** לפני האישור.
3. בדקו **ניקוי שיחות** למספרים שהוסרו/נשמרו/ממתינים. נסו שוב רק את הניקוי הרשום שנותר, אם מוצע.

מחיקת משימה אינה זהה לעצירתה; השתמשו בעצירה ובדקו עבודה שנותרה תחילה. מתאמים ושיחות בשימוש חוזר נשמרים. גם מומחים משותפים, מועברים, בעלי ילדים או שלא ניתן לאמת בעלות עליהם עשויים להישמר. ניקוי חלקי אינו מוחזר לאחור ואינו מושלם בשקט ברקע. כרטיס המשימה עשוי להיעלם בזמן שאימות המחיקה עדיין ממתין, גם כשניקוי השיחות מציג 0 בהמתנה. המשיכו להשתמש בפעולת **ניסיון נוסף** המקורית עד שהמחיקה תאומת; היא שומרת על אותה בקשת מחיקה ועל אותן אפשרויות. קורא הסקירה שומר את 20 הניקויים האחרונים שהושלמו. מחיקת משימות מפנה את האחסון שלהן בפרויקט: משימות מחוקות ישנות יותר מנוקות אוטומטית.

ראו [אישורים](permissions.md), [שיחות](conversations.md) ו־[הגדרת OpenCode](opencode.md) לעבודה מקורית ולפקדי שירות.
