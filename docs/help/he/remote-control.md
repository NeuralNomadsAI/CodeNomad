# שליטה מרחוק

שליטה מרחוק מאפשרת לדפדפן או ללקוח שולחן עבודה מצומד להשתמש בשרת הקצה הפועל של CodeNomad בלי לפתוח יציאת רשת נכנסת. אין צורך בסיסמת שרת, ב־`--host` שאינו loopback או ב־VPN. זהו נתיב גישה נפרד מ־[חיבורים ישירים](remote-access.md).

## הפעלה וצימוד {#start-and-pair}

1. במארח, פתחו **הגדרות → גישה מרוחקת**.
2. בחרו **הפעל שליטה מרחוק**. המתינו ל־**מוכן לחיבורים מרחוק**; בשימוש ראשון הקצאת זהות המנהרה והתעודה עשויה לקחת זמן.
3. תחת **חיבור מכשיר נוסף**, סרקו את קוד ה־QR או בחרו **העתק קישור**, ואז פתחו את הקישור החד־פעמי במכשיר המיועד.
4. שמרו את נתוני האתר בדפדפן המצומד. פתחו שוב את כתובת המנהרה כדי להתחבר מחדש בזמן ששרת הקצה פועל.

הקישור תקף ל־**חמש דקות** ומצליח **פעם אחת**. התייחסו אליו כאישור גישה: כל מי שמנצל אותו יכול להפוך למכשיר מצומד. הקוד נמצא במקטע הכתובת, לא במחרוזת השאילתה. **צור קישור צימוד חדש** מבטל מיד את הקישור הקודם שלא נוצל. כיבוי שרת הקצה מבטל קישור צימוד שטרם נוצל; עצירה וכשל במנהרה מבטלים קישור מנהרה.

במחשב אחר שמריץ CodeNomad, הדביקו את קישור הצימוד בשדה **הגדרות → שרתים → כתובת או קישור של השרת**.

לצימוד חוזר, הדביקו קישור חדש בטופס ההתחברות של השרת או הפרויקט.

## צימוד דרך HTTPS ישיר {#direct-https}

כשהמנהרה חסומה אך שרת הקצה נגיש דרך HTTPS מהימן, למשל דרך מתווך הפוך עם אישור אמיתי, אפשר לצמד מכשירים בכתובת זו במקום. הכתובות המותרות הן כתובות ה-HTTPS של שרת קצה זה ומקורות ה-HTTPS ב־`CODENOMAD_ALLOWED_ORIGINS` (ראו [מקורות מורשים](remote-access.md#upgrading)); שמות loopback ו-HTTP רגיל לעולם אינם מצמדים. אין צורך להפעיל שליטה מרחוק.

1. במארח, פתחו את **הגדרות → גישה מרוחקת → שליטה מרחוק**.
2. תחת **צימוד HTTPS ישיר**, בחרו את **כתובת HTTPS** אם מוצגות כמה, ואז בחרו **צור קישור צימוד HTTPS**.
3. פתחו את הקישור במכשיר, כמו קישור מנהרה. אפשר ללחוץ עליו מדף אחר.

על הקישור חלים אותם כללים של חמש דקות ושימוש יחיד, והוא מחליף כל קישור שלא נוצל; קודים שגויים חוזרים מוגבלים. מתווך הפוך חייב לסיים TLS מהימן, להעביר את כותרות `Host` ו־`Origin` המקוריות ולהגיע לשרת הקצה דרך loopback או רשת מוגנת.

מכשיר כזה מתחבר רק דרך כתובת ה-HTTPS שלו, לעולם לא דרך המנהרה, ו־**מכשירים מצומדים** מציג את הכתובת מתחת לשמו. עצירת שליטה מרחוק אינה מבטלת את הקישור ואינה מנתקת מכשירים אלה; **בטל גישה**, 30 יום ללא שימוש, מגבלת 32 המכשירים או הסרת הכתובת מהתצורה מסיימים את הגישה שלהם. דפדפן שמציג אישור מכשיר שבוטל או פג בכתובת זו אינו יכול לחזור לסיסמת השרת: צמדו מחדש, או נקו את נתוני האתר כדי להתחבר עם הסיסמה.

ראו את [הפעולות הזמינות](#remote-surface), כולל החריג של HTTPS ישיר לתוכן SideCar. הצימוד אינו מעניק הרשאות loopback, גם דרך מתווך במארח.

## ניהול מכשירים מצומדים {#paired-devices}

1. במארח, חזרו אל **הגדרות → גישה מרוחקת → שליטה מרחוק**.
2. בדקו **מכשירים מצומדים** ואת זמן **נראה לאחרונה** שלהם. כל מכשיר נקרא על שם הפלטפורמה והדפדפן שצימדו אותו, כגון `iPhone · Safari`.
3. בחרו **בטל גישה** למכשיר שכבר לא אמור להתחבר. אם מופיע **ביטול הגישה ממתין**, בחרו שוב **בטל גישה** לפני הפעלה מחדש של המארח.

ביטול גישה מסיים את חיבורי HTTP/SSE הנוכחיים של המכשיר וגם גישה עתידית. בצעו צימוד מחדש בקישור חדש לשחזור הגישה. מכשיר פג לאחר **30 ימים ללא שימוש**. ב־**מגבלת 32 מכשירים**, צימוד חדש מחליף את המכשיר שנראה לפני הזמן הרב ביותר וסוגר את חיבוריו.

ניקוי נתוני אתר, החלפת פרופיל דפדפן או גלישה פרטית עשויים לחייב צימוד מחדש.

שינוי סיסמת גישה ישירה **אינו** מבטל מכשירים. **עצור שליטה מרחוק** מנתק את המנהרה אך שומר את רשימת המכשירים המצומדים; השתמשו ב־**בטל גישה** כשברצונכם להסיר הרשאה.

### צימוד מחדש בלי לאבד את המקום {#re-pair}

1. אם הלקוח מציג **יש לצמד מחדש את המכשיר הזה**, השאירו את הדף פתוח.
2. במארח, צרו קישור לסוג החיבור המקורי: **צור קישור צימוד חדש** למנהרה, או בחרו את **כתובת HTTPS** המקורית תחת **צימוד HTTPS ישיר** ואז **צור קישור צימוד HTTPS**. פתחו אותו באותו דפדפן או פרופיל לקוח. חלון מרוחק נפרד משתמש שוב באחסון הקיים שלו.
3. חזרו לדף הממתין ובחרו **בדיקת חיבור**; הבדיקה מתבצעת שוב גם כשהדף חוזר למיקוד.

ההתאוששות משמרת את הדף הפתוח והטיוטות; היא אינה חוזרת על פעולה שנכשלה. בדקו אם שליחה, תשובה או מחיקה נכנסו לתוקף לפני ניסיון חוזר. סיסמת גישה ישירה אינה יכולה לשחזר צימוד לשליטה מרחוק.

## זמינות ומשך חיים {#lifetime}

| פעולה/מצב | השפעה |
| --- | --- |
| הפעלת שליטה מרחוק | מחברת את שרת הקצה הזה וזוכרת את הבחירה להפעלות עתידיות. |
| סגירת הדפדפן המרוחק | אינה עוצרת את שרת הקצה במארח או מבטלת את המכשיר. |
| עצירת שליטה מרחוק | מנתקת גישה דרך המנהרה ומנקה חידוש אוטומטי בהפעלה; שומרת רשומות מכשירים. |
| כיבוי שרת הקצה / חלון שולחן העבודה האחרון נסגר והיישום יוצא | שליטה מרחוק הופכת ללא מקוונת. השירות המשותף של OpenCode יכול להמשיך לפעול, אך אינו יכול להגיש ממשק זה דרך שרת קצה עצור. |
| הפעלה לאחר השארת שליטה מרחוק מופעלת | מתחברת מחדש ברקע בלי להנפיק קישור צימוד חדש. התקנות שמעולם לא הופעלו אינן מפעילות את עצמן. |

חידוש אוטומטי בהפעלה מוגבל לשרת קצה אחד לכל תיקיית תצורה. אל תפעילו מארחים מתחרים עם אותה תצורה כדי להשיג קיבולת מנהרה נוספת. למארח שצריך להישאר נגיש לאחר יציאה משולחן העבודה, פרסו [שרת עצמאי](server.md) המנוהל בנפרד; שליטה מרחוק אינה דמון עצמאי.

## ממשקים זמינים ולא זמינים {#remote-surface}

מכשירים מצומדים יכולים להשתמש ב־API רגילים של פרויקטים/שיחות, לשלוח קלט, לבדוק קבצים ולענות לאישורים/טפסים בכפוף לאותן בדיקות בעלות. צימוד הוא גישה חזקה, לא קישור שיתוף לקריאה בלבד. הוא לעולם אינו מעניק הרשאות loopback, גם שהמנהרה מעבירה תעבורה פנימית במארח.

| ממשק | דרך שליטה מרחוק |
| --- | --- |
| ממשק מאומת רגיל, סביבות עבודה, שיחות ו־SSE | זמין למכשיר מצומד. |
| התחברות/יציאה בסיסמה, שינויי סיסמה, אתחול אסימון מקומי | לא זמינים; נדרשים אישורי מכשיר גם אם אימות ישיר מושבת. |
| מצב שליטה מרחוק | ניתן לקריאה בידי מכשיר מצומד; הניהול אינו זמין. הפעלה/עצירה, יצירת צימוד, רשימת מכשירים וביטול גישה נשארים בנתיב הגישה של המארח. |
| שרתים שמורים ותיווך דרך השרת העורפי | לקוחות מרוחקים מאומתים יכולים להשתמש בכל שרתי המארח השמורים ולנהל אותם כשהתכונה ויכולות המארח מאפשרות זאת. סיסמאות שרת חדשות וקישורי צימוד דורשים שליטה מרחוק או HTTPS, ולא HTTP רגיל ברשת המקומית. ראו [שרתים שמורים](remote-access.md#saved-servers). |
| חלונות מרוחקים בשולחן העבודה והמתווך שלהם | למארח בלבד (`/api/remote-proxy/`). |
| תוכן SideCar וחיבורי WebSocket ‏(`/sidecars/`) | אינם זמינים דרך המנהרה. השתמשו ב־loopback או הפעילו במארח [גישה ישירה ב־HTTPS ל־SideCars](browser-sidecars.md#register-sidecar). |
| רישום SideCar ‏(`/api/sidecars`) | זמין למכשירים מצומדים וללקוחות ישירים מאומתים. |
| תוכן תצוגה מקדימה של אתר | [פתיחת דפדפן לסשן](browser-sidecars.md#session-browser) |
| גשר אוטומציה | לא זמין (`/api/opencode-plugin/`). יכולות שולחן עבודה מקוריות אינן הופכות ליכולות דפדפן. |
| שדרוגי WebSocket | זמינים לתצוגות מקדימות של אתרים, ובמכשירים מצומדים גם ל[שיחות קוליות בזמן אמת](voice.md#conversation). |

השתמשו בחיבור loopback במארח עבור מתווכים וחיבורי WebSocket השמורים למארח ועבור ניהול שליטה מרחוק (`/api/remote-control/`). גם בגישת LAN ישירה פעולות אלה דורשות loopback; ראו [מקורות מורשים](remote-access.md#upgrading).

## ממסר ופרטיות {#relay-privacy}

CodeNomad משתמש ב־[OpenTunnel](https://github.com/anomalyco/opentunnel) ותובע נתיב אקראי אחד בזהות המנהרה המשותפת כברירת מחדל במחשב.

TLS מסתיים בשרת הקצה של CodeNomad. הממסר מעביר טקסט מוצפן ואינו יכול לקרוא תוכן יישום, אך יכול לראות שמות מארחים, זמני חיבור ונפחי תעבורה. תעודת המנהרה/המפתח הפרטי נשארים במארח. הגנו על אחסון המנהרה של המארח ועל תצורת CodeNomad כאישורי גישה; כתובת שאי אפשר לנחש אינה הרשאה.

`CODENOMAD_REMOTE_CONTROL_API` בוחר API של OpenTunnel באירוח עצמי; כשהוא אינו מוגדר משתמשים בשירות המתארח. הדבר משנה את פריסת המנהרה, לא את דרישות הצימוד או הממשקים החסומים. ראו [אבטחה](security.md) לטיפול באישורים ובאבחון.

## מדיניות מנהל המערכת {#administrator-policy}

מנהל מערכת יכול לכבות את השליטה מרחוק לכל המשתמשים במחשב: הגדירו את משתנה הסביבה `CODENOMAD_REMOTE_CONTROL=disabled` ברמת המערכת והפעילו מחדש את CodeNomad. השרת לא יחבר מנהרה לעולם, ידחה את **הפעל שליטה מרחוק** ואת קישורי הצימוד ולא יתחבר מחדש בהפעלה; ההגדרות מציגות **הושבת על ידי מנהל המערכת**. מכשירים שצומדו קודם לא יכולים להתחבר ונשארים ברשימה כדי שתוכלו לבטל אותם. ללא הגדרה או ערך ריק אין מדיניות; כל ערך אחר, כולל רווחים בלבד, מונע את הפעלת השרת.
