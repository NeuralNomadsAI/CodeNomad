# גישה ישירה מרחוק

גישה ישירה מתחברת למאזיני HTTP/HTTPS של CodeNomad באמצעות סיסמת השרת שלו. היא נפרדת מ־[שליטה מרחוק](remote-control.md): צימוד אינו דורש האזנה ב־LAN או יציאה נכנסת, ואף נתיב אינו עובר בשקט לאחר כחלופה.

## בחירת נתיב גישה {#access-paths}

| נתיב | מה עליכם לנהל |
| --- | --- |
| דפדפן באותו מחשב | השאירו האזנת loopback; השתמשו בכתובת המקומית המודפסת. |
| LAN או VPN | האזינו בממשק נגיש, הגבילו את חומת האש ללקוחות המיועדים והשתמשו ב־HTTPS מהימן. VPN אינו מגדיר עבורכם את מאזין CodeNomad. |
| העברת SSH | השאירו את שרת הקצה בהאזנת loopback; העבירו את היציאה המודפסת בפועל. המנהרה מגינה על התעבורה אך אינה מחליפה אימות CodeNomad. |
| מתווך הפוך | השאירו את שרת הקצה בממשק פרטי/loopback; סיימו TLS מהימן במתווך, הגנו על המקטע לשרת שמאחוריו ותמכו ב־SSE ארוך־חיים ובכל WebSocket שנדרש לכלי הגישה הישירה שלכם. |
| שליטה מרחוק | צמדו את המכשיר מהמארח; ראו [שליטה מרחוק](remote-control.md) לממשק המצומצם יותר ולמשך החיים שלה. |

האזנה אינה יוצרת כללי חומת אש, העברת יציאות, DNS או VPN. אל תפרסמו מאזין HTTP לא מאומת לאינטרנט. שורש סביבת עבודה אינו ארגז חול אבטחתי; קראו [אבטחה](security.md) לפני חשיפת השרת.

## הפעלת גישה ישירה {#enable-direct-access}

1. במארח, פתחו **הגדרות → גישה מרוחקת** והרחיבו **גישה ישירה (רשת מקומית, מתקדם)**.
2. תחת **סיסמת שרת**, בחרו **הגדר סיסמה** או **שנה סיסמה**, הזינו **סיסמה חדשה** ו־**אשר סיסמה**, ואז **שמור סיסמה**. סיסמאות שסופקו בזמן ריצה אינן ניתנות לשינוי כאן; ראו [אבטחה](security.md).
3. הפעילו **אפשר חיבורים מכתובות IP אחרות** תחת **מצב האזנה**. קראו את אזהרת ההפעלה מחדש ובחרו **הפעל מחדש עכשיו** רק כשתהיו מוכנים להפרעה הזמנית.
4. לאחר ההפעלה מחדש, השתמשו ב־**רענן** ובדקו **כתובות נגישות**. פתחו את כתובת ה־HTTPS הנגישה במכשיר האחר, או בחרו **הצג QR** במארח וסרקו אותו במכשיר האחר, ואז התחברו.

הדבר משנה את מצב ההאזנה הישירה של המארח, לא פרויקט אחד ולא שליטה מרחוק. הסעיף נפתח אוטומטית כשהשרת מאזין מעבר ל־localhost. אם הפעלה מחדש אוטומטית אינה זמינה, הפעילו את CodeNomad מחדש ידנית; פריסות עצמאיות חייבות להגדיר בעקביות את `--host` בעת ההפעלה. להסרת חשיפה, כבו את המתג והפעילו מחדש, או הפעילו מחדש את ה־CLI בהאזנת loopback. הדבר אינו מבטל מכשירים מצומדים לשליטה מרחוק.

### טבלת האזנה {#binding-matrix}

ברירת המחדל של `--host` היא `127.0.0.1`; `localhost` מנורמל לכתובת זו. הכללים הבאים חלים על המאזינים המופעלים:

| הפעלה/מצב | HTTP מאזין ב־ | HTTPS מאזין ב־ |
| --- | --- | --- |
| עצמאי, HTTPS בלבד (ברירת מחדל) | מאזין loopback פרטי בלבד | `--host` |
| עצמאי, HTTP בלבד | **`--host`**, לרבות כתובת LAN/כל הממשקים | לא מופעל |
| עצמאי, שני מאזינים | `127.0.0.1` ללא תלות ב־`--host` | `--host` |
| שרת קצה מקורי לשולחן העבודה | מאזין HTTP שלו נשאר ב־`127.0.0.1`, לרבות המאזין הפנימי במארח | `--host` כש־HTTPS מופעל |

כתובת LAN מסוימת אינה חייבת לקבל חיבורי loopback. `0.0.0.0` פירושו כל ממשקי IPv4; `::` הוא מאזין כללי דו־מחסניתי. השתמשו בכתובת נגישה ממשית בדפדפן, לא בכתובת כללית. מזהי אזור IPv6 אינם נתמכים ב־`--host`.

לפריסת HTTPS עצמאית, הגדירו סיסמה באמצעות [נוהל האתחול](security.md), ואז הריצו:

```sh
codenomad --host 0.0.0.0 --https=true --http=false
```

ל־HTTP ב־loopback בלבד, למשל מאחורי מתווך מקומי מהימן:

```sh
codenomad --host 127.0.0.1 --https=false --http=true
```

אל תניחו יציאה 9898 או 9899: יציאות שלא צוינו יכולות להתחלף כשהן תפוסות. `--https-port` מפורש שאינו אפס, או `--http-port` כש־HTTP מופעל, מקבעים את היציאה ונכשלים אם אי אפשר להאזין בה; `0` מבקש ממערכת ההפעלה להקצות אחת. **Local Connection URL** ו־**Remote Connection URL** המודפסות, ו־**כתובות נגישות** לאחר רענון, הן הסמכות לאותה הרצה. ראו [מדריך CLI המלא לשרת](server.md).

## מדיניות מנהל המערכת {#administrator-policy}

מנהל מערכת יכול לקבע את כתובת ההאזנה: הגדירו את `CODENOMAD_LOCKED_HOST` ברמת המערכת לכתובת שהשרת חייב להשתמש בה והפעילו מחדש את CodeNomad. היא גוברת על `--host`, `CLI_HOST` ועל **אפשר חיבורים מכתובות IP אחרות**, שמציג את התוצאה אך לא יכול לשנות אותה. השתמשו בכתובת אינטראנט כדי שעמיתים יגיעו לשרת דרך רשת החברה, או ב־`127.0.0.1` כדי לשמור אותו במחשב זה. כדי שכל גישה תישאר ברשת החברה, הגדירו גם `CODENOMAD_REMOTE_CONTROL=disabled` ([שליטה מרחוק](remote-control.md#administrator-policy)).

## מקורות מורשים {#upgrading}

עבור כינוי לשם מארח, מתווך הפוך או ממשק שמתארח בנפרד, הגדירו בשרת הקצה את `CODENOMAD_ALLOWED_ORIGINS` למקורות המהימנים של הממשק (סכמה, שם מארח ויציאה). לקוחות LAN מקוריים חייבים לספק כותרת `Origin` מותרת בבקשות לשינוי נתונים. מקורות ה-HTTPS שלו מאפשרים גם למארח לצמד מכשירים בלי המנהרה; ראו [צימוד דרך HTTPS ישיר](remote-control.md#direct-https).

אם הממשק מתארח בנפרד, פרסו אותו וטענו מחדש את הכרטיסיות והחלונות הפתוחים לפני עדכון השרת. אם השרת מספק את הממשק, טענו אותם מחדש אחרי העדכון.

השתמשו בחיבור loopback לפעולות השמורות למארח: תוכן SideCar ‏(`/sidecars/`) ו־WebSockets, ניהול שליטה מרחוק (`/api/remote-control/`), גשר התוספים (`/api/opencode-plugin/`), מתווכים מרוחקים (`/api/remote-proxy/`), שינוי סיסמה ואתחול באמצעות אסימון. פעולות אלה דורשות loopback גם לאחר התחברות מאומתת בגישה ישירה דרך LAN. רק ל־SideCars יש חריגה: ההגדרה **פתיחת SideCars דרך HTTPS** במארח פותחת את התוכן ואת חיבורי ה־WebSocket שלהם לדפדפנים שמחוברים דרך מקור HTTPS מהימן ([SideCars](browser-sidecars.md#register-sidecar)). תוכן תצוגות מקדימות פעילות (`/previews/`) זמין בגישת LAN ישירה עם אסימון יכולת תקף.

ממשקי הרישום `/api/sidecars` נשארים זמינים ללקוחות LAN ישירים מאומתים ולמכשירים מצומדים. תצוגות האינטרנט של שליטה מרחוק נשארות זמינות עם אסימון היכולת שלהן כל עוד הן מופעלות במארח. לניהול שרתים ולהזנה בטוחה של פרטי כניסה, ראו [שמירת שרת מרוחק](remote-access.md#saved-servers).

## הגדרת TLS מהימן {#tls}

### אספקת תעודה משלכם {#custom-certificates}

1. השיגו תעודה שה־Subject Alternative Names ‏(SANs) שלה כוללים את שם המארח או כתובת ה־IP שהלקוחות משתמשים בהם בפועל.
2. ספקו גם `--tls-key <path>` וגם `--tls-cert <path>` כקובצי PEM. הוסיפו `--tls-ca <path>` אם הפריסה דורשת שרשרת/חבילת CA.
3. הפעילו מחדש את CodeNomad ואמתו את התעודה ואת כתובת ה־HTTPS המודפסת ממכשיר הלקוח.

קובצי תעודה מותאמים נקראים בהפעלה ולעולם אינם נכתבים מחדש בידי CodeNomad. החידוש וההפעלה מחדש הנדרשת לטעינת קבצים מחודשים הם באחריותכם. `--tlsSANs` מגדיר תעודות שנוצרות; אינו יכול להוסיף שמות לתעודה שסופקה. הגנו על מפתחות פרטיים ותנו אמון רק בתעודות שאת זהות המארח שלהן אימתתם.

### שימוש ב־CA המקומי שנוצר {#generated-certificates}

כש־HTTPS פעיל ולא סופק זוג מפתח/תעודה, CodeNomad יוצר CA מקומי ותעודת שרת תחת בסיס התצורה:

| קובץ | מטרה |
| --- | --- |
| `tls/ca-cert.pem` | תעודת CA ציבורית להפצה מאובטחת ללקוחות שבניהולכם. |
| `tls/ca-key.pem` | מפתח CA פרטי; לעולם אל תפיצו. |
| `tls/server-cert.pem` | תעודת שרת. |
| `tls/server-key.pem` | מפתח שרת פרטי; לעולם אל תפיצו. |

1. הוסיפו כל שם DNS/כתובת IP הפונים ללקוח באמצעות `--tlsSANs "host.example.test,192.0.2.10"`. האזנה בכל הממשקים אינה מגלה את כל כתובות ה־LAN שלכם עבור SANs.
2. הפעילו מחדש את שרת הקצה כדי ליצור/לבדוק מחדש את התעודה.
3. אמתו את המארח/ה־CA בערוץ מהימן, ואז ייבאו **רק את תעודת ה־CA** למאגר האמון של כל לקוח/דפדפן מיועד. לחלופין השתמשו בתעודה מהימנה ציבורית או במתווך TLS הפוך.

תעודת השרת שנוצרת תקפה ל־30 יום. בהפעלה היא מתחדשת בשלושת הימים שלפני תפוגתה, כשחסרים SANs נדרשים, כשהתעודה נכשלת בבדיקות או כשקובץ המפתח הפרטי חסר. ה־CA שנוצר תקף ל־365 יום ומוחלף כשפג, כשהתעודה שלו נכשלת בבדיקות או כשקובץ המפתח הפרטי שלו חסר; החלפתו גם מנפיקה מחדש את תעודת השרת. לקוחות חייבים לתת אמון ב־CA החלופי. אין חידוש רציף בתוך התהליך: תכננו הפעלה מחדש מכוונת לפני התפוגה בפריסות ארוכות־חיים.

אם לקוח מדווח על אזהרת תעודה, עצרו ובדקו את שם המארח, ה־SANs, מאגר האמון והתפוגה. אל תשביתו אימות ואל תהפכו אישור אזהרות בלחיצה לנוהל הפריסה. HTTPS מהימן נדרש גם לתכונות דפדפן מרוחקות כגון [התקנת PWA וגישה למיקרופון](mobile.md).

## שמירת שרת מרוחק {#saved-servers}

לקוחות מרוחקים מאומתים יכולים להשתמש באותם שרתים שמורים כמו לקוחות מקומיים ולנהל אותם. הזנת סיסמת שרת חדשה או קישור צימוד דורשת HTTPS או שליטה מרחוק.

ב־**הגדרות → שרתים**, הדביקו כתובת או קישור צימוד ב־**כתובת או קישור של השרת**, או הקלידו ולחצו Enter. כך שומרים שרת בלי לפתוח פרויקט. **עריכת שרת** משנה את **כתובת URL** או את ה־**שם** האופציונלי; שינוי שם עם אותה כתובת ומדיניות TLS פועל גם במצב לא מקוון. לאחר אישור, **הסרה** סוגרת את לשוניות השרת בחלון זה ומסירה את קיצורי הדרך האחרונים שלו. בפרויקטים זמניים, בחרו **שמור** או **מחק**; **מחק** מוחק את הקבצים והשיחות שלהם. שאר הפרויקטים והשיחות נשארים בשרת.

במארח של CodeNomad צריך להיות מותקן OpenSSH, ו־CodeNomad צריך כבר לפעול ביעד. ב־**הגדרות → שרתים**, בחרו **הוספת שרת SSH**. הזינו את כתובת ה־**URL** של CodeNomad כפי שהיא נגישה ממארח ה־SSH, את **מארח SSH (אופציונלי)** או הכינוי שלו, ובחרו **שמור**. אפשר לשמור את הפרופיל ללא חיבור. OpenSSH דורש אימות במפתח ומפתח מארח מאומת ב־`known_hosts`. התחברו ל־CodeNomad בשרת; אישורי HTTPS נבדקים.

בעורך השרת יש תיבת סימון **דילוג על אימות TLS**. השדה **כתובת או קישור של השרת** מציע אפשרות זו רק לאחר שגיאת תעודה בכתובת זו; שינוי הכתובת מאפס את הבחירה. צימוד תמיד מאמת TLS.

רק אם `multiBackend` מוגדר כ־`false`, השתמשו בשלבים הבאים לפתיחה בחלון שולחן עבודה נפרד:

1. **הגדרות → גישה מרוחקת → שרתים** → **התחבר לשרת CodeNomad**.
2. ב־**התחבר לשרת**, הזינו **שם השרת** ו־**כתובת השרת** עם מקור HTTPS מהימן. השאירו את **דלג על אימות TLS עבור תעודות בחתימה עצמית.** לא מסומן; הגדירו אמון במקום זאת.
3. בחרו **שמור** לסימנייה, או **התחבר** לשמירה ולפתיחה. התחברו באותו שרת.

סגירת החלון המקומי האחרון בזמן שחלונות מרוחקים נשארים פתוחים שומרת את הלשוניות שלו: **חלון → חלון חדש** בחלון מרוחק, או הפעלה מחדש של CodeNomad, פותחים אותו שוב.

לשליטה מרחוק, הדביקו במקום זאת קישור צימוד חדש ב־**כתובת השרת**. הסימנייה שומרת רק את מקור המנהרה, לעולם לא את קוד הצימוד החד־פעמי; ראו [שליטה מרחוק](remote-control.md) לצימוד מחדש לאחר אובדן עוגיית המכשיר.

## פתיחת פרויקט מרוחק בלשונית {#remote-project-tabs}

במסך הבית או בלשונית חדשה בחרו **עיון** ואז בשרת. כדי לשמור שרת, הדביקו כתובת או קישור שיוך בשדה **כתובת או קישור של השרת**. התחברו אם תתבקשו. לחצו על תיקייה כדי לעיין בה; לחצו Enter בשדה הנתיב או בחרו **פתח** כדי לפתוח אותה. **חזרה לעיון** מחזיר לרשימת השרתים.

פרויקטים מקומיים ומרוחקים נפתחים באותו חלון. **כרטיסיות אחרונות** מציג את קיצורי השרת שנבחר בזמן העיון. הרשימה המשולבת מציגה את סמל השרת ואת שמו לפרויקטים שנפתחו כאן. [שחזור לשוניות מרוחקות](projects.md#restore-remote-tabs).

ב־**הגדרות → שרתים**, **פתיחה** בוחרת את השרת ב־**עיון** ומשתמשת בלשונית ריקה שכבר פתוחה, אם יש כזו.

### `--connect-server` {#connect-server}

`--connect-server <name-or-url>` פותח חלון מרוחק נפרד ללא תלות בערך `multiBackend`. השתמשו בשם שמור, במזהה שמור או בכתובת HTTP(S). כתובת חדשה נשמרת בשם המארח שלה. כתובת ההפעלה אינה יכולה לכלול שם משתמש, סיסמה או קוד צימוד. ראו את [טבלת הארגומנטים לשולחן העבודה](desktop.md#desktop-cli) לתחביר ולהפעלת החלון המרוחק בלבד.
