# גישה ישירה מרחוק

גישה ישירה מתחברת למאזיני HTTP/HTTPS של CodeNomad באמצעות סיסמת השרת שלו. היא נפרדת מ־[שליטה מרחוק](remote-control.md): צימוד אינו דורש האזנה ב־LAN או יציאה נכנסת, ואף נתיב אינו עובר בשקט לאחר כחלופה.

## בחירת נתיב גישה {#access-paths}

| נתיב | מה עליכם לנהל |
| --- | --- |
| דפדפן באותו מחשב | השאירו האזנת loopback; השתמשו בכתובת המקומית המודפסת. |
| LAN או VPN | האזינו בממשק נגיש, הגבילו את חומת האש ללקוחות המיועדים והשתמשו ב־HTTPS מהימן. VPN אינו מגדיר עבורכם את מאזין CodeNomad. |
| העברת SSH | השאירו את שרת הקצה בהאזנת loopback; העבירו את היציאה המודפסת בפועל. המנהרה מגינה על התעבורה אך אינה מחליפה אימות CodeNomad. |
| מתווך הפוך | השאירו את שרת הקצה בממשק פרטי/loopback; סיימו TLS מהימן במתווך, הגנו על המקטע לשרת שמאחוריו ותמכו ב־SSE ארוך־חיים ובכל WebSocket שנדרש לכלי הגישה הישירה שלכם. |
| שליטה מרחוק | צמדו את המכשיר מהמארח; ראו [שליטה מרחוק](remote-control.md) לממשק המצומצם יותר ולמשך החיים שלה. |

האזנה אינה יוצרת כללי חומת אש, העברת יציאות, DNS או VPN. אל תפרסמו מאזין HTTP לא מאומת לאינטרנט. שורש סביבת עבודה אינו ארגז חול אבטחתי; קראו [אבטחה](security.md) לפני חשיפת השרת.

## הפעלת גישה ישירה {#enable-direct-access}

1. במארח, פתחו **הגדרות → גישה מרוחקת** והרחיבו **גישה ישירה (רשת מקומית, מתקדם)**.
2. תחת **סיסמת שרת**, בחרו **הגדר סיסמה** או **שנה סיסמה**, הזינו **סיסמה חדשה** ו־**אשר סיסמה**, ואז **שמור סיסמה**. סיסמאות שסופקו בזמן ריצה אינן ניתנות לשינוי כאן; ראו [אבטחה](security.md).
3. הפעילו **אפשר חיבורים מכתובות IP אחרות** תחת **מצב האזנה**. קראו את אזהרת ההפעלה מחדש ובחרו **הפעל מחדש עכשיו** רק כשתהיו מוכנים להפרעה הזמנית.
4. לאחר ההפעלה מחדש, השתמשו ב־**רענן** ובדקו **כתובות נגישות**. פתחו את כתובת ה־HTTPS הנגישה במכשיר האחר, או בחרו **הצג QR** במארח וסרקו אותו במכשיר האחר, ואז התחברו.

הדבר משנה את מצב ההאזנה הישירה של המארח, לא פרויקט אחד ולא שליטה מרחוק. הסעיף נפתח אוטומטית כשהשרת מאזין מעבר ל־localhost. אם הפעלה מחדש אוטומטית אינה זמינה, הפעילו את CodeNomad מחדש ידנית; פריסות עצמאיות חייבות להגדיר בעקביות את `--host` בעת ההפעלה. להסרת חשיפה, כבו את המתג והפעילו מחדש, או הפעילו מחדש את ה־CLI בהאזנת loopback. הדבר אינו מבטל מכשירים מצומדים לשליטה מרחוק.

### טבלת האזנה {#binding-matrix}

ברירת המחדל של `--host` היא `127.0.0.1`; `localhost` מנורמל לכתובת זו. הכללים הבאים חלים על המאזינים המופעלים:

| הפעלה/מצב | HTTP מאזין ב־ | HTTPS מאזין ב־ |
| --- | --- | --- |
| עצמאי, HTTPS בלבד (ברירת מחדל) | מאזין loopback פרטי בלבד (ראו להלן) | `--host` |
| עצמאי, HTTP בלבד | **`--host`**, לרבות כתובת LAN/כל הממשקים | לא מופעל |
| עצמאי, שני מאזינים | `127.0.0.1` ללא תלות ב־`--host` | `--host` |
| שרת קצה מקורי לשולחן העבודה | מאזין HTTP שלו נשאר ב־`127.0.0.1`, לרבות המאזין הפנימי במארח | `--host` כש־HTTPS מופעל |

כל שרת קצה שומר גם מאזין HTTP ב־`127.0.0.1` עבור תוספי OpenCode שמגיעים עם CodeNomad עצמו, כגון משימות. כש־HTTP לא התבקש, או כשמאזין ה־HTTP המבוקש מאזין בכתובת שאינה `127.0.0.1` או `0.0.0.0`, שרת הקצה מוסיף מאזין HTTP פרטי ביציאה אקראית של `127.0.0.1`. הוא לעולם אינו מודפס או מוצע ככתובת חיבור, אינו נגיש ממחשבים אחרים ומגיש את אותו יישום מאומת.

כתובת LAN מסוימת אינה חייבת לקבל חיבורי loopback. `0.0.0.0` פירושו כל ממשקי IPv4; `::` הוא מאזין כללי דו־מחסניתי. השתמשו בכתובת נגישה ממשית בדפדפן, לא בכתובת כללית. מזהי אזור IPv6 אינם נתמכים ב־`--host`.

לפריסת HTTPS עצמאית, הגדירו סיסמה באמצעות [נוהל האתחול](security.md), ואז הריצו:

```sh
codenomad --host 0.0.0.0 --https=true --http=false
```

ל־HTTP ב־loopback בלבד, למשל מאחורי מתווך מקומי מהימן:

```sh
codenomad --host 127.0.0.1 --https=false --http=true
```

אל תניחו יציאה 9898 או 9899: יציאות שלא צוינו יכולות להתחלף כשהן תפוסות. `--https-port` מפורש שאינו אפס, או `--http-port` כש־HTTP מופעל, מקבעים את היציאה ונכשלים אם אי אפשר להאזין בה; `0` מבקש ממערכת ההפעלה להקצות אחת. **Local Connection URL** ו־**Remote Connection URL** המודפסות, ו־**כתובות נגישות** לאחר רענון, הן הסמכות לאותה הרצה. ראו [מדריך CLI המלא לשרת](server.md).

## הגדרת TLS מהימן {#tls}

### אספקת תעודה משלכם {#custom-certificates}

1. השיגו תעודה שה־Subject Alternative Names ‏(SANs) שלה כוללים את שם המארח או כתובת ה־IP שהלקוחות משתמשים בהם בפועל.
2. ספקו גם `--tls-key <path>` וגם `--tls-cert <path>` כקובצי PEM. הוסיפו `--tls-ca <path>` אם הפריסה דורשת שרשרת/חבילת CA.
3. הפעילו מחדש את CodeNomad ואמתו את התעודה ואת כתובת ה־HTTPS המודפסת ממכשיר הלקוח.

קובצי תעודה מותאמים נקראים בהפעלה ולעולם אינם נכתבים מחדש בידי CodeNomad. החידוש וההפעלה מחדש הנדרשת לטעינת קבצים מחודשים הם באחריותכם. `--tlsSANs` מגדיר תעודות שנוצרות; אינו יכול להוסיף שמות לתעודה שסופקה. הגנו על מפתחות פרטיים ותנו אמון רק בתעודות שאת זהות המארח שלהן אימתתם.

### שימוש ב־CA המקומי שנוצר {#generated-certificates}

כש־HTTPS פעיל ולא סופק זוג מפתח/תעודה, CodeNomad יוצר CA מקומי ותעודת שרת תחת בסיס התצורה:

| קובץ | מטרה |
| --- | --- |
| `tls/ca-cert.pem` | תעודת CA ציבורית להפצה מאובטחת ללקוחות שבניהולכם. |
| `tls/ca-key.pem` | מפתח CA פרטי; לעולם אל תפיצו. |
| `tls/server-cert.pem` | תעודת שרת. |
| `tls/server-key.pem` | מפתח שרת פרטי; לעולם אל תפיצו. |

1. הוסיפו כל שם DNS/כתובת IP הפונים ללקוח באמצעות `--tlsSANs "host.example.test,192.0.2.10"`. האזנה בכל הממשקים אינה מגלה את כל כתובות ה־LAN שלכם עבור SANs.
2. הפעילו מחדש את שרת הקצה כדי ליצור/לבדוק מחדש את התעודה.
3. אמתו את המארח/ה־CA בערוץ מהימן, ואז ייבאו **רק את תעודת ה־CA** למאגר האמון של כל לקוח/דפדפן מיועד. לחלופין השתמשו בתעודה מהימנה ציבורית או במתווך TLS הפוך.

תעודת השרת שנוצרת תקפה ל־30 יום. בהפעלה היא מתחדשת בשלושת הימים שלפני תפוגתה, כשחסרים SANs נדרשים, כשהתעודה נכשלת בבדיקות או כשקובץ המפתח הפרטי חסר. ה־CA שנוצר תקף ל־365 יום ומוחלף כשפג, כשהתעודה שלו נכשלת בבדיקות או כשקובץ המפתח הפרטי שלו חסר; החלפתו גם מנפיקה מחדש את תעודת השרת. מפתחות פרטיים קיימים פגומים, בלתי קריאים או לא תואמים אינם מתוקנים אוטומטית. לקוחות חייבים לתת אמון ב־CA החלופי. אין חידוש רציף בתוך התהליך: תכננו הפעלה מחדש מכוונת לפני התפוגה בפריסות ארוכות־חיים.

אם לקוח מדווח על אזהרת תעודה, עצרו ובדקו את שם המארח, ה־SANs, מאגר האמון והתפוגה. אל תשביתו אימות ואל תהפכו אישור אזהרות בלחיצה לנוהל הפריסה. HTTPS מהימן נדרש גם לתכונות דפדפן מרוחקות כגון [התקנת PWA וגישה למיקרופון](mobile.md).

## שמירת שרת מרוחק {#saved-servers}

1. השתמשו ב־**עיון** בדף הבית או בחלונית השנייה של לשונית ריקה והזינו כתובת או קישור ב־**כתובת או קישור של השרת**. הדבקה מוסיפה מיד; Enter מאשר טקסט שהוקלד. השרת נשמר, השורה מקבלת מיקוד והבורר נשאר; קישור גם מצמד את שרת הקצה המקומי לעיון. לחצו על השורה לעיון. **הגדרות → שרתים** מציע אותו שדה.
2. השתמשו במקור HTTPS מהימן. שגיאות תעודה ושרת לא נגיש מתורגמות; כפתור המידע מציג אבחון טכני לפי דרישה. **דילוג על אימות TLS** דורש בחירה מפורשת: הפעילו רק לשרת מהימן ואשרו שוב. פעולת הפתיחה מודיעה בעת בחירת הפרויקט שפרופיל זה משתמש בחלון נפרד.
3. שם השרת נשאר גלוי בהתחברות ובניווט, עם שדות מתויגים ואזורים נפרדים של **אחרונים** ו־**תיקיות**. שגיאות צימוד מציינות את השרת. **עריכת שרת** ב־**הגדרות → שרתים** משנה כתובת ושם; כפתורי `i` מציגים עזרת כתובת/TLS לפי דרישה.

**הגדרות → שרתים** מנהל פרופילים (**עריכת שרת**, **הסר שרת שמור**). הסרה שוכחת תחילה את פרטי ההתחברות וסשן העיון שבשרת הקצה, ואז מסירה את הסימנייה וסוגרת את לשוניותיה. פרויקטים ושיחות מרוחקים נשארים בשרת שלהם. שרת הקצה המקומי שומר את סודות העיון ב־`remote-server-credentials.json` לצד התצורה שלו; הגנו על קובץ זה כמו על סיסמה. תצוגות מוטמעות שומרות אימות נפרד.

כדי לפתוח שרת שמור ישירות משורת הפקודה, הפעילו את אפליקציית שולחן העבודה עם `--connect-server <name>` (או `--connect-server=<name>`), עם השם השמור של השרת או עם כתובת ה־`https://` שלו. CodeNomad פותח רק את החלון המרוחק, עם בדיקות ה־TLS של הפרופיל וההתחברות העצמאית של החלון המרוחק המקורי; כש־CodeNomad כבר פועל, החלון הנוכחי שלו פותח אותו במקום חלון חדש. כתובת שאינה תואמת אף שרת שמור נשמרת בשם המארח שלה. ערכי הפעלה לעולם אינם נושאים פרטי התחברות: כתובת עם שם משתמש, סיסמה או קוד צימוד נדחית. אם השם אינו מוכר, הכתובת אינה תקינה או שהחיבור נכשל, CodeNomad מופעל כרגיל ומציג את השגיאה. כשהחיבור דורש אישור, כמו התקנת התעודה המקומית לשרת בחתימה עצמית, CodeNomad גם מופעל כרגיל ומבקש אותו שם. ב־Windows, גרסת Tauri מסרבת לעלות כשארגומנט הפעלה מכיל `|`; השתמשו במקום זאת בכתובת השרת, או שנו את שם השרת.

חלון מרוחק תמיד משאיר דרך לחזור למחשב הזה. סגירת החלון המקומי האחרון בזמן שחלונות מרוחקים נשארים פתוחים שומרת את הלשוניות שלו: **חלון → חלון חדש** בחלון מרוחק, או הפעלה מחדש של CodeNomad, פותחים אותו שוב. אם לא ניתן לטעון שרת, החלון שלו מציין זאת ומציע **נסו שוב**, **פתיחת חלון מקומי** ו**סגירת החלון**; בגרסת Tauri, השתמשו בכפתור הרענון של הדף וב־**חלון → חלון חדש**.

הדבקת קישור חדש של שליטה מרחוק שומרת את מקור המנהרה ומצמדת את שרת הקצה המקומי לעיון; אישור המכשיר נשמר בפרטיות גם בין הפעלות. הקוד נמחק לאחר הניסיון. לאחר ביטול בחרו **חזרה לעיון** והדביקו קישור חדש ב־**כתובת או קישור של השרת**. תצוגות מוטמעות מצומדות בנפרד. אם צימוד בצד השרת אינו זמין, עדכנו את השרת המרוחק או השתמשו בכתובת ההאזנה הישירה שלו להתחברות בסיסמה; כתובות מנהרה דורשות צימוד. ראו [שליטה מרחוק](remote-control.md).

## פתיחת פרויקט מרוחק בלשונית {#remote-project-tabs}

ביישום שולחן העבודה (Electron, או Tauri ב-Windows), שרת שמור יכול לפתוח גם אחד מהפרויקטים שלו בלשונית של החלון הזה, לצד הפרויקטים המקומיים שלך:

1. בדף הבית או בלשונית ריקה פתחו **עיון** ובחרו שרת. הוסיפו שרת עם **כתובת או קישור של השרת**, ואז לחצו על השורה שלו.
2. השרת המזוהה מציג **אחרונים** ו־**תיקיות** באותו מקום. התחברו בטופס המתויג לפי הצורך. בחרו פרויקט או נווטו ובחרו **פתיחת תיקייה זו**. **חזרה לעיון** מציגה שרתים.
3. בחירת תיקייה יוצרת מופע מרוחק חדש במקום הלשונית הריקה ומוסיפה אותו ל־**אחרונים**. הפעולה הנפרדת **פתוח** בוחרת מופע קיים. פתיחה בחלון נפרד מוכרזת בזמן הבחירה, כולל מקרי TLS ו־Tauri ב־macOS/Linux. מגבלה ידועה: העיון דרך שרת הקצה והתצוגה המקורית משתמשים באימות עצמאי.

השיחות, הקבצים, Git, ההגדרות ו־Missions בלשונית פועלים בשרת המרוחק. התצוגה המוטמעת חולקת את אחסון החלון המרוחק שלו ועשויה לדרוש התחברות נפרדת מעיון. לשוניות מרוחקות משתתפות בשחזור בהפעלה. שרתים ללא מצב מוטמע מציגים את הממשק המלא; פרופילים שמדלגים על TLS ו־Tauri ב־macOS/Linux פותחים חלון נפרד. הדף המוטמע נשאר בשרת שלו ויכול רק לשלוח התראות למארח. ללקוחות דפדפן ולמכשירי שליטה מרחוק אין לשוניות מרוחקות.

העיון דרך שרת הקצה מקבל את כתובת היעד של כל פרופיל שמור, כולל loopback, רשתות LAN מסוג RFC1918, Docker, Hyper-V, CGNAT/Tailscale (`100.64.0.0/10`), MagicDNS ו־`*.ts.net`, כתובות IPv6 ULA/link-local ושמות שמתורגמים לכתובות אלה. נתיבי הרשת והגדרות ה־TLS שלכם חייבים לאפשר את החיבור. בדיקת התעודה פועלת לפי הפרופיל השמור ואישור ה־TLS המפורש שלו.
