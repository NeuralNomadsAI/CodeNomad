# Workspace tree row

`workspace_tree::row(dark, rtl, Row { label, depth, selected, expanded, icon, busy, actions })` draws one row. The owner supplies the key, focus/tab policy, handlers, translated labels and independent action elements. `depth` is the Source level, starting at one. `expanded: Some(false)` preserves an unloaded directory's branch semantics. State, listing, sorting, preview and menu policy belong to the owner.

The Source sheet is generated by `node scripts/rune/component-inventory.mjs` from the real `WorkspaceTree.tsx`. `generate-theme.mjs` extracts indentation and glyph dimensions through its AST, resolves CSS metrics in Chromium and generates the Source Lucide SVGs from the installed dependency's literal AST. Generated icons are exported in `workspace_tree::icons`; the caller chooses them.

The pinned kit's public `TreeRow::expanded(Some(...))` supports manually described branches. Its `TreeItem::build` fixes chevron and glyph sizes at 16, fixes row height and uses symmetric padding. The Source requires 12/14 glyphs, minimum height, asymmetric logical padding and a closed ChevronRight in both visual directions. This shared adapter composes Rune elements to preserve that geometry. The pinned TreeModel's lazy-directory behavior is tracked in Rune issue 1348.

The selected Source row resets `background-image` through its later `background` declaration. The shared adapter retains the selected background; unselected hover and keyboard focus within show the Source overlay. Actions receive the row's hover group and can use `group_opacity` while preserving their own active/disabled states.

## Reproduce without windows

```powershell
node scripts/rune/generate-theme.mjs --check
node --test scripts/rune/generate-theme.test.mjs
$env:CARGO_INCREMENTAL='0'
$env:CARGO_TARGET_DIR='D:/CodeNomad/.codenomad/worktrees/rune-native-chat/packages/rune-chat/target'
cargo +1.99.1 test -p rune-theme-codenomad --lib --offline --locked
cargo +1.99.1 fmt -p rune-theme-codenomad --check
cargo +1.99.1 build -p rune-theme-codenomad --example workspace-tree-row --offline --locked
node scripts/rune/parity/workspace-tree-row.mjs
node scripts/rune/parity/workspace-tree-row-native.mjs --binary "$env:CARGO_TARGET_DIR/debug/examples/workspace-tree-row.exe"
node scripts/rune/parity/compare-workspace-tree-row.mjs --thresholds scripts/rune/parity/workspace-tree-row-thresholds.json
```

The real Source component is mounted in a private Vite fixture with synthetic state; all requests are restricted to its loopback origin. Native scenes use the shared component and isolated `trial-*` profiles. The gallery requires `--tree` and `--snap` and exits before opening a window when these are absent. Evidence, hashes, geometry, accessibility, interactions, PNG pairs and regional error measurements live under `target/rune-parity/workspace-tree-row/`.

The matrix covers both appearances, both visual directions, files, closed/open directories, busy and keyboard focus. Native Runtime checks names, levels, selection and branch states through AccessKit and verifies independent row/action activation. The comparison checks geometry before pixels and records one-pixel displacement and mirrored-chevron negative controls. Pixel budgets require independent review; the 12px SVG raster issue 1346 remains a component-specific qualification gate.

Windows scale-one evidence contains twenty Source/Rune pairs with equal row, label, icon and chevron bounds. The row is 30px with its 24px action controls and 3px block padding; its CSS minimum remains 27px. Depth one starts at 22px from the logical start. Closed chevrons point right in both directions, as the real Source SVGs show.

For the light closed chevron, the observed channel-error sum is 1,203. Moving the candidate one pixel increases it to 4,215; mirroring it increases it to 5,243. Dark controls also worsen the measured result. These checks run as assertions before any pixel budget is adopted. Visible focus actions retain measured errors up to 18 channels in light and 10 in dark and require separate action-composite qualification.

## Proposed regional thresholds

`workspace-tree-row-thresholds.json` has `reviewState: proposed`. Its limits are a review proposal. The comparator records `adopted: false`, hashes the proposal and comparison scripts, validates complete unique case coverage and assigns every pixel to exactly one region. It also checks the current Source, theme, component, generated SVG, gallery and private executable hashes before evaluating the PNGs.

The 14px icon envelope allows at most two channel units and a regional error sum of 650. The separate 12px chevron envelopes allow the observed high-amplitude stroke discrepancy, with tighter limits for open/focused states. Surface and edge limits are exact apart from one-unit dark selected compositing. Text limits distinguish labels, appearance and selection; action limits distinguish hidden and visible caller controls. No whole-row budget combines these regions.

All twenty recorded pairs pass the proposal. All 208 applicable mutations fail their own regional thresholds: absent/displaced chevrons, the wrong mirror for closed chevrons, absent/displaced/wrong Source Lucide 14px glyphs, absent/displaced text, altered surfaces and edges, absent selected surfaces and focus outlines, absent visible caller actions, and absent/displaced busy indicators. The wrong glyph donor is another actual native fixture capture using a different Source Lucide path. Removal controls restore the captured background; surface-removal controls use the captured unselected state. Each mutation must change at least one candidate pixel and exceed a declared regional limit.

A downward Source chevron is symmetric under horizontal mirroring; the wrong-mirror mutation applies to closed folders. Files use a zero-height empty spacer and receive no chevron-removal mutation. These Source geometries are recorded in `solid-evidence.json`.

Actions remain caller-supplied `El` content: the measured action envelope concerns this gallery's actual Source `FileRowActions` assembly, whose CSS and component hashes and computed opacity are recorded. Every action-region pixel is still evaluated. Busy-frame envelopes also evaluate every pixel and detect removal/displacement; phase, timing and reduced-motion behavior require independent motion qualification. Neither envelope adopts a general caller-action or animation contract.

The DOM mirror omits a treeitem that contains independent pressable actions; its treeitem controls also omit level. Native AccessKit retains these semantics. Pointer focus within, busy rotation phase, coarse-pointer action visibility, long-label clipping and actual application menu assembly require further qualification.
