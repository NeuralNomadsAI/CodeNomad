# AGENT NOTES

## Styling Guidelines
- Right-panel customization keeps Extensions below a separator in a native disclosure, collapsed on each popup opening. Expanding mounts one compact searchable list combining installed and online addons, deduplicated by ID; collapse, dismissal and inactive/instance changes dispose its requests and confirmations. Do not restore separate list modes or a floating extension window. The existing per-addon checkbox above the disclosure is the sole profile-wide activation control, including disabled installed addons; never add a manager switch or a second per-window visibility gate. Reset changes built-in layout only, not addon consent. Keep metadata on hover/focus and technical consent details folded; retain explicit trust and digest-bound replacement/removal. Installation and activation are profile-wide only; do not restore per-folder scopes without a demonstrated need. Legacy folder grants never become general consent.
- External panel extensions use `components/panel-extensions/` and `styles/panels/panel-extensions.css`. The official online catalogue is in `NeuralNomadsAI/CodeNomad-Extensions`; metadata discovery never downloads author code. Inspect/install revalidate the exact index/manifest/digest and use bounded credential-free HTTPS GitHub release downloads, never client-provided URLs. Never import author JavaScript into the main renderer or expose native/OpenCode bridges. ZIPs contain only a manifest and a self-contained HTML panel; install/replacement revokes activation. API versions belong to the public extension contract, not internal Solid modules. See `dev-docs/PANEL_EXTENSIONS.md` for distribution, consent, scope and sandbox limits.
- Extension API 1 stays context-only; API 2 requires explicit `session.assets.read` consent. `assets-channel.ts` derives session authority from the current mounted host, never author selectors, and exposes only bounded asset pages/exact digest-bound embedded reads. Use the presence-owned history bundle's fixed `assets`/`assetRead` methods, not transcript stores, generic RPC, remote downloads or filesystem fallbacks. Recheck consent and Location ownership after IO; revoke old-port/session/reconnect results. Gallery HTML belongs in the independent catalogue repository, not the application renderer.
- Provider accounts use a native dropdown like Web search defaults, without an Accounts disclosure or selectable account rows. Provider headers keep the name and text Manage models button on one row; a faint separator distinguishes the account controls below. Account actions are always visible, not hover-revealed. The `provider-account` container stacks the label above the dropdown/actions at narrow card widths. Native account ordering supplies the current account; rename/remove drafts stay keyed by credential. Environment connections are read-only. The browser never reads credential secrets. Native labels win; only `default` may display a sanitized login email from the owned server adapter. Opt-in rotation is per integration (`providerAccounts.autoSelect.<integrationID>`) through the selection-adapter registry in `provider-accounts/adapters.ts`, for subscription accounts with quota windows only: Codex, OpenCode Go (Go key and Console sign-in, Go provider only), Claude Pro/Max (OpenCode Anthropic OAuth, never the Claude Code login), GitHub Copilot and key-based coding plans; pay-as-you-go keys/credits stay manual. It runs before prompt/command admission, reading each explicit credential's fresh quota (reusing Usage readers) without activating candidates or refreshing tokens, with local manual-change fences and no mutation/prompt replay; the only switch condition is a full current account. Native `provider.quota` failures add bounded in-memory per-connection marks (`quota-observer.ts`); reactive adapters (Go, Console, Claude) accept unknown-but-unmarked candidates, others need "available". Go's usage endpoint and Console OAuth usage are unverified upstream. Account styling lives in `styles/components/provider-accounts.css`, backend policy in `provider-accounts/`, with limitations and isolated validation in `dev-docs/PROVIDER_ACCOUNTS_UX_PLAN.md`. Browser preview percentages remain simulated.
- Reuse the existing token & utility layers before introducing new CSS variables or custom properties. Extend `src/styles/tokens.css` / `src/styles/utilities.css` if a shared pattern is needed.
- Keep aggregate entry files (e.g., `src/styles/controls.css`, `messaging.css`, `panels.css`) lean—they should only `@import` feature-specific subfiles located inside `src/styles/{components|messaging|panels}`.
- When adding new component styles, place them beside their peers in the scoped subdirectory (e.g., `src/styles/messaging/new-part.css`) and import them from the corresponding aggregator file.
- Prefer smaller, focused style files (≈150 lines or less) over large monoliths. Split by component or feature area if a file grows beyond that size.
- Co-locate reusable UI patterns (buttons, selectors, dropdowns, etc.) under `src/styles/components/` and avoid redefining the same utility classes elsewhere.
- Use the shared `.window-*` primitives from `src/styles/components/window.css` for dialog, popover, and floating-window headers, toolbars, bodies, footers, titles, and actions.
- Persistent utility windows and transcript-covering previews expose an upper-right close button in their existing top toolbar; do not add a dedicated row just for dismissal. Use `components/window-close-button.tsx` with shared window chrome. Transient popups such as transcript filters dismiss on outside interaction and have no close button.
- Authentication recovery uses `lib/auth-recovery.ts` and `components/auth-recovery-dialog.tsx`: confirm CodeNomad auth status before showing an expired-login form, reconnect in place to preserve drafts, and never replay failed mutations. Its shared window styles live in `styles/components/auth-recovery.css`.
- Confirmation dialogs (`components/alert-dialog.tsx`) keep Kobalte's initial focus on Cancel, so Enter never confirms by reflex, while the confirm button stays the filled primary action. Alert-dialog buttons show the accent focus ring on any `:focus` (`styles/components/alert-dialog.css`), including the initial focus of a mouse-opened dialog, so the ring marks the button Enter acts on. Prompts focus their input, where Enter submits. Covered by `tests/browser/alert-dialog.test.ts`.
- Persistent command/search utility windows use `components/dismissible-window.tsx`: non-modal, no scrim, outside interactions keep them open, and explicit toggles use `.icon-toggle` with `aria-expanded`/`aria-controls`. Keep search state scoped to its instance/session and close it when that view becomes inactive.
- The `.icon-toggle` active state (`aria-pressed`/`aria-expanded`/`data-active`) is one shared rule in `styles/utilities.css`: one uniform partial accent tint for every palette (an ink of accent leaning 20% toward `--text-on-accent`, then 10% toward `--surface-base`, at 40% opacity, 50% on hover) over the surface beneath, primary-text icon, disabled toggles excluded. It is for icon toggles only: text list rows select through `--list-item-highlight-*` instead (Mission past runs). Do not add per-button or per-palette active overrides; the only exception is `.tool-call-output-rail`, which keeps its compact output-rail toggles transparent. `tests/browser/icon-toggle-active.test.ts` samples real active toggles on every ready-made palette over the session header (search), sessions sidebar header, right-panel tab bar, user and assistant message cards (speech button), interruption dock header and transcript canvas (overlay windows share the canvas colour): OKLab ΔE ≥ 8 from the surface on the header and ≥ 5 elsewhere, ≥ 6 from the header's idle hover, ≥ 1.4 from active to active hover, icon ≥ 3:1 on both fills.
- Movable utility windows opt into `DismissibleWindow.draggable` and mark their existing top bar with `data-window-drag-handle`; keep drag geometry shared and controls interactive. `--window-visible-height` bounds their height to the visual viewport; native scrolling and a sticky existing top bar keep results, pagination and drag/close controls reachable.
- The composer reserves `/btw` for native `session.generate`, outside ordinary prompt/command submission. Its ephemeral question/answer window uses `DismissibleWindow` and `styles/components/session-aside.css`; cancellation and inactive/session transitions fence late results without interrupting the main session.

Pending questions appear only in the dock; the transcript retains native completed question results. Badges target the dock via `interruptionFocus`; omit transcript-source and answer-in-dock links. Keep selection stable by request kind/id across queue refreshes, with bounded previous/next navigation hidden for a single request. Preserve request drafts across refreshes and session navigation. Keep its square, height-bounded chrome in `styles/components/interruption-dock.css`, with a token-based accent header and fixed action footer outside the scrolling request content. See `dev-docs/NATIVE_INTERRUPTION_UX.md`.

Collapsed unrelated-conversation requests show the full shared red `session-permission` badge (shield and localized request-status text) at the trailing end of the header, separate from the request icon.

Keep persistent textual provenance prominent (other conversation, subagent with parent, or sessionless project request), with an explicit View conversation action for session-owned requests. Arrival never replaces the request being edited or navigates sessions. Newly selected external requests after settlement remain compact until explicitly opened. Hidden/inert keyed editors retain drafts, and only an expanded editor compacts the composer. Project badges open the dock in place rather than silently navigating to another conversation.
- Durable permission decisions render through `components/permission-receipts.tsx` outside native tool visibility, with bounded mounted-row reads and a paginated session disclosure for unanchored receipts. Virtualized rows remount continuously: `stores/permission-receipt-cache.ts` retains each row's completed snapshot (no re-read on remount) and shares in-flight reads among mounted rows on the dedicated one-slot `receiptReads` lane; a read no mounted row awaits is cancelled. Receipt-change events (mounted or not) and reconnects invalidate; pagination writes are fenced by the invalidation generation. Keep receipts out of native message/copy/search/speech projections; styles live in `styles/messaging/permission-receipts.css`.
- The browser opens only a few connections to the CodeNomad server. The selected transcript and its metadata read directly; secondary panel and timeline reads (plugin controls, outlines/previews) go through `secondaryRead` in `lib/api-client.ts`, sharing the bounded `backgroundReads` budget. Provider usage stays direct (superseded reads are fenced, not cancelled), and so does the OpenCode status read awaited by Restart/Start, so daemon-bound reads in the shared budget can never hold it. Startup effects must not track app-wide state they only await (`untrack` readiness gates), or every restored workspace update restarts and requeues the transcript read. Search visibility must be value-diffed before its close effect: reactive instance metadata can change while search stays closed, and running search cleanup then would cancel the initial transcript read. Restore tests must exercise reactive identity accessors and assert visible messages, not only request counts.
- An expanded interruption temporarily reduces the composer to its minimum without changing its saved height or draft; resizing resumes after collapse/settlement. `instance/shell/useInterruptionViewport.ts` bounds the request/composer stack to the visual viewport during keyboard resize/pan. Keep the dock non-shrinking and its footer reachable on short mobile layouts.
- Completed question receipts share native answer decoding with text projection through `tool-call/renderers/question-data.ts`. Preserve selected-option descriptions and verbatim free text; keep remaining choices in a native disclosure. Receipt styles live in `styles/messaging/tool-call/question.css`.
- Automatic pending-request recovery uses the authenticated loaded-only broker in `packages/server/src/server/routes/pending-requests.ts`; it must never fall back to ordinary lists across inactive worktrees, on any daemon version. Validate directory ownership before querying and every returned placement before publishing; retain execution-host authority even for cold/empty coverage, including WSL and path aliases. Preserve idle/global Forms, per-kind mutation fences and settled-request tombstones. Missing capability, errors or incomplete coverage retain known queues/drafts immediately; the existing notification system warns once after two consecutive incomplete recoveries (the 30-second liveness pass retries transient failures) and stays quiet until successful recovery or removal. Never add a permanent banner or dedicated icon. Compaction deferral, invalidation and rehydration do not notify, count toward or rearm the warning. Rehydration does not clear queues. Only explicit settlement reconciliation uses an ordinary list at that request's authorized location. Capability is negotiated per connection, not inferred from a version label; validate actual private graph/queue contracts, never an untested-version allowlist.

Only version details and troubleshooting are collapsed disclosures at the bottom of the runtime panel; log levels remain the final settings card. Troubleshooting always exposes an explicit, confirmed shared-service restart independently of updates; retain the inline activation shortcut after an update, and never downgrade a newer daemon through an older selected CLI. Configuration reload remains a separate process-preserving action. Share controls with the startup recovery dialog rather than routing settings through a separate management modal. Disclosure styles live in `styles/components/opencode-setup.css`.

Keep this window-owned continuation separate from the latest manually requested folder: run the manual open first, then resume only still-unbound saved tabs under their original selection/order/removal guards. Read-only status refresh and settings maintenance do not replay restoration; disposal cancels it. Never replay uncertain creations, generic errors or session mutations.

## Coding Principles

- Closing a project tab detaches it immediately and requests deletion of that occurrence's logical backend workspace record; failures notify and never retry automatically. Separate occurrences of the same folder are independent. A `workspace.stopped` deletion closes the same record in other windows and notifies only windows displaying it that did not initiate the close. CodeNomad never evicts native Locations; OpenCode sessions keep running and reopening finds them. Whole-window close, app quit, renderer reload and backend shutdown keep existing restoration behavior. Temporary discard and server stop events use local-only tab detachment, not another DELETE; Keep closes the retained project normally.

- Tauri updates use `desktop_updater.rs` and the all-window shutdown coordinator. Only verified downloads can become a pending installer, with restart admission atomic with shutdown. Unsigned builds and Debian packages use the release-page fallback. Native checks follow the saved update feed like server notifications (`update_releases.rs`: stable = newer final releases; preview = newest publication, dev or release); renderers never supply URLs. Keep updater/process plugin commands unavailable to renderers; grant only the guarded application commands to local webviews, and target native menu events at one webview. Publication verifies all four platform receipts, including the signed version, before uploading each release's `latest.json`; only `tauri build` steps see the private key. The vendored updater's Windows exit callback runs only after successful installer launch; see `dev-docs/TAURI_UPDATER.md` and `packages/tauri-app/vendor/README.md`.

- Native session previews behave as tabs in one browser: share the persistent preview profile's cookies/site storage across sessions and projects within a CodeNomad native channel/config profile, but never with the trusted app renderer. Keep documents, navigation stacks, history cursors and automation attachments session-owned. Electron uses `persist:codenomad-browser-shared-v1`; Windows Tauri uses `browser/shared-v1`. Preserve old isolated profiles without silently merging potentially conflicting accounts. Iframe fallbacks keep their existing sandbox; profile sharing is not a reason to grant guest native capabilities.

- The user explicitly forbids modifying OpenCode for Missions autonomy. Use and qualify existing native service/plugin mechanisms; do not infer an upstream-extension requirement from the absence of a named scheduling API or replace the target with a persistent CodeNomad backend.

- Missions autonomy target is explicitly native: the OpenCode service/plugin runs scheduled passages with both CodeNomad UI and intermediary backend closed; a persistent CodeNomad backend is not a substitute. Recurring missions follow `dev-docs/MISSIONS_RECURRING_SIMPLE.md` (2026-10-08), superseding signed recurring authority. One process-local native Job per running schedule sleeps until min(nextDueAt, now + 1h), then rereads clock/document and admits only the latest due civil day newer than lastDaily. A native session-execution terminal event (Bus `listen`, 3 s debounce) also wakes the Job so archives follow family quiescence promptly; the event is a wake hint, never settlement evidence. Pause/Stop cancel the Job; desired running without a live Job is Interrupted until explicit Resume, never automatic rearming. Do not rely on native continuation after a restart: Resume never sends one, and a family turn cut by the restart settles `ended-without-report` / `interrupted`. Host-lifetime work lives outside this tree (see below) and is not native-plugin autonomy acceptance.

- One-time Missions ships through `DesktopPluginLifecycle("missions")` and backend presence, with project-scoped native storage. Recurring `mission_*` tools register independently of backend presence and route by native session to the passage's isolated journal, otherwise the one-time journal. Keep roles independent of native execution IDs. Persist explicit agent/model/variant selections and never switch a busy actor for a queued task. Preserve authenticated admission, ownership/connection/worktree fences and per-send profile environment. One-time map update/control/delete/recovery routes share `server/routes/mission-map-mutation.ts`: creation's fenced connection and worktree-deletion admission, a fresh workspace/connection/location recheck after all preparation, and the permit held through the single unretried RPC. Native permissions govern ordinary tools, including read/shell; recurring passages require no whitelist or per-tool receipts. See `dev-docs/MISSIONS.md` and `dev-docs/MISSIONS_RECURRING_SIMPLE.md`; validate one-time behavior with the isolated `scripts/test-missions-native.mjs` fixture.
- The durable refactor deliberately drops old Mission compatibility: retain the one-time journal `codenomad-missions/v2`, wire/schema version 1 and existing one-time receipts; the historical `codenomad-missions/authority-v2` signed recurring layer is superseded by the simple plugin-kv schedule contract. Do not read, import, mutate or delete old namespaces, restore `migrateLegacy`, or add migration UI; the shipped plugin setup never initializes `authority-v2` and ships no managed-owner observer (`desktop-plugin.test.ts` traps old-namespace access; the bundle test forbids its literal). Recurring create stores paused metadata; Play requires a separate explicit user action, never an automatic send after creation, and needs no signed authorization. Namespace isolation is not native writer quiescence or session/family ownership. Desktop rollout remains subject to current journey validation in `dev-docs/MISSIONS_REFACTOR_VALIDATION.md`, not superseded recurring authority gates.
- A durable mission report and its coordinator notification are distinct. Recover only unacknowledged report notifications through the existing bridge with stable native message IDs and lifecycle fencing; never turn notification recovery into task dispatch or a workflow engine. An admission acknowledgement is not proof of model consumption or mission completion.
- The recurrence core lives in `missions/recurrence-{contract,clock,store,runner}.ts`; its simple schedule document uses plugin kv with custom revision CAS (native kv has none), title/instructions/daily clock, frozen profiles/taskMode/template, watched conversations, paused/running/stopped state, lastDaily, pending and history ≤30. Stopped is terminal. CAS-write pending deterministic passageID/coordinatorSessionID/messageID before native effects; rely on caller-ID idempotent session creation and first-admission-wins message IDs. Reconcile session/message/inbox after crashes, never resend under a new identity; Resume with pending is reconcile-only. Archive/clear pending/update lastDaily atomically only after coordinator and all descendants are inactive, inboxes empty, no pending Form/permission or running Shell/background subagent. Outcomes are completed with final report, native terminal failed, or ended-without-report; only completed advances watched cursors. Unknown coverage stays pending. No per-minute polling, window timer, signed grants, effect receipts/budgets or exact event-log replay settlement. Variant omission is valid, day-end DST gaps advance, and wholly skipped civil days have no passage.
- Wayfinder human gates in one-time and recurring missions accept only native Forms with the backend's simple UI-answer mark `{ formID, sessionID, answeredAt, via: "ui" }`, recorded when answered through `InterruptionDock` by an explicit bridge principal: a local auth-enabled cookie session or a live paired Remote Control device (never a device ID posing as a cookie), revalidated across native I/O. Family membership is root `codenomad.mission` metadata or, for attached existing coordinators, exact durable one-time journal coordinator membership confirmed by the plugin; marks live under `codenomad-missions/human-marks-v1`. Native OpenCode has no Form answerer identity; no signatures or reserved/replied/settled answer receipts. This mark is provenance under native permissions/OS isolation, not protection against an unrestricted shell reading the service password or kv database; in-process signatures would not provide that protection either.
- Explicit targeted Mission recovery uses `missions/recovery-input.ts` and `missions/native-recovery-observation.ts`: reconcile saved actor locations, all bounded descendant inboxes and activity, applicable global Forms/permissions and uncorrelated running Shells; recheck identities after asynchronous preparation. Unknown observations fail closed. Recovery never replays an assignment, changes the plan or claims model consumption from admission.
- `packages/server/src/host-lifetime/` keeps only the private-storage, process-identity and profile-scope primitives that the shipped Missions code uses (`storage`, `private-storage-sync`, `windows-storage`, `process-identity`, `protocol`). The persistent-backend foundation (manager/backend entries, native runtime/Missions channel, `packages/native-host-lifetime`, the durable host and its fixtures) is separate, non-activated work kept on the local branch `experiment/host-lifetime-foundation-20261009`; it is not Missions native-plugin acceptance and must not be reintroduced through this product tree. Never replace a native ownership gate with a no-op or environment flag, steal a live/unknown owner, log secrets, or include the shared OpenCode daemon in backend cleanup.
- Optional mission specialist cleanup records immutable tombstone targets and per-session receipts. Use the authenticated bridge and authoritative `cleanupTarget` RPC before native HTTP deletion; plugin contexts do not expose native session removal. Preserve coordinators, reused/shared/moved sessions and roots with descendants. Partial cleanup retries retain the original request identity and never become a background dispatcher.
- One-time Mission Play starts/resumes through durable explicit lifecycle intent; Pause interrupts the whole native mission family and parks Mission notifications/dispatch, while Stop is terminal. Each root target first walks its native descendants (`readNativeControlFamily`, ≤4096, paginated, cycle-safe, never the 32-session display read) and interrupts active ones deepest first through the same `session.interrupt({ resume: false })`, with bounded re-interrupt passes because native subagent results resume their parent; Stop also cancels queued descendant inputs and the root's mission and native `source: "subagent"` deliveries so a stopped coordinator is not re-woken (`missions/native-family-interrupt.ts`). Receipts carry a bounded `descendants` summary; budget exhaustion or anything still active is `complete: false` and surfaces as "some sub-agents may still be running" — never claim a full stop without that evidence. Play tells the coordinator which descendant conversations were interrupted; it re-delegates, there is no workflow engine. One-time native acknowledgements retain per-target receipts and explicit retries, with the same authenticated bridge, environment and ownership fences; these receipts are not required for recurring passages. Recurring Pause/Stop cancel the schedule Job and do not prove native passage sessions stopped. Coordinator recovery is offered only on observed `idle-without-report`, never on `unknown`; an oversized family with an active descendant projects as background/recovery-busy. Do not turn notification recovery into a control-action runner. One-time lifecycle state and actions live in `createMissionLifecycle` (`components/mission-lifecycle-controls.tsx`), surfaced only as the toolbar's primary action and Stop; an unresolved request offers Check status, and the header ⟳ resends it with the same request identity after its read-only refresh, never a fresh action.

- Browser preview state is keyed by project folder and session ID. Keep explicitly opened guests mounted in stable DOM order across chat/session/Info/project visibility changes; the preview's X also hides it and returns to chat without discarding history. Only their lightweight session shells remain: inactive transcripts and composers still unmount and the transcript memory budget stays independent. Hidden guests must stop being automation targets (Electron unregisters, Tauri hides). Old project-wide URLs migrate once to the first restoring session. Across renderer restart, restore URL history/cursor only on explicit browser opening; never eagerly visit saved pages or persist native pageState/forms/POST bodies. Reuse owned CDP history IDs for live traversal and load just the selected saved URL when its native entry no longer exists. History is bounded to 32 URLs/session within the existing 4 KB aggregate layout budget; trim history before evicting saved previews.

- Settings → Info's Report a bug opens the `bug_report.yml` issue form with its text fields prefilled by id (`BUG_REPORT_FIELDS` in `lib/bug-report.ts`). When the template changes, keep those ids and their input/textarea types in sync: `lib/bug-report.test.ts` checks the repository's template. The section warms a bounded read of the form published on the default branch; the click never waits for it (WebKit drops user activation after about 1 s), using the settled assessment or else the form while a background read retries. Only a proven incompatible form (missing, unparsable, prefilled field removed or retyped) falls back to a blank issue carrying the same Markdown report; an unreachable read keeps the form. Never prefill listeners, addresses, paths, credentials or conversation data.

- Notification icon badges mirror the existing per-window bell/history unread count, never session status or native OS notification delivery. The browser favicon uses a dot; native Electron/Tauri hosts aggregate live primary-window counts and clear contributions on reload/close, keeping preferences and preview guests outside the badge authority. Keep UI projection in `lib/notification-icon-badge.ts` and host dispatch in `lib/native/notification-badge.ts`; do not add discovery scans or polling. PWA launcher badging is separate from tab favicons and is not enabled by this feature.

- Distinguish two production models: (1) a product built and shipped with a controlled, pinned toolchain/library set, where pins define the reproducible build; (2) an application integrating with an independently installed and updated service, where compatibility depends on the API/capability contracts actually consumed. CodeNomad connecting to OpenCode is model (2), even when its SDK/build dependencies are pinned. Never turn the versions used to build or test CodeNomad into an allowlist for the external daemon. Review upstream changes against actual callers; private API use requires contract scrutiny, not automatic exclusion of unfamiliar versions. "Tested with" does not mean "works only with".

- Never block a runtime or feature solely because its version is untested. A version-specific restriction requires either a demonstrated failing test or an identified breaking API change affecting a contract actually consumed by CodeNomad; cite the evidence and explain why the restriction is necessary. Review upstream changes and affected callers rigorously; exhaustive testing of unchanged contracts is not required. Distinguish untested from incompatible and prefer validated capabilities/contracts over speculative version allowlists. Missing capabilities must fail safely without destructive or mass-loading fallbacks.

- Workspace text remains editable in the central file reader (including Markdown source), with Save and Ctrl/Cmd+S. Keep dirty drafts in `components/workspace-file-editor.ts`, scoped by instance/directory/path; invalidation must not replace them. Saves reread for external-change confirmation and pass the exact owned directory through the deletion-fenced filesystem write route. Images, binary content and historical diffs remain read-only.

Keep selection beneath the entire row including controls and rollover in `styles/panels/control-hover.css`. Changes keeps staged/unstaged disclosures with commit actions at the top of the staged section. Git image readers use exact bounded HEAD/index/worktree or parent/commit bytes, not current-file substitutes for historical content.

- The Files panel combines Workspace, Changes and Commits in one compact switch, initially on Workspace. Its lazy worktree tree preserves expanded folders while switching modes; tree styles live in `styles/panels/workspace-tree.css`, Git navigation in `styles/panels/git-history.css`, row actions in `styles/panels/file-row-actions.css`. The UI uses a small custom i18n layer (no ICU/messageformat). When building features, never hardcode user-visible strings.

- **Runtime API:** use `useI18n()` in components (`const { t } = useI18n();`) and `tGlobal(...)` in stores/non-component code.
  - Implementation: `packages/ui/src/lib/i18n/index.tsx`
- **Where messages live:** `packages/ui/src/lib/i18n/messages/<locale>/` as TypeScript objects (`"flat.dot.keys": "string"`).
  - Each locale has an `index.ts` that merges message parts; duplicate keys throw at build time.
  - Merge helper: `packages/ui/src/lib/i18n/messages/merge.ts`
- **Adding a new string:** add it to the appropriate `.../messages/en/*.ts` part file, then add the same key to each other locale’s corresponding file.
  - Missing translations fall back to English (and finally to the key), so gaps can be easy to miss.
- **Interpolation:** placeholders are simple `{name}` replacements (word characters only). Avoid placeholders like `{file-name}`.
- **Pluralization:** handle manually via separate keys like `something.one` / `something.other` and choose in code.
- **Adding a new language:** add a new `messages/<locale>/` folder + `index.ts`, register it in `packages/ui/src/lib/i18n/index.tsx`, and add it to the language picker in `packages/ui/src/components/folder-selection-view.tsx`.

- **Avoid English-only paths:** do not import `enMessages` directly in feature code; always go through `t(...)` so locale changes apply.

## File Length Guidelines (Highlight Only)
